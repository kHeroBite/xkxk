# 소스 구조 공통 원칙

> 상태: 확정 · 최종 갱신일: 2026-11-26
> 역할: 저장소의 모든 영역이 함께 따르는 소스 구조 원칙을 담는다. 층 이름·참조 허용표·검사 도구는 영역마다 다르므로 영역 문서에 둔다.
> 근거: 사용자 지시 '레이어 철저 분리'와 '소스는 짧게'(제품군 공통). 향후과제 UTODO-0010 의 처리 결과다.

## 1. 층 분리 원칙
- 화면 조립(UI/UX), 컨트롤, 데이터를 서로 다른 층으로 나눈다. 시험·PoC 코드도 같은 규칙을 따른다.
- 참조는 한 방향으로만 흐른다. 아래 층은 위 층과 호스트를 알지 못한다.
- 데이터 층은 UI 프레임워크 패키지를 참조하지 않는다. 순수 UI 층은 업무 데이터를 참조하지 않는다.
- 층 경계는 말로만 두지 않고 검사 도구가 규칙 파일로 자동 점검하게 한다. 위반이면 검사가 실패한다.
- 층의 이름과 참조 허용표는 영역마다 정한다. 예시는 별별UI 영역의 `/mnt/c/DATA/Project/xkxk/frameworks/ui/AGENTS.md` §5 와 `/mnt/c/DATA/Project/xkxk/frameworks/ui/plan/04_기술스택/02_소스구조_분할규칙.md` 이다.

## 2. 소스 파일 크기와 책임 분할
- 소스 파일은 300줄 이하로 둔다. 넘으면 책임 단위로 나눈다.
- 분할 기준은 책임이다. 줄 수만 맞추려고 기계적으로 쪼개거나 `partial` 로 나누지 않는다.
- 언어·파일 종류별 세부 상한(예 axaml)은 영역 정본에 둔다. 별별UI 는 위 `02_소스구조_분할규칙.md` 에 있다.

## 3. 첫 줄 헤더 주석
- 새 소스 파일 첫 줄의 한국어 한 줄 역할 주석 규칙은 저장소 루트 `/mnt/c/DATA/Project/xkxk/CLAUDE.md`(Tier1)가 정본이다. 이 문서에 다시 적지 않는다.
