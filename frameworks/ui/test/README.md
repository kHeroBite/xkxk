## 안전 규칙 (모든 도구 공통)
1. 사용자 파일(layout.json·settings.json)은 건드리지 않는다. 임시 프로필(`--profile-dir` 빈 새 폴더)이나 `--fresh` 로 띄우고, 시험 전후 md5 를 결과에 남긴다(common/measure/retest_user_files.py).
2. 스크린샷은 경로를 명시한다(retest_remote 의 shot_dir_ok, `--data-dir` 필수).
3. 실입력(커서·클릭·끌기)은 `.claude/scripts/safe_click.ps1` 로만 보낸다(`-ExpectedProcessId` 필수). 입력 직전마다 common/measure/fg_info.ps1 로 전경 pid 를 확인한다. 화면 경계 100px 이내 좌표와 가장자리 끌기는 금지다. 이 규칙은 좌표 입력 규칙이므로 좌표를 쓰지 않는 UIA 경로(tray_uia.ps1 등)는 적용 대상이 아니다. 2026-11-25(D-7)부터 `tools/safe_click.ps1` 은 safe_wheel.ps1 과 같은 형식으로 자기 주입(`click`·`dblclick`·`drag`·`wheel`·`cursor_move`, 각각 `_pre`→완료 또는 `_failed`)을 `logs/pcaway/injections.jsonl` 에 스스로 남긴다(`-InjectionLog` 로 바꿀 수 있음, 기록 실패면 입력하지 않음). 그래서 감싸지 않고 불러도 PC 비움 감시기가 시험 클릭을 사용자 입력으로 오인하지 않는다.
4. 프로세스 종료는 자기가 띄운 PID 만 한다(`taskkill /PID`). 이름으로 일괄 종료하지 않는다.
5. 판정 규칙은 결과를 보기 전에 파일로 고정한다. 사후 완화는 하지 않는다.
6. 파이썬은 `python3 -B` 로 실행한다.
7. 기본값을 바꾼 옵션의 공식 측정(예: A15 `w10_web.py` drag_os)은 설정 키가 없는 새 프로필로 재고, 같은 해시 진단판 원격 조회(`chrome.moveLight`)로 적용값을 먼저 확인한다. 설정 저장은 값을 항상 기록하므로 한 번 저장한 프로필에는 옛 값이 남아 새 기본값이 적용되지 않는다(리드 결정 D-47, 2026-11-15).
8. WSL 이 강제 종료된 뒤에는 실행기 상태 파일의 done 기록을 믿지 않는다. 결과 파일이 0바이트가 아니고 끝이 NUL 이 아니며 JSON 으로 파싱되는지 확인하고, 아니면 그 회차를 무효로 다시 잰다(2026-11-15 r12d 공식 측정에서 mdi.json 0바이트·로그 끝 NUL 실례).

  - `retest_window_menu.py --target desktop --isolated`: 사용자 폴더(%LOCALAPPDATA%\xkxk\frameworks\ui) layout·settings 백업·복원을 생략한다. 연결된 앱 PID 명령줄에 사용자 폴더(하위 폴더·정션 포함)가 아닌 `--data-dir` 가 있을 때만 실행하고(`--profile-dir` 만으로는 격리로 보지 않는다), 확인하지 못하면 rc=3 으로 거부한다. 재기동은 `--no-kill` 로 하고 첫 기동의 `--data-dir`·`--profile-dir`·`--multi-instance` 를 넘긴다. 재기동한 앱이 격리 확인에 실패하면 이 도구가 띄운 앱(run_desktop_bg 출력의 로그 이름이 명령줄에 있는 PID)만 내린다. 종료는 시험 앱 PID 하나만 한다(사용자 Pd 는 종료하지 않음).
  - `retest_remote_z.py --isolated`: 동작은 위와 같다(사용자 폴더 백업·복원 생략, 앱 격리 확인 실패 시 rc=3, 재기동 앱도 다시 확인). user 모드에서는 첫 기동의 `--profile-dir` 를 넘기지 않고, 도구 인자 `--profile-dir`(비어 있는 새 임시 폴더)를 앱에 준다.
  - 두 도구 모두 비격리 기본 모드는 사용자 Pd(run_desktop_bg 로 띄우지 않은 Pd)가 떠 있으면 실행 전에 rc=3 으로 거부한다. 사용자 Pd 를 그대로 둔 채 시험하려면 `--isolated` 를 쓴다.
