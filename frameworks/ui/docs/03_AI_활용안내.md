## 별별UI(xkxk.frameworks.ui) 사용 규칙 — AI 에이전트용

이 프로젝트는 별별UI 프레임워크를 쓴다. UI 셸·메뉴·명령·아이콘·창을 다룰 때 아래 규칙을 따른다.
경로는 별별UI 저장소(XKXK 모노레포) 기준이다.

### 규칙
1. 공개 네임스페이스 `xkxk.frameworks.ui.shell.Framework` 의 형식만 쓴다. 쓸 수 있는 멤버의 정본은 `frameworks/ui/docs/api/README.md` 와 그룹 문서다. 없는 멤버를 추측해 만들지 않는다.
2. 확장은 모듈로 한다. `UiModule` 을 상속해 `Id` 와 `Configure` 를 구현하고, 빌더에 `XkxkUiBuilder.AddModule` 로 넣는다. `Configure` 인자 이름은 `ui` 로 쓴다(명세의 이름은 `context` 지만 재정의 때 이름을 바꿔도 되며, 문서 검사기가 `ui.` 체인으로 멤버 실재를 확인하기 때문이다).
3. 등록은 `ui.Icons`·`ui.Commands`·`ui.Menus`·`ui.Windows` 의 `Add` 로 한다(아이콘은 `IUiIconRegistry.AddGeometry` 도 있다). 옵션 객체의 속성을 람다 안에서 채운다(예 `UiCommandOptions`·`UiMenuItemOptions`·`UiWindowOptions`).
4. ID·키는 자기 제품 접두어로 짓는다(예 `ohoops.report.open`). 모듈 ID 도 같다.
5. 셸 기본 항목은 상수로 가리킨다. 명령은 `ShellCommandIds`, 메뉴는 `ShellMenuIds` 다. 문자열을 손으로 적지 않는다.
6. 셸 메뉴를 바꿀 때는 비파괴 동작을 먼저 쓴다. 숨김은 `IUiMenuRegistry.SetHidden`, 자리 옮김은 `IUiMenuRegistry.Move` 다. 셸 항목은 `Remove` 할 수 없다.
7. 등록 결과는 반환값(bool)과 진단으로 확인한다. 진단은 `XkxkUiApplication.Diagnostics`(빌드 때)와 `IUiAppContext.Diagnostics`(실행 중, `XkxkUi.Current` 로 얻음)에 쌓인다.
8. 개발 중에는 `XkxkUiBuilderOptions.ErrorPolicy` 를 `UiErrorPolicy.Throw` 로 두어 Error 진단을 `UiConfigurationException` 으로 바로 드러낸다. 기본값은 `UiErrorPolicy.Collect` 다.
9. 창은 강타입 등록을 먼저 쓴다. `UiWindowViewModel<TArgs>`(인자 없으면 `UiWindowViewModel`)를 상속한 뷰모델과 `Control` 뷰를 만들고, 모듈에서 `ui.Windows.Register<뷰모델, 뷰, 인자>(id, o => …)` 로 등록한다(`using xkxk.frameworks.ui.views.Windows;` 필요). 이 확장 메서드는 화면 층(`xkxk.frameworks.ui.views`)의 `UiWindowViewRegistration` 에 있고, 화면 층에서 쓰는 것은 이 클래스뿐이다. 서명은 `frameworks/ui/docs/04_확장_창.md` 3절이 정본이다(api/ 명세에 없음). 첫 열기를 빠르게 해야 하면 옵션의 `Prewarm = UiWindowPrewarm.Warm`(또는 `KeepReady`)을 쓴다(기본 `None`, 같은 문서 2.4절).
10. 뷰모델은 `OnOpenedAsync` 에서 초기화하고 `Window`(`IUiWindowContext`)로 `SetTitle`·`Close`·`BeginBusy` 를 쓴다. 생성자에서 `Window` 를 읽지 않는다. 복원한 문서는 인자가 null 이라 `Args` 가 기본값이므로 처리한다.
11. 창은 `IUiWindowRegistry.Open` 으로 연다(명령 처리기에서는 `UiCommandContext.Windows`). `Configure` 안에서는 열지 않는다. 강타입이 맞지 않는 창만 `UiWindowOptions.CreateContent` 를 직접 채워 부를 때마다 새 Avalonia `Control` 을 돌려준다.

### 금지
- 옛 정적 위임 접근자를 쓰지 않는다: `App.MainViewModel`·`App.Shell`·`ViewRegistry.Current`·`Loc.Instance`·`UiSettings.Current`·`ThemeCatalog.Current`·`TourCatalog.Current`·`MonitorMenuViewModel.Instance`. 앱 컨텍스트로 위임만 하는 옛 길이며 뒤 판에서 사용 중단 예고 뒤 지울 예정이다. 대신 `XkxkUi.Current` 의 멤버를 쓴다.
- 프레임워크 예약 접두어 `xkxk.` 로 새 명령·메뉴·창 ID 나 창 별칭을 만들지 않는다(`xkxk.*` 는 프레임워크 전용, 진단 `XKUI0308`·`XKUI0407`·`XKUI0503`).
- 옛 이름·숫자 `Grid`·`Gantt`·`Form`·`0`·`1`·`2`(대소문자 무시)를 창 ID·별칭으로 쓰지 않는다. 데모 창을 가리키는 영구 예약어다(ID 는 진단 `XKUI0502` 로 등록 거부, 별칭은 `XKUI0503` 으로 그 별칭만 버림). 데모 창·데모 열기 명령은 별별UI 저장소의 시험대 모듈 것이라 소비 앱에는 없다.
- 뷰모델의 `AttachWindow`·`NotifyOpenedAsync`·`NotifyClosed` 는 프레임워크 전용이다. 부르지 않는다. 창 문맥(`IUiWindowContext`)도 구현하지 않는다.
- 화면 층에서 '시험대 지원용'으로 public 이 된 형식(벤치·그리드 내부 형식 등)을 쓰지 않는다. 공개 계약이 아니다.
- 공개 네임스페이스 밖의 형식(뷰모델·`IShellCommands`·Docking·Theming·데이터 층 등)에 직접 기대지 않는다. public 이어도 공개 계약이 아니라 예고 없이 바뀐다.
- 프레임워크 인터페이스(`IUiAppContext`·`IUiModuleContext`·레지스트리 인터페이스)를 직접 구현하지 않는다. 프레임워크만 구현한다.
- 공개 API 가 지금 모양 그대로 고정이라고 가정하지 않는다. 사전판 동안 전부 Unshipped 다. 판을 올릴 때마다 명세를 다시 확인한다.
- 문서에 없는 "예정" 기능(독·테마·설정 확장, 창 닫기 거부 등)을 지금 있는 API 로 지어내지 않는다.

### 검증
- 빌드: 솔루션을 빌드해 오류 0 을 확인한다.
- 진단: 앱 빌드 뒤 `UiDiagnostics.HasErrors` 가 false 이고 `UiDiagnostics.Entries` 에 내 모듈 ID 로 된 Warning·Error 가 없는지 본다.
- 등록 확인: `IUiCommandRegistry.Contains`·`IUiIconRegistry.Contains`·`IUiMenuRegistry.GetState`·`IUiWindowRegistry.Contains` 로 실제 등록·표시 상태를 본다.
- 진단 코드(`XKUI` + 4자리)가 나오면 `frameworks/ui/docs/api/README.md` 진단 표에서 뜻을 찾아 고친다.

## 2. 작업 절차 — AI 가 별별UI 확장 작업을 받았을 때

1. 요청을 "아이콘·명령·메뉴·창 중 무엇을 더하거나 바꾸는가"로 나눈다. 창이면 [창 확장](04_확장_창.md) 을 따르고 강타입 등록(3절)을 먼저 쓴다. 그 밖(독·테마·설정)이면 [메뉴·명령·아이콘 확장](02_확장_메뉴명령아이콘.md) 의 '예정' 절을 보고, 지금 공개 API 가 없으면 없다고 보고한다.
2. [공개 API 명세](api/README.md) 에서 쓸 형식·멤버를 고른다. 명세에 없는 멤버는 쓰지 않는다.
3. 자기 모듈(`UiModule` 파생) 하나에 등록 코드를 모은다. 모듈 ID·명령 ID·메뉴 ID·창 ID·아이콘 키는 같은 제품 접두어로 짓는다.
4. 명령이 쓰는 아이콘을 먼저, 메뉴가 쓰는 명령을 그다음, 메뉴를 마지막에 등록한다. 메뉴 항목의 명령 확인(`XKUI0405`)은 빌드 끝에 한 번 하므로 다른 모듈의 명령을 가리켜도 되지만, 같은 모듈 안에서는 이 순서가 읽기 쉽다.
5. 빌드하고, 위 블록의 '검증' 을 한다. 진단이 나오면 4절 대응표로 고친다.
6. 결과 보고에 쓴 공개 형식·멤버 이름과 남은 진단(0 이어야 한다)을 적는다.

## 3. 예제

예제는 지금 있는 공개 API 만 쓴다. `using xkxk.frameworks.ui.shell.Framework;` 를 전제로 한다.

### 3.1 모듈 1개에 아이콘·명령·메뉴 등록

```csharp
using xkxk.frameworks.ui.shell.Framework;

public sealed class OhoopsModule : UiModule
{
    public override string Id => "ohoops.main";

    public override void Configure(IUiModuleContext ui)
    {
        // 아이콘 — 경로 데이터로 등록한다(키는 예약하지 않지만 자기 접두어를 쓴다)
        ui.Icons.AddGeometry("ohoops.icon.report", "M0,0 L16,0 L16,16 L0,16 Z");

        // 명령 — 옵션 람다로 제목·아이콘·단축키·실행을 채운다
        ui.Commands.Add("ohoops.report.open", c =>
        {
            c.Title = "보고서 열기";
            c.Icon = "ohoops.icon.report";
            c.Gesture = "Ctrl+Shift+R";
            c.Execute = ctx => { /* 자기 제품 코드로 보고서를 연다 */ };
        });

        // 메뉴 — 셸 '파일' 메뉴의 그리드 열기 뒤에 넣는다
        ui.Menus.Add("ohoops.menu.reportOpen", m =>
        {
            m.Parent = ShellMenuIds.File;
            m.Kind = UiMenuItemKind.Command;
            m.CommandId = "ohoops.report.open";
            m.InsertAfter = ShellMenuIds.FileOpenGrid;
        });
    }
}
```

빌더에 넣고 진단을 확인하는 부분이다. 호스트 연결(`UseXkxkUi`·`UiHostOptions`)은 [시작하기](01_시작하기.md) 를 따른다.

```csharp
var options = new XkxkUiBuilderOptions { ErrorPolicy = UiErrorPolicy.Throw }; // 개발 중
var app = XkxkUi.CreateBuilder(options)
    .AddModule<OhoopsModule>()
    .Build();

foreach (var d in app.Diagnostics.Entries)
    Console.WriteLine(d); // 비어 있어야 한다
```

- 메뉴 제목을 주지 않으면 명령 제목(`UiCommandDefinition.Title`)을 쓴다. 메뉴 아이콘도 명령 아이콘으로 이어진다.
- 단축키가 셸 기본 단축키와 같으면 `XKUI0310` 경고가 나고 셸 쪽이 키를 받는다. 다른 조합을 쓴다.

### 3.2 셸 메뉴 숨김·이동

```csharp
public sealed class OhoopsMenuTweaks : UiModule
{
    public override string Id => "ohoops.menuTweaks";

    public override void Configure(IUiModuleContext ui)
    {
        // 숨김 — 비파괴. false 로 되돌릴 수 있다
        ui.Menus.SetHidden(ShellMenuIds.SystemGpuRestart, true);

        // 이동 — '도움말' 을 '파일' 메뉴의 끝내기 앞으로 옮긴다
        ui.Menus.Move(ShellMenuIds.SystemHelp, p =>
        {
            p.Parent = ShellMenuIds.File;
            p.InsertBefore = ShellMenuIds.FileExit;
        });
    }
}
```

- `SetHidden`·`Move` 는 등록 주체와 무관하게 허용되며 셸 항목의 Owner 는 바뀌지 않는다.
- 최상위로 옮길 때는 `UiMenuPlacementOptions.ToRoot` 를 true 로 둔다.
- 숨긴 항목은 `IUiMenuRegistry.GetState` 의 `UiMenuItemState.IsVisible` 이 false 다. 모바일 서랍에서도 그 하위까지 빠진다.
- 이동 대상이 없거나, 자기 자손 아래로 옮기거나, 새 부모가 하위 메뉴가 아니면 `XKUI0410` 이고 옮기지 않는다.

### 3.3 강타입 창 등록과 열기

뷰모델(`UiWindowViewModel<TArgs>` 상속)·뷰(`Control`)·인자 형식의 전체 예제는 [창 확장](04_확장_창.md) 3.4절이다. 모듈 쪽 핵심은 아래 두 줄이다(화면 층 네임스페이스 using 필요, 같은 문서 3절).

```csharp
// Configure(IUiModuleContext ui) 안. 파일 머리에 using xkxk.frameworks.ui.views.Windows;
ui.Windows.Register<OhoopsReportViewModel, OhoopsReportView, OhoopsReportArgs>("ohoops.report.view", o => o.Title = "보고서");
ui.Commands.Add("ohoops.report.open", c =>
{
    c.Title = "보고서 열기";
    c.Execute = ctx => ctx.Windows.Open("ohoops.report.view", w => w.Parameter = new OhoopsReportArgs("R-001"));
});
```

- 인자 형식이 다른 값으로 열면 `XKUI0509` 이고 열기 반환값은 true 다. 진단으로 확인한다.
- 3.1절의 메뉴 항목이 이 명령을 가리키면 메뉴에서 창이 열린다.

## 4. 진단 대응표

전체 표는 [공개 API 명세](api/README.md) 의 진단 절이다. AI 작업에서 자주 나오는 것만 모았다.

| 코드 | 뜻 | 고치는 법 |
|---|---|---|
| `XKUI0001` | 모듈 ID 가 비었다 | `UiModule.Id` 에 자기 접두어 ID 를 준다 |
| `XKUI0002` | 같은 모듈 ID 를 두 번 넣었다 | `AddModule` 중복을 지우거나 ID 를 바꾼다 |
| `XKUI0003` | 모듈 `Configure` 가 예외를 냈다 | 메시지의 예외를 고친다. Throw 정책이면 `UiConfigurationException.Diagnostics` 를 본다 |
| `XKUI0201` | 아이콘 키가 비었다 | 키를 준다 |
| `XKUI0202` | 같은 아이콘 키 중복 | 다른 키를 쓰거나 `UiIconOptions.Replace` 를 true 로 둔다 |
| `XKUI0203` | 아이콘 옵션의 `PathData`·`ResourceKey` 가 0개 또는 2개다 | 둘 중 하나만 준다 |
| `XKUI0301` | 명령 ID 가 비었다 | ID 를 준다 |
| `XKUI0302` | 같은 명령 ID 중복 | 다른 ID 를 쓰거나 `UiCommandOptions.Replace` 를 true 로 둔다 |
| `XKUI0303` | 명령에 실행 대리자가 없다 | `UiCommandOptions.Execute` 를 채운다 |
| `XKUI0304` | 명령의 아이콘 키를 해석하지 못했다(명령은 아이콘 없이 남음) | 아이콘을 먼저 등록하거나 키 철자를 고친다 |
| `XKUI0305` | 단축키 문법이 틀렸다 | `Ctrl+Shift+R` 꼴(수정자 Ctrl·Shift·Alt·Meta + 키)로 쓴다 |
| `XKUI0308` | `xkxk.` 로 새 명령 ID 를 만들었다 | 자기 제품 접두어로 바꾼다 |
| `XKUI0309` | 다른 주체의 명령을 지우려 했다 | 지우지 않는다. 바꾸려면 `Replace` 로 재정의한다 |
| `XKUI0310` | 단축키가 기존 명령과 겹친다 | 다른 조합을 쓴다(등록은 됨) |
| `XKUI0403` | 메뉴 부모가 없거나 하위 메뉴가 아니다 | `ShellMenuIds` 의 하위 메뉴 상수나 자기가 등록한 Submenu 를 부모로 준다 |
| `XKUI0404` | 삽입 앵커가 같은 부모 아래 없다 | `InsertAfter`·`InsertBefore` 를 같은 부모의 항목으로 고친다(맨 뒤에 붙음) |
| `XKUI0405` | 메뉴의 명령 ID 가 없다 | 명령을 등록하거나 철자를 고친다(항목은 비활성으로 남음) |
| `XKUI0406` | 메뉴 종류와 속성 조합이 틀렸다 | Command 는 `CommandId`, Section 은 `Section` 을 준다 |
| `XKUI0407` | `xkxk.` 로 새 메뉴 ID 를 만들었다 | 자기 제품 접두어로 바꾼다 |
| `XKUI0408` | 다른 주체의 메뉴를 지우려 했다 | 셸 항목은 `SetHidden` 으로 숨긴다 |
| `XKUI0410` | 메뉴 이동이 무효다 | 대상·새 부모(하위 메뉴)·순환 여부를 확인한다 |
| `XKUI0411` | 표시 조건·툴팁 대리자가 예외를 냈다 | 대리자 안의 예외를 고친다 |
| `XKUI0501` | 창 ID 가 비었거나 공백이다 | 자기 접두어 ID 를 준다 |
| `XKUI0502` | 창 ID 를 쓸 수 없다. 같은 ID 중복, 다른 창의 ID·별칭과 겹침(대소문자 무시), 옛 이름·숫자 ID(등록 안 됨) | 겹치지 않는 자기 접두어 ID 를 쓴다. 같은 ID 의 창을 바꾸려면 `UiWindowOptions.Replace` 를 true 로 둔다 |
| `XKUI0503` | `xkxk.` 로 새 창 ID 를 만들었다(등록 안 됨). 또는 `xkxk.`·옛 이름·숫자 별칭을 더했다(그 별칭만 버리고 창은 등록) | ID 는 자기 제품 접두어로 바꾸고, 해당 별칭은 지운다([창 확장](04_확장_창.md) 2.1절) |
| `XKUI0504` | 창 별칭이 다른 창과 겹친다(그 별칭만 버림) | 다른 별칭을 쓴다 |
| `XKUI0505` | 등록 안 된 창을 열거나 복원했다 | ID 철자를 확인하고 모듈 `Configure` 에서 등록한다 |
| `XKUI0506` | 셸 준비 전에 창을 열었다 | 화면이 뜬 뒤(예 명령 실행)에 연다 |
| `XKUI0507` | 창 내용 생성이 실패했다(예외·null·`Control` 아님), `CreateContent` 가 없다, 또는 강타입 등록의 뷰모델 생성 함수가 null·예외다 | 강타입 등록으로 바꾸거나 `CreateContent` 를 채워 새 `Control` 을 돌려주게 한다 |
| `XKUI0508` | 다른 주체의 창을 지우려 했다 | 지우지 않는다. 바꾸려면 `Replace` 로 재정의한다 |
| `XKUI0509` | 강타입 창을 뷰모델이 받지 않는 형식의 값으로 열었다(자리표시 문서) | `UiWindowOpenOptions.Parameter` 에 등록한 인자 형식을 넣는다 |
| `XKUI0510` | 뷰모델 `OnOpenedAsync`·`OnClosed` 가 예외를 냈다(뷰는 유지) | 메시지의 예외를 고친다. 창이 닫혀 취소된 것은 남지 않는다 |

## 5. 이 문서 갱신 방법(별별UI 저장소 작업자용)

- 공개 API 가 바뀌는 batch 는 명세 생성기를 다시 돌린 뒤 이 문서를 맞춘다. 순서는 아래와 같다(영역 루트 `frameworks/ui` 기준).
  1. `python3 -B tools/gen_api_docs.py` — `docs/api/` 재생성(손으로 고치지 않는다)
  2. 이 문서의 블록·예제·대응표를 새 API 에 맞춘다. 예정 API 는 코드 블록이나 백틱에 넣지 않는다.
  3. `python3 -B test/framework/judge/consumer_docs_check.py` — 식별자 실재·링크·마커(블록 80줄 이하) 검사, rc=0
  4. `bash test/framework/verify_framework.sh --stage docs` — rc=0
- 복사용 블록을 바꾸면 '최종 갱신일' 을 고치고, 소비 제품(ohoops 등)에 블록을 다시 붙여 넣으라고 알린다.
- 1절 블록의 시작·끝 마커 주석 두 줄은 문자열을 바꾸지 않고, 이 파일 안에 각각 한 번만 둔다. 소비 제품이 이 두 줄로 블록을 찾아 교체한다.
