# 02 확장 — 메뉴·명령·아이콘

- 상태: 사전판(0.x 이전). 여기 나오는 공개 API 는 전부 미출시(Unshipped) 표면이다.
- 최종 갱신일: 2026-11-27
- 먼저 읽을 것: [01_시작하기.md](01_시작하기.md)(빌더·모듈·진단). 정확한 서명은 [api/README.md](api/README.md).

별별UI 의 메뉴·명령·아이콘은 각각 **레지스트리** 하나에 ID 로 등록한다. 레지스트리는 프로세스에 하나씩이며 두 곳에서 얻는다.

| 얻는 곳 | 등록 주체(Owner) | 쓰는 때 |
|---|---|---|
| 모듈의 `IUiModuleContext.Icons`·`IUiModuleContext.Commands`·`IUiModuleContext.Menus` | 그 모듈 ID | 모듈 `Configure` 안(권장) |
| 앱 컨텍스트의 `IUiAppContext.Icons`·`IUiAppContext.Commands`·`IUiAppContext.Menus`(`XkxkUi.Current`) | `app`(`UiRegistryOwners.App`) | 실행 중 바꿀 때 |

두 길은 같은 저장소를 보므로 어디서 등록해도 모두에게 보인다. 셸 기본 명령·메뉴의 주체는 `xkxk.shell`(`UiRegistryOwners.Shell`), 기본 생성 아이콘 공급자의 주체는 `xkxk.generated`(`UiRegistryOwners.Generated`)다.

## 1. 공통 규칙

### 1.1 예약 접두어 `xkxk.`

- `xkxk.` 로 시작하는 ID 는 프레임워크 몫이다(`UiRegistryOwners.ReservedPrefix`, 대소문자 구분).
- 쓰는 쪽은 `xkxk.` 로 시작하는 **새** 명령 ID(XKUI0308)·메뉴 ID(XKUI0407)·아이콘 공급자 Id(XKUI0206)를 만들 수 없다. 이미 있는 셸 ID 를 `Replace` 로 바꾸는 재정의는 된다.
- 쓰는 쪽 ID 는 자기 접두어를 붙인다(예 `acme.report.open`). 그러면 프레임워크가 다음 판에 기본 명령을 더해도 충돌하지 않는다.
- 아이콘 **키**는 예약하지 않는다. 프레임워크는 아이콘을 명시 등록하지 않고 공급자로만 더한다.

### 1.2 등록 정책 P1~P4

| 정책 | 규칙 |
|---|---|
| P1 | `Replace=true` 인데 같은 ID 가 없으면 새로 등록한다. 먼저 `Contains` 로 볼 필요가 없다 |
| P2 | 제거(`Remove`)는 그 항목을 등록한 주체만 한다. 다른 주체면 진단(XKUI0207·XKUI0309·XKUI0408)을 남기고 지우지 않는다 |
| P3 | 교체(`Replace=true`)는 주체와 무관하게 허용하고 목록 안의 자리를 지킨다. 교체한 주체가 새 등록 주체가 되어 제거 권한도 옮겨 간다 |
| P4 | `Build` 뒤 모듈이 붙잡아 둔 레지스트리로 등록하면 실행 중 등록과 같다. 즉시 검사하고, 진단은 `XkxkUi.Current.Diagnostics` 로 가며 예외가 없다 |

- 옵션 객체는 대리자가 끝난 시점의 값을 레지스트리가 복사한다. 등록 뒤 옵션 객체를 고쳐도 반영되지 않으니 `Replace` 로 다시 등록한다.
- 규칙 위반은 예외 대신 진단을 남기고 false 를 돌려준다. null 인자만 `ArgumentNullException` 이다.
- 레지스트리는 UI 스레드에서 부른다. 변경 알림 `Changed`(`UiRegistryChangedEventArgs`: `Id`·`Kind`)는 내부 잠금 밖에서 발생한다. 모르는 `UiRegistryChangeKind` 값을 받으면 전체가 바뀐 것으로 보고 다시 읽는다.
- `Commands`·`Items`·`Keys`·`Providers` 같은 목록은 부를 때마다 그 시점의 사본이다.

## 2. 아이콘 — `IUiIconRegistry`

| 멤버 | 뜻 |
|---|---|
| `AddGeometry(key, pathData)` | SVG path 문법(24 격자) 그림으로 명시 등록 |
| `Add(key, configure)` | `UiIconOptions` 로 명시 등록. `PathData`·`ResourceKey` 중 **정확히 하나**만 채운다(아니면 XKUI0203) |
| `AddProvider(provider)`·`RemoveProvider(providerId)` | 키 묶음을 내는 공급자(`UiIconProvider`) 등록·제거 |
| `TryGet`·`Contains`·`Keys`·`Providers`·`Remove` | 해석·확인·전체 키·공급자 목록·명시 등록 제거 |

해석 순서는 ① 명시 등록 ② 공급자(나중에 더한 공급자가 앞, 기본 생성 공급자 `xkxk.generated` 가 맨 끝)이며 첫 일치를 돌려준다. 명시 등록이 공급자 키를 가리는 것은 정상 재정의이고, 명시 키를 지우면 공급자 값이 다시 보인다.

```csharp
using System;
using System.Collections.Generic;
using System.Diagnostics.CodeAnalysis;
using xkxk.frameworks.ui.shell.Framework;

public sealed class AcmeIconProvider : UiIconProvider
{
    private static readonly string[] keys = ["acme.chart", "acme.table"];

    public override string Id => "acme.icons";

    public override IReadOnlyCollection<string> Keys => keys;

    public override bool TryGetIcon(string key, [NotNullWhen(true)] out UiIconDefinition? icon)
    {
        icon = Array.IndexOf(keys, key) >= 0 ? UiIconDefinition.FromPathData(key, "M4 4h16v16H4z") : null;
        return icon is not null;
    }
}

public sealed class AcmeIconModule : UiModule
{
    public override string Id => "acme.icon";

    public override void Configure(IUiModuleContext ui)
    {
        ui.Icons.AddGeometry("acme.report", "M4 4h16v16H4z");
        ui.Icons.Add("acme.export", o => o.ResourceKey = "AcmeExportGeometry"); // 앱 리소스의 Geometry 키
        ui.Icons.AddProvider(new AcmeIconProvider());
    }
}
```

- 공급자 `Id` 가 비었거나 겹치면 XKUI0205, 예약 접두어면 XKUI0206 이다. `Id`·`Keys` 는 등록 뒤 바뀌지 않는 것으로 보며, 여러 스레드에서 불릴 수 있으니 읽기 전용 자료로 답한다.
- 공급자가 돌려준 정의의 `Owner` 는 레지스트리가 공급자 `Id` 로 맞춘다.
- 그리기에 실패한 PathData 는 해석할 때 XKUI0204(Warning, 키당 1회)다.

## 3. 명령 — `IUiCommandRegistry`

| 멤버 | 뜻 |
|---|---|
| `Add(id, configure)` | `UiCommandOptions` 로 등록(또는 `Replace=true` 로 교체) |
| `Execute(id)`·`Execute(id, parameter)` | 실행. 끝까지 불렀으면 true |
| `CanExecute(id)`·`CanExecute(id, parameter)` | 지금 실행 가능한지. 대리자가 없으면 true, 없는 ID 면 false |
| `Remove`·`Contains`·`TryGet`·`Commands` | 제거·확인·정의 조회·전체 목록(등록 순서) |

| `UiCommandOptions` | 뜻 |
|---|---|
| `Execute` | 실행 대리자(`UiCommandContext` 를 받는다). **필수** — 없으면 등록하지 않는다(XKUI0303) |
| `CanExecute` | 실행 가능 여부 대리자. 없으면 항상 가능 |
| `TitleKey`·`Title` | 제목 문구 키·제목. 문구 키가 먼저다 |
| `Icon` | 아이콘 키. 해석 못 해도 명령은 등록된다(XKUI0304) |
| `Gesture` | 단축키(3.1) |
| `Category`·`DescriptionKey` | 분류·설명 문구 키 |
| `Replace` | 같은 ID 교체 여부. false 인데 이미 있으면 XKUI0302(첫 등록 유지) |

```csharp
public override void Configure(IUiModuleContext ui)
{
    ui.Commands.Add("acme.report.export", o =>
    {
        o.TitleKey = "acme.report.export";
        o.Icon = "acme.export";
        o.Gesture = "Ctrl+Shift+E";
        o.CanExecute = c => c.Parameter is not null;
        o.Execute = c => Export(c.Parameter);
    });

    // 셸 기본 명령 재정의 — 자리는 유지되고 등록 주체가 이 모듈로 바뀐다
    ui.Commands.Add(ShellCommandIds.SystemHelp, o =>
    {
        o.Replace = true;
        o.Title = "도움말";
        o.Execute = _ => OpenAcmeHelp();
    });
}
```

- `UiCommandContext` 는 `App`(앱 컨텍스트)·`CommandId`·`Parameter`(호출자가 넘긴 값)를 담는다.
- 대리자가 던진 예외는 레지스트리가 받아 XKUI0306 을 남기고 false 를 돌려준다(호출자에게 다시 던지지 않는다). 없는 ID 실행은 XKUI0307(Warning)이다.
- 셸 기본 명령 ID 는 `ShellCommandIds` 상수와 `ShellCommandIds.All` 에 있다(예 `ShellCommandIds.WindowCloseAll` = `xkxk.window.closeAll`).

### 3.1 단축키

- 문법: `+` 로 나눈 구간들 중 마지막이 키 1개, 앞은 수정자 0개 이상이다. 수정자는 Ctrl·Shift·Alt·Meta(대소문자 무시, 각 한 번, 순서 무관)다. 예 `Ctrl+Shift+N`·`Ctrl+F4`·`Alt+Enter`.
- 키: A~Z, D0~D9, F1~F24, NumPad0~NumPad9, Tab, Enter, Escape, Space, Back, Delete, Insert, Home, End, PageUp, PageDown, Left, Up, Right, Down, OemPlus, OemMinus, OemComma, OemPeriod, Add, Subtract, Multiply, Divide.
- 무효(빈 구간·수정자만·목록 밖 키·키 2개·수정자 중복·구간 안 공백)면 XKUI0305 를 남기고 단축키만 버린 채 명령은 등록한다.
- 프레임워크가 아닌 주체의 단축키가 이미 있는 명령과 같으면 XKUI0310(Warning)을 남기고 등록한다. 겹치면 먼저 등록되고 지금 실행할 수 있는 쪽이 키를 받는다. 셸 기본 단축키와 겹치면 셸이 먼저 처리해 소비자 명령은 그 키를 받지 못한다.
- 실제 키 입력 연결은 **소비자 명령만**, 주 화면이 있는 창 하나에서만 한다. 독립(SDI) 창에서는 연결하지 않는다.

셸이 먼저 처리하는 기본 단축키는 아래와 같다. 쓰는 쪽 명령에는 이 조합을 쓰지 않는다. 왼쪽은 별별UI 단축키 문법으로 적은 값이다(문법으로 적을 수 없는 키는 그렇게 표시했다). 명령 ID 열은 그 단축키를 메타데이터(`UiCommandDefinition.Gesture`)로 가진 셸 명령이다.

| 단축키 | 동작 | 명령 ID |
|---|---|---|
| `F1` | 도움말 투어 | 명령 없음(셸 직접 처리) |
| `F10` | 메뉴 막대로 이동 | 명령 없음(셸 직접 처리) |
| `Escape` | 입력 컨트롤이 쓰지 않은 Esc 로 활성 문서 창 닫기 | 명령 없음(셸 직접 처리) |
| `Tab`·`Shift+Tab` | 포커스 이동 | 명령 없음(셸 직접 처리) |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 다음 / 이전 창 | `ShellCommandIds.WindowNext` / `ShellCommandIds.WindowPrevious` |
| `Ctrl+F6` / `Ctrl+Shift+F6` | 다음 / 이전 창(같은 동작) | 명령 없음(셸 직접 처리) |
| `Ctrl+F4` | 창 닫기 | `ShellCommandIds.WindowClose` |
| `Ctrl+S` | 배치 저장 | `ShellCommandIds.LayoutSave` |
| `Ctrl+D0` | 글자 크기 초기화(`Ctrl` + 휠은 확대·축소, 명령 없음) | `ShellCommandIds.ViewFontReset` |
| `Alt+Space`·`Alt+OemMinus` | 창 메뉴·문서 창 메뉴 | 명령 없음(셸 직접 처리) |
| `Ctrl+Alt+Left`·`Ctrl+Alt+Right`·`Ctrl+Alt+Up`·`Ctrl+Alt+Down` | 창 배치(반쪽·최대화·복원). 스냅 키보드 설정이 꺼져 있으면 키를 쓰지 않는다 | 명령 없음(셸 직접 처리) |
| `Alt+F4` | 종료(키는 OS 창 닫기가 처리) | `ShellCommandIds.AppExit` |
| `Meta+W`·`Meta+M` | macOS 전용 창 닫기·최소화 | 명령 없음(셸 직접 처리) |
| Meta+백틱·Meta+Shift+백틱 | macOS 전용 창 순환. **이 문법으로 쓸 수 없음** — 백틱 키는 문법 키 목록에 없어 소비자 명령에는 등록할 수 없고, 셸 화면 층이 직접 처리한다 | 명령 없음(셸 직접 처리) |

- XKUI0310 은 **명령의** 단축키 메타데이터와만 비교한다. 그래서 위 표에서 명령 ID 가 있는 6개 조합과 겹칠 때만 경고가 나온다. '명령 없음' 행의 키(`F1`·`Tab`·`Ctrl+F6` 등)와 겹치면 경고 없이 셸이 먼저 키를 처리해, 소비자 명령은 그 키를 조용히 받지 못한다.
- 명령의 단축키 메타데이터 출처는 셸 내부 파일 `src/xkxk.frameworks.ui.shell/Framework/ShellDefaultCommands.cs`·`src/xkxk.frameworks.ui.shell/Framework/ShellDefaultCommands.Menu.cs` 다. 키 처리 출처는 `src/xkxk.frameworks.ui.shell/Tour/tour_catalog.json` 의 shortcuts 목록과 화면 층 `src/xkxk.frameworks.ui.views/Input/WindowKeyGestures.cs` 다(2026-11-26 기준). 공개 계약이 아니어서 검사기가 이 표를 지켜 주지 않으므로 판을 올릴 때 출처와 다시 대조한다.

## 4. 메뉴 — `IUiMenuRegistry`

| 멤버 | 뜻 |
|---|---|
| `Add(id, configure)` | `UiMenuItemOptions` 로 등록(또는 `Replace=true` 로 교체) |
| `Move(id, configure)` | `UiMenuPlacementOptions`(`Parent`·`ToRoot`·`InsertAfter`·`InsertBefore`)로 부모·자리를 바꾼다. 하위 메뉴는 자식째 옮긴다 |
| `SetHidden(id, hidden)` | 숨기거나 다시 보인다. 지우지 않는다 |
| `Remove(id)` | 제거. 하위 메뉴는 자식 전원이 같은 주체일 때만 자식째 지운다 |
| `GetState(id, surface)` | 지금 표시 상태(`UiMenuItemState`: `IsVisible`·`IsEnabled`·`Title`·`Icon`·`Gesture`·`ToolTip`) |
| `GetChildren(parentId)`·`Items`·`TryGet`·`Contains` | 자식 목록(null 은 최상위)·전체(깊이 우선)·조회·확인 |

| 종류(`UiMenuItemKind`) | 필요한 옵션 |
|---|---|
| `UiMenuItemKind.Command`(기본) | `CommandId` 필수 |
| `UiMenuItemKind.Submenu` | 자식을 담는다. `CommandId` 를 둘 수 없다 |
| `UiMenuItemKind.Separator` | 구분선. `CommandId` 를 둘 수 없다 |
| `UiMenuItemKind.Section` | `Section` 키 필수. 화면이 그 키의 내용을 채운다 |

종류와 옵션이 맞지 않으면 XKUI0406 으로 등록하지 않는다. `Parent` 는 이미 있는 하위 메뉴여야 한다(XKUI0403).

```csharp
public override void Configure(IUiModuleContext ui)
{
    ui.Menus.Add("acme.menu", o =>
    {
        o.Kind = UiMenuItemKind.Submenu;
        o.Title = "보고서";
        o.InsertBefore = ShellMenuIds.System; // 최상위 '시스템' 앞
    });
    ui.Menus.Add("acme.menu.open", o =>
    {
        o.Parent = "acme.menu";
        o.CommandId = "acme.report.open";
        o.Icon = "acme.report";
        o.IsVisible = m => m.App.Commands.Contains("acme.report.open"); // 메뉴를 열 때 평가
        o.ToolTip = _ => "보고서 목록을 엽니다";
        o.Mobile.TabOrder = 0;            // 모바일 하단 탭 첫 칸
        o.Mobile.TabTitleKey = "acme.report.tab";
    });
    ui.Menus.Add("acme.menu.sep1", o =>
    {
        o.Parent = "acme.menu";
        o.Kind = UiMenuItemKind.Separator;
    });
}
```

실행 중 셸 메뉴를 숨기거나 옮기는 예(주체와 무관하게 허용, 등록 주체는 바뀌지 않음):

```csharp
XkxkUi.Current.Menus.SetHidden(ShellMenuIds.SystemUpdate, true);
XkxkUi.Current.Menus.Move(ShellMenuIds.SystemAbout, o => o.InsertBefore = ShellMenuIds.SystemHelp);

var state = XkxkUi.Current.Menus.GetState("acme.menu.open", UiMenuSurface.Desktop);
```

- 삽입: `InsertAfter` 가 `InsertBefore` 보다 우선이고, 둘 다 없으면 부모 아래 맨 뒤다. 기준 항목이 같은 부모 아래에 없으면 맨 뒤에 붙이고 XKUI0404(Warning)를 남긴다.
- 명령 연결: `CommandId` 가 명령 레지스트리에 없으면 항목은 남고 비활성으로 보이며 XKUI0405 다. 모듈이 빌드 중 등록한 메뉴는 빌드 끝에 한 번 검사하므로 뒤 모듈이 등록하는 명령을 가리켜도 된다.
- 셸 기본 메뉴 행 중 표시 조건 키가 `cmd` 인 행은 그 행의 명령이 명령 레지스트리에 등록됐을 때만 보인다(하위 메뉴 묶음은 자식 명령 행 중 하나라도 등록돼 있으면 보인다). 이런 행은 명령이 없는 것이 정상이므로 XKUI0405 검사에서 뺀다. 파일 메뉴의 데모 열기(Grid·Gantt·Form, SDI 포함)와 벤치 열기가 이 행이다. 이 명령 3개(`xkxk.demo.open`·`xkxk.demo.openSdi`·`xkxk.bench.open`)는 시험대 모듈로 옮겨졌고 ID 상수(`ShellCommandIds.DemoOpen`·`DemoOpenSdi`·`BenchOpen`)는 그대로다. 시험대 모듈을 붙이지 않은 앱에서는 명령이 없어 이 행들이 보이지 않는다. 벤치 열기는 진단+벤치 빌드에서만 등록된다.
- 표시 상태는 **메뉴를 열 때** 평가한다. `IsVisible`·`ToolTip` 대리자(`UiMenuContext`: `App`·`Item`·`Surface`)가 예외를 던지면 숨김·툴팁 없음으로 보고 XKUI0411(Warning, 항목·키당 1회)이다. 제목은 `Title` → `TitleKey` 문구 → 명령 제목 순서다.
- 교체(`Replace=true`)는 이전 값을 이어받지 않는다. 숨김도 풀리므로 계속 숨기려면 `SetHidden` 을 다시 부른다. `Parent` 를 바꾼 교체는 새 부모 아래로 옮긴다.
- `Move` 가 대상 없음·순환·하위 메뉴 아닌 새 부모면 XKUI0410 으로 옮기지 않는다.
- 자동화 이름(`AutomationId`)은 기본이 `menu.` + 메뉴 ID 다.
- 셸 기본 메뉴 ID 는 `ShellMenuIds` 상수에 있다. 최상위는 `ShellMenuIds.File`·`ShellMenuIds.Window`·`ShellMenuIds.View`·`ShellMenuIds.System`(`ShellMenuIds.Roots`)이다.

### 4.1 섹션

- 섹션은 화면이 키에 맞는 내용을 채우는 동적 자리다. 셸 섹션 키는 `ShellMenuIds.SectionSnap`(스냅 배치 칸)·`ShellMenuIds.SectionMonitors`(모니터 목록)·`ShellMenuIds.SectionOpenWindows`(열린 창 목록) 셋이다.
- 화면이 모르는 키는 그 자리를 비우고 XKUI0409(Warning)를 남긴다. 지금 판에는 쓰는 쪽이 자기 섹션 키를 채울 화면을 붙이는 공개 수단이 없으므로, 쓰는 쪽은 셸 섹션 키만 쓴다.

### 4.2 모바일형 화면

`UiMenuItemOptions.Mobile`(`UiMenuMobileOptions`)은 모바일형(하단 탭·삼선 서랍) 표시 힌트다. 데스크톱 메뉴에는 영향이 없다.

| 속성 | 기본값 | 뜻 |
|---|---|---|
| `InDrawer` | true | 서랍에 넣을지. false 는 그 항목만 빼고 자식은 계속 넣는다 |
| `Available`·`UnavailableReasonKey` | true·null | false 면 서랍에 비활성과 사유 문구로 보인다 |
| `TabOrder`·`TabTitleKey`·`TabIcon` | -1·null·null | 0 이상이면 하단 탭에 그 순서로 둔다 |
| `EntryId`·`TitleKey` | null | 모바일 항목 ID·제목 문구 키 |
| `CommandId`·`CommandParameter` | null | 모바일에서 대신 실행할 명령과 값 |

- `SetHidden(true)` 인 항목은 하위까지 서랍에서 빠진다.

## 6. 한계

- 레지스트리는 프로세스 전역이고 리셋이 없다. 시험에서는 시험마다 고유 ID 를 쓴다.
- P2 는 실수 방지일 뿐 보안 경계가 아니다. `Replace=true` 로 주체를 가져온 뒤 `Remove` 하면 다른 주체의 항목도 지워진다.
- 셸 기본 명령·메뉴를 교체한 뒤 `Remove` 하면 같은 `xkxk.*` ID 는 그 프로세스에서 다시 만들 수 없다(XKUI0308·XKUI0407).
- 기본 생성 아이콘과 같은 이름 꼴의 키를 먼저 명시 등록하면 나중에 생기는 생성 아이콘이 조용히 가려진다. 자기 접두어 키를 쓴다.
- 명령의 실행 가능 여부 변경 알림이 없다. 메뉴를 열 때 다시 묻는다. 열린 채로 바뀐 표시 조건은 다음 열기 때 반영된다.
- 모바일에서만 하위 묶음을 한 번에 빼는 수단이 없다. `SetHidden` 은 데스크톱에서도 숨기고, `Mobile.InDrawer=false` 는 자식을 빼지 않는다.
- 셸 기본 단축키와 같은 단축키를 쓴 소비자 명령은 그 키를 받지 못한다. 셸 명령에 연결된 키는 XKUI0310 으로 알리지만, 명령 없이 셸이 직접 처리하는 키는 알림이 없다(3.1절 표).
- 모듈 ID 의 `xkxk.` 접두어는 예약 검사 밖이다. 쓰지 않는다.

## 7. 예정

아래는 아직 없는 기능이다. 지금 코드에 쓰지 않는다.

- 명령의 실행 가능 여부 변경 알림, 토글 상태, 여러·화음 단축키, 비동기 실행은 명령 옵션 속성이나 레지스트리 멤버를 더해 열 예정이다.
- 아이콘 격자·다색, 공급자 키 목록 변경 알림은 아이콘 옵션 속성과 공급자 가상 멤버로 열 예정이다.
