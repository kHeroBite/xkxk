# 01 시작하기

- 상태: 사전판(0.x 이전). 여기 나오는 공개 API 는 전부 미출시(Unshipped) 표면이다.
- 최종 갱신일: 2026-11-27
- 근거: 공개 API 명세 [api/README.md](api/README.md), 셸 층 소스 `src/xkxk.frameworks.ui.shell/Framework/`.

이 문서의 코드는 **지금 있는 공개 API 만** 쓴다. 아직 없는 기능은 맨 끝 '예정' 절에 문장으로만 적었다.

## 1. 층 구성과 참조 방법

별별UI 는 네 층과 세 호스트로 나뉜다. 쓰는 쪽은 셸 층 하나만 참조한다.

| 층(프로젝트) | 역할 | 쓰는 쪽이 직접 쓰나 |
|---|---|---|
| `xkxk.frameworks.ui.shell` | 셸 컨트롤과 **공개 계약**(네임스페이스 `xkxk.frameworks.ui.shell.Framework`) | 예 — 이 층만 참조한다 |
| `xkxk.frameworks.ui` | 순수 UI 컨트롤·테마 자원 | 셸이 끌어온다(공개 계약 아님) |
| `xkxk.frameworks.ui.data` | 비 UI 데이터(배치 저장 등) | 셸이 끌어온다(공개 계약 아님) |
| `xkxk.frameworks.ui.views` | 화면 조립(시험대 화면 포함) | 쓰지 않는다. 예외 ①강타입 창 등록 확장 메서드(`views.Windows`, 04_확장_창.md 3절)는 소비자 공개 표면이다. 예외 ②실행 호스트는 6.1절대로 이 층을 참조해야 한다(공개 계약 아님) |
| `xkxk.frameworks.ui.desktop`·`xkxk.frameworks.ui.browser`·`xkxk.frameworks.ui.android` | 저장소의 호스트 실행 파일 | 참고용(공개 계약 아님) |

참조는 지금 ProjectReference 뿐이다(패키지 게시는 예정).

```xml
<ItemGroup>
  <ProjectReference Include="<저장소>/frameworks/ui/src/xkxk.frameworks.ui.shell/xkxk.frameworks.ui.shell.csproj" />
</ItemGroup>
```

- 대상 프레임워크는 `net11.0` 이고 Avalonia 12.1.4 를 쓴다. 쓰는 쪽 프로젝트도 같은 판을 맞춘다.
- 코드에는 `using xkxk.frameworks.ui.shell.Framework;` 한 줄이면 된다. 다른 네임스페이스의 형식은 계약 밖이다.

## 2. 빌더 만들기 — `XkxkUi.CreateBuilder`

진입점은 정적 클래스 `XkxkUi` 다. 빌더는 `XkxkUi.CreateBuilder` 로만 만든다. 오버로드는 셋이다.

| 호출 | 뜻 |
|---|---|
| `CreateBuilder()` | 기본 옵션(인자 없음·호스트 `unknown`·오류 정책 `Collect`) |
| `CreateBuilder(string[] args)` | 명령줄 인자만 넘긴다. 배열은 복사해 보관한다 |
| `CreateBuilder(XkxkUiBuilderOptions options)` | 옵션 객체를 그대로 쓴다(권장) |

`XkxkUiBuilderOptions` 의 속성은 모두 기본값이 있다. 필요한 것만 채운다.

| 속성 | 기본값 | 뜻 |
|---|---|---|
| `Args` | 빈 목록 | 명령줄 인자. null 을 넣으면 빈 목록이 된다 |
| `ApplicationId` | null | 앱 식별자 |
| `HostKind` | `unknown` | 호스트 종류. `UiHostKinds` 상수(`UiHostKinds.Desktop`·`UiHostKinds.Browser`·`UiHostKinds.Android`)를 쓴다 |
| `ErrorPolicy` | `Collect` | 구성 오류 처리(5절) |
| `Host` | 빈 묶음 | 호스트 값(6절). 대입할 수 없고 속성을 채운다 |
| `Properties` | 빈 사전 | 정식 속성이 생기기 전의 실험 값(키는 대소문자 구분) |

빌더(`XkxkUiBuilder`)의 메서드는 모두 자기 자신을 돌려주므로 이어 쓸 수 있다.

| 멤버 | 뜻 |
|---|---|
| `AddModule(module)`·`AddModule<TModule>()` | 모듈 등록. 구성은 `Build` 때 등록 순서대로 한다 |
| `ConfigureServices(configure)` | 서비스 등록부(`UiServiceRegistry`)를 채운다 |
| `Build()` | 모듈을 1회씩 구성하고 `XkxkUiApplication` 을 만든다. 두 번 부르면 `InvalidOperationException` |
| `Options`·`Services`·`Diagnostics` | 옵션·서비스 등록부·진단 모음 |

```csharp
using System;
using xkxk.frameworks.ui.shell.Framework;

var options = new XkxkUiBuilderOptions
{
    Args = args,
    ApplicationId = "acme.report",
    HostKind = UiHostKinds.Desktop,
    ErrorPolicy = UiErrorPolicy.Collect,
};

var app = XkxkUi.CreateBuilder(options)
    .ConfigureServices(s => s.Add<IReportService>(new ReportService()))
    .AddModule<ReportModule>()
    .Build();

foreach (var d in app.Diagnostics.Entries)
    Console.Error.WriteLine(d); // "[Error] XKUI0302: ..." 형태(출처가 있으면 함께 적힌다)
```

`IReportService`·`ReportService`·`ReportModule` 은 쓰는 쪽이 만드는 형식이다(3절).

호스트가 모듈을 붙이는 방법은 `AddModule<TModule>()` 한 줄이다. 저장소의 실행 호스트(`DesktopUiHost` 등)는 시험용 모듈인 `xkxk.frameworks.ui.testbed` 의 `TestbedModule` 하나만 붙이는데, 이는 별별UI 를 시험하는 시험대 전용이다. 소비 앱은 시험대 모듈을 붙이지 않고 자기 모듈(위 `ReportModule` 꼴)을 붙인다. 셸에는 데모 창(Grid·Gantt·Form)이 들어 있지 않다. 그 창과 데모 열기 명령은 시험대 모듈이 등록하므로, 시험대 모듈을 붙이지 않은 앱에서는 파일 메뉴의 데모·벤치 열기 항목이 보이지 않는다(상세는 [02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 4절).

## 3. 모듈 — `UiModule` 상속

모듈은 쓰는 쪽이 기능 묶음을 별별UI 에 등록하는 단위다. 추상 클래스 `UiModule` 을 상속해 `Id` 와 `Configure` 두 개를 구현한다.

- `Id` 는 비어 있으면 안 되고(XKUI0001) 같은 빌더 안에서 겹치면 안 된다(XKUI0002). 자기 솔루션 접두어를 붙인다(예 `acme.report`). `xkxk.` 로 시작하는 ID 는 프레임워크 몫이므로 쓰지 않는다.
- `Configure` 에서 예외가 나면 XKUI0003 진단을 남기고 다음 모듈은 계속 구성한다.
- `Configure` 가 받는 `IUiModuleContext` 로 레지스트리·서비스·옵션·진단에 닿는다.

| `IUiModuleContext` 멤버 | 뜻 |
|---|---|
| `ModuleId` | 구성 중인 모듈 ID |
| `Options` | 빌더 옵션(같은 인스턴스) |
| `Services` | 서비스 등록부(같은 인스턴스) |
| `Diagnostics` | 진단 모음(빌드 중에는 빌더 것) |
| `Icons`·`Commands`·`Menus`·`Windows` | 아이콘·명령·메뉴·창 레지스트리. 여기서 등록한 항목의 등록 주체(Owner)는 이 모듈 ID 다 |

```csharp
using xkxk.frameworks.ui.shell.Framework;

public sealed class ReportModule : UiModule
{
    public override string Id => "acme.report";

    public override void Configure(IUiModuleContext ui)
    {
        var reports = ui.Services.Get<IReportService>();

        ui.Commands.Add("acme.report.open", o =>
        {
            o.Title = "보고서 열기";
            o.Category = "report";
            o.Execute = c => reports.Open(c.Parameter);
        });
    }
}
```

- 메뉴·아이콘을 더하는 방법과 등록 규칙은 [02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 에 있다.
- 자기 창 종류를 등록하고 여는 방법은 [04_확장_창.md](04_확장_창.md) 에 있다.
- `Build` 가 끝난 뒤에도 모듈이 붙잡아 둔 레지스트리로 등록할 수 있다. 그때는 실행 중 등록과 같아 즉시 검사하고, 진단은 앱 진단 모음(`XkxkUi.Current.Diagnostics`)으로 가며 오류 정책과 무관하게 예외를 던지지 않는다.

## 4. 서비스 — `UiServiceRegistry`

형식 하나에 인스턴스 하나를 두는 간단한 서비스 등록부다. 의존성 주입 컨테이너가 아니다.

| 멤버 | 뜻 |
|---|---|
| `Add<TService>(instance)`·`Add<TService>(factory)` | 등록. 같은 형식이 이미 있으면 XKUI0101(Warning) 을 남기고 첫 등록을 유지한다. 팩토리는 첫 조회 때 1회 부른다 |
| `Replace<TService>(…)` | 등록을 바꾼다(없으면 추가) |
| `Remove<TService>()`·`Contains<TService>()`·`Count` | 제거·확인·개수 |
| `Get<TService>()`·`TryGet<TService>(out …)` | 조회. `Get` 은 없으면 `InvalidOperationException` |

빌드 뒤에는 `XkxkUiApplication.Services`(읽기 전용 `IUiServiceProvider`)로 조회한다.

## 5. 오류 정책과 진단

별별UI 는 규칙 위반을 예외 대신 **진단**(`UiDiagnostic`: 코드·심각도·메시지·출처)으로 남긴다. 레지스트리 메서드는 위반 때 false 를 돌려준다. null 인자만 `ArgumentNullException` 이다.

| 정책(`UiErrorPolicy`) | 빌드 중 Error 진단이 있을 때 |
|---|---|
| `UiErrorPolicy.Collect`(기본) | 모아 두고 그대로 진행한다. `XkxkUiApplication.Diagnostics` 로 확인한다 |
| `UiErrorPolicy.Throw` | `Build` 끝에 `UiConfigurationException` 을 던진다. 예외의 `Diagnostics` 에 목록이 있다 |

```csharp
using System;
using xkxk.frameworks.ui.shell.Framework;

try
{
    var app = XkxkUi.CreateBuilder(new XkxkUiBuilderOptions { ErrorPolicy = UiErrorPolicy.Throw })
        .AddModule<ReportModule>()
        .Build();
}
catch (UiConfigurationException ex)
{
    foreach (var d in ex.Diagnostics)
        Console.Error.WriteLine($"{d.Id} {d.Severity} {d.Message}");
    throw;
}

// 빌드 뒤 실행 중 진단은 앱 컨텍스트 한 곳에 쌓인다
XkxkUi.Current.Diagnostics.Reported += (_, d) => Console.Error.WriteLine(d);
```

- 진단 모음은 둘이다. 빌드 중 진단은 빌더(`XkxkUiApplication.Diagnostics`), 빌드 뒤 실행 중 진단은 앱 컨텍스트(`XkxkUi.Current.Diagnostics`)이며 서로 합치지 않는다.
- `UiDiagnostics.HasErrors` 는 Error 가 하나라도 있으면 true 다. 심각도는 `UiDiagnosticSeverity.Info`·`UiDiagnosticSeverity.Warning`·`UiDiagnosticSeverity.Error` 이다.
- 코드 대역은 XKUI00xx 모듈, XKUI01xx 서비스, XKUI02xx 아이콘, XKUI03xx 명령, XKUI04xx 메뉴, XKUI05xx 창이다. 코드별 뜻은 명세 [api/README.md](api/README.md) 의 진단 표에 있다.
- 기준: 구성을 바꾼 뒤에는 Error·Warning 진단이 0건이어야 한다.

## 6. Avalonia 앱에 연결 — `UseXkxkUi`

`Build` 로 얻은 앱을 Avalonia `AppBuilder` 에 확장 메서드 `UseXkxkUi` 로 연결한다. 이 호출이 빌더 옵션의 호스트 값(`XkxkUiBuilderOptions.Host`)을 셸에 1회 연결하고, 앱 설정이 끝나면 `XkxkUiApplication.IsAttached` 가 true 가 된다.

```csharp
using Avalonia;
using xkxk.frameworks.ui.shell.Framework;

// BuildAvaloniaApp 은 쓰는 쪽(호스트)의 AppBuilder 구성 메서드다
var code = BuildAvaloniaApp()
    .UseXkxkUi(app)
    .StartWithClassicDesktopLifetime(args);
```

- `UiHostOptions`(옵션의 `Host`)는 호스트가 채우는 값 묶음이다. 배치·설정 저장소, 주 창 구성, 모니터 공급자, 독립 창 생성 등이 있다. 값이 null(기본)이면 연결하지 않고 셸 기본 동작을 쓴다.
- 이 속성들의 형식 상당수(저장소·모니터·창 호스트 형식)는 다른 층 형식이라 공개 계약이 아니다. 일반 소비자는 비워 둔다.
### 6.1 실행 호스트 만들기 — 지금 판의 한계

**공개 계약만으로는 실행 호스트를 만들 수 없다.** 공개된 Avalonia `Application` 형식과 공개 호스트 확장(데스크톱 기동 한 줄 같은 것)이 아직 없어서, 이 문서는 공개 API 만으로 된 최소 App 예제를 줄 수 없다. 공개 호스트 확장은 호스트 단계에서 열 예정이다(9절).

지금 실제로 동작하는 경로는 저장소의 데스크톱 호스트(`src/xkxk.frameworks.ui.desktop/`)와 같은 구성뿐이다. 이 경로는 **공개 계약 밖**의 형식에 기대므로 다음 판에서 깨질 수 있다. 그 위험을 받아들일 때만 아래를 따른다.

| 호스트 프로젝트에 직접 두는 참조 | 판 | 비고 |
|---|---|---|
| PackageReference Avalonia.Desktop | 12.1.4 | 데스크톱 플랫폼(`UsePlatformDetect`·`StartWithClassicDesktopLifetime`) |
| ProjectReference 셸 프로젝트(`src/xkxk.frameworks.ui.shell/`) | — | 공개 계약. 아래 패키지를 전이로 끌어온다 |
| ProjectReference 화면 층 프로젝트(`src/xkxk.frameworks.ui.views/`) | — | 앱 형식 PdApp 이 여기 있다. **공개 계약 아님** |

| 셸이 전이로 끌어오는 것(직접 둘 필요 없음) | 판 |
|---|---|
| Avalonia·Avalonia.Themes.Fluent·Avalonia.Controls.ColorPicker | 12.1.4 |
| Avalonia.Controls.DataGrid | 12.1.2 |
| Dock.Avalonia·Dock.Avalonia.Themes.Fluent·Dock.Model.Mvvm·Dock.Settings | 12.1.0.12 |
| 프로젝트 `xkxk.frameworks.ui`·`xkxk.frameworks.ui.data` | — |

호스트 프로젝트 속성은 저장소 호스트처럼 출력 형식 WinExe, 대상 `net11.0` 이다. 진입점 절차는 다음과 같다.

1. `Main` 에서 2절처럼 옵션을 만들고(`HostKind` 는 `UiHostKinds.Desktop`) 모듈을 더해 `Build` 한다.
2. Avalonia 앱 빌더를 화면 층 앱 형식 PdApp 으로 구성하고(`UsePlatformDetect` 포함) 위 예제처럼 `UseXkxkUi(app)` 를 붙여 `StartWithClassicDesktopLifetime(args)` 로 띄운다.
3. 호스트 값(`UiHostOptions`)은 비워 둔다. 저장소 호스트는 내부 형식으로 배치 저장소·모니터 공급자·창 호스트를 채우는데, 비워 둔 상태로 어디까지 동작하는지는 이 문서 작성 시점에 실측하지 않았다(확실하지 않음).
4. 브라우저·Android 호스트는 플랫폼별 진입 구성이 더 많아 이 문서에서 다루지 않는다. 필요하면 저장소의 `src/xkxk.frameworks.ui.browser/`·`src/xkxk.frameworks.ui.android/` 를 참고하되, 역시 공개 계약 밖이다.

## 7. 앱 컨텍스트 — `XkxkUi.Current`

`XkxkUi.Current` 는 프로세스 전역의 앱 컨텍스트(`IUiAppContext`)다. 항상 같은 비 null 인스턴스이고 대입·리셋이 없다.

| 멤버 | 쓰는 쪽에서 |
|---|---|
| `Icons`·`Commands`·`Menus`·`Windows` | 쓴다. 여기서 등록한 항목의 등록 주체는 `UiRegistryOwners.App`(`app`)이다 |
| `Diagnostics` | 쓴다. 실행 중 진단 모음 |
| `Localization` | 쓴다(`IUiLocalizer`: `Get`·`Format`·`HasKey`·`Language`·`Languages`·`LanguageChanged`·`Observe`) |
| `MainViewModel`·`Shell`·`Settings`·`Themes`·`Tour`·`Monitors`·`Views`·`RegisterViews` | 반환·인자 형식이 공개 계약 밖이다. 지금은 쓰지 않는다 |

- `MainViewModel` 은 주 창이 만들어지기 전에는 null, `Shell` 은 셸이 준비되기 전에는 null 이다.
- 명령 대리자에 오는 `UiCommandContext.App` 도 같은 앱 컨텍스트다.

## 8. 쓰면 안 되는 것

| 쓰지 말 것 | 이유·대신 쓸 것 |
|---|---|
| 옛 정적 접근자 `App.MainViewModel`·`App.Shell`·`ViewRegistry.Current`·`Loc.Instance`·`UiSettings.Current`·`ThemeCatalog.Current`·`TourCatalog.Current`·`MonitorMenuViewModel.Instance` | 앱 컨텍스트로 위임만 하는 옛 길이며 뒤 판에서 지울 예정이다. 문구는 `XkxkUi.Current.Localization`, 레지스트리는 `XkxkUi.Current` 를 쓴다 |
| `xkxk.` 로 시작하는 새 ID(모듈·명령·메뉴·창·아이콘 공급자) | 프레임워크 예약 접두어다. 새 명령·메뉴·창 ID 는 XKUI0308·XKUI0407·XKUI0503 으로 거부된다 |
| 공개 계약 인터페이스 구현(`IUiAppContext`·`IUiModuleContext`·레지스트리 인터페이스 등) | 프레임워크만 구현한다. 확장점은 `UiModule`·`UiIconProvider` 상속뿐이다 |
| `xkxk.frameworks.ui.shell.Framework` 밖의 public 형식 | 공개 계약이 아니다 |
| 미출시 표면이 영원히 같다는 가정 | 사전판이라 바뀔 수 있다. 판을 올릴 때 명세와 진단을 다시 확인한다 |
