# 04 확장 — 창

- 상태: 사전판(0.x 이전). 여기 나오는 공개 API 는 전부 미출시(Unshipped) 표면이다.
- 최종 갱신일: 2026-11-27
- 먼저 읽을 것: [01_시작하기.md](01_시작하기.md)(빌더·모듈·진단), [02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 의 공통 규칙. 정확한 서명은 [api/09_창.md](api/09_창.md).

**창 레지스트리**(`IUiWindowRegistry`)에 창 종류를 문자열 ID 로 등록하면, 그 ID 로 창(문서)을 열 수 있고 저장한 배치를 복원할 때도 같은 ID 로 내용을 만든다.

## 1. 얻는 곳과 멤버

| 얻는 곳 | 등록 주체(Owner) | 쓰는 때 |
|---|---|---|
| 모듈의 `IUiModuleContext.Windows` | 그 모듈 ID | 모듈 `Configure` 안에서 등록(권장) |
| 앱 컨텍스트의 `IUiAppContext.Windows`(`XkxkUi.Current`) | `app`(`UiRegistryOwners.App`) | 실행 중 열기·조회·등록 |

두 길은 같은 저장소를 본다. 레지스트리는 UI 스레드에서 부른다.

| 멤버 | 뜻 |
|---|---|
| `Add(id, configure)` | `UiWindowOptions` 로 등록(또는 `Replace=true` 로 교체). 거부하면 false 와 진단 |
| `Remove(id)` | 제거. 등록한 주체만 된다. 별칭도 함께 없어진다 |
| `Contains(id)`·`TryGet(id, out …)` | ID 로만 확인·조회(별칭은 보지 않는다) |
| `TryResolve(idOrAlias, out …)` | ID → 별칭(대소문자 무시) → 옛 이름·숫자(2.3절) 순서로 찾는다 |
| `Items` | 등록 순서의 정의 목록(부를 때마다 사본) |
| `Open(id)`·`Open(id, configure)` | `TryResolve` 와 같은 순서로 찾아 열기. `UiWindowOpenOptions` 로 이번 열기만 바꾼다 |
| `Changed` | 등록·교체·제거 알림(`UiRegistryChangedEventArgs`) |

## 2. 등록

| `UiWindowOptions` | 기본값 | 뜻 |
|---|---|---|
| `TitleKey`·`Title` | null | 창 이름. 문구 키 → 제목 → 창 ID 순서로 쓴다 |
| `Icon` | null | 아이콘 키([02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 2절) |
| `Category`·`DescriptionKey` | null | 분류·도움말 문구 키 |
| `Placement` | `UiWindowPlacement.Default` | 보통 문서 배치. `UiWindowPlacement.Sdi` 면 분리창 |
| `AllowDuplicate` | false | 같은 제목 중복 허용의 **처음 값**. 사용자의 '중복 허용' 전환과 저장한 배치가 바꿀 수 있다 |
| `Aliases` | 빈 목록 | ID 대신 쓰는 이름(대소문자 무시). `Add` 로 더한다 |
| `CreateContent` | null | 내용 생성 함수. **솔루션 창은 반드시 채운다** |
| `Replace` | false | 같은 ID 교체 여부 |

```csharp
using Avalonia.Controls;
using xkxk.frameworks.ui.shell.Framework;

public sealed class AcmeProjectModule : UiModule
{
    public override string Id => "acme.project";

    public override void Configure(IUiModuleContext ui)
    {
        ui.Icons.AddGeometry("acme.icon.project", "M4 4h16v16H4z");

        ui.Windows.Add("acme.project.editor", o =>
        {
            o.Title = "프로젝트 편집";
            o.Icon = "acme.icon.project";
            o.Category = "project";
            o.Aliases.Add("acme.editor");
            o.CreateContent = context =>
            {
                var projectCode = context.Parameter as string; // 복원한 문서는 null
                return new TextBlock { Text = projectCode ?? "프로젝트를 선택하세요" };
            };
        });

        ui.Commands.Add("acme.project.open", o =>
        {
            o.Title = "프로젝트 편집 열기";
            o.Execute = c => c.App.Windows.Open("acme.project.editor", w => w.Parameter = c.Parameter);
        });

        ui.Menus.Add("acme.menu.project", m =>
        {
            m.Parent = ShellMenuIds.File;
            m.CommandId = "acme.project.open";
            m.InsertAfter = ShellMenuIds.FileOpenGrid;
        });
    }
}
```

모듈은 [01_시작하기.md](01_시작하기.md) 대로 `XkxkUiBuilder.AddModule` 로 넣는다.

### 2.1 ID 와 별칭

- ID 는 대소문자를 구분하고 자기 접두어를 붙인다(예 `acme.project.editor`). 비었거나 공백뿐이면 XKUI0501 이다.
- 저장한 배치에 ID 가 남으므로 배포한 ID 는 바꾸지 않는다. 바꿔야 하면 옛 ID 를 새 창의 `Aliases` 에 넣는다. 복원할 때 별칭은 새 ID 로 바뀐다.
- ID 와 별칭은 **한 이름공간**이다. 새 ID 가 다른 창의 ID·별칭과 대소문자 무시로 같으면 등록하지 않는다(XKUI0502, `Add` 는 false). 기존 창은 그대로다. `Replace=true` 교체는 대소문자까지 같은 ID 에만 되며, 대소문자만 다른 ID 는 새 ID 라 거부된다.
- 다른 창의 ID·별칭과 겹치는 별칭은 그 별칭만 버리고 창은 등록한다(XKUI0504). 빈 별칭·자기 ID 와 같은 별칭·목록 안 중복은 진단 없이 버린다.
- `xkxk.`(`UiRegistryOwners.ReservedPrefix`)는 프레임워크 예약 접두어다. 아직 없는 `xkxk.` ID 를 새로 만들면 등록하지 않는다(XKUI0503, false). 이미 있는 `xkxk.` 창을 `Replace=true` 로 재정의하는 것은 된다. `xkxk.` 별칭(대소문자 무시)은 그 별칭만 버리고 창은 등록한다(XKUI0503, true).
- `Grid`·`Gantt`·`Form`·`0`·`1`·`2` 는 셸 데모 창을 가리키는 **영구 예약어**다(대소문자 무시). 앱·모듈이 창 ID 로 쓰면 `Replace` 와 무관하게 등록하지 않는다(XKUI0502, false). 별칭으로 넣으면 그 별칭만 버리고 창은 등록한다(XKUI0503, true).
- 별칭만 버린 경우는 `Add` 가 true 이므로 진단도 확인한다. XKUI0503 은 Error 라 `UiErrorPolicy.Throw` 에서는 빌드 중에 예외가 된다.

### 2.2 내용 생성 — `CreateContent`

- 반환값은 Avalonia `Control` 이어야 한다. 예외·null·`Control` 아닌 값이면 자리표시 내용과 XKUI0507 이다.
- 프레임워크는 내용을 만들 때마다 부르므로 부를 때마다 **새 컨트롤**을 만들어 돌려준다.
- 비워 둬도(null) 등록은 된다. 다만 화면이 내용을 만들어 주는 창은 셸 데모 창 3종(ID 접두어 `xkxk.demo.*`)뿐이고, 그 밖의 창은 자리표시 내용과 XKUI0507 이다.
- 인자 `UiWindowContentContext` 는 `WindowId`(별칭으로 열어도 등록 ID)·`DocumentId`·`Title`·`Parameter` 를 담는다.

### 2.3 교체와 제거

- `Replace=true` 는 새 정의로 통째로 바꾼다. 이전 값은 이어받지 않으므로 별칭·내용 함수까지 다시 채운다(옛 이름·숫자는 아래처럼 예외). 목록 자리는 유지되고 등록 주체는 교체한 쪽이 된다. 같은 ID 가 없으면 새로 등록하되 2.1절의 ID 규칙은 그대로 적용한다.
- 제거는 등록 주체만 한다. 모듈이 등록한 창을 `XkxkUi.Current.Windows` 로 지우면 주체가 달라 XKUI0508 이다. 없는 ID 는 진단 없이 false 다.
- 옛 이름·숫자(`Grid`·`Gantt`·`Form`·`0`·`1`·`2`)는 창 정의의 별칭과 무관하게 **언제나 셸 데모 창 3종의 ID 로 풀린다.** 그래서 데모 창을 교체해도 셸 메뉴·저장본의 옛 이름은 새 정의를 연다. 교체할 때 옛 이름을 `Aliases` 에 넣지 않는다. 넣으면 그 별칭은 버려지고 XKUI0503 이다.
- 데모 창의 정확한 ID 는 `TryResolve("Grid", out …)` 처럼 얻는다. 교체한 쪽이 그 창을 `Remove` 하면 원래 셸 정의는 되살아나지 않고, 옛 이름으로 열어도 XKUI0505 다.

## 3. 열기

| `UiWindowOpenOptions` | 기본값 | 뜻 |
|---|---|---|
| `Title` | null | 문서 제목. null 이면 "창 이름 번호" 자동 제목이고 **항상 새 문서**다 |
| `Placement` | `Default` | `Default` 는 창 정의를 따르고 `Sdi` 는 분리창 |
| `AllowDuplicate` | null | null 은 현재 설정(처음 값은 정의의 `AllowDuplicate`) |
| `Parameter` | null | `CreateContent` 에 넘길 값. 저장하지 않는다 |

```csharp
var windows = XkxkUi.Current.Windows;

// 같은 제목이 이미 열려 있으면 그 문서를 활성화한다
var opened = windows.Open("acme.project.editor", o =>
{
    o.Title = "프로젝트 P-001";
    o.AllowDuplicate = false;
    o.Parameter = "P-001";
});

// 별칭으로 분리창 열기
windows.Open("acme.editor", o => o.Placement = UiWindowPlacement.Sdi);
```

- 중복 막기는 **제목을 지정하고** 중복을 허용하지 않을 때만 동작한다. 기존 문서를 활성화할 때도 true 이며, 이번에 준 `Parameter` 는 기존 문서에 반영되지 않는다.
- false 는 등록 안 된 창(XKUI0505) 또는 셸 미준비(XKUI0506)다. 이때 문서를 만들지 않는다.
- 모듈 `Configure` 안에서는 셸이 아직 없으므로 `Open` 을 부르지 않는다. 명령 실행처럼 화면이 뜬 뒤에 부른다.
- true 는 셸에 열기를 요청했다는 뜻이다. 내용 생성 실패(XKUI0507)는 반환값에 드러나지 않는다.

## 4. 조회와 실행 중 등록

```csharp
var windows = XkxkUi.Current.Windows;

if (windows.TryResolve("ACME.EDITOR", out var definition))
{
    System.Console.WriteLine($"{definition.Id} / {definition.Owner}");
}

windows.Changed += (_, e) => System.Console.WriteLine($"{e.Kind} {e.Id}");

windows.Add("acme.app.notes", o =>
{
    o.Title = "메모";
    o.CreateContent = _ => new Avalonia.Controls.TextBox();
});
windows.Remove("acme.app.notes"); // 같은 주체(app)라 지워진다
```

- 정의(`UiWindowDefinition`)는 등록 시점 옵션의 사본이다. 옵션 객체를 나중에 고쳐도 반영되지 않는다.
- 모르는 `UiRegistryChangeKind` 값을 받으면 전체를 다시 읽는다.

## 5. 저장한 배치와 호환

- 저장 형식은 Version 6 이다. 문서마다 창 ID(`WindowId`)를 저장하고, 데모 3종은 옛 판 앱을 위해 옛 이름(`Kind`)도 함께 쓴다.
- Version 5 이하 저장본은 읽을 때 옛 이름·옛 숫자 0~2 를 셸 데모 창 ID 로 바꾼다. 옛 저장본은 계속 열린다.
- 복원한 문서의 `Parameter` 는 항상 null 이다. 저장한 배치에 값을 싣는 수단은 지금 없으므로, 대상을 되살려야 하면 쓰는 쪽이 따로 보관한다. 내용 생성 함수는 null 을 반드시 처리한다(예 대상 선택 화면).
- 창은 배치를 복원하기 전에 등록돼 있어야 하므로 모듈 `Configure` 에서 등록한다.
- 자동 제목 문서는 등록된 창이면 복원할 때 현재 언어의 창 이름으로 제목을 다시 만든다. 사용자가 바꾼 제목과 등록 안 된 창의 제목은 저장값을 지킨다.

저장본에는 '중복 허용'을 **켠 창과 끈 창**이 함께 남는다. 복원할 때는 창마다 위에서부터 처음 맞는 줄을 적용한다.

| 저장본 상태 | 그 창의 설정 |
|---|---|
| 켠 목록에 있음(두 목록에 모두 있어도) | 켬 |
| 끈 목록에 있음 | 끔. 등록 안 된 창이어도 기억해 다음 저장에 남긴다 |
| 둘 다 없고 Version 5 이하이며 셸 데모 창 | 끔 |
| 그 밖 | 바꾸지 않는다 |

그래서 저장 뒤에 추가한 창은 저장본을 복원해도 `AllowDuplicate` 처음 값(또는 사용자가 바꾼 값)이 유지된다.

## 6. 모르는 창

| 상황 | 동작 |
|---|---|
| `Open` 에 모르는 ID·별칭 | false 와 XKUI0505. 문서를 만들지 않는다 |
| 저장한 배치에 등록 안 된 창 | **자리표시 문서**로 열고 ID·제목·위치를 보존한다. XKUI0505. 다시 저장해도 사라지지 않는다 |
| 저장소 호스트의 자동화 인자 `--open` 에 모르는 이름 | 자리표시 문서와 XKUI0505. `--open` 은 옛 이름·옛 숫자 0~2·창 ID·별칭을 받는다 |

- 자리표시 상태에서 창을 늦게 등록해도 열려 있는 화면이 바로 바뀐다고 기대하지 않는다. 문서를 닫고 다시 열거나 배치를 다시 불러온다.
- XKUI0505 는 **열기마다 1건**, 저장한 배치를 **복원(적용)할 때마다 창 ID 당 1건** 쌓인다. 같은 창의 문서가 여러 개여도 복원 한 번에는 1건이다. 자리표시 화면을 그리는 것만으로는 더 쌓이지 않는다.

## 7. 진단 코드

| 코드(`UiDiagnosticIds`) | 심각도 | 상황 → 결과 |
|---|---|---|
| XKUI0501 `WindowIdInvalid` | Error | 빈·공백 ID → 등록 안 함 |
| XKUI0502 `WindowDuplicate` | Error | `Replace=false` 로 같은 ID(첫 등록 유지), 새 ID 가 다른 창의 ID·별칭과 겹침, 옛 이름·숫자 ID → 등록 안 함 |
| XKUI0503 `WindowReservedId` | Error | 새 `xkxk.` ID → 등록 안 함. `xkxk.` 별칭·옛 이름·숫자 별칭 → 그 별칭만 버리고 등록 |
| XKUI0504 `WindowAliasConflict` | Warning | 별칭 충돌 → 그 별칭만 버림 |
| XKUI0505 `WindowNotRegistered` | Warning | 등록 안 된 창 열기·복원 → 6절 |
| XKUI0506 `WindowShellUnavailable` | Warning | 셸 준비 전 `Open` → false |
| XKUI0507 `WindowContentFailed` | Error | 내용 생성 실패, 또는 셸 데모 창이 아닌데 `CreateContent` 없음 → 자리표시 내용 |
| XKUI0508 `WindowRemoveDenied` | Error | 다른 주체의 창 제거 → 지우지 않음 |

- 규칙 위반은 예외 대신 진단이다. null 인자만 `ArgumentNullException` 이다.
- 모듈의 등록 진단은 Build 중이면 빌더 진단 모음, 그 뒤에는 `XkxkUi.Current.Diagnostics` 에 쌓인다. 열기 진단은 늘 앱 진단 모음이다.
- 빌드 중 Error 진단은 `UiErrorPolicy.Throw` 정책에서 `Build` 가 예외를 던지게 한다.

## 8. 한계

- `Parameter` 는 저장하지 않는다. 복원한 뒤에는 null 이다.
- 창을 `Remove`·`Replace` 해도 이미 열린 문서는 닫히거나 바뀌지 않는다. 그 뒤의 새 열기·복원부터 새 정의(제거면 자리표시)를 쓴다.
- 옛 판 앱도 Version 6 저장본을 읽도록 설계했지만, 옛 판 앱이 **다시 저장**하면 창 ID 와 창 ID 기준의 중복 허용 설정이 사라진다. 솔루션 창은 옛 이름이 없어 새 앱에서 Grid 창으로 굳는다(문서는 남고 종류만 잃는다). 옛 판 앱을 실제로 띄워 확인한 결과는 아니다.
- `IShellCommands` 는 공개 계약이 아니다. 창을 열 때는 `IUiWindowRegistry.Open` 을 쓴다. 이 판에서 그 형식의 문서 열기 첫 인자가 문자열 창 ID 로 바뀌어, 직접 쓰던 코드는 고쳐 다시 컴파일해야 한다.
- 옛 이름 변환 도우미 등 `xkxk.frameworks.ui.shell.Framework` 밖의 형식은 계약이 아니다.
- 레지스트리는 프로세스 전역이고 리셋이 없다. 제거 권한 검사는 실수 방지일 뿐 보안 경계가 아니다(`Replace=true` 로 주체를 가져올 수 있다).
