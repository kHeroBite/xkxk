# 04 확장 — 창

- 상태: 사전판(0.x 이전). 여기 나오는 공개 API 는 전부 미출시(Unshipped) 표면이다.
- 최종 갱신일: 2026-11-27
- 먼저 읽을 것: [01_시작하기.md](01_시작하기.md)(빌더·모듈·진단), [02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 의 공통 규칙. 정확한 서명은 [api/09_창.md](api/09_창.md).

**창 레지스트리**(`IUiWindowRegistry`)에 창 종류를 문자열 ID 로 등록하면, 그 ID 로 창(문서)을 열 수 있고 저장한 배치를 복원할 때도 같은 ID 로 내용을 만든다.
새 창은 뷰모델·뷰 형식으로 한 줄에 등록하는 **강타입 등록**(3절)을 먼저 쓴다. `CreateContent` 를 손으로 채우는 등록(2절)은 그 아래 바탕이다.

> **이번 판 변경 알림(소비자 영향)**
> - 셸은 기본 창을 더 이상 등록하지 않는다. 데모 창 3종(`xkxk.demo.*`)·데모 열기 명령·벤치 열기 명령은 같은 ID 로 저장소의 시험대 모듈이 등록한다. 시험대 모듈을 붙이지 않은 앱에서는 이 창을 열면 XKUI0505 이고, 파일 메뉴의 데모·벤치 열기 항목은 보이지 않는다(메뉴 자리와 `ShellMenuIds` 상수는 남는다).
> - 화면 층의 `BenchEntry` 형식이 없어졌다. 쓰던 코드는 지운다. 화면 층 `GridViewPool.TryTake()` 의 반환형이 `GridDocumentView?` 에서 `Control?` 로 바뀌었다(소스·바이너리 비호환, 다시 컴파일).
> - 창 등록 옵션에 `Prewarm`(2.4절)이 더해졌다(기본 `None` 이라 쓰던 코드는 그대로). 화면 층에 `IWindowOpenTracking`(열기 측정 알림 계약)이 새로 생겼고, 데모 문서 화면 형식(`GridDocumentView` 등)은 시험대 모듈로 옮겨 화면 층에서 없어졌다. 쓰던 코드는 지운다.
> - 화면 층에 '시험대 지원용'으로 새로 public 이 된 형식이 있다. 공개 계약이 아니므로 쓰지 않는다. 목록은 별별UI 저장소 정본 부록 a11(강타입 창 등록) 7절에 있다.

## 1. 얻는 곳과 멤버

| 얻는 곳 | 등록 주체(Owner) | 쓰는 때 |
|---|---|---|
| 모듈의 `IUiModuleContext.Windows` | 그 모듈 ID | 모듈 `Configure` 안에서 등록(권장) |
| 앱 컨텍스트의 `IUiAppContext.Windows`(`XkxkUi.Current`) | `app`(`UiRegistryOwners.App`) | 실행 중 열기·조회·등록 |

두 길은 같은 저장소를 본다. 레지스트리는 UI 스레드에서 부른다.

| 멤버 | 뜻 |
|---|---|
| `Add(id, configure)` | `UiWindowOptions` 로 등록(또는 `Replace=true` 로 교체). 거부하면 false 와 진단 |
| `Remove(id)` | 제거. 등록한 주체만 된다. 별칭도 함께 없어진다 |
| `Contains(id)`·`TryGet(id, out …)` | ID 로만 확인·조회(별칭은 보지 않는다) |
| `TryResolve(idOrAlias, out …)` | ID → 별칭(대소문자 무시) → 옛 이름·숫자(2.3절) 순서로 찾는다 |
| `Open(id)`·`Open(id, configure)` | `TryResolve` 와 같은 순서로 찾아 열기. `UiWindowOpenOptions` 로 이번 열기만 바꾼다 |
| `Items`·`Changed` | 등록 순서의 정의 목록(부를 때마다 사본)·등록·교체·제거 알림(`UiRegistryChangedEventArgs`) |

## 2. 등록

| `UiWindowOptions` | 기본값 | 뜻 |
|---|---|---|
| `TitleKey`·`Title` | null | 창 이름. 문구 키 → 제목 → 창 ID 순서로 쓴다 |
| `Icon` | null | 아이콘 키([02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 2절) |
| `Category`·`DescriptionKey` | null | 분류·도움말 문구 키 |
| `Placement` | `UiWindowPlacement.Default` | 보통 문서 배치. `UiWindowPlacement.Sdi` 면 분리창 |
| `AllowDuplicate` | false | 같은 제목 중복 허용의 **처음 값**. 사용자의 '중복 허용' 전환과 저장한 배치가 바꿀 수 있다 |
| `Aliases` | 빈 목록 | ID 대신 쓰는 이름(대소문자 무시). `Add` 로 더한다 |
| `CreateContent` | null | 내용 생성 함수. **솔루션 창은 반드시 채운다** |
| `Replace` | false | 같은 ID 교체 여부 |
| `Prewarm` | `UiWindowPrewarm.None` | 내용을 미리 준비하는 수준(2.4절). 등록 시점 값이 정의로 복사된다 |

```csharp
// 모듈 Configure(IUiModuleContext ui) 안 — 모듈은 01_시작하기.md 대로 XkxkUiBuilder.AddModule 로 넣는다
ui.Windows.Add("acme.project.editor", o =>
{
    o.Title = "프로젝트 편집";
    o.Aliases.Add("acme.editor");
    o.CreateContent = context =>
    {
        var projectCode = context.Parameter as string; // 복원한 문서는 null
        return new Avalonia.Controls.TextBlock { Text = projectCode ?? "프로젝트를 선택하세요" };
    };
});
```

명령·메뉴로 여는 길은 3.4절 예제와 [02_확장_메뉴명령아이콘.md](02_확장_메뉴명령아이콘.md) 를 따른다.

### 2.1 ID 와 별칭

- ID 는 대소문자를 구분하고 자기 접두어를 붙인다(예 `acme.project.editor`). 비었거나 공백뿐이면 XKUI0501 이다.
- 저장한 배치에 ID 가 남으므로 배포한 ID 는 바꾸지 않는다. 바꿔야 하면 옛 ID 를 새 창의 `Aliases` 에 넣는다. 복원할 때 별칭은 새 ID 로 바뀐다.
- ID 와 별칭은 **한 이름공간**이다. 새 ID 가 다른 창의 ID·별칭과 대소문자 무시로 같으면 등록하지 않는다(XKUI0502, `Add` 는 false). 기존 창은 그대로다. `Replace=true` 교체는 대소문자까지 같은 ID 에만 되며, 대소문자만 다른 ID 는 새 ID 라 거부된다.
- 다른 창의 ID·별칭과 겹치는 별칭은 그 별칭만 버리고 창은 등록한다(XKUI0504). 빈 별칭·자기 ID 와 같은 별칭·목록 안 중복은 진단 없이 버린다.
- `xkxk.`(`UiRegistryOwners.ReservedPrefix`)는 프레임워크 예약 접두어다. 아직 없는 `xkxk.` ID 를 새로 만들면 등록하지 않는다(XKUI0503, false). 이미 있는 `xkxk.` 창을 `Replace=true` 로 재정의하는 것은 된다. `xkxk.` 별칭(대소문자 무시)은 그 별칭만 버리고 창은 등록한다(XKUI0503, true).
- `Grid`·`Gantt`·`Form`·`0`·`1`·`2` 는 데모 창 3종을 가리키는 **영구 예약어**다(대소문자 무시). 앱·모듈이 창 ID 로 쓰면 `Replace` 와 무관하게 등록하지 않는다(XKUI0502, false). 별칭으로 넣으면 그 별칭만 버리고 창은 등록한다(XKUI0503, true).
- 별칭만 버린 경우는 `Add` 가 true 이므로 진단도 확인한다. XKUI0503 은 Error 라 `UiErrorPolicy.Throw` 에서는 빌드 중에 예외가 된다.

### 2.2 내용 생성 — `CreateContent`

- 반환값은 Avalonia `Control` 이어야 한다. 예외·null·`Control` 아닌 값이면 자리표시 내용과 XKUI0507 이다.
- 프레임워크는 내용을 만들 때마다 부르므로 부를 때마다 **새 컨트롤**을 만들어 돌려준다.
- 비워 둬도(null) 등록은 된다. 다만 화면이 대신 내용을 만들어 주는 창은 없다. 데모 창을 포함해 모든 창이 자리표시 내용과 XKUI0507 이다.
- 인자 `UiWindowContentContext` 는 `WindowId`(별칭으로 열어도 등록 ID)·`DocumentId`·`Title`·`Parameter`·`Window`(그 문서의 창 문맥, 3.2절)를 담는다.

### 2.3 교체와 제거

- `Replace=true` 는 새 정의로 통째로 바꾼다. 이전 값은 이어받지 않으므로 별칭·내용 함수까지 다시 채운다(옛 이름·숫자는 아래처럼 예외). 목록 자리는 유지되고 등록 주체는 교체한 쪽이 된다. 같은 ID 가 없으면 새로 등록하되 2.1절의 ID 규칙은 그대로 적용한다. 제거는 등록 주체만 한다. 모듈이 등록한 창을 `XkxkUi.Current.Windows` 로 지우면 주체가 달라 XKUI0508 이다. 없는 ID 는 진단 없이 false 다.
- 옛 이름·숫자(`Grid`·`Gantt`·`Form`·`0`·`1`·`2`)는 창 정의의 별칭과 무관하게 **언제나 데모 창 3종의 ID 로 풀린다.** 그래서 데모 창을 교체해도 셸 메뉴·저장본의 옛 이름은 새 정의를 연다. 교체할 때 옛 이름을 `Aliases` 에 넣지 않는다. 넣으면 그 별칭은 버려지고 XKUI0503 이다. 데모 창의 정확한 ID 는 `TryResolve("Grid", out …)` 처럼 얻는다(등록돼 있을 때만 true). 그 ID 의 창이 등록돼 있지 않거나 교체한 쪽이 `Remove` 하면 옛 이름으로 열어도 XKUI0505 다. 지운 정의는 되살아나지 않는다.

### 2.4 예열 — `Prewarm`

`None`(기본)은 처음 열 때 내용을 만든다. `Warm` 은 앱이 한가할 때 한 번 미리 만들어 첫 열기를 빠르게 하고, `KeepReady` 는 시작 뒤 유휴 때 미리 만들고 열 때 준비된 뷰를 먼저 쓰며(GridViewPool 설정이 켜진 경우) 쓴 뒤 유휴 때 하나를 다시 채운다. 강타입 등록은 예열하지 않는다(XKUI0511). 예열 대상의 내용 함수(`CreateContent`)는 임시 문서 문맥으로 불리므로 `context.Window`·`DocumentId` 를 쓰지 않는다. 값은 추가만 된다.

```csharp
ui.Windows.Add("acme.project.editor", o => { o.CreateContent = _ => new Avalonia.Controls.TextBlock(); o.Prewarm = UiWindowPrewarm.Warm; });
```
- 등록 뒤에 옵션을 고쳐도 등록된 창은 바뀌지 않는다. 예열 내용은 `CreateContent` 로 만들므로 `Parameter` 를 받지 않는다(null 처리).

## 3. 강타입 등록 — 뷰모델·뷰·인자 형식

뷰모델 형식과 뷰 형식(과 열 때 받을 인자 형식)을 주면 `CreateContent` 를 프레임워크가 채운다. 뷰모델은 창 문맥으로 자기 창의 제목·닫기·바쁨 표시를 다룬다.

- 등록 메서드는 화면 층 프로젝트(`xkxk.frameworks.ui.views`)의 정적 확장 클래스 `UiWindowViewRegistration` 에 있다. 쓰려면 그 프로젝트를 참조하고 네임스페이스 `xkxk.frameworks.ui.views.Windows` 를 using 한다. 화면 층에서 소비자가 쓰는 것은 이 클래스뿐이다.
- 화면 층은 공개 API 목록 추적 밖이라 [api/](api/README.md) 생성 명세에 이 클래스가 없고 서명의 정본은 아래 표다. 뷰모델 기반 형식(`UiWindowViewModel`·`UiWindowViewModel<TArgs>`)과 창 문맥(`IUiWindowContext`)은 공개 네임스페이스에 있고 명세에 실린다.

### 3.1 등록 6 오버로드

| # | 서명(첫 인자 `this IUiWindowRegistry registry` 생략) | 뷰모델 제약 |
|---|---|---|
| 1 | `Register<TViewModel, TView>(string id)` | `UiWindowViewModel, new()` |
| 2 | `Register<TViewModel, TView>(string id, Action<UiWindowOptions> configure)` | `UiWindowViewModel, new()` |
| 3 | `Register<TViewModel, TView>(string id, Action<UiWindowOptions> configure, Func<UiWindowContentContext, TViewModel> createViewModel)` | `UiWindowViewModel` |
| 4 | `Register<TViewModel, TView, TArgs>(string id)` | `UiWindowViewModel<TArgs>, new()` |
| 5 | `Register<TViewModel, TView, TArgs>(string id, Action<UiWindowOptions> configure)` | `UiWindowViewModel<TArgs>, new()` |
| 6 | `Register<TViewModel, TView, TArgs>(string id, Action<UiWindowOptions> configure, Func<UiWindowContentContext, TViewModel> createViewModel)` | `UiWindowViewModel<TArgs>` |

- 뷰 제약은 모두 `TView : Control, new()` 다. 반환값은 `Add` 결과(bool)이고 ID·별칭 규칙(2.1절)·진단은 `Add` 와 같다. 선택 파라미터는 없고, 인자가 null 이면 `ArgumentNullException` 이다.
- `configure` 로 제목·아이콘·별칭 등 `UiWindowOptions` 를 채운다. 그 안에서 `CreateContent` 를 채워도 이 등록이 덮어쓴다(진단 없음).
- 생성 함수(3·6번)는 서비스 주입 등 `new()` 로 만들 수 없는 뷰모델에 쓴다. 내용을 만들 때마다 불러 새 뷰모델을 돌려준다.

### 3.2 뷰모델과 창 문맥

| 뷰모델 멤버 | 뜻 |
|---|---|
| `Window` | 이 뷰모델의 창 문맥(`IUiWindowContext`). 생성자 안 등 연결 전에 읽으면 `InvalidOperationException` |
| `Parameter` · `Args` | 열 때 넘긴 값. `Args` 는 `UiWindowViewModel<TArgs>` 에만 있고, 값이 없으면 기본값 |
| `OnOpenedAsync(CancellationToken)` | 창이 열린 뒤 1회. 자료 읽기 등 비동기 초기화. 토큰은 창이 닫히면 취소된다 |
| `OnClosed()` | 창이 닫힌 뒤 1회. 구독 해제 등 정리 |
| `AcceptParameter(object?)` | 넘긴 값을 받을지 판정. 제네릭 판은 null·`TArgs` 만 받는다. 비제네릭 판은 재정의해 직접 검사한다 |
| `OnPropertyChanged`·`SetProperty` | 속성 변경 알림(`INotifyPropertyChanged`) |

| 창 문맥 멤버(`IUiWindowContext`) | 뜻 |
|---|---|
| `WindowId`·`DocumentId`·`Title`·`Parameter`·`IsOpen` | 창 ID(별칭으로 열어도 등록 ID)·문서 ID·현재 제목·넘긴 값·열림 여부 |
| `SetTitle(title)`·`Close()` | 문서 제목을 바꾼다·이 창을 닫는다. 이미 닫혔으면 false |
| `BeginBusy()`·`BeginBusy(reason)` | 바쁨 표시를 켠다. 돌려받은 값을 해제하면 꺼진다. 닫힌 뒤에는 아무 일도 하지 않는 값 |
| `Closed` | 창이 닫힌 뒤 1회 |

- 뷰모델 생성자는 매개변수 없는 protected 하나다. 생성자에서는 `Window` 를 읽지 않고 `OnOpenedAsync` 부터 쓴다. 창 문맥은 프레임워크만 구현하며 소비자는 구현하지 않는다(시험용 가짜는 예외).
- 뷰모델의 `AttachWindow`·`NotifyOpenedAsync`·`NotifyClosed` 는 **프레임워크 전용**이다(편집기 자동 완성에 숨김). 소비자는 부르지 않는다. 직접 부르면 수명 호출이 겹칠 수 있고, 두 번째 연결과 연결 전 열림 알림은 `InvalidOperationException` 이다.
- 명령 처리기에서는 `UiCommandContext.Windows`(= 앱 컨텍스트의 `Windows`)로 창을 연다.

### 3.3 흐름과 오류

1. 내용을 만들 때마다 뷰모델을 만든다(생성 함수 또는 `new()`). 생성 함수가 null 을 돌려주거나 예외를 던지면 XKUI0507 과 자리표시 내용이다.
2. 창 문맥과 넘긴 값을 연결한다. `AcceptParameter` 가 false 면 연결하지 않고 XKUI0509 와 자리표시 내용이다. 복원한 문서는 값이 null 이라 오류가 아니다(`Args` 는 기본값).
3. 뷰를 `new TView { DataContext = 뷰모델 }` 로 만든다.
4. 뷰가 처음 화면 트리에 붙을 때 `OnOpenedAsync` 를 1회 부른다. 분리창 이동·탭 재부착으로 다시 붙어도 다시 부르지 않는다. 예외는 XKUI0510 이고 뷰는 그대로 둔다. 창이 닫혀 토큰이 취소된 뒤의 취소 예외는 남기지 않는다.
5. 창이 닫히면 토큰을 취소하고 `OnClosed` 를 1회 부른다. 그 처리의 예외도 XKUI0510 이며 앱은 멈추지 않는다.

### 3.4 예제

```csharp
using System.Threading;
using System.Threading.Tasks;
using Avalonia.Controls;
using xkxk.frameworks.ui.shell.Framework;
using xkxk.frameworks.ui.views.Windows; // 화면 층 — 강타입 등록 확장 메서드

public sealed record AcmeIssueArgs(string IssueCode);

public sealed class AcmeIssueViewModel : UiWindowViewModel<AcmeIssueArgs>
{
    private string _summary = "불러오는 중";
    public string Summary { get => _summary; private set => SetProperty(ref _summary, value, nameof(Summary)); }

    protected override async Task OnOpenedAsync(CancellationToken cancellationToken)
    {
        using (Window.BeginBusy("이슈 읽기"))
        {
            await Task.Delay(100, cancellationToken); // 자기 제품의 자료 읽기 자리
            var code = Args?.IssueCode ?? "새 이슈"; // 복원한 문서는 Args 가 null
            Window.SetTitle($"이슈 {code}");
            Summary = code;
        }
    }
    protected override void OnClosed() { /* 구독 해제 등 정리 */ }
}

public sealed class AcmeIssueView : UserControl
{
    public AcmeIssueView()
    {
        var text = new TextBlock(); Content = text;
        DataContextChanged += (_, _) => // 뷰모델은 DataContext 로 들어온다
        {
            if (DataContext is not AcmeIssueViewModel vm) return;
            text.Text = vm.Summary;
            vm.PropertyChanged += (_, _) => text.Text = vm.Summary;
        };
    }
}

public sealed class AcmeIssueModule : UiModule
{
    public override string Id => "acme.issue";
    public override void Configure(IUiModuleContext ui)
    {
        ui.Windows.Register<AcmeIssueViewModel, AcmeIssueView, AcmeIssueArgs>("acme.issue.detail", o => o.Title = "이슈");
        ui.Commands.Add("acme.issue.open", o =>
        {
            o.Title = "이슈 열기";
            o.Execute = c => c.Windows.Open("acme.issue.detail", w => w.Parameter = new AcmeIssueArgs("I-001"));
        });
    }
}
```

- 별별UI 저장소의 시험대 표본 창(뷰모델·코드 전용 뷰·인자 문자열 3형식)이 같은 꼴의 실행 예다. 인자 형식이 다른 값(예 숫자)으로 열면 XKUI0509 와 자리표시 문서다. 열기 반환값은 true 이므로 진단으로 확인한다.

### 3.5 한계

- 앱을 끝낼 때는 열린 문서의 `OnClosed` 가 불리지 않는다. 종료 때 꼭 해야 할 정리는 앱 종료 이벤트를 따로 쓴다. 내용을 만들기 전에 닫힌 문서는 창 문맥이 없다. 그 문서의 뷰모델은 만들어지지 않으므로 `OnClosed` 도 불리지 않는다. 닫기를 거부하는 수단은 없다. 뷰모델과 창 문맥은 UI 스레드에서만 쓴다(다른 스레드 호출 보호 없음).

## 4. 열기

| `UiWindowOpenOptions` | 기본값 | 뜻 |
|---|---|---|
| `Title` | null | 문서 제목. null 이면 "창 이름 번호" 자동 제목이고 **항상 새 문서**다 |
| `Placement` | `Default` | `Default` 는 창 정의를 따르고 `Sdi` 는 분리창 |
| `AllowDuplicate` | null | null 은 현재 설정(처음 값은 정의의 `AllowDuplicate`) |
| `Parameter` | null | `CreateContent` 에 넘길 값. 저장하지 않는다 |

```csharp
var windows = XkxkUi.Current.Windows;
// 같은 제목이 이미 열려 있으면 그 문서를 활성화한다
var opened = windows.Open("acme.project.editor", o => { o.Title = "프로젝트 P-001"; o.AllowDuplicate = false; o.Parameter = "P-001"; });
// 별칭으로 분리창 열기
windows.Open("acme.editor", o => o.Placement = UiWindowPlacement.Sdi);
```

- 중복 막기는 **제목을 지정하고** 중복을 허용하지 않을 때만 동작한다. 기존 문서를 활성화할 때도 true 이며, 이번에 준 `Parameter` 는 기존 문서에 반영되지 않는다.
- false 는 등록 안 된 창(XKUI0505) 또는 셸 미준비(XKUI0506)다. 이때 문서를 만들지 않는다.
- 모듈 `Configure` 안에서는 셸이 아직 없으므로 `Open` 을 부르지 않는다. 명령 실행처럼 화면이 뜬 뒤에 부른다. true 는 셸에 열기를 요청했다는 뜻이다. 내용 생성 실패(XKUI0507)는 반환값에 드러나지 않는다.

## 5. 조회와 실행 중 등록

```csharp
var windows = XkxkUi.Current.Windows;
if (windows.TryResolve("ACME.EDITOR", out var definition))
    System.Console.WriteLine($"{definition.Id} / {definition.Owner}");
windows.Changed += (_, e) => System.Console.WriteLine($"{e.Kind} {e.Id}");
windows.Add("acme.app.notes", o => { o.Title = "메모"; o.CreateContent = _ => new Avalonia.Controls.TextBox(); });
windows.Remove("acme.app.notes"); // 같은 주체(app)라 지워진다
```

- 정의(`UiWindowDefinition`)는 등록 시점 옵션의 사본이다. 옵션 객체를 나중에 고쳐도 반영되지 않는다. 모르는 `UiRegistryChangeKind` 값을 받으면 전체를 다시 읽는다.

## 6. 저장한 배치와 호환

- 저장 형식은 Version 6 이다. 문서마다 창 ID(`WindowId`)를 저장하고, 데모 3종은 옛 판 앱을 위해 옛 이름(`Kind`)도 함께 쓴다.
- Version 5 이하 저장본은 읽을 때 옛 이름·옛 숫자 0~2 를 데모 창 ID 로 바꾼다. 옛 저장본은 계속 열린다.
- 복원한 문서의 `Parameter` 는 항상 null 이다. 저장한 배치에 값을 싣는 수단은 지금 없으므로, 대상을 되살려야 하면 쓰는 쪽이 따로 보관한다. 내용 생성 함수는 null 을 반드시 처리한다(예 대상 선택 화면).
- 창은 배치를 복원하기 전에 등록돼 있어야 하므로 모듈 `Configure` 에서 등록한다.
- 자동 제목 문서는 등록된 창이면 복원할 때 현재 언어의 창 이름으로 제목을 다시 만든다. 사용자가 바꾼 제목과 등록 안 된 창의 제목은 저장값을 지킨다.

저장본에는 '중복 허용'을 **켠 창과 끈 창**이 함께 남는다. 복원할 때는 창마다 위에서부터 처음 맞는 줄을 적용한다. 그래서 저장 뒤에 추가한 창은 저장본을 복원해도 `AllowDuplicate` 처음 값(또는 사용자가 바꾼 값)이 유지된다.

| 저장본 상태 | 그 창의 설정 |
|---|---|
| 켠 목록에 있음(두 목록에 모두 있어도) | 켬 |
| 끈 목록에 있음 | 끔. 등록 안 된 창이어도 기억해 다음 저장에 남긴다 |
| 둘 다 없고 Version 5 이하이며 데모 창 | 끔 |
| 그 밖 | 바꾸지 않는다 |

## 7. 모르는 창

| 상황 | 동작 |
|---|---|
| `Open` 에 모르는 ID·별칭 | false 와 XKUI0505. 문서를 만들지 않는다 |
| 저장한 배치에 등록 안 된 창 | **자리표시 문서**로 열고 ID·제목·위치를 보존한다. XKUI0505. 다시 저장해도 사라지지 않는다 |
| 저장소 호스트의 자동화 인자 `--open` 에 모르는 이름 | 자리표시 문서와 XKUI0505. `--open` 은 옛 이름·옛 숫자 0~2·창 ID·별칭을 받는다 |

- 자리표시 상태에서 창을 늦게 등록해도 열려 있는 화면이 바로 바뀐다고 기대하지 않는다. 문서를 닫고 다시 열거나 배치를 다시 불러온다. XKUI0505 는 **열기마다 1건**, 저장한 배치를 **복원(적용)할 때마다 창 ID 당 1건** 쌓인다. 같은 창의 문서가 여러 개여도 복원 한 번에는 1건이다. 자리표시 화면을 그리는 것만으로는 더 쌓이지 않는다.

## 8. 진단 코드

| 코드(`UiDiagnosticIds`) | 심각도 | 상황 → 결과 |
|---|---|---|
| XKUI0501 `WindowIdInvalid` | Error | 빈·공백 ID → 등록 안 함 |
| XKUI0502 `WindowDuplicate` | Error | `Replace=false` 로 같은 ID(첫 등록 유지), 새 ID 가 다른 창의 ID·별칭과 겹침, 옛 이름·숫자 ID → 등록 안 함 |
| XKUI0503 `WindowReservedId` | Error | 새 `xkxk.` ID → 등록 안 함. `xkxk.` 별칭·옛 이름·숫자 별칭 → 그 별칭만 버리고 등록 |
| XKUI0504 `WindowAliasConflict` | Warning | 별칭 충돌 → 그 별칭만 버림 |
| XKUI0505 `WindowNotRegistered` | Warning | 등록 안 된 창 열기·복원 → 7절 |
| XKUI0506 `WindowShellUnavailable` | Warning | 셸 준비 전 `Open` → false |
| XKUI0507 `WindowContentFailed` | Error | 내용 생성 실패, `CreateContent` 없음, 강타입 등록의 뷰모델 생성 함수 null·예외 → 자리표시 내용 |
| XKUI0508 `WindowRemoveDenied` | Error | 다른 주체의 창 제거 → 지우지 않음 |
| XKUI0509 `WindowArgumentMismatch` | Error | 강타입 창에 뷰모델이 받지 않는 값으로 열기 → 자리표시 내용 |
| XKUI0510 `WindowViewModelFailed` | Error | 뷰모델 `OnOpenedAsync`·`OnClosed` 예외 → 뷰는 그대로 두고 앱은 계속 |
| XKUI0511 `WindowPrewarmIgnored` | Warning | 강타입 창 등록에 Prewarm 지정 → None 으로 바꿔 등록 |

- 규칙 위반은 예외 대신 진단이다. null 인자만 `ArgumentNullException` 이다(프레임워크 전용 진입점은 3.2절).
- 모듈의 등록 진단은 Build 중이면 빌더 진단 모음, 그 뒤에는 `XkxkUi.Current.Diagnostics` 에 쌓인다. 열기 진단은 늘 앱 진단 모음이다. 빌드 중 Error 진단은 `UiErrorPolicy.Throw` 정책에서 `Build` 가 예외를 던지게 한다.

## 9. 한계

- `Parameter` 는 저장하지 않는다. 복원한 뒤에는 null 이다. 강타입 창의 한계는 3.5절이다. 원격 열기(`docs.open`)는 문자열 param 만 전달한다. 문자열이 아닌 인자 형식의 강타입 창은 원격으로 열 수 없다. 창을 `Remove`·`Replace` 해도 이미 열린 문서는 닫히거나 바뀌지 않는다. 그 뒤의 새 열기·복원부터 새 정의(제거면 자리표시)를 쓴다. 옛 판 앱도 Version 6 저장본을 읽도록 설계했지만, 옛 판 앱이 **다시 저장**하면 창 ID 와 창 ID 기준의 중복 허용 설정이 사라진다. 솔루션 창은 옛 이름이 없어 새 앱에서 Grid 창으로 굳는다(문서는 남고 종류만 잃는다). 옛 판 앱을 실제로 띄워 확인한 결과는 아니다.
- `IShellCommands` 는 공개 계약이 아니다. 창을 열 때는 `IUiWindowRegistry.Open` 을 쓴다. 이 판에서 그 형식의 문서 열기 첫 인자가 문자열 창 ID 로 바뀌어, 직접 쓰던 코드는 고쳐 다시 컴파일해야 한다. 옛 이름 변환 도우미 등 `xkxk.frameworks.ui.shell.Framework` 밖의 형식은 계약이 아니다. 레지스트리는 프로세스 전역이고 리셋이 없다. 제거 권한 검사는 실수 방지일 뿐 보안 경계가 아니다(`Replace=true` 로 주체를 가져올 수 있다).
