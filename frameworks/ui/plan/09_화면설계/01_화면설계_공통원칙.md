### 2-1. 제목 줄 규칙
- **크기:** 제목 줄 높이는 설정 ▸ 모양의 '탭 줄 높이'(`ui.shell.tab_strip_height_dp`)로 정한다. 제목 탭 높이는 줄 높이 × 16/19 를 반올림한 값이다. 탭 글자는 시스템 글자 토큰 `PdFontCaption` 을 따른다(§5.2). 닫기 ×·SDI 아이콘(16 DIP)은 제목 줄 안에 들어가야 한다. 메뉴 줄 32 DIP 는 OS 캡션 기준이라 바꾸지 않는다(05_창크롬 문서). 데스크톱·웹 같다.
- **제목 탭 폭:** 자연 폭을 최소·최대 폭(`ui.shell.title_tab.min_width_dp`·`ui.shell.title_tab.max_width_dp`) 사이로 자른다. 합계가 가용 폭(오른쪽 SDI 아이콘 칸 제외)을 넘으면 모든 탭에 같은 상한 `max(최소 폭, 가용 폭/탭 수)` 를 적용한다(짧은 제목은 자연 폭 유지). 최소 폭에서도 넘치면 2px 얇은 스크롤(U4)이다. 잘린 제목은 말줄임(…)으로 표시하고 툴팁에 전체 제목을 보인다. 활성 탭만 넓히지 않는다(탭 위치가 흔들림). 폭 계산은 UI 와 분리한 순수 계산이다. 값의 조사 근거는 a13 §3 이다.
- **툴팁:** 모든 제목 탭은 전체 제목(프로젝트가 있으면 "제목 — 프로젝트")을 툴팁으로 보인다.
- **탭 아이콘·표시 방식:** 제목 탭은 제목 앞에 그 창의 메뉴 아이콘을 보인다. 아이콘만·아이콘+제목·제목만을 `ui.shell.title_tab.display` 로 고르고(기본 아이콘+제목), 아이콘만이면 탭 폭은 `ui.shell.title_tab.icon_only_width_dp` 고정이다. DOCK 문서 탭도 같은 방식이다. 아이콘 정본·표시 자리는 `22_메뉴아이콘_제목탭_즐겨찾기_설계.md` §2·§3 이다(REQ-113, D-578~D-580).
- **즐겨찾기 영역:** 제목 줄 오른쪽 끝(독립 창 아이콘 오른쪽, 구분선 뒤)에 화면 즐겨찾기를 아이콘만으로 오른쪽부터 쌓는다. 제목 탭 가용 폭은 즐겨찾기 영역과 독립 창 아이콘 칸을 뺀 폭이다. 0개면 영역과 구분선을 숨긴다. 규칙은 22 §4 다(D-581).
- **불러오는 중 표시:** 창 콘텐츠를 다 불러오기 전까지 창 아이콘을 스피너로 바꾸고 끝나면 원래 아이콘으로 되돌린다. 검색·새로고침 때도 같다. **새 화면은 콘텐츠 불러오기 보고 계약을 반드시 구현한다**(구현하지 않으면 뷰가 붙은 순간을 완료로 보는 한계가 남는다). 계약·표시 규칙은 `23_창_불러오는중_표시_설계.md` 다(REQ-114, D-583·D-584).
- **독립 창(SDI) 아이콘:** 떠 있는 독립 창은 제목 탭에 두지 않고 제목 줄 오른쪽 끝의 작은 아이콘(16 DIP)으로 보인다. 활성은 강조 바탕, 비활성은 투명, 최소화는 흐린 글리프다. 툴팁은 창 이름(문서 2개 이상이면 "활성 제목 외 N"), 클릭하면 그 창을 활성화하고 최소화 상태면 복원한다. 아이콘 수는 독립 창 수와 같다.
- **제목 탭 닫기 × 표시:** `ui.shell.title_tab.close_mode` 로 고른다(값 `always`·`hover`·`active_and_hover`·`auto`). `always` 는 모든 탭에 ×, `hover` 는 마우스를 올린 탭에만, `active_and_hover` 는 활성 탭과 마우스를 올린 탭에만 보인다. `auto` 는 마우스 기기면 `hover`, 터치 기기면 `always` 로 동작한다. × 는 제목 끝 위에 겹쳐 그리고 그 아래 제목 글자를 흐리게 한다(× 가 나타나거나 사라져도 글자는 밀리지 않는다). × 가 숨겨진 탭은 그 자리를 제목에 돌려줘 제목이 더 길게 보인다(말줄임 위치만 달라지고 탭 폭은 그대로다). 키보드 포커스가 탭에 있으면 모드와 상관없이 그 탭의 × 를 보인다. 가운데(휠) 클릭은 × 가 숨겨져 있어도 그 탭을 닫는다. 숨김 시 접근성 이름의 닫기 동작은 유지한다.
- **DOCK(태블릿형):** 가운데 문서 탭이 목록을 맡으므로 제목 줄의 제목 탭을 숨긴다. 독립 창이 있으면 제목 줄은 아이콘만 남고, 없으면 줄 자체를 숨긴다. 문서 영역에 제목 탭과 같은 이름의 탭을 중복해 보이지 않는다. NAV 는 제목 줄이 없다.
- **타이틀바 오른쪽 배치:** 메뉴 줄 오른쪽은 `[자동][PC형][태블릿형][모바일형] [테마 아이콘] [_][□][X]` 순서다. 테마 아이콘은 최소화 버튼 바로 왼쪽에 두고, 그 바로 왼쪽에 UI 방식 아이콘 4칸이 온다. 캡션 버튼이 없는 웹·Android 는 테마 아이콘이 오른쪽 끝이다. 5개 모두 직접 그린 벡터 아이콘(U10)이고 이름은 툴팁과 접근성 이름으로 보인다. 테마 아이콘은 지금 어두우면 해, 밝으면 달 그림이며 누르면 라이트·다크가 바뀐다. 메뉴 줄 아래 별도 도구모음 줄(라이트/다크 스위치·설정 버튼)은 두지 않는다. 설정은 시스템(Y) ▸ 설정으로 연다. 오른쪽 도구 폭이 늘어난 만큼 셸 메뉴는 더보기로 일찍 접힌다.
- **UI 방식 스위치:** 메뉴 줄 스위치는 [자동]·PC형·태블릿형·모바일형 4칸(아이콘)이다. [자동]을 켜면 자동 판정 칸이 옅은 강조(강조색 1px 테두리+옅은 바탕)로 표시된다. 창 폭 경계 규칙(`ui.layout.expanded_width_dp`·`ui.layout.compact_width_dp`, 히스테리시스·디바운스 포함 — 08 용어 §1-3)으로 PC형·태블릿형·모바일형이 자동 전환된다. 자동 상태에서도 PC형·태블릿형·모바일형 칸은 눌리며, 누르면 한 번에 자동이 풀리고 그 방식으로 전환된다. 칸이 비활성이 되는 경우는 기기가 허용하지 않을 때뿐이다(폰은 모바일형만 허용, 스위치 숨김). 자동 상태에서 [자동]을 다시 누르면 자동을 끄고 현재 판정 형을 수동 선택으로 저장해 화면이 바뀌지 않는다.

## 3. 셸 메뉴와 메뉴 줄 (ADR-052)

- 한 줄 배치: `[로고] [파일] [창] [보기] [시스템] …빈 공간… [_][□][X]`. 빈 공간은 끌어서 창을 옮기고, 더블클릭하면 최대화↔복원이며, 가장자리 스냅을 지원한다(Q14).
- 메뉴 줄에는 'Pd' 글자를 표시하지 않는다(U17). 접근성 이름은 유지한다.
- '창'과 '윈도우'는 같은 뜻이라 '창(W)' 하나로 합쳤다(U16). 합친 결과 트리는 `02_메뉴구조.md` §1 이다. 내부 명령·설정 키는 호환을 위해 바꾸지 않는다.
- 시스템(Y) 메뉴는 `05_아키텍처/05_제품구성_시스템메뉴.md` §2·§3.1 순서를 따른다(디버그모드·GPU·중복모드·모니터링·로그·문의·업데이트·변경이력·도움말·정보).
- 셸 메뉴 문구는 다국어 키로만 쓴다(§10). 영어로 바꿔도 한 줄에서 잘리지 않아야 한다(Q17). 폭이 모자라면 오른쪽부터 '더보기'로 접는다.

### 4.2 창 크롬
- 창 스타일은 3종이다. **Windows 11**(기본)·**macOS**·**클래식**. '클래식'은 옛 'Mars 클래식'의 표시 이름이다(U2). 수치(모서리·외곽선·그림자·제목줄 높이)는 `05_창크롬_OS디자인_기준.md` 를 따른다.
- 캡션 버튼은 글자 글리프가 아니라 직접 만든 벡터 아이콘이다(U10, 외부 저작권 아이콘 복사 금지). 호버·누름·켜짐 표현은 아래 크롬 버튼 상태 표를 따른다. 최소화 아이콘은 아래쪽 기준선에 둔다.
- 캡션 버튼 간격은 스타일과 상관없이 좁게 맞춘다(U11).
- 앱 로고는 독립 창(SDI)과 메인 창에만 표시하고 MDI 문서 창에는 두지 않는다(U12, 근거 조사는 05 문서 U12 절).
- 하단 모서리는 바깥 둥근 반경과 내용 영역 반경을 맞춰 창틀 두께를 일정하게 한다. 맞출 수 없는 렌더 경로는 하단 모서리를 각지게 한다(U8).
- 메인 창 제목 줄은 창이 비활성이면 제목 줄 요소 전체를 반투명으로 흐리게 한다(근거 `05_창크롬_OS디자인_기준.md`, Windows 공식 문구는 투명도 수치를 주지 않는다). 비활성이면 요소에 `PdChromeInactiveOpacity` 를 적용하고 바탕은 `PdBrushMainTitleBarInactive` 다. 웹과 Android 는 OS 창 활성 개념이 달라 흐리지 않고 활성 바탕을 유지한다.
- 메인 창 타이틀바는 바로 아래 제목 줄과 바탕색으로 구분한다(모든 테마). 전용 토큰 `PdBrushMainTitleBar`(활성)·`PdBrushMainTitleBarInactive`(비활성)·`PdBrushMainTitleText`(글자)를 쓰고, 창 스타일에 따라 표면색이 되는 문서 창 별칭(`PdChrome*`)은 쓰지 않는다. 판정 기준은 활성 바탕 대 제목 줄 3.0 이상, 활성 글자 대 바탕 4.5 이상, 비활성 글자(투명도 반영) 대 바탕 3.0 이상, 비활성 바탕 대 제목 줄 1.2 이상이다. OS 기준 문서에 값이 없어 [WCAG 2.1 SC 1.4.11](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html)·[SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 을 준용한 기본값이고, 비활성 2개는 PD 판단값이다.
- 문서 창(MDI·SDI) 기능 버튼 7개는 인접 그림 사이 빈 공간을 9px 로 둔다(버튼 폭 19, 클래식 13). 터치 기기는 인접 버튼을 겹치지 않고는 눌림 영역을 지킬 수 없어 28×32 를 쓴다. 이 값과 `06_모바일_화면설계.md` 의 터치 기준(48dp·44pt)의 어긋남은 TODO-645 가 맞춘다.
- 크롬 버튼 상태 표현은 다음과 같다. 호버·누름에는 테두리를 쓰지 않고 바탕색만 바꾼다. 호버 바탕은 메뉴 막대 항목 호버와 같은 토큰이다. 켜짐·꺼짐은 바탕을 바꾸지 않고 기호 색과 불투명도로 구분한다. 대상은 문서 창 기능 단추 줄(MDI·웹 관리형·SDI), 문서 창 캡션 3단추, 메인 제목줄의 테마 단추·UI 형 스위치(A·PC·태블릿·모바일)·최소·최대·닫기다. 전환은 즉시이며 애니메이션은 없다. 값은 테마 토큰(별칭 `PdChromeState*`)이고 내장 테마별 값과 대비 실측은 a13 §4.2 다.

| 상태 | 바탕 | 테두리 | 기호 | 적용 |
|---|---|---|---|---|
| 꺼짐(쉼) | 없음 | 없음 | 쉬는 기호 색, 불투명도 `PdChromeToggleOffOpacity`(기본값 0.85, 허용 0.82~0.9) | 토글 5개·UI 형 스위치 비선택 칸. 일반 단추(새로고침·도움말·테마·캡션)는 1.0 |
| 켜짐 | 없음(바탕 그대로) | 없음 | 켜짐 기호 색(`PdChromeGlyphChecked`, 강조 띠 위는 `PdBrushChromeGlyphCheckedOnAccent`) + 불투명도 1.0 + 1.15배 | 토글 5개(독립·항상 위·위치 고정·동기화·중복)·UI 형 스위치 선택 칸 |
| 호버 | 메뉴 막대 호버와 같은 바탕(`PdChromeHover`), 비활성 창은 `PdChromeHoverInactive` | 없음 | 꺼짐도 1.0 으로 또렷해짐, 켜짐은 기호 색 유지 | 기능·캡션·메인 제목줄 단추(터치 기기는 고착을 막으려고 끈다) |
| 누름 | 호버 바탕 유지 | 없음 | 누름 기호 색(`PdChromeGlyphPressed`) | 위와 같음 |
| 사용 불가 | 없음 | 없음 | 불투명도 `PdChromeDisabledOpacity`(기본값 0.3), 호버 반응 없음 | UI 형 스위치에서 기기가 허용하지 않는 칸 |
| 닫기 호버·누름 | 위험 빨강 채움 | 없음 | 밝은 기호 | 닫기(메인·MDI·SDI 같은 관례) |

- 켜짐·누름에서 바탕을 반전해 채우지 않고, 호버·누름에 외곽선을 쓰지 않는다. 기능 버튼 기호는 같은 선 굵기의 단순한 모양이다.
- UI 형 스위치에서 자동일 때 지금 판정된 칸은 불투명도 1.0 의 쉬는 기호 색이고, 기호 아래에 점(`PdUiAutoDotSize`, 0 이면 숨김)을 둔다. 선택 칸의 강조색 채움·테두리는 쓰지 않는다.
- 켜짐 표식 점(`PdChromeCheckedDotSize`)은 기본값 0 이라 보이지 않는다. 색·불투명도·크기 세 가지로 구분이 모자라는 테마만 토큰으로 켠다.
- 키보드 포커스 링은 제목줄 크롬 단추·UI 형 스위치 칸·문서 창 크롬 단추에 2px 안쪽 링(제목줄 기호·글자색)으로 그리고, 키보드로 옮긴 포커스(:focus-visible)에서만 보인다. 강조색 1px 기본 링은 강조색 제목줄에 묻히기 때문이다. 캡션·스위치 기호의 세로 중심을 맞춘다.
- 판정 기준은 켜짐 기호 색 대 제목줄 바탕 3:1 이상, 꺼짐 기호(불투명도 합성 뒤) 대 바탕 3:1 이상, 비활성 창 호버 바탕 대 비활성 제목줄 바탕 3:1 이상(비활성 단추 줄 흐림을 반영한 실효 대비)이다. 활성·항상 위 바탕에서 상태 간 인접 색 대비는 3.0 이상, 비활성 바탕에서 기본↔켜짐은 2.0 이상이다. 3.0 은 [WCAG 2.1 SC 1.4.11](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html) 을 준용한 기본값이고 2.0 은 PD 판단값이다. 12px 기호는 앤티앨리어싱으로 실측 대비가 계산보다 낮게 나오므로 판정은 실측으로 한다. 비활성 창 호버 토큰은 내장 테마 전부에 값을 두고, 사용자 정의 테마에 키가 없으면 활성 호버 값으로 채운다. 강조 제목줄만 이 토큰을 쓰고 표면색 제목줄은 `PdBrushCaptionHover` 를 쓴다.
- 비활성 창은 기호만 흐리게 한다. 꺼짐 불투명도와 곱해져 너무 흐리면 비활성 창에서는 꺼짐 불투명도를 1.0 으로 둔다(캡처로 판단).
- 새로고침 아이콘 색은 캐시 적중률을 나타낸다(0% 은색, 1~99% 연노랑에서 금색, 100% 주황 계열). 강조 띠 위 네 토큰(`PdBrushChromeGlyph`·`PdBrushCacheLow`·`PdBrushCacheHigh`·`PdBrushCacheFull`)과 표면색 제목줄 위 네 토큰(`PdBrushCache*OnSurface`)은 내장 테마에서 각 활성 바탕 대비 3.0 이상으로 둔다. 정확한 값은 툴팁으로 확인한다. 터치 기기는 툴팁을 띄우지 않아 색만 남는다(적중률은 보조 정보라 별도 표시를 두지 않는다).
- 기능 버튼에는 사용 불가 상태가 없다(사용 불가는 UI 형 스위치 칸에만 있다). 동기화 버튼은 기본이 켜짐이다. macOS 신호등은 위 표의 대상이 아니다.
- 모든 창은 고도 그림자를 갖는다. 활성 창은 진하게, 비활성 창은 약하게 하고, 최대화 창은 그림자가 없다(판정보고서 §6.2).
- MDI 문서 창 끌기 중 가벼운 크롬의 규칙·옵션(`ui.mdi.move_light.*`·`ui.mdi.tab_join.*`)은 `01a_화면설계_공통원칙_끌기경량크롬.md` §2·§3 이 정본이다. 정지 상태 창 크롬 수치는 바뀌지 않는다.

### 4.3 위치 고정·항상 위·자석·Z 순서
- **위치 고정(핀)** 과 **항상 위** 는 별개 버튼·별개 기능이다. 위치 고정 중 최대화·최소화 허용 여부는 Visual Studio 관례를 따른다.
- **자석:** 창 이동 때는 창 전체, 크기 조절 때는 끄는 가장자리만 다른 창 가장자리·작업 영역 경계에 붙는다. 켜기/끄기(`ui.mdi.magnet.enabled`)와 범위(`ui.mdi.magnet.range_dp`)를 설정하고 저장한다. 위치 고정·최대화 창은 제외한다.
- **MDI 창 끌기 경계(이 항목이 정본):** 창은 Windows 창처럼 캔버스 밖으로 밀 수 있고, 다시 끌 수 있는 만큼만 남긴다. 잡을 곳(끌 수 있는 제목 구간)은 50 DIP 이상 보여야 하며, 기능 버튼·캡션 버튼만 남고 잡을 곳이 없는 상태는 금지한다. 하한 50 DIP 는 제품 상수다(근거 사용자 결정, 원문 기록 a13 §3·§4.3). 잡을 곳 최소값(`ui.mdi.min_grab_dp`)은 이 하한 위에서만 바꾸고, 범위 밖 값은 가까운 경계로 맞추며 값이 없으면 기본값을 쓴다. 접기·펴기 판정과 왼쪽 잔존도 이 값을 따른다.
- 창이 밀려 기능 버튼 줄이 잡을 곳을 가리면 그 줄을 접어 잡을 곳을 확보하고, 다시 펼 때는 여유(`ui.mdi.strip_unfold_margin_dp`)를 둔다(접기·펴기 경계 흔들림 방지).
- 위쪽은 제목 줄이 사라지지 않게 0 에서 멈춘다. 아래쪽은 잔존 비율만큼(비율 0 이면 제목 줄 전체가) 보이는 데까지 밀 수 있다. 크기 조절도 같은 경계를 따르며, 오른쪽·아래쪽 가장자리는 캔버스 밖으로 늘어날 수 있다. 캔버스 밖 부분은 잘려 패널을 덮지 않고 스크롤바도 생기지 않는다. 측면 패널 쪽으로 민 부분도 문서 칸 경계에서 잘리므로, 화면에서는 불투명한 패널 아래로 들어간 것과 같다.
- **MDI 창 잔존 비율:** 창을 캔버스 밖이나 측면 패널 쪽으로 밀 때 창 크기의 일정 비율(`ui.mdi.min_visible_percent`, 0 이면 잡을 곳 규칙만)은 남기고 나머지는 가려지게 한다.
  - 남기는 양은 축마다 비율과 잡을 곳 규칙 중 큰 값이다. 가로 잔존은 `min(W, max(ceil(W × p), 막힌 폭 + 잡을 곳))`, 아래 잔존은 `min(H, max(ceil(H × p), 제목 줄 아래 끝))` 이다. 왼쪽으로 밀면 오른쪽 끝부터, 오른쪽으로 밀면 왼쪽 끝부터 보인다. 위쪽은 비율과 무관하게 0 에서 멈춘다.
  - 크기 조절도 같은 잔존 계산을 쓴다. 기능 버튼 줄 접기 규칙은 그대로이며, 잔존이 이미 '막힌 폭 + 잡을 곳' 보다 크면 접기 조건이 생기지 않는다.
  - 잡을 수 없는 창을 되돌리는 복구 판정은 비율과 무관하다. 비율은 끌기 한계이고 복구는 잡을 수 없을 때만 한다. 캔버스가 줄어 비율보다 적게 보이게 된 창도 잡을 곳이 있으면 그대로 둔다.
  - 데스크톱·웹은 같은 Shell 코드라 동작이 같다. 독립 창(SDI)은 OS 창이라 해당하지 않는다.
  - 위쪽 이탈은 창 본문을 잡는 다른 잡을 곳이 있어야 하므로 별도 요구로 받는다. 끌기 경계를 캔버스 전체로 넓혀 창을 패널 위에 그리는 안은 쓰지 않는다(근거 a13 §4.3).
- 프로그램을 닫았다가 다시 열어도 맨 위에 있던 창이 맨 위에 보인다(Z 순서 유지).
- **항상 메인 창 위**(설정, 기본 켬)와 창별 **항상 위**(OS 최상위)는 별개다. 독립 창(SDI)은 OS 소유 관계(owner) 없이 독립 창으로 뜨므로 메인을 최소화해도 그대로 남는다. 설정을 켜면 메인 창을 활성화해도 독립 창과 그 그림자 아래로 들어가 독립 창이 메인 위에 남고, 끄면 클릭한 창이 위로 오는 평범한 형제 창이 된다. 다른 앱 위로 올리는 것은 창별 항상 위뿐이다. 웹은 관리형 창이라 이 설정이 없다(04 웹 W-17).
- 활성 창을 바꿔도 이전 활성 창이 사라지거나 아래 창 내용이 위로 비쳐 그려지면 안 된다(U3, GPU 켬 기준 시험).

### 4.4 패널(서랍)과 분할 (UI-20·U13·U14·U18)
- 문서 창을 패널에 끌어 놓으면 탭으로 합류하고, 패널 가장자리에 놓으면 1/2 로 나뉜다. 모든 패널·분할 경계는 끌어서 크기를 바꾼다.
- 패널에서 가운데로 끌어 놓으면 **MDI 떠 있는 창**으로 연다(U13). 분할은 가장자리 표적에서만 한다.
- 분할을 되돌리는 수단을 둔다(U14). ① 분할 영역 탭·제목 우클릭 '분할 해제'(모든 문서를 주 영역 MDI 로 합침) ② 분할 영역 창을 주 영역 가운데로 끌어 합류. 빈 분할 영역은 자동으로 없앤다.
- 알림 서랍도 다른 패널과 같은 합류·도킹 규칙을 따른다(U18).
- 독립 창(SDI)에 문서가 1개면 탭 줄을 숨기고, 2개 이상 합치면 보인다(U15). 창이 칸으로 나뉘어 문서가 2개 이상이면 칸마다 문서가 1개여도 탭 줄을 보인다. 제목줄은 초점 문서의 제목이다. MDI 탭 막대는 위쪽이 기본이고 상·하·좌·우 어디든 둘 수 있으며 제거(숨김)는 불가하다(D-254, 결정 120, 정본 PLT-06, `13_UX패턴_카탈로그.md` UX-71).
- **창 탭 합류:** 독립 창(SDI)끼리, MDI 창끼리 두 개 이상을 탭으로 묶는다. 끌다 보면 창이 자주 겹치므로 실수로 묶이지 않게 표적 위에 놓을 때만 합친다. 창 배치(스냅)와의 우선순위는 `11_창배치_스냅레이아웃.md` §5 를 따른다.
  1. 끌던 창이 다른 창과 겹치기만 해서는 합쳐지지 않는다.
  2. 합류 표적은 두 가지다. ① 대상 창의 창 아이콘 칸이다. SDI 는 제목 줄 왼쪽 로고이고, MDI 는 로고가 없으므로(U12) 끌기 중에만 대상 창 제목 줄 왼쪽에 나타나는 20×20 '탭으로 합치기' 아이콘(제목 글자를 밀지 않는 겹침 표시)이다. ② 대상 창에 이미 탭 줄이 있으면 그 탭 줄이다(SDI 문서 2개 이상, MDI 탭 묶음 창).
  3. 포인터가 같은 표적 위에 머무는 시간(`ui.mdi.tab_join.dwell_ms`) 이상 머문 뒤 놓으면 합친다. 누른 곳에서 끌기 시작 거리(`ui.mdi.tab_join.drag_start_dp`) 이상 움직여야 끌기로 본다. 패널 합류도 같은 두 키를 쓴다.
  4. 끄는 동안 머무는 표적을 강조한다(패널 합류 강조와 같은 계열의 테마 클래스 `pdTabJoinTarget`). 놓기 전까지 창은 지금처럼 움직인다.
     - **아이콘 바꿔 보이기:** 합치기 아이콘이 보이는 동안 그 창의 원래 아이콘(MDI 문서 기호·SDI 앱 로고)은 숨긴다. 합치기 아이콘은 원래 아이콘 칸(로고 칸)의 가운데에 놓아 두 아이콘의 중심이 같다. 로고 칸이 없는 스타일(macOS)은 제목 줄 왼쪽 24 DIP 칸 가운데다. 데스크톱 SDI 제목줄도 로고 칸 안에 같은 20×20 합치기 아이콘을 보인다. 숨김은 불투명도로 하므로 표적 사각형(로고 칸)은 그대로다. 합치기 아이콘 바탕은 활성 제목줄 불투명색(`PdChromeTitleActive`)이며, 끄는 동안 비활성 창 제목줄에 합성되지 않는다(SDI·MDI 공통).
  5. 합치면 끌던 창의 문서(묶음이면 전부)가 대상 창 탭 줄 끝에 붙고 끌던 문서가 활성 탭이 된다. 끌던 창은 닫히고 대상 창의 위치·크기는 그대로다.
  6. 범위는 MDI→MDI(같은 문서 칸)와 SDI→SDI 다. MDI↔SDI 교차 합류는 하지 않으며 기존 Dock 탭 끌기 안내 표적의 가운데 놓기로 한다. 탭형(DOCK) 문서 영역과 모바일형은 이미 탭이라 해당하지 않는다.
  7. 탭을 묶음 밖으로 끌어내면 MDI 떠 있는 창이 된다. MDI 묶음에 문서가 1개만 남으면 묶음을 풀어 같은 위치·크기의 보통 MDI 창으로 되돌린다. 분리한 창은 활성 창이 되어 Z 순서 맨 위에 온다. 묶음을 푸는 정리가 남은 문서를 활성화하더라도 그 뒤에 분리한 창을 다시 활성화한다. 항상 위 창 그룹 규칙은 그대로라 항상 위 창보다 위로는 가지 않는다.
  8. 기존 Dock 탭 끌기 안내 표적(가운데 놓기)은 바꾸지 않는다. 명시 표적이라 '겹침만으로 합류' 가 아니다.
  - MDI 탭 묶음은 탭형 문서 영역을 MDI 창 하나로 띄운 구조이고 묶음 창 제목 줄은 활성 탭 문서의 제목을 보인다(구조 판단 근거 a13 §4.4). 데스크톱·웹 동작은 같다(웹 차이는 `04_웹` W-23). 묶음은 레이아웃 저장 형식의 묶음 기록으로 저장·복원하고, 묶음 기록이 없는 옛 저장본은 묶음 없이 읽는다. MDI 탭 묶음 창의 제목·캡션·탭 줄은 `03_데스크톱` §3.1, SDI 합류 화면은 §3.2 에 있다.
- 패널 머리글의 선택 상태는 창 제목과 같은 반전색으로 표시한다(U19).
- 패널 모서리 버튼(한 패널이 모서리를 가져가는 조작)의 동작 4가지:
  1. 모서리를 가져가 줄어든 패널이 최소 크기(48 dip) 하한에 걸리면, 되돌려도 원래 두께로 돌아오지 않는다. 하한에 걸리지 않을 때의 왕복은 그대로다.
  2. 이 하한은 모서리 버튼을 누를 때만 계산한다. 그 뒤 창을 더 줄이면 48 dip 아래로 갈 수 있다.
  3. 문서를 분할하면 모서리 버튼이 사라지므로, 모서리를 바꾼 상태라도 분할을 풀 때까지 되돌릴 수 없다(분할 중 모서리 조작은 거절한다).
  4. 위 상태에서도 패널 가장자리는 옮길 수 있다. 옮기면 모서리 소유가 기본으로 돌아간다(문서 칸이 패널 단과 분리돼 트리가 깨지지 않는다).
- **패널 기능 설정:** 설정 ▸ 창 페이지에서 패널 기능(`ui.panel.feature_mode`)을 자동·켬·끔으로 고른다. 자동은 지금 적용된 UI 형이 PC형이면 켬, 태블릿형·모바일형이면 끔이다(형이 자동 전환되면 다시 계산). 끔이면 ① 패널 고정(📌)을 할 수 없고 버튼도 숨기며 ② 창을 끌 때 가운데 분할을 정하는 안내 박스(도킹 표적)를 보이지 않는다. 같은 패널 탭 영역 안의 순서 바꾸기는 막지 않는다. 끔에서도 패널 안의 문서를 원하는 위치(문서 영역·창·다른 패널의 탭 영역 가운데 놓기)로 끌어 뺄 수 있고, 방향 분할만 하지 않는다. 앱(데스크톱·Android)과 웹, PC형·태블릿형 모두 같다. 사용자가 직접 고른 켬·끔이 자동보다 우선하고, UI 형이 바뀌면 자동 값을 다시 판정한다. 끔으로 바뀌는 순간 이미 고정된 패널은 고정을 풀고 원래 비율로 돌아가며, 켬으로 돌아와도 자동으로 다시 고정하지 않는다. 저장된 레이아웃에 고정 패널이 있어도 끔이 우선한다. 규칙은 UI 와 분리한 순수 규칙이 맡는다.
- **패널 위치:** 모든 패널은 같은 규칙을 따른다. 제목 줄을 끌거나 제목 줄·패널 안 탭을 우클릭해(터치 기기는 제목 줄 ▾) 네 가장자리와 다른 패널로 옮긴다. 항목·규칙·같은 가장자리 처리는 `03_데스크톱` §7.3. 현재 위치는 체크·비활성이다. 알림 건수는 탭 제목에 보인다(`알림(5건)`, 0건이면 `알림`).
- 패널 끝 확장 버튼은 평소에 숨기고, 포인터가 버튼 경계에서 50 dip 이내일 때만 보인다(배율 100%에서 50 px, 50 포함). 거리는 포인터가 다른 패널·분할선·문서 위에 있어도 같은 기준으로 잰다.
  - 숨김 상태는 불투명도 0에 클릭이 아래로 지나가고 자리는 그대로라 레이아웃이 밀리지 않는다. 페이드는 100 ms 다.
  - 숨기는 경우: 거리 밖, 포인터가 창을 떠남, 마우스 단추를 누른 끌기 중(분할선·탭 끌기, 버튼 자신을 누른 경우는 제외), 버튼 중심의 맨 위가 다른 층임(투어, 웹의 관리형 창, 웹에서 메뉴가 열린 동안은 메뉴가 버튼 자리를 덮지 않아도 숨는다). 데스크톱 메뉴는 별도 OS 창이라 포인터가 메뉴 위면 창 떠남으로 숨는다.
  - 키보드 포커스가 오면 포인터와 무관하게 보인다. 마우스로 받은 포커스는 포인터가 멀어지면 숨는다.
  - 터치 기기(Android·iOS, 웹은 `(pointer: coarse)`)는 호버가 없어 항상 표시한다. Windows 터치 노트북처럼 터치 기기로 판별되지 않는 환경에서 터치만 쓰면 버튼이 보이지 않고 키보드로만 닿는다.
  - 독립 창(SDI)에는 이 버튼이 없어 추적도 하지 않는다. 버튼이 있는 창만 포인터 이동을 구독하고, 이동마다 그 창의 버튼 수만큼 거리만 잰다.

### 4.5 레이아웃 템플릿·사용자 레이아웃
- 읽기 전용 템플릿(프리셋)과 사용자별 이름 있는 레이아웃을 함께 둔다. 저장 범위는 Dock 배치·창 위치/크기·Z 순서·활성 창·위치 고정·항상 위·창별 확대다.
- 저장할 때 이름 입력칸을 보이고 기본값은 현재 날짜·시간(`yyyy-MM-dd HH:mm:ss`)이다. 같은 이름은 덮어쓰기를 확인하고, 빈 이름은 금지한다. 관리 목록에서 이름 수정·삭제(확인 1회)·기본 지정을 한다.
- 방식(MDI·DOCK·NAV)별 레이아웃을 따로 저장하고 그 방식으로 돌아오면 복원한다(REQ-46-6).
- 형식은 데스크톱·웹·모바일 공통이다. PoC 는 로컬 프로필 폴더, 제품(M1)은 서버 사용자 설정에 저장한다.

### 4.6 다중 모니터 (U20)
- '창 ▸ 모니터'에 연결된 모니터 전부(이름·해상도·주 모니터 표시)를 라디오로 보인다. 일반 최대화는 창과 겹치는 면적이 가장 큰 모니터에서 하고(메인·독립 창 공통), 고른 모니터는 '선택한 모니터로 최대화' 명령과 최대화 중 라디오 변경에만 쓴다.
- 저장된 모니터가 없어지면 주 모니터로 대체한다. 웹·스마트폰은 단일 표면이라 해당 없다(08 용어 §7-3 9행).

## 5. 테마·타이포그래피·확대

### 5.1 테마 (UI-07)
- 라이트·다크·시스템 따르기를 고르고 즉시(재시작 없이) 바뀐다. IDE 처럼 색 조합 템플릿(PoC: pd-light·pd-dark·pd-contrast·pd-ocean·pd-ember·pd-forest)을 두고, 사용자가 편집·저장·내보내기·가져오기를 한다(보기 ▸ 테마 편집기). 요소별 사용자 지정은 `17_테마_요소별_사용자지정_설계.md`(REQ-101), 디자인 테마 축은 `18_디자인테마_설계.md`(REQ-104)다.
- 모든 색은 의미 토큰(`PdBrush*`)으로만 쓴다. 화면 코드에 색 값을 직접 쓰지 않는다.

### 5.2 타이포그래피 토큰
> 글자 선명도는 특정 폰트 이름으로 분기하지 않고 전역 설정·굵기 처리로 해결한다. 선택 글꼴에 없는 굵기를 합성 굵게로 그려 번지는 현상은 실재 굵기 선택 또는 색 강조로 막는다.
| 토큰 | 기준 대비 | 쓰임 |
|---|---|---|
| PdFontTitle | +4 | 화면 제목 |
| PdFontSubtitle | +2 | 구역 제목 |
| PdFontBody | 0 | 본문·입력값 |
| PdFontDetail | −1 | 보조 설명 |
| PdFontCaption | −2 | 캡션·상태 |
- 글자 설정은 두 범위다. **문서 글자**는 문서 창 안이고 글꼴(`ui.font.doc_family`)·문서 글자 크기(`ui.font.doc_size`)·Ctrl+휠로 바꾼다. **시스템 글자**는 문서 창 밖 셸 전체(메뉴 줄·제목 줄 탭·탐색기 등 패널·상태바·설정 창·창 제목줄)이고 설정 ▸ 모양의 '시스템 글꼴'(`ui.font.shell_family`)과 '시스템 글자 크기'(`ui.font.shell_size`)로 바꾼다. 바꾸면 모든 화면에 즉시 반영된다.
- 시스템 글자 크기는 앱 전역 토큰(위 표의 PdFont*, 기준 + 오프셋)에 쓰이고 문서 창 래퍼는 문서 크기로 다시 덮는다. 시스템 글꼴은 앱 전역 `PdFontFamily` 에 쓰이고 문서 창 래퍼는 문서 글꼴로 다시 덮는다. 시스템 글꼴 값이 없는 옛 저장본은 시스템 글꼴 = 문서 글꼴로 읽는다. Ctrl+휠·Ctrl+0 은 문서 창에만 작용한다.
- 웹은 시스템 글꼴을 나열할 수 없어 번들 글꼴만 고른다(판정보고서 §5.1 UI-04). 모바일은 OS 글자 크기 설정을 기준 크기에 반영한다(배율 상한은 06 문서).

### 5.3 확대(줌) — 문서 창 단위 (UI-05·UI-06)
- Ctrl+휠(macOS Cmd+휠)은 **활성 문서 창 하나**의 모든 구성요소 크기를 키우고 줄인다. Ctrl+0 은 그 창을 100% 로 되돌린다(U1). 메인 창 크롬(메뉴 줄·제목 줄)은 크기가 바뀌지 않는다.
- 화면의 +/− 버튼은 두지 않는다. 대신 **문서 창 우클릭 메뉴**에 '글자 크게(+)·글자 작게(−)·기본 크기(Ctrl+0)'를 넣는다(본 개발 요구). 메인 창 크롬 메뉴에는 넣지 않는다.
- Ctrl+휠이 창 배율을 바꿀지 글자 크기만 바꿀지는 `ui.zoom.ctrl_wheel_mode` 로 고른다.
- 스마트폰·태블릿은 핀치로 문서 창 안만 확대한다(ADR-041). 웹은 브라우저 확대와 겹칠 수 있어 메뉴·우클릭 경로를 함께 둔다(08 용어 §7-3 5행).

### 5.4 표·목록·간트의 수식키+휠 조작

프로젝트 관리·목록형·그리드형처럼 행이 늘어선 화면은 같은 키로 같은 축을 조절한다. 판정은 공통 부품 한 곳에서 하고, 화면은 대상만 연결한다. 화면마다 휠 코드를 두지 않는다.

| 조작 | 뜻 | 간트 | 그리드 | 로그·문의 목록 창 | 알림 패널 |
|---|---|---|---|---|---|
| 휠 | 세로 스크롤 | 세로 | 세로 | 세로 | 세로 |
| Ctrl+휠(macOS Cmd+휠) | 전체 크기 | §5.3 전역 처리 | §5.3 전역 처리 | 그 목록 글자만(문서 창이 아니라 전역 대상이 아님) | 처리 안 함(메인 창 크롬 고정, 세로 스크롤) |
| Alt+휠 | 가로 배율 | 일당 픽셀(1.5~60) | 열 폭(약 0.5~3배, 머리글 폭 아래로 줄지 않음) | 축 없음(아무것도 안 함, 스크롤도 안 함) | 축 없음 |
| Shift+휠 | 가로 스크롤 | 60px | 표 자체 처리 | 로그는 가로 스크롤, 문의는 넘치는 내용 없음 | 넘치는 내용 없음 |
| Alt+Shift+휠 | 세로 배율(행 두께) | 행 높이 | 행 높이 | 항목 위아래 여백 | 항목 위아래 여백 |

- 행 두께 단계는 1.25배씩 −1~+6이다. 하한은 글자가 잘리지 않는 0.8배이고 상한은 약 3.8배다. 곱셈을 누적하지 않고 단계 번호로 계산하므로 왕복하면 처음 값으로 돌아온다.
- 행 두께를 바꿀 때 커서 아래 행은 제자리에 둔다. 간트의 왼쪽 작업명과 오른쪽 막대는 같은 행 높이 값 하나를 쓴다.
- Alt·Alt+Shift 값은 저장하지 않는다(화면을 다시 열면 처음 값). Ctrl 은 §5.3 설정 값을 따른다.
- 사용자가 머리글 경계를 끌어 바꾼 열 폭은 배율을 바꿔도 남는다.
- 대상에서 뺀 곳은 짧은 선택 목록(레이아웃 관리·백업, 창 더보기, 테마 편집기, 설정 분류), 크롬(제목 탭, SDI 아이콘), 터치 전용 모바일 메뉴다.
- macOS 는 Ctrl 자리에 Cmd 를 본다. Shift 와 함께 돌린 휠이 가로 값으로 오면 그 값을 방향으로 쓴다.
- 한계: 입력 언어가 2개 이상인 Windows PC 는 Alt+Shift 로 입력 언어가 바뀔 수 있고 앱에서 막을 수 없다. 터치(휠 없음)는 Ctrl 을 핀치(§5.3), 간트 Alt 를 도구줄 ＋·－ 로 대신하며, 행 두께(Alt+Shift)와 그리드·목록의 Alt 는 터치 대체 수단이 없다. 플랫폼별 확인 기록은 a13 §4.5 다.
- 표(그리드)는 공통 그리드 부품 하나를 쓴다. 새 화면은 열 정의와 데이터만 쓰고 휠·줄무늬·터치 처리는 부품 한 곳에서 고친다. 그리드 구현 판단·셀 지연 생성·예열 옵션과 성능 실험은 a13 §4.5 다. 재검토 조건은 업무 그리드가 3개를 넘어 열 정의 복제가 실제로 늘 때, 또는 그리드 구현을 교체할 때다.

## 6. 권한·표시 판정의 화면 표현
- 화면·메뉴가 보이는지는 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §3 의 표시 판정식이 정한다. 역할·권한 코드의 정본은 `../10_API설계/iam.md` §3·§13 이다. 운영사 전용 화면은 Pd 메뉴에 두지 않고 pd-admin 으로 보낸다(ADR-040). 이 절은 판정 결과별 화면 표현만 정한다.
- 역할 권한이 없는 화면은 메뉴에서 숨긴다. 읽기 권한만 있으면 편집 컨트롤을 비활성으로 보인다.
- 기능 게이트가 닫힌 화면은 숨기지 않고 **잠금 아이콘**으로 보이며, 누르면 필요한 요금제와 업그레이드 안내(업셀)를 보인다(표현 `ui.screen.gate_closed_display`). 요금제·기능 배치는 데이터라 화면 코드에 등급을 쓰지 않는다(ADR-027).
- 테넌트 허용에 없는 모듈의 화면은 메뉴·명령 팔레트·검색에서 보이지 않는다(표현 `ui.screen.not_entitled_display`). 회사가 끈 화면(`ui.screen.visible`)은 딥링크로 열면 '회사 설정으로 사용하지 않는 화면' 안내만 보인다.
- 개인용 테넌트에는 기업 전용 화면(`메뉴구조.csv` 개인용 열 '—')을 아예 보이지 않는다.

## 7. 포커스·키보드 (U21)
- Tab 은 상단 메뉴 영역 안에서만 돌되, 메뉴 영역 마지막 항목에서는 활성 문서 창의 크롬 단추로 이어지고 그 끝에서 메뉴 첫 항목으로 돌아온다. 활성 문서가 없으면 크롬 단추는 건너뛴다. SDI 창은 포커스가 그 창 제목줄에 있을 때만 그 창 크롬 단추 안에서 돈다. SDI 창에서 포커스가 없거나 창 루트에 있을 때 Tab 은 그 창 크롬 단추 첫 항목으로, Shift+Tab 은 마지막 항목으로 들어간다. 창이 열릴 때 포커스를 자동으로 가져가지는 않는다. 문서 내용 안의 Tab 은 바뀌지 않는다.
- 입력 컨트롤(텍스트·콤보 등)은 클릭으로 포커스를 받고 편집한다. 입력 화면 안의 필드 이동 키는 화면 설계에서 정한다(본 개발 과제).
- 포커스 표시는 굵은 검정 테두리가 아니라 1px 테마 강조색 둥근 사각형이다.

## 8. 화면 방식 전환과 상태 유지
- 전환 수단은 시스템 메뉴와 제목줄(보기 ▸ 화면 방식)이다. 선택지는 자동·PC형(MDI)·태블릿형(DOCK)·모바일형(NAV)이고, 기기별 기본·선택 집합은 08 용어 §1-3 을 따른다(PC=PC형 기본, 태블릿=태블릿형 기본, 스마트폰=모바일형만이며 선택 UI 없음). 전환해도 열린 문서·보던 문서·입력 중인 내용·선택·포커스·스크롤(첫 행 기준 1행 이내)을 유지한다(REQ-46-7).
- **자동 전환:** '자동'이면 창 폭에 따라 PC 는 넓은 경계(`ui.layout.expanded_width_dp`) 이상 PC형·좁은 경계(`ui.layout.compact_width_dp`) 이상 태블릿형·그 미만 모바일형이고, 태블릿은 좁은 경계 이상 태블릿형·미만 모바일형이다. 히스테리시스(`ui.layout.switch_hysteresis_dp`)와 디바운스(`ui.layout.switch_debounce_ms`)로 경계 떨림을 막는다. 수동 선택은 폭과 무관하게 유지한다. 기기 판정은 짧은 변 기준이다.
- **자동 판별 입력:** 자동 UI 형은 화면 크기만으로 정하지 않고 기기 정보(터치·정밀 포인터·기기 종류·창 모드)를 더해 정한다. 판정표 정본은 `05_아키텍처/08_지원_폼팩터_용어.md` 이고 여기에는 요약만 둔다. 접은 폴드는 모바일형, 펼친 폴드·태블릿은 태블릿형이다. `ui.layout.compact_window_keeps_tablet`(좁은 창에서도 태블릿형 유지)을 켜면 창 폭이 좁은 경계 아래여도 태블릿형을 유지한다(기기 분류는 그대로). 분할 화면·창 모드로 창 폭이 좁은 경계 아래면 모바일형이다(위 옵션이 끔일 때). 정밀 포인터(마우스·터치패드)가 있는 터치 노트북은 PC형이다. 웹에서 접힘 상태를 알 수 없으면 창 폭으로 폴백한다.
- **애니메이션:** 급작스럽지 않게 전환한다(전체 시간 `ui.layout.switch_fade_ms` — 불투명도를 1→0.15 로 낮추고, 교체하고, 6dp 미끄럼과 함께 되돌린다). OS 애니메이션 줄이기 설정이면 즉시 교체한다. 전환 요청이 겹치면 마지막 1건만 처리하고, 끌기·모달·IME 조합 중이면 끝난 뒤로 미룬다(입력 손실 0).
- 독립 창(SDI)은 MDI 방식에 속한다. 모바일형으로 바꿔도 독립 창을 닫거나 합치지 않고 그대로 두며(데스크톱에만 있고 스마트폰에는 없다), 열린 문서 목록에 '독립 창'으로 표시한다. 방식별 레이아웃은 재시작 뒤 복원하지 않고 실행 중 왕복 복귀만 한다.
- **서버 재연결 중 화면(ADR-050):** 웹·앱 모두 서버 연결이 끊기면 업무 화면을 가리고 `서버 재연결 중` 화면과 자동 재시도만 보인다. 캐시 내용을 대신 보여 주지 않는다(오프라인 모드 없음, 05/20 §7.1 전역 설계 원칙). 재연결되면 가렸던 화면을 그대로 되돌린다. 재시도 간격·횟수는 `ui.reconnect.interval_seconds`·`ui.reconnect.max_attempts` 다.
- **업데이트:** 시스템(Y) 메뉴의 `업데이트 확인`(`05_아키텍처/05_제품구성_시스템메뉴.md` §2 S9)으로 사용자가 수동으로 새 버전을 확인·설치한다. 관리자가 지정한 강제(필수) 업데이트 버전이 현재 클라이언트보다 높으면 실행 시 로그인 화면 전에 업데이트 진행 화면을 보이고 자동으로 업데이트한다. 그 밖에는 강제하지 않는다. 웹은 새로고침 배너로 대신한다. 판정은 `../10_API설계/00_공통규약.md` §2, 버전 규칙은 05/21 §4.8 이다.

## 8-1. 도움말 투어 내용 관리 (요건 6)

투어 단계·단축키·기능 설명은 코드와 분리한 카탈로그와 사전으로 관리한다. 대상은 자동화 id 로 찾고, 없거나 숨었거나 권한·폼팩터가 안 맞는 단계는 건너뛰며 번호를 다시 매긴다. 메인 화면 키 바인딩과 단축키 표는 같은 등록을 쓰고, 기능 레이어의 메뉴 줄은 메뉴 카탈로그에서 만든다. 새 메뉴·버튼이 설명 없이 들어오면 빌드 전 검사가 실패시킨다. 작성 방법은 `poc/ui/README.md` 의 도움말 카탈로그 절을 본다.

## 8-2. 차트 뷰 공통 규칙 (REQ-58)

정본은 [`08_차트뷰_설계.md`](08_차트뷰_설계.md) §3(뷰 카드는 08a·08c)이고 이 절은 화면 공통 관점의 요약이다.

- **뷰 전환 컨트롤:** 같은 데이터를 보는 뷰(간트·타임라인·캘린더·칸반 등)는 한 문서 창 안에서 뷰 종류를 바꿔 본다. 뷰 저장은 08 §3.2 다.
- **ViewContext:** 프로젝트·조직·기간·기준선·권한 범위를 담은 `ViewContext` 하나를 모든 뷰가 구독하고, 뷰를 바꾸거나 드릴다운해도 유지한다(08 §3.3·§3.4).
- **레이어:** 그리기와 입력은 UI 레이어, 뷰 상태·명령·선택 동기화는 컨트롤 레이어, API·읽기 모델·캐시는 데이터 레이어가 맡는다. 차트 라이브러리는 어댑터 규격만 거친다(ADR-047). 시간축 뷰는 같은 시간축 렌더러를 공유한다(ADR-077). 분석 차트는 "n분 전 기준"을 표시한다(08 §3.1·§3.5).
- **공통 차트·보드 컴포넌트(ADR-091):** 차트 대부분은 공통 차트 컴포넌트 하나가 `ChartSpec`(설정 JSON)으로 종류·축·시리즈·색·범례·드릴다운·내보내기를 받아 그린다. 뷰마다 새 컴포넌트를 만들지 않고 설정과 파라미터(`ui.chart.params`, 값 층은 05/30 §5)로 바꾼다. 칸반은 보드 컴포넌트 하나를 같이 쓰고 열 정의·카드 필드·전이 판정만 모듈별 플러그인으로 둔다. 전이 규칙은 서버가 판정한다(08 §3.11).
- **폼팩터:** 스마트폰은 NAV 고정이고 뷰별 노출은 08 §3.10 표를 따른다(모바일 반영은 06 문서). 성능 측정은 사용자가 PC 를 쓰지 않을 때만 한다(08 §4).

## 8-3. 공통 부품·입력 규칙
- 대상을 다루는 목록·선택 상자·검색·명령 팔레트의 즐겨찾기·최근 조회·개인 순위·개인 추천은 공통 부품이고 정본은 `20_개인화_빠른찾기_설계.md` 다.
- 고객사·협력사를 지정하는 모든 화면은 두 입구(법인 검색·선택, 비공인 거래처 등록)만 둔다(`../05_아키텍처/26_Pd_거래처_법인마스터_설계.md` §4).

## 8-4. 설정 값 출처 표시
- 키 등록부(`../06_기능목록/20_Pd_상세기능설계_공통_권한_화면.md` §5.1)에서 허용 층이 둘 이상인 키를 보이는 모든 화면(라이선스·관리 설정·항목 정책·개인 설정 화면 등)은 같은 출처 표시 규칙을 쓴다. 층과 해석은 05/30 §5 가 정본이다.
- 항목마다 유효값과 그 값을 준 층(제품 기본·운영 시스템·회사·하위 범위·사용자)을 보인다. API 응답의 `value`·`source`·`limit` 를 그대로 쓴다(`../10_API설계/00_공통규약.md` §11.1).
- 화면을 연 주체가 값을 지정할 수 있는 층에서는 '위 층 값 상속'과 '이 층에서 지정'을 고르는 토글을 둔다. 상속 중이면 위 층 값을 읽기 전용으로 보이고 입력을 막는다. 지정으로 바꾸면 입력이 열리고 처음 값은 그때의 유효값이다.
- 지정 중에는 허용 상한(`limit`)을 입력란 옆에 표시하고, 상한을 넘는 값은 저장 때 거부된다. 위 층이 상한을 낮춰 지정 값이 상한을 넘게 되면 응답의 `clamped` 표시를 보고 '상한으로 맞춰졌다' 는 안내를 보인다.
- 제약원(기능 문서 선언·국가 팩·권리 묶음·제품 허용)이 좁힌 값은 잠금 표시와 제약원 이름을 보이고 입력을 막는다. 국가 팩 잠금은 회사가 풀 수 없다.
- 지정한 항목에는 '위 층 값으로 되돌리기' 버튼을 둔다. 누르면 확인 뒤 그 층의 값을 지우고 위 층 값으로 돌아간다(05/30 §5.1).
- 운영 시스템 값이나 회사 값을 저장하기 전에는 영향받는 대상 수(상속 중인 수와 자기 값을 가진 수)를 미리 보인다. 자기 값을 가진 대상은 값이 바뀌지 않는다. 운영 시스템 값은 pd-admin 에서 바꾼다.
- 권한이 없으면 토글과 버튼을 비활성으로 두고 읽기 전용으로 보인다(§6).

## 9. 화면 ID·메뉴 구조
- 화면 ID 는 `SCR-<기능 영역 코드>-NN` 이다. 기능 영역 코드는 기능목록과 같다(`06_기능목록`). 화면 ID·기능 ID·메뉴 ID 는 한 번 발급하면 바꾸지 않는다(D-496). 접두는 발급 당시의 기능 영역 코드이며 소유 모듈을 뜻하지 않는다.
- 메뉴 ID 는 pd 본체 4자리, pd-admin `a`+4자리, 오케스트레이터 `o`+4자리다. dev·staging·qa 빌드만 `[0042] 이름` 꼴로 보이고(좁으면 툴팁) prod 빌드는 이름만 보인다. 보이는 채널은 `ui.menu_id.visible_channels` 이고 값 분류는 제품 상수(결정 55·57·90)다. 화면 안 탭과 실행 중 셸 항목에는 메뉴 ID 가 없다. 서버로 보내는 오류 로그에는 화면 ID 와 메뉴 ID 를 싣는다. 정본은 `09_메뉴ID_규칙.md` §5·§8 이다.
- 업무 메뉴 그룹·순서·화면 배치와 건수는 메뉴 데이터(`_build/menu_data.py`, 생성물 `02_메뉴구조.md`)가 정본이다. 한 화면은 여러 기능을 묶고, 누락·중복·예외는 `menu_tree.py` 가 검사한다. 모듈이 메뉴·패널을 기여하는 확장 자리는 `../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7 이다.
- 스마트폰 노출은 ○(전체)·△(조회·간단 처리)·✕(대화면 안내) 셋이다. 기준은 ① 현장·이동 중에 쓰는가 ② 넓은 표·간트·설정처럼 대화면이 필요한가 ③ admin·root 관리 화면인가다.

## 10. 다국어 (UI-16, ADR-039)
- 언어 팩·로캘·RTL·번역 관리의 정본은 `../05_아키텍처/27_Pd_다국어_로캘_설계.md` 다(언어 팩 등록형 §3, 형식 로캘 분리 §4, RTL §5, 팽창 배율·시험 §14). 이 절은 화면 쪽 규칙만 둔다.
- 화면 문구는 키 기반 사전에서만 가져온다. 언어를 바꾸면 모든 화면이 즉시 바뀌고, 언어별 키 집합은 같아야 한다(`check_i18n.py`).
- 문구 폭에 여유를 둔다. 기본값은 영어 기준 1.3배 폭이고 잘림 시험으로 확인한다. 더 긴 언어의 근거와 가짜 로캘 배율은 05/27 §14 다.
- RTL 에서 읽는 순서의 배치는 미러링하고, 시간의 흐름·수치의 크기·미디어의 진행 방향은 미러링하지 않는다. 컨트롤·뷰는 자기 정의에 방향 속성(`mirror`·`fixed`·`option`, 이름 후보)을 선언하고 선언이 없으면 미러링한다(05/27 §5).

## 11. 자동화 제어 채널 (UI-08)
- 모든 화면 요소에 AutomationId 를 붙인다. 규약은 `<영역>.<접두어><이름>` 이다(PoC 예: `shell.mnuWindow`·`sys.*`·`chrome.*`·`theme.*`). 업무 화면은 화면 ID 를 영역으로 쓴다(예: `scr-prj-01.btnSave`).
- 외부(AI·시험 도구)가 실행 중인 프로그램을 조작·검사하는 원격 제어 채널은 **개발·시험 전용**이다. 진단 빌드에서만 들어가고 제품 빌드에서는 빠진다(PdDiagnostics=false). 켤 때는 127.0.0.1·토큰·CORS 금지를 지킨다. 웹은 같은 명령 집합을 JS 브리지로 쓴다. API 쪽 상세는 `10_API설계/00_공통규약.md` 의 자동화 채널 절이다.
