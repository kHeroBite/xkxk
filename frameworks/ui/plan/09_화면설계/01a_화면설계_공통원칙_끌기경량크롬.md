# 화면 설계 공통 원칙 부록 — MDI 문서 창 끌기 중 가벼운 크롬

> `01_화면설계_공통원칙.md` §4.2 에서 나눈 하위 주제 문서다. MDI 문서 창을 끄는 동안의 화면 규칙과 그 옵션은 이 문서가 정본이다.
> 정지 상태의 창 크롬 수치(모서리·외곽선·그림자)는 `../04_기술스택/05_창크롬_OS디자인_기준.md` 가 정본이다. 이 문서는 그 값을 바꾸지 않고 끌기 중 한시 표현만 다룬다.
> 끌기 성능의 측정 기록(회차별 값·비교 규칙·판정 결과·진단)은 UI PoC 판정 보고서 부록(`../04_기술스택/04_판정보고서_부록/`)에 둔다. 합격 기준 수치의 정본은 `../04_기술스택/03_PoC_UI_합격기준_Mars실측.md` 다.
> 구현 위치·클래스 이름·진단 빌드 인자는 `../../poc/ui/README.md` 에 둔다.
> 이 문서에서 덜어 낸 측정 기록(커밋 b7bacb6 원문)은 `../04_기술스택/04_판정보고서_부록/a12_끌기경량크롬_측정기록.md` 에 있다.

## 1. 범위

- 대상은 MDI 문서 창 끌기다. 독립 창(SDI)은 OS 가 끌기를 처리하므로 해당하지 않는다.
- 데스크톱·웹·모바일이 같은 규칙을 쓴다.
- 탭 막대 위치(PLT-06, D-254)와 상관없이 같게 적용한다. 탭 줄 합류 표적은 탭 막대가 놓인 변을 따른다.
- 위쪽이 아닌 탭 막대 배치에서의 끌기 성능은 미검증이다.
- 데스크톱 MDI 에서 이 규칙을 가리키는 자리는 `03_데스크톱_화면설계.md` §3.1 이다.

## 2. 끌기 중 화면 규칙

- '이동 중'은 포인터가 아니라 MDI 창의 위치 변화로 판정한다. 끌기·자석 배치·전체 이동이 모두 해당한다.
- 최대화 창은 이동으로 보지 않는다.
- 끄는 창은 이동하는 동안 그림자를 끈다. 기본 동작이며, 끌기 중 그림자 옵션(`ui.mdi.move_light.shadow`)을 '유지'로 고르면 끄는 창과 겹친 정지 창 모두 정지 상태 그림자를 그대로 둔다(결정 143). 모서리·내용 히트 테스트·원복 시점 규칙은 옵션과 무관하게 같다.
- 끄는 창의 바깥 모서리와 잘라냄 반경은 이동 중에도 정지 상태와 같다.
- 원래 크롬으로 되돌리는 시점은 포인터를 놓는 순간이 아니라 마지막 위치 변화 뒤 조용 시간(`ui.mdi.move_light.quiet_ms`)이 지난 때다.
- 그래서 놓은 뒤 조용 시간만큼 가벼운 크롬이 남을 수 있다.
- 활성 창과 비활성 창의 그림자 차이, 최대화 창 무그림자 규칙은 끌기 전후 모두 유지한다.
- 겹친 정지 창은 같은 MDI 영역에서 움직이지 않는 보통 상태 창이다.
- 겹친 정지 창 옵션(`ui.mdi.move_light.siblings`)이 켜져 있으면 끄는 동안 이 창들도 그림자를 끄고 모서리는 유지한다. 원복 시점은 끄는 창과 같다.
- 겹친 정지 창 처리를 켜면 끌기 시작과 원복 때 정지 창 전체가 한 번씩 다시 그려진다.
- 끄는 동안 그 창의 내용 영역은 입력 히트 테스트에서 빠진다. 제목줄과 크기 조절 손잡이는 빠지지 않는다.
- 그래서 끄는 창 내용 위의 호버 효과는 끄는 동안 나타나지 않는다. 원복 시점은 가벼운 크롬과 같다.
- '탭으로 합치기' 아이콘은 근접 표시 옵션(`ui.mdi.tab_join.arm_near`)이 켜져 있으면 포인터가 그 창의 합류 아이콘 자리를 반경(`ui.mdi.tab_join.arm_radius_dp`)만큼 키운 영역에 들어올 때만 켜고, 밖으로 나가면 끈다.
- 근접 표시를 끄면 끌기 시작 때 다른 창 전부에 합류 아이콘을 켠다.
- 합류 판정(머무름 시간·가림 판정)과 묶음 창 탭 줄 표적은 아이콘 표시와 무관하다. 정본은 `01_화면설계_공통원칙.md` §4.4 다.
- 화면 결과를 바꾸지 않는 계산 절감은 옵션 없이 적용한다.
- 위치만 바뀐 창은 끌 수 있는 구간을 다시 재지 않는다. 입력이 직전과 같으면 기능 버튼 줄 접기 판정을 다시 하지 않는다.
- 정지 창 찾기는 같은 MDI 영역(MDI 배치 패널) 안에서 멈춘다. 그 영역에 끄는 창 하나뿐이면 찾기를 건너뛴다.

## 3. 옵션

키 이름은 후보다. 값 꼴·기본값·범위·값 분류·허용 층의 선언은 `../10_API설계/plt_2.md` §12.1 이다. 이 표는 키의 뜻과 화면 차이만 적는다.

| 키 | 뜻 | 화면 차이 |
|---|---|---|
| `ui.mdi.move_light.enabled` | 끌기 중 가벼운 크롬(§2) | 끄면 이동 중에도 정지 상태와 같은 크롬이다 |
| `ui.mdi.move_light.shadow` | 끌기 중 그림자 처리(`hide` 숨김·`keep` 유지, 기본 `hide`) | `keep` 이면 끄는 창·겹친 정지 창의 그림자가 이동 중에도 남는다. 설정 창 '창' 페이지에 '끌기 중 그림자: 숨김(빠름, 기본)/유지'로 둔다. 효과 단계(`21_창_움직임효과_배경_설계.md` §5) 묶음에 든 키다 |
| `ui.mdi.move_light.quiet_ms` | 원복 조용 시간 | 짧을수록 잠깐 멈출 때 크롬이 되살아났다 사라지는 깜박임이 잦다 |
| `ui.mdi.move_light.square_corners` | 이동 중 모서리 반경 0 | 켜면 끄는 창과 겹친 정지 창의 모서리가 이동 중 각진다 |
| `ui.mdi.move_light.siblings` | 겹친 정지 창 가벼운 크롬 | 끄는 동안 정지 창 그림자가 사라졌다가 원복 때 돌아온다 |
| `ui.mdi.move_light.siblings_per_frame` | 끌기 시작 때 한 프레임에 가벼운 크롬을 거는 정지 창 수(0 은 한 번에) | 0 보다 크면 정지 창 그림자가 N 개씩 차례로 사라진다 |
| `ui.mdi.move_light.restore_per_frame` | 원복 때 한 프레임에 되돌리는 정지 창 수(0 은 한 번에) | 0 보다 크면 정지 창 그림자가 N 개씩 차례로 돌아온다. 끄는 창 자신의 원복은 늦어지지 않는다 |
| `ui.mdi.move_light.bitmap_cache` | 이동 중 끄는 창 안쪽을 비트맵 한 장으로 그린다 | 끄는 창 글자가 회색조로 보이거나 약간 흐려 보일 수 있다(추정) |
| `ui.mdi.move_light.static_cache` | 이동 중 정지 창을 비트맵 한 장으로 그린다 | 정지 창 글자가 약간 흐려 보일 수 있다(추정) |
| `ui.mdi.tab_join.arm_near` | 합류 아이콘 근접 표시 | 멀리서는 합류 표적이 미리 보이지 않는다 |
| `ui.mdi.tab_join.arm_radius_dp` | 근접 표시 반경 | 클수록 멀리서 켜진다. 범위 상한에 가까우면 끌기 시작 때 모두 켜는 동작에 가깝다 |

- 범위 밖 값은 범위 안으로 맞춘다. 값이 없으면 기본값으로 읽는다.
- 값을 바꾸면 다음 이동부터 반영한다. 끄는 순간 걸려 있던 처리는 바로 푼다.
- 사용자 층에는 사용자가 바꾼 키만 저장한다(희소 저장, `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §5.1). 그래야 제품 기본값을 바꿀 때 기존 사용자에게도 새 기본값이 닿는다.
- 화면 차이가 없는 성능 스위치는 설정 키가 아니라 진단 빌드 인자다. 내용 히트 테스트 끔, 다시 그리기 영역 추적, 포인터 이동 합치기, 놓기 반영 앞당기기, 끌기 시작 계산 미리 하기, 비활성 제목줄 흐림 방식이 여기에 든다.
- 제품 빌드는 진단 스위치의 기본 상태로 동작한다. 기본 상태는 내용 히트 테스트 끔만 켬이고 나머지는 지금 동작 그대로다. 목록과 인자 이름은 `../../poc/ui/README.md` 에 둔다.

## 4. 기본값의 근거

- 가벼운 크롬 기본 켬. 이동 1회 렌더에서 그림자와 둥근 잘라냄이 큰 몫을 차지했고, 켜면 이동 프레임 시간이 크게 줄었다(실측). 한 PC 한 구성의 측정이라 다른 환경의 절감량은 미검증이다.
- 끌기 중 그림자 기본 숨김(`hide`). 이동 1회 렌더에서 그림자가 큰 몫이었다는 위 실측을 따른다. 사용자가 그림자 깜박임보다 모양 유지를 원하면 '유지'를 고른다(사용자 결정, 결정 143). '유지'의 끌기 프레임 증가분은 PERF-16 으로 기록만 하고 판정선을 두지 않으며, 25ms 를 넘으면 설정 화면에 부하 경고를 보인다(`../04_기술스택/03_PoC_UI_합격기준_Mars실측.md` §6.4).
- 조용 시간 300ms. 끌다가 잠깐 멈출 때 크롬이 되살아났다 다시 사라지는 깜박임 반복을 막는다. 크롬을 켜고 끌 때마다 창 전체를 다시 그리기 때문이다.
- 겹친 정지 창 기본 켬. 끄는 창 자신에게 하는 처리를 같은 시간 동안 뒤 창에 넓힌 것이고, 놓으면 돌아오는 일시 변화이며, 웹 끌기 렌더 시간이 약 절반이 됐다(실측).
- 합류 아이콘 근접 표시 기본 켬. 끌기 시작 프레임에 한꺼번에 바뀌는 화면 요소 수가 줄어 웹 끌기 판정값이 합격 기준 안으로 들어왔다(실측). 멀리서 합류 표적이 미리 보이지 않는 만큼 발견성은 낮아진다.
- 비트맵 캐시·정지 창 캐시·프레임 분산 기본 끔. 켬·끔 비교에서 효과가 재현되지 않았다(실측).
- 측정값·비교 규칙·회차는 판정 보고서 부록에 있다. 원자료 일부는 저장소 미수록이라 근거 수준은 미확인이다.
