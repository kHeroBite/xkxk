# 디자인 테마 설계 정본 (REQ-104, 결정 134, ADR-118)

- 역할은 색 테마(`BuiltinThemes`)와 직교하는 '디자인 테마' 축(모양·효과 묶음)의 설계 정본이다. 색·요소별 지정은 `17_테마_요소별_사용자지정_설계.md`(REQ-101)가 정본이고, 이 문서는 그 합성 계층에 층 1개를 더한다.
- 옵션화 대원칙(REQ-99·ADR-089)에 따라 모든 수치는 설정 키 + 초기 제시값이다. 값은 `DesignThemes.EffectTable` 한 곳에만 두고 코드에 리터럴로 흩지 않는다.
- 근거 조사는 `plan/01_시장조사/19_디자인테마_앱레퍼런스_조사.md`, 결정 상세는 `plan/90_결정관리/02_결정기록_부록/b40_ADR-118.md`와 `plan/90_결정관리/01_결정대기_부록/d373_디자인테마_확인대기.md`에 있다.

- 움직임 효과(motion.open·close·switch)의 효과 ID·배치 상태별 규칙·효과 단계는 `21_창_움직임효과_배경_설계.md` 가 정본이다(결정 143, D-569·D-571). 옛 `depth.open` 열은 `motion.open` 으로 옮겼고, ds-depth 의 옛 `tilt` 는 `tilt3d` 와 같은 결과다.

- `inherit` 는 기존 설정·동작 그대로라는 뜻이다. ds-classic 이 현재 화면과 화소·계산값까지 같게 하는 장치다.
- 새 내장 색 pd-pastel(밝음)·pd-aurora(어두움)는 기존 7종 표를 바꾸지 않고 추가하며, REQ-101 대비 경고를 통과하는 색만 쓴다.
- 예외(대비 결함 수정). 상태 표시줄 새 알림 배지는 ds-classic 을 포함한 모든 디자인 테마에서 주 타이틀바의 바탕·글자 색 짝과 같은 글자색 1px 테두리로 그린다(마우스 올림·누름 포함, 크기는 그대로). 강조색 + 일반 글자색은 내장 9테마 모두 4.5 에 못 미쳤다.
- 알 수 없는 디자인 테마 ID 가 저장돼 있으면 ds-classic 으로 본다.

| `theme.motion.level` | system | system·full·reduced·off |
| `shortcut.window.overview` | Ctrl+Alt+O | 창 전체 보기 단축키 |

- 허용값·기본값·리소스 키(`PdStyle<효과>`)는 `DesignThemes.EffectTable` 이 소유한다. 허용 목록 밖 값은 무시하고 저장값은 보존한다.
- 기울기 각도·원근 거리·카드 크기·glass 하한·전환 ms 를 코드 숫자 상수로 박지 않는다.
- 한계(PoC). 효과 키가 아닌 수치 키(`decor.*`·`glass.minOpacity`·`depth.*` 등)는 사용자가 조절하는 화면·저장 경로가 없고, 사용자 값이 현재 적용되지 않는다. 회사 값과 기본값만 적용되므로 무늬 농도의 '사용자가 정했으면 올리지 않는다'는 규칙도 지금은 회사 값으로만 확인된다.

## 4. 설정 계층과 우선순위
- 요소 속성은 사용자(REQ-101 Design) ?? 회사 정책 ?? **디자인 테마** ?? 색 템플릿 Design ?? 제품 기본값 순이다. `DesignLayer` 에 `Style` 값을 enum 끝(서수 보존)에 추가하며 표시용이고 직렬화 값이 아니다.
- 효과 키는 사용자 덮어쓰기 ?? 효과 단계 묶음 ?? 회사 정책 ?? 디자인 테마 값 ?? 효과 표 기본값 순이다. 효과 단계(`theme.style.effectLevel`)가 `theme` 이거나 묶음에 없는 키면 단계 층을 건너뛴다. 단계는 덮어쓰기 저장소에 쓰지 않는 해석 층이라 디자인 테마를 바꾸면 묶음 밖 키는 새 테마 값이 보인다(21 §5.1, D-591). 회사 잠금이면 덮어쓰기 자리에 회사 값이 온다. 그 뒤 §7 폴백이 실효값을 낮춘다(저장값은 보존).
- 움직임 수준(`theme.motion.level`)은 접근성 상한이고, 효과 단계는 부하·취향 묶음 선택기다. 둘을 합치지 않으며 효과 단계는 움직임 수준이 허용하는 범위 안에서만 효과를 켠다. 움직임 수준·GPU 끔·소프트웨어 렌더 폴백이 단계보다 앞선다(이 문장의 정본은 이 절이다).
- 색 직교는 디자인 테마가 색 토큰을 바꾸지 않는다는 뜻이다. 추천 색은 1클릭 제안뿐이고 강제하지 않으며, 색 테마를 바꿔도 디자인 테마를 유지하고 반대도 같다.
- 회사 잠금은 `theme.style.locked=true` 일 때 선택·덮어쓰기를 막고 회사 값만 쓴다. 요소 잠금은 기존 `ThemeElements.IsLocked` 를 따른다.
- 레이어는 Theming(모델·적용)·ViewModels·xkxk.frameworks.ui.views(화면·3D)로 나뉜다. xkxk.frameworks.ui.shell 은 xkxk.frameworks.ui.views 를 참조하지 않으므로 전체 보기는 Shell 쪽 `WindowOverviewHost`(정적 대리자 `Open`·`Select`·`State`, 이벤트 `Requested`)를 거친다. Views 의 `WindowOverview3D` 가 시작 때 대리자를 등록하고 원격 명령은 `WindowOverviewHost` 만 호출한다.

| 항목 | 판정 | 근거 |
|---|---|---|
| 창 열기·닫기 원근 기울기 전환 | 가능 | `Rotate3DTransform` https://api-docs.avaloniaui.net/docs/Properties_T_Avalonia_Media_Rotate3DTransform , 변환 안내 https://docs.avaloniaui.net/docs/graphics-animation/transforms |
| 페이지·문서 전환 3D 뒤집기 | 가능 | `Rotate3DTransition` https://api-docs.avaloniaui.net/docs/T_Avalonia_Animation_Rotate3DTransition , 전환 안내 https://docs.avaloniaui.net/docs/graphics-animation/page-transitions |
| 3D 카드 회전목마 '창 전체 보기' | 부분가능 | 카드별 Rotate3DTransform 렌더는 가능. 회전된 요소의 hit-test 동작은 공식 문서에 없음(미확인) → 시험 `hit_test_3d` 로 확인, 실패 시 카드의 투영 사각형인 평면 히트 영역으로 대체 |

| 그림자 | 가능 | BoxShadow https://docs.avaloniaui.net/docs/graphics-animation/effects |
| 유리 재질 | 부분가능 | 반투명 브러시·그라데이션은 가능. 앱 안 배경 흐림은 `ExperimentalAcrylicBorder`(실험 API)라 이번 범위 밖(보류) |
| 진짜 3D 공간 창 관리(카메라·깊이 정렬·자유 회전 큐브·visionOS식 공간 배치) | **불가능(공식 미지원)** | Avalonia 에 3D 장면(Viewport3D) API 가 없다. XPF 미지원 목록에 Viewport3D 가 후속 과제로 있다 https://docs.avaloniaui.net/xpf/missing-features (XPF 문서라 Avalonia 일반에도 적용된다는 것은 추정). 서드파티 3D 엔진은 3D 모델 렌더용이라 UI 창을 3D 장면에 올리는 용도가 아니다 |
| 웹·Android 동등성 | 가능(추정, 시험으로 확인) | 세 플랫폼 모두 Avalonia 합성기·Skia 로 그린다는 구조상 추정이며 시험으로 확정한다 |
| GPU 끄기(소프트웨어 렌더) | 부분가능 | 그려지나 비아핀 변환·그림자 비용이 커서 §7 폴백을 쓴다 |

- 진짜 3D 공간 창 관리는 불가능하므로 타협 구현하지 않는다. Avalonia 가 3D 장면을 공식 지원하면 ADR-118 재검토 조건에 따라 다시 판단한다.
- 공식 지원 범위 안의 대안은 4가지다. ① 원근 기울기 전환(입체 효과) ② 3D 카드 회전목마 전체 보기 ③ 페이지 3D 뒤집기 ④ 그림자·떠 있는 창. 끌기·입력 같은 상호작용은 늘 평면 상태에서 한다.

## 6. 폼팩터
- MDI(PC형)는 모든 효과를 지원한다.
- DOCK(태블릿형)은 그림자·모서리·decor·motion·motion.open·close·switch(문서 탭 내용 영역, `tilt3d` 포함)를 지원하고, depth.page 는 문서 탭 전환에, overview 는 문서 카드로 쓴다. 옛 `depth.open` tilt 가 DOCK 에서 나오던 동작을 motion.open 으로 정본에 올렸다(TODO-657 종결, 21 §4).
- NAV(폰형)는 모양·motion·depth.page(페이지 뒤집기)와 움직임 효과 부분집합(`fade`·`push*`, 21 §4)만 쓰고 overview 는 평면 목록이다(`overview_nav_flat`).
- 웹은 MDI·DOCK 과 같은 규칙이다. SDI 는 OS 창이라 움직임 효과를 적용하지 않는다(평면).
- 용어는 `plan/05_아키텍처/08_지원_폼팩터_용어.md` 를 따른다.

## 7. 성능과 폴백
- 아래 중 하나면 depth.*·motion 실효값을 낮춘다. `GpuSetting.Applied` 가 소프트웨어(`softwareFallback`), 움직임 수준 off 또는 reduced, 열린 창 수가 `maxWindows` 초과인 경우다. 낮춤 규칙은 motion.open·close·switch→none(reduced 는 잘라냄·밀어내기·3D 를 fade 로, 21 §7), depth.overview→flat, depth.page→inherit, motion→none(reduced 는 subtle)이다. GPU 폴백 정본은 `plan/05_아키텍처/05_제품구성_시스템메뉴.md` §3.5.1 이다.
- 3D 변환은 전환 중에만 걸고, 끝나면 RenderTransform 을 **전환 전 원래 값으로 복원**한다(없었으면 null). 정지 상태 비용은 0이며 끌기 경로에 영향이 없다(A15·A29 회귀 방지).
- 전환 중 창 닫기나 끌기가 시작되면 애니메이션을 즉시 끝내고 원래 값으로 복원한다. 창이 0개면 전체 보기를 열지 않는다.
- 디자인 테마 전환 방식(2026-11-18, K13 개선). 전환 때 앱 리소스에 표식 리소스를 넣거나 빼지 않는다. 그렇게 하면 ResourcesChanged 가 셸 전체에 방송돼 전환 비용 대부분을 차지했다(실측). 대신 사용자·회사 값이 없으면 내장 5종의 요소 디자인 규칙을 한 Styles 에 미리 계산해 두고, 최상위 창(TopLevel)의 표식 클래스(`pdDesign-<ID>`)만 바꿔 고른다. 새 창은 첫 렌더 전(TemplateApplied)에 요소 디자인 표식 클래스를 단다. 효과 표식(chrome·decor 클래스)은 첫 렌더 전이 아니라 창 Loaded(첫 렌더 뒤)에만 붙는다(의도된 동작이며 첫 프레임 판정 대상이 아니다). 팝업 루트는 클래스를 달지 않고 원래 창 표식을 따른다. 사용자·회사 값이 있거나, Loaded 때 요소 디자인 표식이 이미 맞지 않았음(첫 프레임 어긋남)이 확인되면 현재 테마 규칙만 쓰는 단일 경로로 돌아간다. 폴백 보고는 요소 디자인 표식의 hit·miss 만 센다. 어느 경로든 걸리는 규칙 집합과 순서는 테마 하나로 만든 규칙과 같아야 한다(동치 점검). 요소 규칙 정본은 `plan/09_화면설계/17_테마_요소별_사용자지정_설계.md` 의 적용 방식이다.
- decor 는 작업 영역 배경 1장(타일·그라데이션 브러시)으로만 그리고 문서 창 안에는 그리지 않는다.
- 성능 기준(초기 제시값)은 디자인 테마 전환 p95 ≤300ms 다. 문서 창 열기 기준(옛 'ds-depth ≤ ds-classic×1.15')은 PERF-12(열기 명령 → 첫 프레임, 효과 켬 p95 ≤ 효과 끔 p95 × 1.15)로 옮겼고, 효과 재생 중 프레임은 PERF-13 이다. 정본은 `../04_기술스택/03_PoC_UI_합격기준_Mars실측.md` §6.4 다(D-594). 측정은 PC 비움(away) 상태에서만 한다.

## 8. 접근성
- 움직임 수준 system 은 웹에서 `prefers-reduced-motion` 을 JSImport 로 읽어 반영한다. 데스크톱·Android 의 OS 연동은 TODO 이고 그동안 수동 설정을 제공한다. 웹 matchMedia 가 없으면 줄이기 없음으로 본다.
- surface=gradient·glass 의 글자 대비는 양 끝 색 중 나쁜 쪽으로 REQ-101 대비 경고를 계산한다(`contrast_ok`). glass 불투명도는 하한(`theme.style.glass.minOpacity`) 아래로 내려가지 않는다.
- 전체 보기는 키보드로 ←→·Enter·Esc 를 지원하고, 카드 AutomationId 는 `overview.card.<n>` 이다.

## 9. 모델·저장·호환
- `UiThemeSettings` 에 `DesignThemeId`·`MotionLevel`·`EffectOverrides`(Dictionary<string,string>, 희소 저장)를 더하고 DTO 필드를 추가한다.
- 요소별 사용자 지정(17)의 저장 형식. 사용자 테마의 요소 값 사전 `Design` 에 바꾼 키만 저장하고(희소 저장) 복제 원본 내장 템플릿 Id `BaseTemplateId` 를 함께 저장한다. 옛 저장본은 `Design` 이 빈 사전이라 화면이 변하지 않고, `BaseTemplateId` 가 없으면 기반(Light·Dark)에 맞는 내장(pd-light·pd-dark)을 되돌리기 기준으로 한다. 이름 변경 뒤에도 `BaseTemplateId` 가 우선이다. 사용자 테마를 삭제하면 `Design` 도 함께 사라진다. 내보내기 JSON 에는 `Design` 과 `BaseTemplateId` 가 실린다.
- 옛 프로필(필드 없음)은 ds-classic·빈 덮어쓰기로 읽는다(`legacy_profile`). 내장 색이 늘어 목록 순서가 바뀌어도 저장된 ThemeId 는 Id 기준으로 유지한다.
- 서버 저장은 TODO-170 경로를 따른다.

## 13. 요소 디자인 적용 방식(구현 대응)
17 은 화면 규칙만 갖고, 구현 방식은 이 절이 갖는다.
- 정적 리소스 Setter 는 쓰지 않는다. 지정된 (요소, 속성)만 실행 중에 스타일·Setter 로 만들어 앱 스타일의 전용 묶음 1개에 넣고, 값이 바뀌면 그 묶음을 다시 만든다. 미지정이면 스타일이 없어 기존 화면이 그대로다. 정적 Setter 가 키가 없을 때 속성 기본값을 내서 기존 렌더를 덮는 것이 시험에서 실측됐다(버튼·입력칸 모서리·테두리·여백 0, 셸 글자 14→12). 요소별 선택자 문자열은 요소 표(데이터)에 두고 코드에 박지 않는다(REQ-99).
- 사용자·회사 값이 하나도 없으면 묶음을 전환형으로 만든다. 내장 디자인 테마마다 규칙을 미리 계산해 한 묶음에 넣고, 테마마다 다른 규칙만 최상위 창 표식 클래스(`pdDesign-<디자인 테마 ID>`) 아래로 한정한다. 값이 하나라도 있으면 지금 디자인 테마 규칙만 담은 단일 경로로 만들어 같은 동작을 따른다. 두 경로 모두 늘 켠 표식(`pdDesignOn`)을 붙여 Setter 우선순위 등급을 같게 둔다. 전환 때 표식을 바꾸는 방식과 안전 폴백은 §7 이다.
- 버튼 요소의 제외 대상은 크롬 클래스(pdChrome·tabTitle·tabClose·sdiIcon)와 제목줄(MainTitleBar·SdiTitleBar, 루트 클래스 pdTitleBar) 안 버튼이다. 형식 이름이 아니라 클래스로 판정한다(웹 트리밍에서도 동작). 스타일 선택자와 원격 측정 대상이 같은 제외 규칙을 쓴다.
- 숨은 컨트롤(예 모바일형의 메뉴 줄)에는 묶음 교체가 다시 적용되지 않으므로 교체 뒤 전체 컨트롤의 스타일을 다시 평가한다(Android 시험에서 확인, 문서 5개 열린 상태 p50 4.3ms·p95 18.4ms).
