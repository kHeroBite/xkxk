# Pd 화면 설계 — 창 배치(스냅 레이아웃)

> 상태 설계 정본(ADR-099, `plan/90_결정관리/02_결정기록_부록/b21_ADR-099.md`)
> 설정 키는 §8 에 이름과 뜻만 적는다. 값 꼴·기본값·값 분류·허용 층의 선언 자리는 `../10_API설계/plt_2.md` §12.1 의 `ui.*` 표다. 기본값의 근거 수준은 미검증이다. 표에 없는 시각 값(테두리·모서리·색)은 테마 토큰을 쓴다.
> 충돌 규칙: 창 탭 합류(`01_화면설계_공통원칙.md` §4.4), 다중 모니터 최대화 기준(`03_데스크톱_화면설계.md` §5), MDI 창 끌기 경계 규칙(01 §4.2), 폼팩터별 기본 UI 모드(`../05_아키텍처/08_지원_폼팩터_용어.md` §1-3)와 달라 보이면 그 정본이 우선이다.

## 1. 목적과 요구 원문

- 사용자 요구(2026-11-11, 원문 일부): "상단으로 끌어서 최대화나 정해진 레이아웃대로 변경… 창을 끌어서 원하는 위치를 지정".
- 목적은 Windows 11 Snap Layouts 와 비슷하게, 창을 끌어 위쪽에 놓으면 최대화하거나 정해진 칸 배치로 바꾸는 것이다. 좌·우 가장자리와 모서리에 놓으면 반쪽·4분의 1 로 배치한다.
- 대상은 MDI 문서 창, SDI(독립 OS 창), 웹 관리형 창이다. 데스크톱·웹·태블릿의 MDI 모드가 같은 규칙을 쓴다.
- 소속 기능은 PLT-06(창 관리)이고 이 문서는 그 기능 블록의 확장이다. 단계와 WBS 행은 PLT-06 을 따른다(M1, WBS-M1-06).

## 2. 적용 대상

| 대상 | 기준 영역 | 판단 | Snap Assist(§3.9) |
|---|---|---|---|
| MDI 문서 창(데스크톱·웹·태블릿의 MDI 모드) | 메인 창의 MDI 문서 영역 | 적용 | 적용(MDI 영역 안) |
| SDI(Windows·macOS 독립 OS 창) | 창이 속한 모니터의 작업 영역(겹친 면적이 가장 큰 모니터, 작업표시줄 제외 — 03 §5 와 같은 규칙) | 적용. Windows 는 `ui.snap.sdi_mode` 에 따라 OS Snap 에 맡기거나 앱이 직접 한다(§7) | 적용(그 모니터 작업 영역 위에 후보 창 목록. `ui.snap.sdi_mode` 가 OS·끔이면 없음) |
| 웹 관리형 창(04 W-02, SDI 대체) | 브라우저 뷰포트 안 MDI 영역 | 적용. MDI 와 같은 규칙이다 | 적용(MDI 와 같음, 썸네일은 실패하면 카드로 폴백) |
| 태블릿의 MDI 모드 | MDI 영역 | 적용. 손가락 끌기도 같은 포인터 경로라 같은 규칙이다. 키보드 대안은 하드웨어 키보드가 있을 때만 쓴다 | 적용 |
| 태블릿(펼친 폴드 포함) DOCK·대화면 NAV | — | 해당 없음. 떠 있는 창이 없고 영역 패널과 탐색만 있다 | 해당 없음 |
| 스마트폰(바형·접은 폴드) NAV | — | 해당 없음. 문서가 화면 전체를 쓰고 끌 창이 없다(스마트폰은 NAV 만 쓴다, 05/08 §1-3) | 해당 없음 |

- 위치 고정 창은 대상이 아니다. 최대화 창은 제목줄을 끌어 복원되는 순간부터 대상이 된다. 최소화 창은 끌 수 없어 해당 없다.
- 창 크기 조절 끌기(가장자리 잡기)는 대상이 아니다. 이동 끌기만 대상이다.

## 3. 동작

### 3.1 상단 레이아웃 막대

- 끄는 중 포인터가 기준 영역 위쪽 가장자리에서 감지 거리(`ui.snap.edge_distance_dp`) 안에 들고 막대 표시 지연(`ui.snap.bar_delay_ms`)만큼 머무르면, 위쪽 가운데에 레이아웃 막대가 나타난다.
- 막대 안에는 칸 종류별 작은 배치도가 있다. 배치도의 한 칸 위에 놓으면 그 칸의 사각형을 적용한다.
- 막대는 포인터가 막대와 위쪽 감지 띠를 벗어나면 닫힌다.

### 3.2 칸 종류 (등록형, D-509)

칸 종류는 데이터다. 한 행은 id·칸 비율 목록·칸 최소 영역을 갖는다. 아래 여섯이 출하 기본 시드이고, 회사·사용자가 `ui.snap.custom_layouts` 로 칸 종류를 더한다(예 넓은 모니터의 3:1·1:2:1 배치, 회사 표준 배치). 더한 칸 종류도 막대·호버 팝업·창 메뉴에 같은 규칙으로 나온다. 쓸 칸 종류는 `ui.snap.layouts` 로 고른다.

| id | 배치 | 칸 |
|---|---|---|
| max | 최대화 | 1 |
| half | 좌우 1:1 | 2 |
| twothird | 좌우 2:1 | 2 |
| thirds | 세로 3열 1:1:1 | 3 |
| leftsplit | 왼쪽 1/2 + 오른쪽 위아래 | 3 |
| quad | 2×2 4분할 | 4 |

- 세로가 더 긴 영역에서는 좌우 배치를 위아래 배치로 바꾼다. Windows 세로 모니터도 이렇게 바뀐다고 보았으나 **미확인**(추정, 공식 문서로 확인하지 못했다)이다. Pd 동작은 이 추정과 상관없이 위와 같이 정한다.

### 3.3 위쪽 가장자리 놓기 — 최대화

- 막대 칸 밖이지만 위쪽 가장자리 감지 띠 안에 놓으면 최대화한다(`ui.snap.top_edge_maximize`). 띠 안에 들면 최대화 미리보기를 보인다. 끄면 이 경우는 이동만 한다.
- 근거는 사용자 원문의 '상단으로 끌어서 최대화' 다.
- Windows 와의 비교: Microsoft 지원 문서는 창을 화면 위쪽으로 끌면 Snap 막대가 나타나고 칸에 놓을 수 있다고 적는다(**공식 확인**, https://support.microsoft.com/en-US/windows/experience/snap-your-windows). 막대 칸이 아닌 위쪽 가장자리에 놓으면 최대화되는 동작은 이전 Windows 의 끌기 최대화 기억에 기댄 것이라 **미확인**이다. 같은 문서의 '위로 끌면 세로로만 늘어난다' 는 문장이 창 끌기인지 창 위쪽 테두리 끌기인지도 **미확인**이다.

### 3.4 좌·우 가장자리와 모서리

- 좌·우 가장자리 감지 띠에 들면 반쪽, 네 모서리(가로·세로 감지 띠가 겹치는 정사각 구역)에 들면 4분의 1 이다.
- 들어가면 바로 미리보기를 보이고 놓으면 적용한다.
- 위쪽 모서리는 모서리 규칙(4분의 1)이 위쪽 가장자리(최대화)보다 먼저다.
- `ui.snap.edge_enabled` 로 좌우·모서리만 따로 끈다. `ui.snap.edge_distance_dp` 가 0 이면 가장자리·모서리·막대 감지를 모두 끈다.

### 3.5 막대 밖 놓기와 Esc

- 막대와 감지 띠 밖에 놓으면 칸을 적용하지 않고 놓은 자리로 이동만 한다(일반 이동). 사용자 원문의 '창을 끌어서 원하는 위치를 지정' 은 일반 이동을 유지해야 한다는 뜻으로 읽었다.
- Esc 는 끌기 자체를 취소하고 창을 시작 위치로 돌린다. SDI 는 OS 이동 루프의 Esc 복귀와 같은 결과다.

### 3.6 스냅 해제와 저장

- 스냅으로 크기가 바뀐 창을 다시 끌어내면 스냅 전 크기로 돌아간다. Windows 도 이렇게 동작한다고 보았으나 **미확인**(공식 문서 미확인)이다.
- 스냅 전 크기는 메모리에만 두고 작업공간 저장 형식은 바꾸지 않는다. 재시작 뒤에는 스냅된 사각형을 일반 창 위치·크기로 복원한다.
- SDI 는 예외다. 다시 끌어내도 스냅 전 크기로 돌아가지 않는다(§12.2 한계).

### 3.7 엣지 케이스

- 다중 모니터 SDI: 끄는 중 다른 모니터로 넘어가면 그 모니터 작업 영역으로 막대 위치와 칸을 다시 계산한다. 배율은 현재 모니터 값을 쓴다.
- 작업표시줄이 위·왼쪽에 있거나 자동 숨김이면 작업 영역 기준이라 자동으로 반영된다. 위쪽 작업표시줄이면 감지 띠는 작업 영역 위쪽 가장자리다.
- MDI 영역이 아주 작아 모든 칸이 최소 크기보다 작으면 막대를 띄우지 않는다.
- 끄는 중 포커스나 포인터 캡처를 잃으면 막대·미리보기를 닫고 아무것도 적용하지 않는다.
- 웹에서 포인터가 브라우저 창 밖으로 나가면 취소와 같게 처리한다.
- 터치의 상단 머무름은 손가락이 멈춘 시간으로 판정한다. 끌기가 시작된 뒤에만 판정해 길게 누름 메뉴와 겹치지 않게 한다.
- MDI→DOCK 모드 전환 중의 끌기는 취소한다. 스냅이 꺼져 있으면 첫 판정에서 바로 돌아간다.

### 3.8 최대화 단추 호버 팝업

- 사용자 요청(2026-11-11)으로 넣었다. 최대화/이전 크기 단추 위에 포인터를 `ui.snap.flyout.delay_ms` 만큼 두면 단추 아래에 칸 종류 팝업이 뜬다.
- 팝업 칸을 누르면 그 칸을 적용한다. 창 메뉴 '배치' 와 같은 경로다. 적용할 수 없는 칸은 흐리게 비활성으로 둔다.
- 적용 대상은 MDI 문서 창, 웹 관리형 창, SDI(앱이 그리는 제목줄 단추)다. 데스크톱 SDI 는 `ui.snap.sdi_mode` 가 끔이면 띄우지 않는다. OS 모드여도 SDI 단추는 앱이 그리므로 앱 팝업을 띄운다.
- 메인 창은 Windows 에서 띄우지 않고 OS 메뉴에 맡긴다(§12.2 한계). macOS·Linux 메인 창은 앱 팝업을 띄운다.
- 띄우지 않는 경우는 다음과 같다. 터치 입력, 적용할 칸이 없는 창(스마트폰 NAV·태블릿 DOCK·접은 폴드·위치 고정), 지연 전에 단추를 벗어난 경우, 다른 창이 단추를 덮은 경우다. 호버는 포인터 아래 맨 위 요소가 그 단추의 창에 속할 때만 인정한다.
- 단추와 팝업 사이를 오가는 동안은 `ui.snap.flyout.leave_grace_ms` 만큼 닫지 않는다. 둘 다 벗어나거나 Esc·바깥 클릭이면 닫는다.
- 단추 클릭은 그대로다. 팝업은 단추 아래에 붙어 단추를 덮지 않고, 팝업이 떠 있어도 단추 클릭은 단추로 간다.
- `ui.snap.enabled` 를 끄면 팝업도 함께 꺼진다. `ui.snap.flyout.enabled` 로 팝업만 따로 끈다.
- 제목줄 단추의 호버·누름 모양은 01 §4.2 가 정본이다.
- 근거 수준: 웹 관리형 창·데스크톱 MDI 는 실측, 데스크톱 SDI 의 팝업 열림·칸 배치는 측정 보류(a10 H-11)다.

### 3.9 Snap Assist — 남은 칸에 놓을 창 고르기

- 사용자 요청(2026-11-11)으로 넣었다. 칸 하나에 창을 놓은 뒤 남은 칸마다 놓을 창을 고르게 한다. 끌기 막대와 최대화 단추 팝업 두 경로 모두 해당한다. Esc 를 누르면 그때까지 고른 것만 남고 나머지는 무시한다(사용자 관찰 그대로, 공식 문서로 확인하지 못했다).
- Windows 기준: 설정 이름 "When I snap a window, show what I can snap next to it"(설정 ▸ 시스템 ▸ 멀티태스킹)는 **공식 확인**(https://support.microsoft.com/en-US/windows/experience/snap-your-windows)이다. 한 칸에 배치하면 남은 칸에 나머지 창 썸네일을 보이고 하나를 고르면 다음 칸으로 이어진다는 설명은 외부 해설 기준이라 **미확인**이다(https://www.windowscentral.com/how-use-snap-assist-windows-11). Esc 동작, 최소화 창이 후보에 드는지, 이미 놓인 창이 빠지는지도 **추정**이다. Pd 는 아래 규칙대로 만든다.

| 항목 | Pd 규칙 |
|---|---|
| 진입 1 | 끌기 막대 칸에 놓아 배치 |
| 진입 2 | 최대화/이전 크기 단추 호버 팝업(§3.8) 칸 클릭 |
| 진입 3(옵션) | 가장자리 반쪽은 `half` 의 남은 칸, 모서리는 `quad` 의 남은 3칸. `ui.snap.assist.on_edge` 끔이거나 그 칸 종류가 `ui.snap.layouts` 에서 빠져 있으면 없음 |
| 띄우지 않음 | `max` 칸·위쪽 가장자리 최대화(남은 칸 없음), Esc 취소·이동만·탭 합류, 창 메뉴·단축키 배치, 후보 0개, `ui.snap.assist.enabled`·`ui.snap.enabled` 끔, NAV·DOCK·접힘, SDI `ui.snap.sdi_mode` 가 OS·끔, Windows 메인 창 |
| 남은 칸 표시 | 남은 칸마다 판을 그린다. 판은 테마 표면 토큰을 불투명하게 쓰고 외곽선·모서리는 테마 토큰을 쓴다(뒤 창 글자가 비치지 않게). 활성 칸 하나에만 후보 목록을 보인다 |
| 후보 | 같은 기준 영역의 다른 창. 배치한 창·이번 세션에 이미 놓은 창·위치 고정 창은 뺀다. 최소화·최대화 창은 포함하고 놓을 때 보통 상태로 돌린다. 그 칸 최소 크기에 못 미쳐 적용할 수 없는 창은 뺀다. 순서는 창 겹침 순서(위가 먼저)다 |
| 고르기 | 후보 카드 클릭·탭·Enter 로 창 메뉴 '배치' 와 같은 경로로 배치하고, 칸 번호 순으로 다음 남은 칸으로 넘어간다. 후보가 없는 칸은 건너뛴다 |
| 칸 바꾸기 | 흐린 다른 남은 칸을 누르면 그 칸이 활성이 된다(추정 동작, Windows 와 다를 수 있음) |
| 끝 | 남은 칸이 다 차면 끝. Esc·후보 밖 바깥 클릭·포커스 이탈·기준 영역 크기 변경·UI 모드 전환·배치한 창 닫힘·웹 탭 숨김이어도 끝난다. 끝나도 이미 고른 배치는 되돌리지 않는다 |
| 키보드 | Tab/Shift+Tab·방향키로 후보 사이를 옮기고 Enter/Space 로 고르며 Esc 로 끝낸다. 처음 표시에 첫 후보에 초점이 간다 |
| 누름 동작 | ① 이미 배치된 칸(배치한 창의 제목줄)을 누르면 세션이 끝나며 그 첫 누름은 끌기로 이어지지 않고, 다음 누름부터 끌린다. ② 아직 채우지 않은 활성 칸의 빈 곳을 누르면 무시되고 세션이 유지되며 그 아래 창은 끌리지 않는다. Esc·취소 뒤에는 끌기와 크기 조절이 정상이다 |
| 카드 | 후보 창 전체를 비율을 유지해 축소한 썸네일(`ui.snap.assist.thumbnails`, 잘라내지 않고 카드 안에 맞춤). 이름표(아이콘+제목)는 카드 아래에만 두고 썸네일 위에 겹치지 않는다. 캡처에 실패하거나 썸네일을 끄면 대체 카드를 쓴다. 대체 카드는 큰 아이콘 + 제목 2줄(넘치면 말줄임) + 보조 표기(예 '미리보기 없음' 또는 최소화 상태)로 구성하며 카드 크기는 썸네일 카드와 같다. 웹에서 비트맵을 못 얻으면 대체 카드로 폴백하고 진단에 사유를 남긴다 |
| 다국어 | 카드 제목은 창 제목, 고정 문구는 언어 팩 |
| SDI 재활성화 | SDI 에서 배치 뒤 창이 다시 활성화되는 동안의 판정 시간은 `ui.snap.assist.sdi_grace_ms` 다(SDI 를 지원하는 환경에서만 설정 화면에 보인다) |
| 진단 | 자동화 채널 이벤트 `snapassist.state`·`snapassist.pick`·`snapassist.zone`·`snapassist.skip`·`snapassist.cancel` |

- 근거 수준: 데스크톱 MDI·웹 관리형 창·SDI 앱 모드에서 실측이다. 판정 기준은 `plan/04_기술스택/03_PoC_UI_합격기준_Mars실측.md` §6.4(PERF-07 표시 시간·EXT-06 카드 뒤 글자 비침)이고, 회차별 결과는 `plan/04_기술스택/04_판정보고서_부록/a10_측정보류_목록.md` 에 있다.

## 4. 미리보기

- 적용될 사각형을 강조색 반투명(`ui.snap.preview_opacity_pct`, 테두리는 테마 토큰)으로 기준 영역 위에 그린다. 색은 테마 토큰을 쓴다.
- 끄는 창은 포인터를 따라간다. '놓은 위치 = 보인 위치' 규칙의 예외는 스냅 적용뿐이며, 미리보기로 미리 보여 준다.
- 배치 애니메이션은 넣지 않는다(§12.1 확장 후보).

## 5. 우선순위와 충돌(01 §4.4 와의 관계)

끄는 중 한 지점이 여러 구역에 걸치면 아래 순서로 하나만 고른다.

1. **탭 합치기 표적**(다른 창의 합치기 아이콘·탭 줄) 위이면 스냅 미리보기와 막대를 숨기고 적용하지 않는다. 표적은 작고 명시적이라 탭 합류가 이긴다.
2. 상단 레이아웃 막대 칸
3. 모서리
4. 위쪽 가장자리(막대 칸 밖, 최대화 — `ui.snap.top_edge_maximize`)
5. 좌·우 가장자리

- 자석(UI-12)은 끄는 중 그대로 동작한다. 놓을 때 스냅이 활성이면 스냅 사각형이 자석 결과를 대신한다.
- 계산 비용: 표적·칸 사각형은 끌기 시작 때 1회 계산하고, 이동마다는 포인터 판정만 한다(끌기 프레임 회귀 방지). 끌기 프레임 비용 측정은 a10 의 측정 보류 항목이다.

## 6. 키보드 대안

- Win 키 조합은 OS 예약이라 앱에서 쓰지 않는다.
- 앱 단축키의 기본 키(후보)는 Ctrl+Alt+←/→(반쪽), Ctrl+Alt+↑(최대화), Ctrl+Alt+↓(복원)이다. 03 §6 단축키 목록·04 W-04 와 충돌하는지, 그래픽 드라이버의 화면 회전 단축키와 겹치는지는 **미확인**이다.
- 충돌하거나 웹에서 키가 전달되지 않으면 그 조합은 등록하지 않고 창 메뉴 '배치' 만 남긴다.
- 창 메뉴(메인·MDI·SDI 제목 줄과 제목 탭 공통, 03 §7.2)에 '배치 ▸' 하위 메뉴를 넣어 각 칸을 바로 적용한다. 키보드·마우스가 없는 터치에서도 쓸 수 있는 대체 경로다.
- SDI(Windows)에서 Win+방향키는 OS 동작이다. 앱은 막지 않는다. `ui.snap.keyboard` 로 앱 단축키를 끈다.

## 7. SDI 와 Windows 11 Snap

### 7.1 확인된 사실

- **공식 확인**: 창을 화면 위쪽으로 끌면 Snap 막대가 나타나고, 설정 ▸ 시스템 ▸ 멀티태스킹 ▸ 창 맞춤에서 '창을 화면 위쪽으로 끌 때 맞춤 레이아웃 표시' 를 끌 수 있다(https://support.microsoft.com/en-US/windows/experience/snap-your-windows). 설정 이름의 한국어 표기는 **미확인**이다.
- **공식 확인**: 사용자 정의 제목 줄 앱은 최대화 단추 영역의 적중 판정에서 최대화 단추 값을 돌려줘야 최대화 단추 위 Snap Layouts 메뉴가 보인다(https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu).
- **공식 확인**: Win+Z 는 Snap 메뉴를 여는 OS 단축키다(https://bugzilla.mozilla.org/show_bug.cgi?id=1718629).

### 7.2 확실하지 않은 점

- Pd SDI 는 제목줄 끌기에서 OS 이동 루프를 쓴다. 이 경로에서 OS 의 위쪽 Snap 막대가 뜨는지, 자석 보정과 겹칠 때 어떻게 보이는지는 **미확인**이다. 실기 확인 항목은 a10 H-09 다.
- OS Snap 켜짐 여부를 앱이 읽는 방법은 **미확인**이다. 문서화된 시스템 매개변수 API 를 learn.microsoft.com 공식 문서로 존재와 의미를 확인한 뒤에만 쓴다. 확인되지 않으면 '판정 불가 → 앱' 으로 처리한다. 레지스트리 값 이름을 추측해 읽는 방식은 쓰지 않는다.

### 7.3 `ui.snap.sdi_mode`

| 값 | 동작 |
|---|---|
| 자동(기본) | Windows 이고 OS Snap 이 켜져 있다고 판정되면 OS 에 맡기고 앱 막대·미리보기를 띄우지 않는다. macOS·OS Snap 꺼짐·판정 불가는 앱이 직접 한다 |
| 앱 | OS 판정과 무관하게 앱 막대(포커스를 가져가지 않는 테두리 없는 최상위 창)를 띄우고, 이동이 끝난 뒤 작업 영역 칸을 적용한다 |
| OS | 앱은 아무것도 하지 않는다 |
| 끔 | 앱 스냅을 쓰지 않는다. OS 동작은 앱이 막지 못한다(한계) |

- 자동의 조건: 실기에서 OS 이동 루프로 SDI 를 위로 끌 때 OS 막대가 뜨지 않으면 자동은 '앱' 으로 동작한다. 실기 확인 전 기본 동작은 '판정 불가 → 앱' 이다.
- 이중 표시: '앱' 인데 OS 막대도 뜨는 환경이면 '이중 표시, 자동 사용 권장' 으로 남긴다.
- OS 위임과 탭 합류 충돌: OS 위임 상태에서 SDI 를 메인 창 탭 줄·합치기 아이콘 위로 끌 때 OS 스냅과 탭 합류가 함께 일어나는지 시험에서 본다. 함께 일어나면 앱이 OS 스냅을 막을 수 없으므로 그 사실을 적고, 자동의 기본 해석을 '앱' 으로 바꾸는 것을 검토한다.
- 결과: OS 위임이면 OS 모양을 쓰므로 Pd 칸 종류·옵션·탭 합치기 우선 규칙과 다르다. 같게 하려면 '앱' 을 고른다. 설정 화면의 SDI 방식 설명 문구에도 이 내용을 쓴다.
- SDI 순서: 끄는 동안 자석 보정이 먼저 돌고, 이동이 끝난 뒤 칸을 적용한다. 크기 조절 끌기이면 시작하지 않는다.

## 8. 설정 키

선언 자리는 `../10_API설계/plt_2.md` §12.1 이다. 이 표는 키 이름과 뜻만 적는다. 설정 화면 자리는 설정 ▸ 창이다.

| 키 | 뜻 |
|---|---|
| `ui.snap.enabled` | 창 배치 전체 켜기. 끄면 팝업·Snap Assist 도 꺼진다 |
| `ui.snap.layouts` | 막대·팝업·창 메뉴에 쓸 칸 종류 id 목록. 빈 목록이면 막대를 띄우지 않는다 |
| `ui.snap.custom_layouts` | 회사·사용자가 더한 칸 종류(id·칸 비율 목록·칸 최소 영역의 표, §3.2) |
| `ui.snap.edge_distance_dp` | 가장자리·모서리·막대 감지 거리. 0 이면 감지를 모두 끈다 |
| `ui.snap.bar_delay_ms` | 상단 머무름 뒤 막대 표시 지연 |
| `ui.snap.edge_enabled` | 좌우·모서리 스냅만 따로 켜고 끄기 |
| `ui.snap.top_edge_maximize` | 막대 칸 밖 위쪽 가장자리 놓기 → 최대화 |
| `ui.snap.keyboard` | 앱 단축키 켜기 |
| `ui.snap.sdi_mode` | SDI 처리 방식(자동·앱·OS·끔, §7.3). 데스크톱에서만 뜻이 있고 웹·모바일 설정 화면에서는 숨긴다 |
| `ui.snap.preview_opacity_pct` | 미리보기 사각형 불투명도 |
| `ui.snap.flyout.enabled` | 최대화 단추 호버 팝업(§3.8) |
| `ui.snap.flyout.delay_ms` | 단추 위 머무름 뒤 팝업 표시 지연 |
| `ui.snap.flyout.leave_grace_ms` | 단추와 팝업 사이를 오가는 동안 닫지 않는 유예 |
| `ui.snap.assist.enabled` | Snap Assist(§3.9) |
| `ui.snap.assist.on_edge` | 가장자리·모서리 스냅 뒤에도 Snap Assist 를 띄움 |
| `ui.snap.assist.thumbnails` | 후보 카드 썸네일. 끄면 아이콘+제목 카드 |
| `ui.snap.assist.sdi_grace_ms` | SDI 재활성화 판정 시간 |

- 설정 값은 사용자 설정으로 저장·복원한다(자석 설정과 같은 방식). 저장 위치와 기기 동기화 여부는 선언 표의 칸이다.
- MDI 탭 막대 위치(위쪽 기본, 상·하·좌·우, 제거·숨김 불가)는 이 문서의 스냅 옵션이 아니라 PLT-06 정본이다(D-254, `13_UX패턴_카탈로그.md` UX-71, 01 §4.4).

## 10. MDI 끌기 경계와 최소 크기

- 칸 사각형은 기준 영역 안에 있으므로 01 §4.2 MDI 창 끌기 경계 규칙의 잡을 곳이 늘 남는다(값·값 분류·근거는 그 절).
- 칸이 창 최소 크기(03 §3.2.1)보다 작으면 그 칸은 막대에서 흐리게 비활성으로 두고 적용하지 않는다. 버튼만 남는 창을 만들지 않는다.

## 11. 시험 방법(기능만)

- 원격 진단 명령으로 옵션 값·현재 구역·적용 결과를 확인한다.
- MDI: 위쪽 머무름 → 막대 표시, 칸 놓기 → 칸 사각형, 막대 칸 밖 위쪽 띠 → 최대화, 좌·우·모서리, 막대 밖 → 이동만, Esc → 시작 위치, 탭 합치기 표적 우선, 다시 끌어내기 → 스냅 전 크기.
- SDI: §7 의 OS 막대 표시 여부, 탭 합류 충돌, `ui.snap.sdi_mode` 4값을 스크린샷으로 남긴다.
- 웹 관리형 창과 태블릿의 MDI 모드는 MDI 와 같은 항목을 본다. 스마트폰 NAV·태블릿 DOCK 은 해당 없음을 확인한다.
- Snap Assist: §3.9 진단 이벤트로 칸 이어짐·건너뜀·Esc 후 남은 배치·후보 0개를 확인하고, 끌기 막대 경로와 최대화 단추 팝업 경로를 둘 다 본다. `ui.snap.assist.on_edge`·`ui.snap.assist.thumbnails` 를 끈 경우도 본다.
- 표시·썸네일 시간과 끌기 프레임 비용의 기준은 04/03 §6.4 이고 회차 결과는 a10 에 있다.

## 12. 확장 후보와 한계

### 12.1 확장 후보

- 스냅 그룹(같이 스냅된 창 묶음 관리), 배치 애니메이션, 저장 형식에 스냅 상태 보존. 스냅 그룹은 13 의 UX-69 창 묶음과 함께 본다.
- 겹치는 창 작업공간 패턴은 13 의 UX-69(창 묶음·고정을 이름 저장 레이아웃에 포함)·UX-70(닫은 창 다시 열기)·UX-71(탭 막대 위치)이고 정본은 PLT-06 이다.
- 문서 1개 패널 머리줄을 안내 아이콘 밖 패널 본문에 놓으면 창으로 분리된다(§12.2). 아이콘 밖 본문 놓기도 합치기로 받을지는 개선 후보다.
- 회귀 도구와 Snap 기본 켬의 시나리오 충돌은 a10 H-12 다.

### 12.2 한계

- 세로 모니터: 세로가 긴 영역에서는 실제 칸이 위아래로 바뀐다(§3.2). 최대화 단추 호버 팝업(§3.8)의 칸 그림은 가로 기준 그대로 그린다. 그림은 칸 종류 구분용이다.
- SDI 스냅 전 크기 복원 없음: SDI 는 스냅된 창을 다시 끌어내도 스냅 전 크기로 돌아가지 않는다. 자석 보정과 겹쳐 넣지 않았다. MDI·웹 관리형 창은 돌아간다.
- 메인 창은 Windows 에서 OS 메뉴에 의존한다. 메인 제목줄 최대화 단추는 OS 의 최대화 단추로 표시돼 Win11 Snap 메뉴가 맡는다고 보고 앱 팝업을 띄우지 않는다. OS 메뉴가 실제로 뜨는지는 **미확인**이다. OS 창 맞춤 설정을 읽는 방법이 확인되지 않아 판정 불가로 처리하므로, OS 창 맞춤이 꺼진 PC 의 메인 창에는 어떤 메뉴도 뜨지 않을 수 있다(추정).
- 문서 1개 패널 머리줄 끌기(DOCK 패널 분할 끔): 다른 패널 가운데 안내 아이콘에 놓으면 탭으로 합친다. 문서 영역 가운데에 놓으면 문서 영역 문서로 들어간다. 대상이 없는 곳에 놓으면 관리형 창으로 분리된다. 가장자리 분할은 끔 상태에서 허용하지 않는다. 안내 아이콘이 아닌 패널 본문에 놓으면 합쳐지지 않고 창으로 분리된다(태블릿 실기 재현, 실측). 도구 패널·도구가 든 패널은 이전과 같다.
- Snap Assist(§3.9): 다른 모니터에 있는 SDI 창은 후보에 넣지 않는다(같은 모니터 작업 영역 기준). 웹 비트맵 썸네일은 headless Chromium 에서 얻어졌다(실측). 다른 브라우저에서도 얻어지는지는 **미확인**이고, 못 얻으면 카드로 폴백한다. 창 메뉴·단축키 배치에서는 진입하지 않는다.
- 다른 창이 단추를 덮은 경우의 미표시는 웹 시험의 보조 판정이다.
