## 1. 결론과 범위

- 칸반 보드는 CV-05(일정·이슈 칸반)로 계획에 있다(결정 47). 영업 기회용 보드는 CV-28 이다(CRM-01 정본이 "파이프라인 칸반"을 출력으로 두며 그 정본 출력은 그대로다).
- 영업 단계는 프로젝트 생애주기의 기회·제안·수주 단계(생애주기 코드 L0~L2, 접두 L(생애주기)는 `../05_아키텍처/53_Pd_용어_상태어휘_문서규칙_2.md` 접두 등록부)와 대응한다(CRM-01, REQ-34). 수주 후에는 CRM-02 전환으로 프로젝트가 생기고 CV-01~27 이 이어받는다.
- CV-28~34 는 사용자가 조사 결과를 보고 7종 전부 채택했다(결정 49, D-101). 릴리스는 결정 50(D-102)이 정했다. 사례 근거가 약한 CV-31·32·34 도 사용자 결정으로 채택됐다.
- 새 기능 ID 는 없다. 귀속은 CRM-01~04·PRE-06 의 확장이다. 새 화면도 없고 SCR-CRM-01·SCR-CRM-02 안에 둔다.
- CV 번호는 불변이며 승격 규칙은 08c §5, 다음 번호는 CV 번호 대장(`08f_차트뷰_추가_PERT_할일.md` §4)을 따른다. 뷰 수는 뷰 등록부가 갖는다.
- 정본 대조: `../06_기능목록/21_기능요건상세_부록/a14_CRM.md` CRM-01 출력에 "파이프라인 칸반(단계별 건수·금액 합·가중 금액)"·"단계 체류 기간 보고서", CRM-03 출력에 월별 매출 전망·직군별 인력 수요 대 가용 차트가 있다. CV 카드는 이 출력들의 뷰 카탈로그 기준점이다.
- 데이터와 계약의 정본은 `../08_데이터모델/crm.md`·`../10_API설계/crm.md` 다. 카드의 필요 데이터 칸은 그 문서의 경로·계약을 가리킨다.

## 4. 카드 (CV-28~CV-34)

카드 칸 10개와 AI 활용은 08a 형식을 따른다. 권한 칸은 10 `crm.md` 권한 코드 절의 코드를 가리킨다. 역할별 배정은 `iam` 역할 시드, 기능 게이트는 `lic` 권리 묶음이 정본이다.

### CV-28 영업 파이프라인 보드 (칸반, 결정 49)
- 목적: 계약 전 기회를 단계 열로 보고 카드 이동으로 파이프라인을 관리한다.
- 사용자: 영업 담당·경영진·PMO.
- 관리 동작: 카드의 단계 열 이동(전이 규칙 검사·이력 기록·수주 시 CRM-02 전환·실주 시 사유 입력은 CRM-01 그대로), 열 순서는 단계 설정을 따른다(테넌트 데이터), 정체 강조(RS-05) 켜기·끄기, 담당·고객사·기간 필터.
- 분석 지표(산식): 열별 건수, 열별 금액 합, 열별 가중 금액=Σ(예상 금액×확률). 정체 일수=오늘−현재 단계 진입일. 정체 임계는 키 `crm.pipeline.stale_days` 다.
- 필요 데이터: `crm` — `GET /api/v1/crm/pipeline/summary`(단계별 건수·금액 합·가중 금액), `GET /api/v1/crm/opportunities`(카드), `POST /api/v1/crm/opportunities/{opportunityId}/transition`(열 이동), 열 정의는 `GET /api/v1/crm/settings/stages`.
- 권한: 조회 `crm.opportunity.read`@tenant, 열 이동 `crm.opportunity.transition`@tenant(없으면 카드를 끌 수 없다), 종결 기회 되돌리기 `crm.opportunity.reopen`@tenant. 금액 열 노출은 필드 인가를 따른다.
- 기능 영역: CRM(CRM-01), 연계 CRM-02. 보드 컴포넌트는 CV-05 와 공통이다(§5).
- 화면 ID: SCR-CRM-01.
- 우선순위: 높음(CRM-01 정본과 같은 단계).
- AI 활용: 해당 없음 — 결정적 표시 유형: 카드 배치와 합계이며 전이 판정은 규칙이 한다.

### CV-29 파이프라인 퍼널
- 목적: 단계별 기회 수와 금액을 퍼널로 보아 병목 단계를 찾는다.
- 사용자: 영업 담당·경영진.
- 관리 동작: 단계 막대 선택→해당 기회 목록, 기간·담당 필터. 읽기 전용.
- 분석 지표(산식): 단계별 금액 합(기본 막대 크기), 건수 병기, 직전 단계 대비 비율=다음 단계 금액÷이전 단계 금액(해석 주의: 같은 기회가 단계마다 중복되지 않는 현재 단계 기준 집계이므로 전환율이 아니라 분포다).
- 필요 데이터: `crm` — `GET /api/v1/crm/pipeline/summary`(현재 단계 기준).
- 권한: 조회 `crm.opportunity.read`@tenant.
- 기능 영역: CRM(CRM-01). 화면 ID: SCR-CRM-01.
- 우선순위: 보통.
- AI 활용: 해당 없음 — 결정적 집계 유형: 단계별 합계 집계이다.

### CV-30 가중 파이프라인·매출 전망
- 목적: 기회 금액×확률을 예상 수주 월에 배분해 월별 매출을 전망한다.
- 사용자: 영업 담당·PMO·경영진.
- 관리 동작: 기준(가중·범주 누적·확정만) 전환, 기간·담당·고객사·단계·예측 범주 필터, 월 마감 스냅샷 대비 보기(CRM-03).
- 분석 지표(산식): 월 가중 매출=Σ(예상 금액×확률, 예상 수주 월 기준, 제외 범주 기회는 뺀다), 확정 매출은 수주 완료 청구 일정 합. 스냅샷 대비 차이=현재 전망−스냅샷 전망. 확률은 단계 기본 확률로 채우고 기회별로 고칠 수 있다(D-103).
- 예측 범주(D-103): 범주 목록·누적 순서·수동 지정 전용 여부는 `crm` 소유 테넌트 데이터(범주 설정, 08 `crm.md` §3.2)이고 등록형이다. 기본 시드는 다섯이다(파이프라인·최선·유력·확정·제외, 누적은 확정 → 확정+유력 → +최선 → +파이프라인, 유력은 수동 지정만). 단계 → 범주 매핑은 단계 설정의 값이다(기본 시드: 발굴·제안=파이프라인, 협상=최선, 수주=확정, 실주=제외). 실주·수주의 종결 표시와 제외 범주의 전망 제외는 바꿀 수 없다(데이터 무결성 고정 예외, 10 `crm.md` §9). 참고 사례는 HubSpot 예측 범주(Pipeline·Best case·Commit·Closed won·Not forecasted)이며 기본 시드의 이름과 유력의 정의는 Pd 가 정한 것이다(사례 대응은 §2, 추정).
- 필요 데이터: `crm` — `GET /api/v1/crm/forecast/revenue`(기준·범주별 월 전망, 환율 출처·`asOf`), `GET·POST /api/v1/crm/forecast/snapshots`, 범주 정의 `GET /api/v1/crm/settings/forecast-categories`. 기준 통화 환산은 `crm` 이 `money.q.effective_rate` 로 한다(`money` 는 필수 기반, 환율 원천은 FIN-12). 그 날짜의 환율이 없으면 그 기회를 원 통화로 따로 보이고 합계에서 뺀 건수를 함께 보인다(후보).
- 권한: 조회 `crm.forecast.read`@tenant, 스냅샷 만들기 `crm.forecast.write`@tenant.
- 기능 영역: CRM(CRM-03). 화면 ID: SCR-CRM-01.
- 우선순위: 높음(CRM-03 정본과 같은 단계).
- AI 활용: 보조 — 전망 편차 원인 요약 초안만 제안한다. 사람 확인: 영업 책임자가 요약과 원 수치를 대조한 뒤 공유.

### CV-31 단계 전환율·체류 시간
- 목적: 단계 이동 이력으로 단계별 이탈과 체류 기간을 보아 영업 절차를 개선한다.
- 사용자: 영업 관리자·PMO.
- 관리 동작: 읽기 전용. 기간·담당·고객 유형 필터, 단계 선택→기회 목록.
- 분석 지표(산식): 단계 전환율=다음 단계로 이동한 기회 수÷해당 단계에 진입한 기회 수, 평균 체류=Σ(단계 이탈일−진입일)÷건수(이력 기반). 표본이 키 `crm.stage_conversion.min_sample` 보다 적으면 값을 보이지 않는다.
- 필요 데이터: `rpt` 지표(원천 `crm` 이 지표 원천 포트 `rpt.port.metric_source` 로 등록하는 파이프라인 지표 — 단계 이력 기반, 읽기는 `GET /api/v1/rpt/metrics`). 기회 목록은 `crm` — `GET /api/v1/crm/opportunities`. 전환율·체류 지표의 지표 ID 는 `crm` 선언서가 정한다(계약 없음).
- 권한: 조회 `rpt.metric.read`@tenant 와 `crm.opportunity.read`@tenant. 본인 담당만 보는 범위 규칙은 10 `crm.md` 권한 절이 갖는다.
- 기능 영역: CRM(CRM-01 "단계 체류 기간 보고서"). 화면 ID: SCR-CRM-01.
- 우선순위: 보통. 사례 근거는 약하다(채택은 결정 49).
- AI 활용: 해당 없음 — 결정적 계산 유형: 이력 기반 비율·평균이다.

### CV-32 영업 활동 차트
- 목적: 미팅·통화·메일 활동량과 다음 할 일을 보아 기회 진행의 선행 지표로 쓴다.
- 사용자: 영업 담당·영업 관리자.
- 관리 동작: 읽기 전용. 기간·담당·고객사 필터, 활동 선택→원 기록(CRM-04).
- 분석 지표(산식): 기간별 활동 건수(유형별), 기회당 최근 활동 경과일=오늘−마지막 활동일, 기한 지난 다음 할 일 수.
- 필요 데이터: `crm` — `GET /api/v1/crm/activities/stats`(유형·기간별 건수), `GET /api/v1/crm/activities`(활동 목록, 08 `crm.md` §3.6 `activity`·`followup`), `GET /api/v1/crm/followups/me`. 메일 활동은 `crm` 이 포트 `crm.port.inbound_mail` 로 수신 기록을 잇는다. 그 포트의 구현 모듈이 테넌트 허용에 없으면 메일 유형은 수동 등록 활동만 센다(10 `crm.md` §7).
- 권한: 조회 `crm.activity.read`@tenant, 다른 사람의 비공개 활동은 `crm.activity.admin`@tenant 가 있을 때만 센다. 본인·소속 범위 규칙은 10 `crm.md` 권한 절이 갖는다.
- 기능 영역: CRM(CRM-04). 화면 ID: SCR-CRM-02.
- 우선순위: 낮음. 사례는 미확인이다.
- AI 활용: 해당 없음 — 결정적 집계 유형: 건수 집계이다.

### CV-33 수주 전망 대 인력 수요
- 목적: 수주 예상 기회의 직군별 인력 수요를 가용 인력과 겹쳐 수주 전에 자원 병목을 본다.
- 사용자: PMO·영업 담당·자원 담당.
- 관리 동작: 임계 확률(키 `crm.demand.push_min_probability`) 이상 기회의 수요를 SCH-06 자원 계획에 가상 수요로 보내는 동작은 CRM-03 규칙이다. 이 뷰는 읽기 전용이며 직군·기간 필터만 둔다.
- 분석 지표(산식): 월·직군별 가중 M/M=Σ(슬롯 M/M×기회 확률), 가용 대비=가중 수요−가용 공수(CV-12 가용 정의 재사용).
- 필요 데이터: `crm` — `GET /api/v1/crm/forecast/demand`(직군별 월 가중 M/M, 08 `crm.md` §3.5 `demand_projection`, 역할 슬롯은 `pre` 의 인력 슬롯에서 온다). 직군별 가용 공수는 CV-12 의 `rpt` 가동률 프로젝션을 재사용한다(직군 차원 지표는 계약 없음). 가용 원천(`sch`·`wcal`)이 테넌트 허용에 없으면 수요 막대만 보이고 가용선은 숨긴다.
- 권한: 조회 `crm.forecast.read`@tenant, 가용선은 `rpt.metric.read`@tenant 가 있을 때만. 실명 배정이 없는 가상 수요이므로 개인 정보는 없다.
- 기능 영역: CRM(CRM-03), PRE(PRE-06), SCH(SCH-06). 화면 ID: SCR-CRM-01.
- 우선순위: 보통(CRM-03 정본과 같은 단계). CV-12 가용 정의(D-68)와 단계 순서를 맞춘다.
- AI 활용: 해당 없음 — 결정적 계산 유형: 확률 가중 합계이다.

### CV-34 실주 사유 분석
- 목적: 실주 사유 분포를 보아 영업·제안 개선 항목을 찾는다.
- 사용자: 영업 관리자·경영진.
- 관리 동작: 읽기 전용. 기간·단계(실주 직전 단계)·담당 필터, 사유 선택→기회 목록.
- 분석 지표(산식): 사유별 건수·금액 비율=사유 합÷전체 실주 합, 실주 직전 단계별 분포.
- 필요 데이터: `rpt` 지표(원천 `crm` 의 파이프라인 지표 — 실주 사유 코드·직전 단계, 08 `crm.md` §3.3 `opportunity_stage_history`). 기회 목록은 `crm` — `GET /api/v1/crm/opportunities`(실주 단계 필터). 실주 사유 지표의 지표 ID 는 `crm` 선언서가 정한다(계약 없음).
- 권한: 조회 `rpt.metric.read`@tenant 와 `crm.opportunity.read`@tenant.
- 기능 영역: CRM(CRM-02 실주 사유 필수 규칙). 화면 ID: SCR-CRM-01.
- 우선순위: 낮음. 사례는 미조사다.
- AI 활용: 보조 — 자유 서술 사유의 묶음 제안만 하고 분류 확정은 사람이 한다. 사람 확인: 영업 관리자가 묶음을 검토해 확정.

## 5. 공통 보드 컴포넌트와 보드 플러그인 규격 (결정 52, D-104, ADR-091)

- 원칙: 카드 끌어 이동·가상화·WIP/합계 표시·경고 표시는 하나의 보드 컴포넌트(UI 레이어)가 하고, 열 정의·카드 필드·전이 판정만 보드 플러그인으로 바꾼다. ADR-077(시간축 렌더러 공통화)과 같은 방식이다. 전이 규칙은 플러그인을 낸 모듈의 서버가 판정한다.
- 보드를 쓰는 자리는 닫힌 목록이 아니다. 보드 플러그인은 화면 확장 자리의 한 종류다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7 5번). 보드를 더하려는 모듈은 자기 화면 모듈의 셸 등록 경로로 플러그인을 등록하고 이 절이나 08 §3.11 을 고치지 않는다(D-509).
- 플러그인 규격(필드 이름은 후보).

| 항목 | 플러그인이 내는 것 | 예(CV-05 / CV-28) |
|---|---|---|
| 열 원천 | 열 목록을 돌려주는 계약(열 ID·이름·순서·WIP 한도 또는 합계 지표) | `iss` 보드 조회 / `crm` 단계 설정 조회 |
| 카드 원천 | 열별 카드 목록 계약(커서·필터) | `iss` 보드 조회 / `crm` 기회 목록 |
| 카드 필드 | 카드에 보일 필드와 표시 순서, 금액·담당 등 필드 인가 대상 | 키·제목·담당 / 이름·고객사·금액·확률 |
| 전이 명령 | 카드를 다른 열로 옮길 때 부르는 명령 계약 ID 와 필요한 입력(사유 등) | `iss` 전이 경로 / `crm` 단계 이동 경로 |
| 경고 규칙 | 카드·열 경고의 조건(WIP 초과·정체 등)과 그 기준 설정 키 | WIP 한도 / `crm.pipeline.stale_days` |
| 권한 | 끌기 허용 판정에 쓰는 권한 코드@범위 | `iss.issue.transition` / `crm.opportunity.transition` |
| 허용에 없을 때 | 소유 모듈이 테넌트 허용에 없으면 보드 자체가 메뉴에 없다 | — |

- 보드를 쓰는 모듈의 목록은 이 문서에 적지 않는다. 모듈 선언서의 플러그인 등록에서 모은 파생 표로 보고, 화면 조립 간선은 50 §3.2 화면 조립 표에 올린다.
- 이유: 사용자 판단 기준(원칙·변경 대응 우선)에 따라 보드 변경이 한 곳에서 끝나게 한다.
- 정체 강조와 WIP 초과는 같은 "카드·열 경고" 표시 규칙을 쓴다(색만으로 구분하지 않는다).
- 폼팩터: 08 §3.10 값을 넘지 않는다. CV-28 스마트폰 노출은 `02_메뉴구조.md` 의 SCR-CRM-01 값을 따른다.
