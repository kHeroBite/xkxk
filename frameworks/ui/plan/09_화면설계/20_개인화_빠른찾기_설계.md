# 18. 개인화 빠른 찾기 설계 — 즐겨찾기·최근 조회·개인 순위·개인 추천

## 1. 요구 원문과 해석

- 원문(사용자, 2026-11-18). "그리고 개인화도 곳곳에 반영되어야 한다. 예를들어 프로젝트나 고객사를 즐겨찾기 해서 상단에 보여주거나, 조회한 최근n개를 상단이나 별도 팝업이나 레이아웃으로 보여줘서 빠르게 찾을수 있도록 하거나, 개인이력을 바탕으로 자동으로 상위에 보여주도록 하거나 하는 등의 개인의 활동을 바탕으로 빠른 검색/추천을 할 수 있어야 한다."
- 해석 1. '곳곳에'는 특정 화면 몇 개가 아니라 대상(프로젝트·거래처·문서·이슈·화면 등)을 다루는 모든 목록·검색·선택 자리다. 그래서 화면마다 만들지 않고 공통 부품으로 만든다(§2).
- 해석 2. '최근 n개'의 n 은 고정 값이 아니라 설정 키다(REQ-99, ADR-089).
- 해석 3. '자동으로 상위에'는 사용자가 끌 수 있는 기본 동작이다. 개인 활동 기록은 개인정보이므로 회사 정책·국가 팩의 제약 안에서만 모은다(§7).

## 2. 원칙

1. **횡단 부품 한 벌.** 즐겨찾기·최근 조회·개인 순위·개인 추천은 대상 종류마다 따로 만들지 않는다. 데이터는 `plt` 한 곳이 갖고(§6), 화면은 공유 UI 컴포넌트(PLT-01)가 그린다. 업무 모듈은 대상 종류를 등록하는 일만 한다.
2. **대상 종류는 등록형(D-509).** 대상을 가진 모듈이 모듈 선언서로 대상 종류를 등록하고 대상 확인·삭제 통지 계약 `plt.port.target`(48 §3.2 '대상 확인·삭제 통지')을 구현한다. `plt` 는 구현 모듈 이름을 갖지 않는다. 화면(메뉴 항목) 종류 `screen` 은 `plt` 가 스스로 등록한다. 구현 모듈 목록의 정본은 50 §3.1 의 `plt.port.target` 행이다.
3. **ID 참조만.** 개인 목록은 대상 종류 코드와 대상 ID 만 저장한다. 제목·상태 같은 표시 값은 읽을 때 구현 모듈에서 받는다. 그래서 권한을 잃은 대상의 제목이 개인 목록으로 새지 않는다(§5).
4. **권한 필터 뒤에만 보인다.** 모든 노출은 지금 사용자의 권한 판정(`iam`)과 테넌트 허용 모듈을 통과한 뒤다. 개인 순위가 권한을 넓히지 않는다(UR-04 와 같은 뜻, `13` §3).
5. **조합은 화면 쪽.** 업무 모듈의 목록 API 는 그대로 두고, 화면이 `plt` 개인 목록과 모듈 목록을 합친다. 그래서 업무 모듈 → `plt` 의 새 동기 간선이 생기지 않는다. 동기 간선은 늘지 않고 50 §3.1 포트 행의 용도·구현 모듈만 는다. 검색 결과 개인 재정렬도 화면이 `plt` 개인 순위(`/api/v1/plt/personal/rank`)를 받아 한다.
6. **끌 수 있고 지울 수 있다.** 각 부품은 회사·사용자 설정으로 끌 수 있고, 사용자는 자기 기록을 언제든 지운다.

## 3. 부품 4종

| 부품 | 하는 일 | 근거 데이터 | 사용자 조작 | 키(이름만) |
|---|---|---|---|---|
| ① 즐겨찾기 | 사용자가 고른 대상을 목록·팔레트·홈 맨 위 고정 줄에 둔다 | `plt.personal_favorite` | 별 단추로 넣고 빼기, 끌어서 순서 바꾸기, 폴더로 묶기(후보) | `plt.personal.favorite.max_items`, `plt.personal.favorite.lost_access` |
| ② 최근 조회 | 최근 연 대상 n 개를 시간 역순으로 보인다 | `plt.personal_recent` | 항목 하나 지우기, 전체 지우기, 표시 끄기 | `plt.personal.recent.max_items`, `plt.personal.recent.show` |
| ③ 개인 순위 | 자주·최근 본 대상을 위로 올린다(빈도와 최근성을 합친 점수) | `plt.personal_activity_stat` | 끄기, 점수 초기화, '이 항목 올리지 않기' | `plt.personal.rank.enabled`, `plt.personal.rank.half_life_days` |
| ④ 개인 추천 | 검색·팔레트·1줄 입력 결과에 개인 가중을 더하고 이유를 보인다 | ③ 의 점수 + ① 즐겨찾기 여부 | 이유 보기, 추천 끄기 | `plt.personal.rank.search_weight`, `plt.personal.suggest.show_reason` |

- 공통 스위치는 `plt.personal.enabled`(회사)다. 끄면 네 부품이 모두 화면에서 빠지고, 기록 수집도 멈춘다.
- **점수(③).** 대상마다 열람 신호를 받을 때 `점수 = 이전 점수 × 0.5^(경과 일수 ÷ 반감 일수) + 신호 가중` 으로 갱신한다. 신호 종류(열기·편집·즐겨찾기 넣기)별 가중은 키 `plt.personal.rank.signal_weights` 다. 원시 열람 기록은 남기지 않고 대상별 누적 값만 남긴다(§7).
- **추천 순서(④).** 최종 순서는 검색 관련도 + 개인 가중이다. 개인 가중은 상한을 두어 글자가 정확히 맞는 결과를 넘지 않게 한다(상한은 `plt.personal.rank.search_weight`). 1단계는 통계(위 점수)만 쓰고 AI 모델을 부르지 않는다. AI 추천은 §8.
- **이유 표시(④).** 결과 줄 끝에 '즐겨찾기'·'자주 봄'·'최근 봄' 중 하나를 작은 표지로 보인다. 색만으로 가르지 않는다(UR-01).

## 4. 표시 위치와 폼팩터

UI 방식 용어는 05/08 을 따른다(PC형 = MDI, 태블릿형 = DOCK, 모바일형 = NAV).

| 자리 | PC형(MDI) | 태블릿형(DOCK) | 모바일형(NAV) |
|---|---|---|---|
| 빠른 찾기 팝업 | 명령 팔레트를 빈 입력으로 열면 첫 화면이 즐겨찾기 + 최근(팔레트 홈, UX-76). 여는 키는 팔레트와 같다(`plt.hotkey.key_combo`, 동작 = 명령 팔레트) | 같음(하드웨어 키보드 또는 상단 검색 단추) | 팔레트가 없다. 검색 탭을 열면 빈 상태에서 즐겨찾기 + 최근을 보인다 |
| 목록 화면 상단 고정 줄 | 목록 위 한 줄에 그 대상 종류의 즐겨찾기, 이어서 개인 순위 상위(최대 개수는 `plt.personal.recent.max_items` 와 따로 화면 폭에 맞춰 자른다). 접기 가능 | 같음 | 목록 맨 위 가로 칩 줄(가로 스크롤) |
| 선택 상자(프로젝트·거래처 고르기 등) | 펼치면 맨 위 구역 '즐겨찾기', 다음 '최근', 그 아래 전체 목록 | 같음 | 아래에서 올라오는 시트에 같은 구역 순서 |
| 개인 홈 구역 | 홈 화면 위젯 '즐겨찾기·최근'(DSH-01 개인화 레이아웃의 한 위젯) | 같음 | 홈 탭 맨 위 구역 |
| 탐색 패널·메뉴 | 탐색기 패널 맨 위에 '즐겨찾기' 구역(화면 즐겨찾기 포함) | 측면 패널 맨 위 구역 | 삼선 메뉴 맨 위에 즐겨찾기 화면, 하단 탭은 그대로(하단 탭 + 삼선 규칙) |
| 제목 줄 즐겨찾기 영역(화면 대상) | 메인 창 제목 줄 오른쪽 끝에 화면 즐겨찾기를 아이콘만으로 오른쪽부터 쌓는다(제목 탭은 왼쪽부터). 누르면 그 화면 창을 활성화하거나 연다. 배치·클릭·넘침 규칙은 `22_메뉴아이콘_제목탭_즐겨찾기_설계.md` §4(REQ-113, D-581·D-582) | 제목 탭이 없으므로 탐색 패널 맨 위 구역이 대신한다 | 삼선 메뉴 맨 위 즐겨찾기가 대신한다 |
| 별도 레이아웃 | 즐겨찾기·최근 전용 패널을 창으로 띄워 작업공간 배치(PLT-06)에 저장 | 측면 패널 탭 하나로 둔다 | 해당 없음(검색 탭이 대신한다) |

- 즐겨찾기 넣기·빼기는 대상 상세 머리의 별 단추, 목록 줄 오른쪽 메뉴, 팔레트 결과 줄 메뉴 세 곳에서 한다. 터치 방식에서는 길게 누르기 메뉴로 한다(UR-02).
- 다른 기기에 같은 사용자로 열린 화면은 즐겨찾기 변경 통지를 받아 목록만 다시 읽는다(§6 이벤트, 실시간 그룹 `u:`).
- **빈 상태.** 즐겨찾기가 없으면 '별을 눌러 자주 쓰는 항목을 위에 고정하세요'와 별 단추 위치 그림을 보인다. 최근이 없으면 구역을 숨긴다. 수집이 꺼져 있으면 '최근·자주 본 항목이 꺼져 있습니다'와 설정 바로가기를 보인다(회사가 막았으면 바로가기를 빼고 사유만 보인다).
- 화면 문구는 키 기반 사전이다(PLT-03). 네 부품은 셸 요소와 공유 컴포넌트라 부품 자체에는 화면 ID·메뉴 ID 를 만들지 않는다.
- 사용자 설정 항목(§9 중 허용 층이 사용자인 키, 기록 모두 지우기)은 업무 메뉴 '개인 설정' 그룹에 둘 개인화 설정 화면에 들어간다. 이 화면의 화면 ID·메뉴 ID 는 D-566 의 후보이고 등록은 TODO-640 이다(§11). 지금 그 그룹에 있는 SCR-IAM-05 는 `auth` 소유 로그인 수단 화면이라 이 설정을 싣지 않는다.

## 5. 권한과 노출

- 개인 목록을 읽을 때 `plt` 는 대상마다 `plt.port.target` 의 읽기 확인을 묶음으로 부른다. 결과는 세 가지다. 읽을 수 있음 → 표시, 대상 없음(삭제) → 목록에서 지움, 읽을 수 없음 → 회사 옵션 `plt.personal.favorite.lost_access` 에 따라 숨김 또는 회색 줄.
- 회색 줄은 제목을 보이지 않고 '볼 수 없는 항목'과 빼기 단추만 보인다(§2 원칙 3). 최근 조회와 개인 순위는 회사 옵션과 무관하게 읽을 수 없는 대상을 언제나 숨긴다.
- 대상 종류를 등록한 모듈이 테넌트 허용에 없으면 그 종류 항목은 모두 빠진다(행은 지우지 않는다 — 다시 허용되면 돌아온다).
- 대상 삭제 통지를 받으면 즐겨찾기·최근·순위 행을 함께 지운다. 멤버 종료(`core.MembershipEnded`)는 그 사람의 개인 목록 전부를 지운다.
- 권한 코드는 `plt.personal.read`·`plt.personal.write`·`plt.personal.delete` 이고 범위는 모두 `@self` 다(10 plt §13).

## 6. 데이터·계약 (정본은 08·10 plt)

| 구분 | 이름(후보) | 요지 | 정본 |
|---|---|---|---|
| 테이블 | `plt.personal_favorite` | 사용자 × 대상 종류 × 대상 ID, 폴더 이름(선택), 사전순 순서 키 `rank`(공통규약_2 끌어서 순서 바꾸기 규칙) | 08 plt §3.12 |
| 테이블 | `plt.personal_recent` | 사용자 × 대상, 마지막 연 시각. 사용자당 `plt.personal.recent.max_items` 를 넘으면 오래된 행부터 지운다 | 08 plt §3.12 |
| 테이블 | `plt.personal_activity_stat` | 사용자 × 대상, 점수·마지막 신호 시각·신호 수. 원시 기록 없음 | 08 plt §3.12 |
| API | `/api/v1/plt/personal/favorites`, `/recents`, `/rank`, `/activity` | 조회·넣기·빼기·순서, 열람 신호 묶음 보고, 기록 지우기 | 10 plt §8a |
| 이벤트 | `plt.PersonalFavoriteChanged` | 실시간 그룹 `u:{membershipId}` 기기 간 갱신. 다른 모듈 구독 없음 | 08 plt §6 |
| 포트 | `plt.port.target`(기존) | 대상 확인·삭제 통지. 새 포트를 만들지 않는다. 구현 모듈은 50 §3.1 | 10 plt §11 |

- **신호의 출처는 클라이언트다.** 화면이 대상을 열거나 편집을 저장하면 클라이언트가 열람 신호를 모아 `/api/v1/plt/personal/activity` 로 보낸다(묶음, 화면을 떠날 때·일정 간격). 업무 모듈 이벤트를 구독하지 않으므로 업무 모듈과 `plt` 사이 간선이 늘지 않는다.
- 수집이 꺼진 사용자·회사의 신호는 서버가 받자마자 버린다(204). 클라이언트는 설정을 읽어 보내지 않는 것이 기본이다.
- **소유 판정.** 개인 진행 상태(`plt.user_ui_profile`)·작업공간 배치·저장 보기를 이미 `plt` 가 갖고(D-523), `plt` 는 필수 기반이라 모든 제품에 깔린다(48 §3.1). 개인화를 업무 모듈마다 두면 같은 표가 여럿 생겨 단일 정본 원칙(05/32)에 어긋난다.
- **겹치는 기존 정본.** 주소록 즐겨찾기 `gwr.contact_favorite`(08 gwr.md)는 주소록 전용 표시 이름을 갖는 기존 표다. 이 표를 공통 즐겨찾기(주소록 대상 종류 — 코드 이름은 후보이며 등록되지 않았다. `gwr.personal_contact` 테이블 이름과 겹치지 않게 짓는다)로 흡수한다(D-564). 흡수 전까지 주소록 화면은 `gwr` 표를 쓰고, 나머지 대상은 모두 이 문서의 표를 쓴다.
- **캐시.** 개인 목록 조회는 서버의 캐시 우선 조회 계층을 지난다. 캐시 키에 테넌트·멤버십·목록 종류·대상 종류를 넣고, 즐겨찾기 변경·신호 반영·삭제 통지 때 그 사용자 키만 지운다. 키 꼴과 TTL 의 정본은 07 이다.

## 7. 개인정보

- 개인 활동 기록(최근·순위)은 본인만 본다. 관리자·감사자가 남의 개인 목록을 여는 경로(API·화면)는 두지 않는다. 열람 경로를 두지 않는 것은 D-565 다.
- 수집 스위치는 `plt.personal.activity.collect` 다. 허용 층은 회사·사용자이고 회사가 끄면 사용자는 켤 수 없다(제약원). 국가 팩이 동의를 요구하면 회사 동의 정책(05/30 §7, D-343)을 따라 동의 전까지 수집하지 않는다.
- 보존 기한은 `plt.personal.activity.retention_days` 다. 기한을 넘긴 순위·최근 행은 배치가 지운다. 국가 팩이 상한을 줄 수 있다. 즐겨찾기는 사용자가 직접 만든 값이라 기한으로 지우지 않는다.
- 지우기 경로는 세 가지다. 최근 목록에서 항목 하나 지우기, 개인 설정에서 '최근·자주 본 기록 모두 지우기', 멤버 종료 때 자동 삭제.
- 기록은 원시 열람 로그가 아니라 대상별 누적 값이다(열람 시각 목록을 남기지 않는다). 개인 데이터 내보내기 요청에는 즐겨찾기·최근·순위 행이 들어간다.
- 개인 활동 기록은 외부 AI 공급자에 보내지 않는다(§8).

## 8. AI 추천과의 관계

- 1단계 개인 추천은 §3 통계 점수뿐이다. AI 호출이 없다.
- 2단계 후보는 AI 인사이트(`ain`)가 개인 순위 상위와 업무 맥락을 써서 '오늘 볼 만한 항목'을 제안하는 것이다. 이 제안은 제안 경로(`suggest`, 05/28)로만 나오고 자동 반영하지 않는다. 개인 활동 값은 내부 모델에서만 쓰고 외부 공급자 호출에 싣지 않는다(05/29 §7 데이터 보호).

## 10. 수용 기준 후보

1. 프로젝트·거래처·문서·이슈·화면 다섯 종류에서 별 단추로 넣은 항목이 그 종류의 목록 상단 고정 줄·선택 상자 '즐겨찾기' 구역·팔레트 홈에 같은 순서로 나온다.
2. 대상 다섯 개를 차례로 연 뒤 팔레트를 빈 입력으로 열면 최근 구역에 연 순서의 역순으로 나오고, n 을 넘긴 오래된 항목은 빠진다(n 은 `plt.personal.recent.max_items`).
3. 같은 거래처를 여러 번 연 사용자의 거래처 선택 상자에서 그 거래처가 전체 목록보다 위 구역에 나오고, `plt.personal.rank.enabled` 를 끄면 위 구역이 사라진다.
4. 검색어가 두 대상과 같은 정도로 맞을 때 자주 본 대상이 위에 오고 '자주 봄' 표지가 붙는다. 글자가 정확히 맞는 대상은 개인 가중이 있는 다른 대상보다 아래로 가지 않는다.
5. 즐겨찾기한 프로젝트의 권한을 빼면 다음 조회에서 회사 옵션대로 숨겨지거나 제목 없는 회색 줄로 보이고, 응답 본문에 그 프로젝트의 제목이 없다.
6. 회사가 `plt.personal.activity.collect` 를 끄면 사용자는 켤 수 없고, 신호 보고 API 가 204 로 버리며 순위 행이 늘지 않는다.
7. '기록 모두 지우기' 뒤 최근·순위 행이 0 이고 즐겨찾기는 남는다. 보존 일수를 넘긴 행은 배치 뒤 없다.
8. 관리자 권한으로도 다른 사람의 개인 목록을 읽는 경로가 없다(403 이 아니라 경로 자체가 없다).
9. PC형·태블릿형·모바일형 세 방식에서 §4 표의 자리마다 같은 데이터가 보인다(모바일형은 검색 탭·홈 탭·삼선 메뉴).
10. 대상 종류를 등록한 모듈을 테넌트 허용에서 빼면 그 종류 항목이 개인 목록 응답에서 빠지고, 다시 허용하면 돌아온다.

## 11. 남은 판단(D-561~D-566)

- D-561. 최근 조회 n·즐겨찾기 상한·순위 반감 일수·보존 일수의 기본값.
- D-562. 검색 결과 개인 가중의 상한과 신호 가중 값.
- D-563. 권한을 잃은 즐겨찾기의 기본 처리(숨김·회색).
- D-564. 주소록 즐겨찾기 `gwr.contact_favorite` 를 공통 즐겨찾기로 흡수(§6).
- D-565. 관리자 열람 경로를 두지 않음(§7).
- D-566. 개인화 설정 화면(§4)의 화면 ID·메뉴 ID 는 후보로 둔다.
- D-566. 이 부품은 새 기능 ID 없이 기존 PLT-01·PLT-09 의 범위로 둔다. 릴리스 단계·WBS 는 그 기능 단계를 따른다.
