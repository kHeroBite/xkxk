# 12. 간편 입력·규모 적응 화면 설계 (REQ-68·69·70·72·73·74·76·89·97·98, 결정 117)

> 상태 설계 정본(결정 117, ADR-101)
> 요구는 `../03_개발범위/08_범용화_에이전트PMS_요구.md`, 자동 동작 경로는 `../05_아키텍처/28_Pd_에이전트_자동화_설계.md`, UI/UX 패턴 입력은 `../01_시장조사/16a_경쟁솔루션_UIUX_패턴표.md` 다. 수치는 모두 설정 키의 기본값(후보)이고 키는 §2.5 에 있다(옵션화 대원칙 ADR-089).
> 이 문서는 화면 배치·흐름의 정본이다. 기능 규칙(입출력·권한·수용 기준)은 기능 부록이 정본이다 — PLT-09(규모 단계·점진 공개·명령 팔레트)·TIM-07(한 줄 등록·업무일지)·COL-16(할 일)·IMP-09(붙여넣기)·AIN-08(제안함)·AIN-09(질의응답)·COL-15(실시간 STT 회의록)·PRJ-19(아이디어). 부록과 다르면 부록을 먼저 고치고 이 문서를 맞춘다.
> 폼팩터·UI 모드 용어는 `../05_아키텍처/08_지원_폼팩터_용어.md` 를 따른다. 폼팩터는 데스크톱·태블릿·스마트폰, UI 모드는 MDI·DOCK·NAV 다. 셸·창·단축키 공통 규칙은 `01_화면설계_공통원칙.md`·`03_데스크톱_화면설계.md`·`06_모바일_화면설계.md` 를 참조만 한다(이 문서는 고치지 않는다).
> 새 화면 ID·메뉴 ID 는 이 문서가 부여하지 않는다. 메뉴 정본(`02_메뉴구조.md`·`메뉴구조.csv`, 생성 스크립트 `../_build/menu_data.py`)이 부여한다(§12).

## 0. 결론

- **입력은 한 줄에서 시작한다.** 셸 어디서나 부르는 1줄 입력이 빠른 등록의 공통 입구다(§3). 등록 대상은 모듈이 포트로 올린다. 해석은 규칙(M2)과 AI(M3) 두 단계이고, 해석 결과는 토큰 강조로 보여 사람이 고친다.
- **모든 동작은 명령 팔레트 한 곳에서 닿는다.** 숨긴 기능도 팔레트·검색으로는 항상 닿는다(§4). 그래서 점진 공개가 '기능을 찾을 수 없음' 으로 바뀌지 않는다.
- **계정 종류와 규모 단계는 다른 축이다.** 계정 종류는 개인 공간·회사 공간이고, 규모 단계는 1인·소규모·표준·대규모다(53 §1.1). 개인 공간은 별도 앱이 아니라 같은 Pd 이고 '개인 공간 기본 단계' 를 쓴다(결정 124, D-311). 단계는 메뉴·뷰의 기본 노출만 바꾸고 권한·데이터·권리 묶음은 바꾸지 않는다(§2). 단계 승격은 자동 전환이 아니라 1클릭 제안이다.
- **자동으로 만든 변경은 제안함을 지난다.** 붙여넣기·회의 액션아이템·공정률·재계획 제안은 모두 제안함(AIN-08)에서 1클릭 승인한다(§6, 28 §3).
- **쉬움은 잰다.** 각 흐름에 EZ-01~06 계측점을 둔다(§10). 값은 BETA 게이트 입력이다.

## 1. 공통 원칙

1. 레이어 분리 — 화면(UI/UX)은 토큰 강조·패널 배치·단추만 맡는다. 입력 해석·단계 판정·제안 생성은 컨트롤 레이어 서비스가 하고, 화면은 그 결과를 그린다.
2. 옵션화 — 값은 설정 층(제품 기본·운영 시스템·회사·하위 범위·사용자, 해석 순서와 규칙은 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §5)을 따른다. 키마다 허용 층은 §2.5 의 키가 선언 자리에서 갖는다. 프로젝트별 값은 하위 범위 층(범위 종류 프로젝트)이다. 고정 예외는 감사 기록(데이터 무결성), 질의응답 검색 단계 권한 필터(보안)이고, 녹음 전 고지·동의는 국가 팩 제약원이 허용 집합을 정한다(§8).
3. 사람 최종 확정 — 화면은 AI·규칙 결과를 '초안' 표지와 함께 보이고, 확정 단추는 사람이 누른다. 자동 반영 범위(28 §5)에 든 종류도 '자동 반영됨' 목록에 남는다.
4. 도달 보장 — 어떤 단계·폼팩터에서도 숨긴 기능은 명령 팔레트(데스크톱·태블릿)나 검색 탭(스마트폰 NAV)으로 닿는다. 스마트폰 NAV 의 '도달 100%' 규칙(`06_모바일_화면설계.md` §2)과 같은 기준이다.
5. 다국어 — 토큰 기호·날짜 표현은 언어 팩마다 해석 규칙을 가진다(`../05_아키텍처/27_Pd_다국어_로캘_설계.md`). 전각 기호(＃·＠·！)도 같은 토큰으로 읽는다(기본 언어 팩 값).

## 2. 계정 종류·규모 단계와 점진 공개 (PLT-09, REQ-76·REQ-89)

### 2.1 두 축의 정의

- 계정 종류 축은 개인 공간(개인 계정 가입 때 만들어지는 1인 테넌트, LIC-09)과 회사 공간이다. 개인 공간은 규모 단계를 판정하지 않고 0단계 Personal(코드 `personal`, 후보)을 쓴다(결정 124, D-310). `personal` 은 `plt.scale_mode.default` 의 값 집합에 들지만 개인 계정에서만 고를 수 있다(제약은 10 `plt.md` §4).
- 규모 단계 축은 회사 공간과 그 안 프로젝트에 쓴다. 단계 코드는 불변이고 표시 이름은 언어 팩 값이다(표시 이름 바꾸기 D-311).

| 단계 코드 | 표시 이름(기본) | 대상 | 홈 기본 |
|---|---|---|---|
| `personal` | 개인 공간 | 개인 공간(0단계, 개인 계정만) | 오늘 할 일 + 1줄 입력 + 일정 |
| `solo` | 1인 | 1명, 개인 프로젝트·학습 계획 | 오늘 할 일 + 1줄 입력 + 이번 주 일정 |
| `small` | 소규모 | 구성원 수가 `plt.scale_mode.thresholds` 의 소규모 경계 이하 | 내 작업 + 팀 할 일 + 제안함 요약 |
| `standard` | 표준 | 구성원 수가 같은 키의 표준 경계 이하 | 현행 홈 대시보드(SCR-DSH-01) |
| `large` | 대규모 | 그보다 많거나 진행 프로젝트 수가 `plt.scale_mode.project_threshold` 를 넘음 | 포트폴리오 대시보드(SCR-DSH-02) |

- 화면·뷰마다 '기본 노출 시작 단계' 는 그 화면을 소유한 모듈이 모듈 선언서의 '화면과 메뉴' 항목에서 선언하고 메뉴 생성기 데이터의 열로 모인다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §3.1·§7). 새 솔루션의 화면도 이 표를 고치지 않고 단계를 받는다. 단계마다 보이는 메뉴·뷰 목록은 그 열에서 만든 파생 표이고 이 문서는 값을 다시 적지 않는다. 회사가 단계별 노출을 바꾸는 값은 `plt.scale_mode.exposure` 다.
- PMS 화면의 선언 예는 이렇다. 개인 공간은 할 일(COL-16)·일정·노트/메모(COL-12 개인 공간)·간단 간트(CV-01 축약 보기)·아이젠하워(CV-38)·개인 예산(FIN-01 단순 보기)부터 보인다. 자원·기준선·원가·평가는 표준부터, 포트폴리오·프로그램(PRJ-04)은 대규모부터 보인다.
- 최종 표시 판정은 05/30 §3 이 정본이다(권리 묶음·테넌트 허용·권한·회사 화면 표시·규모 단계). 이 문서는 판정식을 다시 적지 않는다. 회사가 끈 화면은 명령 팔레트로도 닿지 않는다.
- 단계 판정은 회사 구성원 수와 진행 프로젝트 수로 하고 둘 중 큰 쪽 단계를 제안한다. 개인 플래너 진입 구성은 개인 공간 기본 단계로 고정해 연다(결정 125, 화면은 `16_개인플래너_전환유도_화면설계.md`).
- 단계 저장 단위는 회사 층 + 하위 범위 층(범위 종류 프로젝트)이다. 회사 공간 안의 1인 프로젝트는 `solo` 단계로 둘 수 있다.
- 개인 공간 기본 단계에서 처음 보이는 화면 목록은 위 선언에서 모은 값이고 운영 시스템 층에서 바꾼다(D-312).
- 권리 묶음은 별개 축이다. 단계는 권리 묶음이 허용하지 않는 기능을 켜지 않는다. 권리 밖 기능은 숨기지 않고 잠금 표지와 등급 표시 이름을 보인다. 화면은 권리 판정 결과(허용·잠금·등급 표시 이름)만 받는다(등급과 게이트는 `../03_개발범위/20c_Pd_솔루션기획안_요금_패키징_AI과금.md` 와 `lic` 권리 묶음 시드).

### 2.2 점진 공개 규칙

1. 숨김은 메뉴·홈 위젯·뷰 탭의 **기본 노출**만 바꾼다. 데이터·권한·감사·API 는 그대로다. 숨긴 기능의 알림(예: 승인 요청)은 숨기지 않는다.
2. 숨긴 기능은 명령 팔레트·검색으로 항상 열 수 있고, 연 기능은 '이 기능을 메뉴에 두기' 1클릭으로 사용자 표시에 고정한다.
3. 단계 승격 신호(구성원 수 경계 통과, 같은 숨김 기능을 팔레트로 `plt.scale_mode.promote_palette_hits` 회 이상 호출)가 오면 홈 상단에 승격 제안 띠를 보인다. 자동으로 바꾸지 않는다. 승격·강등은 회사 관리자(프로젝트 값은 PM)가 1클릭으로 한다.
4. 강등해도 데이터를 지우지 않는다. 강등으로 숨는 기능에 열린 항목(진행 중 승인 등)이 있으면 강등 화면에 건수를 보이고 그대로 남긴다.
5. 단계 전환은 재시작 없이 즉시 반영한다. 열린 문서 창·탭은 닫지 않는다.

### 2.3 폼팩터와의 관계

- 규모 단계와 UI 모드(MDI·DOCK·NAV)는 서로 다른 축이다. 개인 공간이나 `solo` 단계라도 데스크톱 기본 UI 모드는 MDI 그대로다(05/08 §1-3).
- 스마트폰 NAV 하단 탭은 셸 패널·탭 등록형이고(32 §7), 단계별 기본 구성은 제품 매니페스트의 표시 구성(후보)이 정한다. 개인 공간과 `solo` 단계의 기본 구성(후보)은 오늘·할 일·입력(+)·일정·더보기다. 하단 탭 배분 판정은 06 §2.1(ADR-051)이 갖는다.

### 2.4 개인 공간 화면 규칙 (결정 124, REQ-89)

- 개인 공간에서는 타인 초대 버튼을 숨긴다(`lic.personal.invite_allowed`). 운영 시스템 층에서 허용으로 바꾸면 초대 버튼이 보이고 그 권리 묶음의 초대 상한을 따른다(D-313).
- 공유 링크 수는 `lic.personal.share_links_per_project` 를 따른다. 상한에 닿으면 발급 단추 대신 '기존 링크 보기·회수' 를 보인다. 발급·열람 화면은 `15_외부참여_공유링크_화면설계.md` 가 정본이다.
- 개인 프로젝트 수 한도는 권리 묶음의 한도 `lic.limit.projects`(설정 키가 아니라 `lic` 소유 데이터)다. 한도에 닿으면 새 프로젝트 단추에 잠금 표지와 등급 표시 이름을 보인다.
- 공간 전환기는 셸 상단에 둔다. 개인 계정이 회사 테넌트의 게스트·정식 멤버로 초대받으면 전환기에 그 회사 공간이 더해지고, 고른 공간의 단계로 메뉴가 바뀐다.
- 공간 전환은 테넌트 문맥 교체다. 화면에 두 테넌트의 데이터를 섞지 않는다(오늘 할 일·1줄 입력·제안함·알림 배지 모두 고른 공간 것만). 전환 때 다른 테넌트의 열린 문서 창·탭은 닫고(공간마다 작업공간 배치를 따로 기억해 돌아오면 복원), 알림 배지는 공간별로 따로 센다. 두 테넌트가 다른 서버군에 있으면 전환은 그 테넌트의 서버군으로 다시 접속하는 동작이다(로그인 때 해석 + 클라이언트 기억 + '이동됨' 응답, `../05_아키텍처/06_서버군_리전_라우팅.md` §6.2).
- 숨긴 모듈은 §2.2 점진 공개 규칙대로 명령 팔레트·검색으로 꺼낼 수 있다. 화면에는 '프로젝트 관리' 같은 용어 대신 할 일·일정·노트 이름을 쓴다(표시명은 언어 팩).
- 1인 테넌트 자동 생성·개인 예산·노트 범위·공간 전환의 설계 선행은 TODO-148 이다.

### 2.5 설정 키

선언(값 꼴·기본값·값 분류·허용 층)은 소유 모듈의 10 문서 설정 키 절이 갖는다. 이 표는 키 이름과 뜻만 적는다. 규모 단계·단축키·셸 화면 값은 PLT-09 의 소유 모듈 `plt`(`../10_API설계/plt.md` 설정 키 절), 개인 공간 권리 속성은 `lic`, 붙여넣기 분석은 `imp`, 질문 패널은 `ain` 이다.

| 키 | 뜻 | 쓰는 절 |
|---|---|---|
| `plt.scale_mode.default`·`plt.scale_mode.thresholds` | 회사 공간의 기본 단계, 단계별 구성원 수 경계 | §2.1 |
| `plt.scale_mode.project_threshold` | 대규모 단계로 보는 진행 프로젝트 수 | §2.1 |
| `plt.scale_mode.exposure` | 회사가 바꾸는 단계별 기본 노출 | §2.1 |
| `plt.scale_mode.promote_palette_hits` | 승격 제안을 띄우는 숨김 기능 팔레트 호출 수 | §2.2 |
| `lic.personal.invite_allowed` | 개인 공간의 타인 초대 허용 | §2.4 |
| `lic.personal.share_links_per_project` | 개인 공간 프로젝트당 공유 링크 수 | §2.4 |

## 3. 1줄 입력 (TIM-07·COL-16, UX-05·06)

### 3.1 위치

| 위치 | 데스크톱(MDI)·태블릿(DOCK) | 스마트폰 NAV |
|---|---|---|
| 전역 | 메뉴 줄 가운데 입력칸(`plt.hotkey.key_combo`, 동작 = 전역 1줄 입력) | 하단 가운데 입력(+) 단추 → 아래에서 올라오는 입력 시트 |
| 목록 빠른 추가 | 등록 대상을 가진 목록(할 일·이슈·WBS 등) 맨 위 줄 | 목록 위 '빠르게 추가' 줄 |
| 홈 | 개인 공간·`solo`·`small` 단계 홈 상단 | 오늘 탭 상단 |
| 음성 | 입력칸 오른쪽 마이크(STT 포트 I-48 재사용, UX-06) | 입력 시트 마이크 |

- 전역 단축키가 운영체제·입력기 전환 키와 겹치는지는 미확인(실기 미확인)이다. 회사·사용자가 바꿀 수 있다.

### 3.2 토큰 문법과 빠른 등록 포트

- 1줄 입력은 셸이 정의하는 빠른 등록 포트(`plt.port.quick_add`, 후보)로 대상을 고른다. 포트 규격은 셸이 갖는다. 규격은 토큰 종류, 대상 판정 우선순위, 등록 명령, 미리보기 문구다. 대상을 가진 모듈(예 `tim` 업무일지 줄, `col` 할 일, `iss` 이슈, `sch` 진척)이 모듈 선언서로 구현을 올린다. 셸은 대상 모듈의 이름을 모른다.
- 대상 판정은 선언된 우선순위로 한다. 목록 빠른 추가는 그 목록의 대상으로 만든다. 전역 입력은 토큰이 맞는 대상 가운데 우선순위가 가장 높은 것으로 두고, 아무 대상도 맞지 않으면 기본 대상(선언 우선순위의 맨 앞)으로 둔다. 구현 모듈이 테넌트 허용에 없으면 그 대상은 후보에서 빠지고, 남은 대상이 없으면 1줄 입력은 명령 팔레트로만 동작한다.
- 판정 결과는 입력칸 아래 한 줄 미리보기('할 일로 등록 · #웹개편 · 내일')로 보여 Enter 전에 바꿀 수 있다.
- 기본 토큰 표는 아래와 같다. 토큰 종류는 포트 규격의 값이고 기호·낱말은 언어 팩이 정한다.

| 토큰 | 뜻 | 예 | 쓰는 대상(PMS 구현 예) |
|---|---|---|---|
| 날짜 표현 | 기한·수행일 | `내일`, `금요일`, `11/20`, `다음 주` | 기한(할 일)·수행일(일지) |
| `#이름` | 프로젝트·작업 | `#웹개편`, `#3.2` (WBS 번호) | 연결 대상 |
| `@이름` | 담당·참여자 | `@김PM` | 담당(팀 범위 할 일), 언급 |
| `!상`·`!중`·`!하` | 우선순위 | `!상` | 우선순위·아이젠하워 중요 |
| 숫자+`h`·`시간` | 공수 | `2h`, `1.5시간` | 공수(TIM-01 연결) |
| 숫자+`%` | 진척 | `80%` | 작업 진척 제안 |
| 줄 앞 `/` | 명령 | `/회의`, `/보고` | 명령 팔레트로 넘김(§4) |
| 완료 표현 | 이미 한 일 | `했음`·`완료` 등 언어 팩 사전 | 업무일지 줄 |

- 해석된 토큰은 입력칸 안에서 색 칩으로 강조한다(색만으로 구분하지 않는다, 13 §3 UR-01). 칩을 누르면 해석을 취소하고 평문으로 돌린다(UX-05).
- AI 해석(M3)은 규칙이 못 읽은 자연어를 토큰 후보로 바꿔 칩으로만 보인다. 확정은 Enter 다. AI 실패·한도 도달 때는 규칙 해석만 쓴다(28 §8).
- 프로젝트를 찾지 못하면 등록은 하되 '어느 프로젝트인가요?' 되묻기 제안을 제안함에 올린다(28 §4 되묻기).
- 완료 기준(EZ-02): 입력 1줄 + Enter 1회(+ 판정 변경이 필요하면 1회) = 동작 2회 이하.

### 3.3 일지·하루 흐름 (UX-24, 옵션)

- 업무일지는 하루 등록 줄을 모아 자동 생성된다(28 §4·§5 의 업무일지 생성 종류). 일지 화면은 줄 목록 + 일지 본문 미리보기 + '주간보고 초안 보기' 단추다.
- 아침 계획·저녁 마감 안내 화면은 `plt.daily_ritual.enabled` 로 켠다. 강요하지 않는다.

## 4. 명령 팔레트 (PLT-09, UX-07)

- 여는 키는 `plt.hotkey.key_combo`(동작 = 명령 팔레트)이고 1줄 입력에서 `/` 로 시작해도 열린다. 웹에서 기본 키가 브라우저 주소창 검색 키와 겹칠 수 있어 가로채기 동작을 Chrome 실측으로 확인해야 한다(미확인).
- 빈 입력으로 열면 첫 화면은 즐겨찾기와 최근 항목이고, 결과 순서에는 개인 가중과 이유 표지가 붙는다. 그 규칙·키·개인정보의 정본은 `20_개인화_빠른찾기_설계.md` 다.
- 검색 대상은 동작, 화면(메뉴 전체, 숨김 포함), 최근 항목, 설정 항목이다. 동작은 모듈 선언서가 등록한다(32 §3.1). 셸은 동작 목록을 갖지 않는다. 권한이 없는 동작·항목과 테넌트 허용에 없는 모듈의 동작은 결과에 나오지 않는다.
- 결과 줄 오른쪽에 그 동작의 단축키를 보여 학습시킨다. 숨긴 기능 결과에는 '메뉴에 두기' 단추를 함께 둔다(§2.2-2).
- 한 글자 단축키(UX-08)는 조합 입력 충돌 때문에 넣지 않는다. 다시 볼 조건은 27 §12.3 규칙이 정해지는 것이다.
- 스마트폰 NAV 에는 팔레트가 없고 검색 탭이 같은 검색 대상을 갖는다.

| ① 진입 | (a) 1줄 입력·전역 입력칸에 긴 글을 붙여넣으면 '분석해서 반영할까요?' 띠, (b) 상세 화면의 '붙여넣기 분석' 단추(대상을 가진 모듈이 등록), (c) 명령 팔레트 `붙여넣기 분석` | (a) 의 길이 기준은 `imp.paste.detect_min_lines`·`imp.paste.detect_min_chars` |

| ④ 분석 결과 | 왼쪽 원문(근거 문장 강조), 오른쪽 변경 제안 목록(필드·전 값·후 값·근거 링크) | 제안마다 체크·수정 |

- 원문은 근거 링크로 제안에 붙어 감사 기록에 남는다. 원문 보관 기간은 IMP-09 부록이 정본이다.

## 6. 제안함 (AIN-08, UX-13·22)

### 6.1 배치

| UI 모드 | 위치 |
|---|---|
| MDI(데스크톱·태블릿) | 메뉴 줄 오른쪽 제안함 아이콘(대기 건수 배지) → 오른쪽 패널(알림 서랍과 같은 영역, 탭으로 구분). 전체 목록은 MDI 문서 창 |
| DOCK | 오른쪽 도구 패널 탭 '제안함' |

### 6.2 카드와 동작

- 카드는 공통 꼴이다. 칸은 제안 종류·대상·전 값 → 후 값·근거(원천 링크, AI 근거 문장)·제안 주체(`agent:<종류>` 표기는 '에이전트' 로 표시)·만든 시각·'AI 없이 만든 초안' 표지(강등 때)다. 제안 종류와 대상 종류는 등록형이다. 대상을 가진 모듈이 반영 포트를 구현하며 선언서로 올리고(28 §4), 이 문서는 종류를 열거하지 않는다.
- 단추: 승인(1클릭), 수정 후 승인(카드 안 편집), 거절(사유 선택, 선택 입력). 키보드는 위·아래 이동, Enter 승인, 수정·거절 키는 `plt.hotkey.key_combo`(동작 = 제안 수정·제안 거절)이며 입력칸 포커스 중에는 동작하지 않는다.
- 묶음 승인: 종류·대상으로 묶어 '이 묶음 모두 승인'. 묶음 안 개별 제외 가능.
- 탭: 대기·자동 반영됨·처리됨(승인·거절·만료)·낡음. 자동 반영됨 탭에서 되돌리기 단추(가능 기간 안, 28 §9).
- 낡음(대상 버전 변경): 카드에 '다른 사람이 먼저 바꿨습니다' 와 새로 계산한 제안을 나란히 보인다. 사용자 수정 내용은 새 제안으로 옮긴다.
- 상태 이름·전이는 AIN-08 부록이 정본이다.

## 7. 질의응답 챗봇 패널 (AIN-09, UX-10·11·21)

| UI 모드 | 위치 |
|---|---|
| MDI | 메뉴 줄 '질문' 아이콘 → 오른쪽 패널. 패널을 끌어 독립 창(SDI)으로 뗄 수 있다 |
| DOCK | 오른쪽 도구 패널 탭 '질문' |
| 스마트폰 NAV | 더보기 → 질문, 또는 각 화면 앱 바 '질문' → 전체 화면 대화 |

- 화면 문맥: 지금 열린 화면(대상·뷰·필터)을 질문 문맥으로 쓴다. 패널 위에 문맥 칩('#웹개편 · 간트 · 이번 달')을 보이고 눌러 뺄 수 있다(UX-21). 화면이 줄 문맥의 꼴은 화면을 소유한 모듈이 선언한다.
- 답변마다 출처 목록(제목과 위치)을 단다. 출처 종류는 검색 원천을 가진 모듈이 등록한다(PMS 예 문서·일지·이슈·회의록). 출처를 누르면 원문 위치로 연다. 출처 없는 답은 '근거를 찾지 못했습니다' 로 표시한다.
- 권한: 검색 단계에서 문서 단위 권한 필터를 거친다(끌 수 없음, 고정 예외 보안). 화면에는 '권한 안의 자료만 답합니다' 고정 문구를 둔다.
- 호출 경로: 패널 직접 질문, 댓글·메신저 `@에이전트` 멘션(UX-11), 위키·문서 편집 중 `/질문`(UX-10). 멘션 답은 댓글 스레드에 남고 감사 기록이 붙는다.
- 답에서 바로 변경을 만들지 않는다. 변경이 필요하면 '제안으로 만들기' 단추가 제안함으로 보낸다.
- 사용법 모드(결정 127, REQ-98): 질문 의도를 자동으로 분류해 Pd 사용법·서비스 질문은 매뉴얼·FAQ 를 먼저 찾아 답하고 출처에 매뉴얼 위치를 단다. 패널 위 모드 표시(자동·사용법·프로젝트)는 `ain.chat.mode_badge.visible` 이 정한다.
- 사람 상담 전환: 패널 아래에 '사람과 상담' 단추를 늘 두고, 전환 조건(D-334)을 채우면 전환 안내 카드를 띄운다. 사용자가 확인하면 대화 요약을 붙여 문의로 접수하고 접수 번호와 문의목록(UI-17 S8) 바로가기를 보인다.
- 홈페이지 서비스 문의 챗봇 위젯(REQ-97)은 이 패널 화면 규칙의 축소판이다(화면 문맥·멘션·제안 만들기 없음, 상담 접수·사람 상담 전환만 있음). 정본은 `../05_아키텍처/05_제품구성_시스템메뉴.md` §1.4 다(결정 127).

## 9. 온보딩 (PLT-09, UX-01·03·04)

1. 가입 직후 질문 2~3개(기본 질문 세트, 후보): 혼자 쓰나요/팀인가요(규모 단계 초기값), 어떤 일인가요(업종 팩 추천, '모르겠음' 허용), 지금 가진 자료가 있나요(있음 → ②, 없음 → ③).
2. 자료 투입 첫 프로젝트(DOC-06 확장, UX-01): 파일 끌어놓기·붙여넣기·한 문장 설명 중 하나 → 프로젝트·WBS·일정·담당 초안 미리보기(WBS 트리도 CV-36 들여쓰기 목록) → 고칠 곳 표시 → '이대로 만들기'. 초안은 확정 전까지 저장되지 않는다.
3. 빈 시작: 업종 팩·방법론 템플릿 카드(PRJ-07, UX-02)에서 고르거나 1줄 입력으로 첫 할 일 등록.
4. 빠른 시작 체크리스트(UX-03): 홈에 `plt.onboarding.checklist_max_items` 이하. 항목은 모듈 선언서가 등록하고 기본 구성은 제품 매니페스트의 표시 구성(후보)이 정한다(PMS 예 첫 프로젝트·첫 할 일·첫 일지·팀원 초대·모바일 앱 연결). 숨김 단추로 끌 수 있다.
