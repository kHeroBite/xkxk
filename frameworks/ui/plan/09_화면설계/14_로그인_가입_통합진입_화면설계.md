# 14. 로그인·가입 통합 진입 화면 설계 (SCR-IAM-01 개정, REQ-79, 결정 119)

> 상태 설계 정본(결정 119, ADR-103)
> 근거 D 는 D-268~D-276 이다(상태는 `../90_결정관리/01_결정대기_부록/d268_통합로그인_확인대기.md`). 값은 설정 키의 기본값(후보)이고 선언 자리는 `../10_API설계/iam.md` 의 '설정 키' 절이다(ADR-089). 키가 없는 수치는 후보다.
> 이 문서는 SCR-IAM-01(메뉴 ID 1001)의 화면 배치·상태·흐름 정본이다. 인증 동작(코드 발급·SSO 교환·계정 연결)은 연계 정본 `../05_아키텍처/21l_Pd_연계명세_통합로그인_이메일코드_SSO.md`, 기능 규칙은 `../06_기능목록/21_기능요건상세_부록/a01_IAM.md`(IAM-01·02·03·10)가 정본이다. 부록과 다르면 부록을 먼저 고치고 이 문서를 맞춘다.
> 데스크톱 `03_데스크톱_화면설계.md` 의 SCR-IAM-01 행은 이 문서를 가리킨다.
> SCR-IAM-01 개정에는 새 화면 ID·메뉴 ID 가 없다. 계정 설정의 '로그인 수단 관리'는 결정 129 로 업무 메뉴 새 그룹 '개인 설정' 에 **SCR-IAM-05(메뉴 ID 1088, user)** 로 등재했다(§9, 정본 `02_메뉴구조.md`).
> 용어는 `../05_아키텍처/08_지원_폼팩터_용어.md` 를 따른다. 폼팩터는 데스크톱·태블릿·모바일, UI 방식은 MDI·DOCK·NAV(스마트폰은 스마트폰 NAV)다.
> 참고 이미지는 다른 서비스의 화면이다. 그 서비스의 이름·로고·문구는 쓰지 않고 구조(카드·제목·부제·'계속하기' 버튼 4개·하단 동의 문구)만 참고했다.

## 0. 결론

- **로그인과 가입을 구분하지 않는다.** 첫 화면의 단추는 '계속하기' 하나의 문법이다. 계정이 없으면 만들고 있으면 로그인한다. 사용자는 가입인지 로그인인지 고르지 않는다.
- **단추는 수단별로 4종이 기본이다.** 구글(강조)·이메일·Apple·SSO 순서가 운영 시스템 층의 기본 순서 제안이다. 순서·노출은 회사 층에서 바꾼다(`auth.login_method.enabled`·`auth.login_method.order`, §4).
- **기본 단추 밖의 수단은 등록부가 정한다.** 로그인 수단은 `auth` 소유 등록 데이터이고 국가 팩이 수단을 올릴 때 기본 노출 방식(기본 단추·더 보기 접힘·지역 기준 노출)을 함께 적는다. 수단이 늘어도 이 문서를 고치지 않는다(D-268·D-509, §4.3).
- **이미 로그인한 기기는 패스키 자동 로그인이 먼저다.** 자동 로그인에 비밀번호를 저장하지 않는다(ADR-060, §5).
- **화면은 계정 존재 여부를 드러내지 않는다.** 모든 분기의 응답 모양과 문구가 같다(§6).
- **단계별로 열린다.** 화면은 '사용 가능한 수단만' 그린다. M1~M2 의 '이메일로 계속하기'는 기존 IAM-01(이메일+비밀번호) 경로다(§8).

## 1. 화면 구성 (텍스트 와이어)

데스크톱 전용 창(480×560, 가운데)·웹·태블릿이 같은 카드를 쓰고, 스마트폰은 전체 화면 카드다.

```
┌──────────────────────────────────────────┐
│                 [ Pd 로고 ]                │  ← 로고(테마별 자산)
│                                          │
│          Pd 에 오신 것을 환영합니다           │  ← 제목(가입·로그인 공통)
│        (부제: 한 줄 안내 문구, 후보)          │  ← 부제
│                                          │
│  ┌────────────────────────────────────┐  │
│  │      [G]  구글로 계속하기             │  │  ← 강조(채움) 단추 — 순서의 1순위
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │      [✉]  이메일로 계속하기           │  │  ← 외곽선 단추
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │      [ ]  Apple 로 계속하기          │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │      [▦]  SSO 로 계속하기            │  │
│  └────────────────────────────────────┘  │
│                 더 보기 ▾                  │  ← 등록된 추가 수단(§4.3)
│                                          │
│   가입함으로써 서비스 약관 및 개인정보 처리방침에  │  ← 문구형 동의(§7)
│   동의하는 것으로 봅니다.                    │
└──────────────────────────────────────────┘
```

- 단추 폭은 카드 폭에 맞춘다. 단추 높이·간격은 `01_화면설계_공통원칙.md` 의 컨트롤 기준을 따른다(이 문서는 값을 새로 정하지 않는다).
- 제목·부제·약관 문구는 언어 팩 문자열이다(`../05_아키텍처/27_Pd_다국어_로캘_설계.md`). 약관 문구 원문은 법무 확인(TODO-136) 뒤 정한다.
- 강조(채움) 단추는 1개만 둔다. 어느 수단이 강조인지는 §4 의 첫 번째 단추 규칙이다.

## 2. 상태 9종

한 카드 안에서 내용만 바뀌고 창 크기는 바뀌지 않는다. 뒤로 가기는 모든 상태에서 '초기'로 돌아간다.

| # | 상태 | 보이는 것 | 다음 상태 |
|---|---|---|---|
| S1 | 초기 | §1 의 4단추 + 더 보기 + 동의 문구 | 단추 선택 → S2·S4·외부 제공사 이동 |
| S2 | 이메일 입력 | 이메일 입력칸·'계속' 단추·뒤로 | 제출 → S3(항상) |
| S3 | 코드 입력 | 코드 입력(칸 1개, 자릿수 `auth.email_code.length`)·재발송(`auth.email_code.resend_seconds` 뒤)·뒤로 | 성공 → 로그인 완료·S5 또는 S9 가 필요한 경우 해당 상태. 옵션 허용 시 '비밀번호로 로그인' → S8 |
| S4 | SSO 도메인 입력 | 업무 이메일 입력칸·'계속' 단추·뒤로 | 제출 → S5(항상) |
| S5 | 연결 확인 | 진행 표시·'외부 로그인 화면으로 이동합니다' 안내·취소 | 완료 → 로그인, 실패 → S6 |
| S6 | 오류 | 원인 범주별 고정 문구·다시 시도·다른 방법 | 다시 시도 → S1 |
| S7 | 약관 | 약관·개인정보 처리방침 본문(보기)·재동의(개정 시) | 동의 → 직전 상태 |
| S8 | 비밀번호 입력(옵션 허용 시) | 비밀번호 입력칸·'코드로 로그인' 링크·뒤로 | 성공 → 로그인 완료·S9 가 필요한 경우 S9 |
| S9 | 패스키 등록 권유 | 이 기기에 패스키 등록·'나중에' | 등록·건너뛰기 → 로그인 완료 |

### 2.1 상태별 규칙

- **S2 이메일 입력.** 입력은 소문자·공백 제거·유니코드 정규화 뒤 확인한다. 형식이 틀리면 칸 아래에 한 줄로 알린다. '존재하는 계정인지'는 알리지 않는다.
- **S3 코드 입력.** 입력칸 아래에 '입력한 주소로 코드를 보냈다면 확인해 주세요.' 형태의 중립 문구를 둔다. 주소가 없는 계정이든 있는 계정이든 같은 화면이 뜬다. 시도 초과·만료는 S6 의 같은 문구로 처리한다.
- **S4·S5 SSO.** 도메인이 등록되지 않았거나 SSO 가 꺼진 테넌트이면 S5 로 넘어가되 안내 문구가 같고, 결과 단계(S6)에서 '이 이메일로는 SSO 를 쓸 수 없습니다. 다른 방법을 선택해 주세요.' 형태로만 알린다.
- **S5 연결 확인.** 외부 제공사·IdP 화면으로 이동하는 동안만 보인다. 외부 창이 닫히면 S1 로 돌아간다. 데스크톱 앱은 시스템 기본 브라우저를 쓰고 완료 후 앱으로 돌아온다. 돌아오는 방식은 연계 정본(21i·21l)이 정한다.
- **S6 오류.** 범주는 '일시 장애'·'시간 초과'·'확인할 수 없음'·'권한 없음' 정도로 묶고 문구는 고정한다. 내부 사유(계정 없음·코드 불일치·도메인 미등록)를 구분해 보이지 않는다.
- **S7 약관.** S1 의 문구 속 '서비스 약관'·'개인정보 처리방침' 링크가 연다. 약관이 개정돼 재동의가 필요한 계정은 로그인 직후 S7 이 한 번 끼어든다(D-276).

## 3. 흐름

### 3.1 이메일(M3 이후, 6자리 일회용 코드 기본 + 비밀번호 방식 유지)

초기 → 이메일 입력 → 코드 입력 → 완료. 코드가 기본이다. 비밀번호 방식도 유지하며 신규 가입자도 비밀번호를 설정해 쓸 수 있다(D-269). 이 선택은 설정 키 `auth.password.enabled`(허용 층 운영 시스템·회사)로 끌 수 있다(ADR-089). SSO 강제 테넌트는 비밀번호 경로를 거부한다.

- **비밀번호로 로그인 경로.** 옵션이 허용이면 S3 코드 입력 화면 하단에 '비밀번호로 로그인' 링크를 둔다. 누르면 같은 카드가 비밀번호 입력 상태(S8)로 바뀐다. 입력칸·오류 문구는 S3 과 같은 열거 방지 규칙(§6)을 따르고, '코드로 로그인' 링크로 S3 에 돌아온다.
- **패스키 등록 권유.** 코드나 비밀번호로 로그인한 직후 같은 기기에 패스키가 없으면 '이 기기에 패스키 등록' 권유 상태(S9)가 한 번 끼어든다. 등록하면 다음부터 §5 의 패스키 로그인으로 들어가 비밀번호를 매번 입력하지 않는다. '나중에'로 건너뛸 수 있고 강제하지 않는다.
- 비밀번호는 클라이언트에 저장하지 않는다(ADR-060).

매직 링크는 보조 옵션이고, 링크를 열면 같은 S3 확인 화면에 도착해 확인 단추를 눌러 마친다(스캐너 선소진 방지, 21l 정본).

### 3.2 외부 계정(등록된 제공사)

초기 → 제공사 화면(S5) → 완료. 제공사는 `auth.external_providers` 에 등록된 행이다(21i). 같은 이메일이 이미 있는 계정으로 자동 병합하지 않는다(ADR-072 승계). Apple 이메일(비공개 릴레이 포함)도 연결 후보이며 OTP 소유 증명이 필요하다(D-275, 릴레이 전달은 미확인 — TODO-132). 연결이 필요하면 '연결 확인' 안내(이메일 코드 소유 증명 또는 기존 수단 로그인)를 S3 형식으로 이어서 보인다.

### 3.3 SSO(M4)

초기 → 업무 이메일 입력(S4) → IdP 이동(S5) → 완료. 도메인으로 테넌트를 찾는 방식(Home Realm Discovery)은 21l 정본이다. 화면은 도메인 존재 여부를 노출하지 않는다.

### 3.4 추가 인증(MFA, IAM-02)

로그인 수단과 무관하게 같은 추가 인증 단계가 이어진다(이메일 코드·SSO·외부 계정 뒤에도 같다). 이 단계의 화면은 SCR-IAM-01 안의 같은 카드 상태로 두되 상세는 a01_IAM IAM-02 를 따른다.

### 3.5 서버군(자동 해석)

로그인 화면에는 서버군을 고르는 칸이 없다. 테넌트는 서버군에 배정되고 로그인 때 글로벌 디렉터리가 계정·테넌트의 배정으로 서버군을 해석한다(`../05_아키텍처/06_서버군_리전_라우팅.md` §6.2, ADR-045·REQ-103). 데스크톱·웹·모바일이 같은 규칙이다. 사용자가 서버군을 고르면 '계정 없음'과 구분되지 않는 응답이 생겨 §6 열거 방지와 얽히므로 두지 않는다. 가입 때 서버군을 고르는 것은 '서버군 선택' 기능 게이트가 켜진 테넌트의 업체관리자 가입 화면 한 곳이다(06 §3.2·§5).

### 3.6 게스트 초대 진입(결정 123, REQ-88)

초대 메일 링크 → S1 '계속하기' 와 같은 진입 → 계정이 없으면 이메일 코드(§3.1)로 만들고, 같은 계정에 게스트 멤버십(`kind='guest'` 하나, 예약 게스트와 같은 계정 종류, D-301)이 붙는다. 이미 게스트 계정이 있으면 새 계정을 만들지 않고 권한만 더한다(전환 없음, 감사).

- 로그인 직후 첫 화면에 초대 프로젝트와 종료 조건(종료일 또는 마일스톤)·만료 예정일을 보여 준다. 마일스톤형은 예정일이 바뀌면 표시도 따라 바뀐다(D-302). 만료 전 알림 시점은 `iam.guest.notify_before_days` 다(기본값은 `../10_API설계/iam.md` 설정 키 절).
- 종료 조건에 닿아 권한이 회수된 게스트도 계정은 남는다(권한 0 게스트, D-304). 로그인하면 '참여 중인 프로젝트가 없습니다 — 초대한 사람에게 연장을 요청하세요' 안내를 보인다.
- 만료된 초대 링크는 '초대 기간이 끝났습니다 — 초대한 사람에게 연장을 요청하세요' 고정 문구 하나를 쓴다. 계정 유무는 드러내지 않는다(§6 열거 방지).
- 공개 예약 링크 진입(COL-13)과 예약 이력은 바뀌지 않는다.

## 4. 버튼 노출·순서 옵션 (D-268)

### 4.1 설정 층과 키

수단의 허용과 순서는 설정 키 `auth.login_method.enabled`·`auth.login_method.order`(대상 열 = 로그인 수단 코드)다. 선언·값 분류·기본값은 `../10_API설계/iam.md` 의 '설정 키' 절이 정본이고 해석은 설정 해석 모델 한 벌(`../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §5)을 따른다. 허용 층은 운영 시스템·회사다. 사용자 층에서 단추 순서를 바꾸지 못하는 것은 고정 예외(보안)다. 로그인 화면은 계정을 확인하기 전의 보안 화면이기 때문이다.

| 층 | 정하는 것 |
|---|---|
| 운영 시스템 층 | 수단별 사용 가능 여부(출시 단계), 기본 순서 |
| 회사 층 | 허용할 수단 부분집합, 순서 |

- 강조(채움) 단추는 순서의 첫 단추다. 따로 정하는 값이 없다.
- 회사 도메인을 알기 전의 첫 화면은 운영 시스템 층 값을 그린다. 이메일이나 SSO 도메인을 입력해 회사가 정해진 뒤에는 회사 층 값을 쓴다(21l §1).
- 이 분기는 화면을 고르는 데만 쓴다. 한 계정이 여러 테넌트(개인 모드·게스트·교차 테넌트 포함)에 속하면 허용 수단·SSO 강제·비밀번호 금지는 들어가는 테넌트마다 테넌트 세션을 수립할 때 다시 판정한다(21l §7). 다른 테넌트의 경로로 로그인해도 정책이 엄격한 테넌트에 들어갈 때 그 테넌트의 정책을 통과해야 한다.
- 회사가 허용하지 않은 수단이나 출시 단계가 안 된 수단은 **그리지 않는다**. 비활성 단추로 남기지 않는다.
- 수단의 기본 노출 방식(§4.3)을 회사 층이 바꾸는 키는 아직 없다. 지금은 등록 행의 기본 노출 방식을 그대로 쓴다.

### 4.2 기본 순서

1) 구글(강조) 2) 이메일 3) Apple 4) SSO. 이 순서는 참고 이미지의 구조를 따른 제안(후보)이다. 기본값의 자리는 `auth.login_method.order` 의 키 행이고 나라별 기본 집합은 국가 팩이 제안한다(D-506).

### 4.3 추가 수단의 노출 방식(등록부)

로그인 수단 목록은 `auth` 소유 등록 데이터다. 외부 계정 제공사는 `auth.external_providers` 에 행으로 등록한다(21i, D-509). 국가 팩이 수단을 올릴 때 행마다 수단 종류·제공 팩·기본 노출 방식·기본 순서 값을 적는다. 이 화면은 등록된 행을 읽어 그리므로 수단이 늘어도 이 문서의 절·표·와이어를 고치지 않는다. 등록이 없는 수단은 그리지 않는다.

| 기본 노출 방식 | 동작 |
|---|---|
| 기본 단추 | 순서에 따라 카드의 단추 줄에 그린다 |
| 더 보기 접힘 | 기본 단추 아래 '더 보기 ▾' 를 눌러 펼친다 |
| 지역 기준 노출 | 등록 행이 지정한 언어·지역 설정에서는 기본 단추 줄로 올리고, 그 밖에서는 더 보기 접힘으로 둔다 |

- 사례. 한국 팩은 네이버·카카오를 '지역 기준 노출'로 등록한다(한국어·한국 지역에서는 기본 단추 줄, 그 밖에서는 더 보기, D-268).
- 국가 공통 뼈대 + 국가 팩 구조(결정 113-3)와 같은 방식이다. 지역은 운영체제·브라우저 언어로 추정하고 사용자가 바꿀 수 있다(추정이므로 틀릴 수 있다).

## 5. 패스키 자동 로그인 우선

- 이미 이 기기에서 패스키가 등록된 계정이 있으면 S1 을 그리기 전에 패스키 확인 창을 먼저 띄운다(조건부 자동 요청, WebAuthn). 취소하면 S1 로 간다.
- 비밀번호는 클라이언트에 저장하지 않는다(ADR-060). 코드·비밀번호 로그인 직후(가입 직후 포함) 그 기기에 패스키 등록을 권유하되 강제하지 않는다(S9, IAM-10 승계). 등록한 기기는 다음부터 패스키로 로그인해 비밀번호를 매번 입력하지 않는다(D-269).
- 패스키를 쓸 수 없는 환경(미지원·미등록)이면 이 단계를 건너뛰고 S1 로 간다. 건너뛴 이유는 화면에 보이지 않는다.

### 5.1 앱 잠금(생체 인증, 결정 137)

- 앱 잠금이 켜진 앱은 S1·패스키 확인 창보다 앞에 잠금 카드를 먼저 보인다. 카드에는 '지문으로 잠금 해제' 단추와 '다른 방법으로 로그인'(통합 진입 S1 로 간다)이 있다. 정본은 `../05_아키텍처/47_Pd_생체인증_QR_설계.md` 다(§7).
- 앱 잠금은 기본 켬이다. 첫 로그인을 마치면 켜진 상태로 시작하고(따로 묻지 않음) 사용자가 설정에서 끌 수 있으며, 회사 필수면 끌 수 없다. 보안 화면 잠금이 없는 기기는 꺼진 채 시작하고 화면 잠금 설정 안내를 보인다(D-436·D-474).
- 웹(전 폼팩터)은 앱 잠금이 해당 없다. 브라우저는 생체 장치에 직접 닿지 못하기 때문이다.
- 패스키 로그인 때 지문은 OS 인증자의 사용자 확인일 뿐이다. Pd 는 생체 정보·생체 결과를 받지 않고 서버는 패스키 서명만 믿는다. 비밀번호 저장 금지(ADR-060)는 그대로다.

## 6. 계정 열거 방지 문구 규칙

| 상황 | 규칙 |
|---|---|
| 이메일 제출 | 계정 유무와 상관없이 S3 으로 간다. 응답 문구·지연 시간이 같다. |
| 코드 틀림·만료·시도 초과 | 같은 오류 문구 하나('코드를 확인할 수 없습니다')를 쓴다. |
| SSO 도메인 | 미등록·SSO 꺼짐·비엔터프라이즈 테넌트 모두 같은 안내를 쓴다. |
| 외부 계정 이메일 충돌 | '이미 있는 계정' 이라고 말하지 않고 '다른 방법으로 로그인해 주세요' 계열 고정 문구를 쓴다. |
| 가입 가능 여부 | 입력칸·단추 상태(활성·비활성)로 새어 나가지 않는다. |

- 문구는 언어 팩에 넣는 고정 문자열이고 오류 코드를 사용자 문구에 그대로 쓰지 않는다.
- 요청 속도 제한(IP·이메일·기기)은 서버가 한다. 제한에 걸렸을 때도 문구는 S6 '시간 초과' 범주다.

## 7. 약관·개인정보 처리방침 동의 (D-276)

- 하단 문구형 동의다. '가입함으로써 ... 동의하는 것으로 봅니다' 형태이고 별도 체크박스가 없다(참고 이미지의 구조).
- 가입이 성립하는 시점에 약관·방침 **버전과 시각**을 계정에 기록한다(후보 `iam.terms_consent`).
- 약관·방침이 개정되면 다음 로그인 직후 S7 로 재동의를 받는다.
- 약관 본문 URL·문구는 법무 확인(TODO-136) 뒤 정한다. 이 문서는 문구를 정하지 않는다.

## 8. 출시 단계별 노출 (D-272)

화면은 '사용 가능한 수단만' 그리므로 단계별 출시가 가능하다. 단계를 앞당기지 않는다.

| 단계 | 첫 화면에 보이는 수단 | '이메일로 계속하기'의 동작 |
|---|---|---|
| M1~M2 | 이메일(IAM-01) | **기존 IAM-01 경로** — 이메일+비밀번호 입력(S2 에 비밀번호 칸이 이어짐), 비밀번호 재설정 |
| M3 | 이메일 코드·M3 에 등록된 외부 계정 제공사(IAM-10, 한국 팩 제공사 포함) | **코드 기본**으로 바뀜(S3). 기존 비밀번호 계정은 보조 경로 |
| M3 이후 게이트 | Apple | iOS 심사 게이트 통과 뒤 노출(D-275). 릴레이 주소 연결은 §3.2 와 같다 |
| M4 | SSO(IAM-03) | SSO 단추 노출. 쓸 수 있는 요금제는 `lic` 권리 묶음 시드가 정한다(`../03_개발범위/20c_Pd_솔루션기획안_요금_패키징_AI과금.md`) |

- M1~M2 에서는 S3·S4·S5 가 없고 외부 계정 단추도 없다. S1 에는 이메일 단추 하나만 보이고, 누르면 S2 에 비밀번호 칸이 이어진다(후보).
- 단계 값의 정본은 `../03_개발범위/30a_Pd_WBS_M2_M3_확장.md`·`30b_Pd_WBS_M4_출시뒤X_게이트.md` 다.

## 9. 폼팩터별 배치

| 대상 | 배치 |
|---|---|
| 데스크톱 | **전용 창(모달) 480×560, 가운데.** 크기 변경은 불가(후보). 로그인 전에는 MDI·DOCK 셸이 없다. 서버군 선택 칸은 없다(§3.5). |
| 웹 | 가운데 정렬 카드(최대 폭 480 정도, 후보). 창 크기에 따라 카드는 고정 폭이고 바깥 여백만 변한다. 딥링크로 들어오면 로그인 뒤 원래 주소로 간다(`04_웹_화면설계.md` 참조). |
| 스마트폰(NAV) | 전체 화면 카드, 단추 폭은 화면 폭에 맞춘다. 가상 키보드가 올라오면 입력칸과 '계속' 단추가 가려지지 않도록 스크롤한다. 앱 잠금(생체 인증)은 `../05_아키텍처/47_Pd_생체인증_QR_설계.md` 가 정본이고 모바일 배치는 `06_모바일_화면설계.md` 가 정한다. |
| 태블릿(DOCK) | 가운데 카드(데스크톱 창과 같은 폭). 회전해도 카드 폭은 같다. |

- 로그인 전에는 셸 메뉴·1줄 입력·명령 팔레트가 없다. 셸은 로그인 뒤에 그린다.
- 저해상도·작은 창에서 카드가 넘치면 카드 안에서 세로 스크롤한다(`10_저해상도_소형화면_폼대응.md` 참조).
- **SCR-IAM-05(로그인 수단 관리).** 로그인한 뒤 업무 메뉴 '개인 설정' 그룹에서 연결된 수단 목록·추가·해제·마지막 수단 보호를 보이는 화면이다. 결정 129 로 업무 메뉴 '개인 설정' 그룹에 user 화면으로 등재했다(메뉴 ID 1088, 릴리스 M3 — IAM-10). 열림 모달·스마트폰 ○·그룹 순서는 후보다. 기능 규칙은 IAM-10 ⑦⑧ 승계다. 이 화면 안에 '앱 잠금' 영역(결정 137, M3 부터)을 둔다. M1~M2 는 작업공간 셸 SCR-PLT-01 의 시스템 메뉴 항목이 설정 자리이고, M3 부터 그 항목은 이 영역으로 가는 바로가기로 남는다(D-445).

## 10. 접근성

- **키보드.** 모든 단추는 Tab 으로 닿고 Enter·Space 로 실행한다. 포커스 순서는 단추 위→아래, 더 보기, 약관 링크 순이다. Esc 는 S1 을 뺀 모든 상태(§2 표)에서 '뒤로'다. S1 에서 Esc 는 데스크톱 창 닫기가 아닌 무동작이다(창 닫기는 창 단추).
- **초기 포커스.** S1 은 첫 번째 단추, S2·S4 는 입력칸, S3 은 코드 칸이다.
- **스크린리더.** 단추 이름은 '구글로 계속하기'처럼 동작 전체를 읽는다. 아이콘은 장식이라 숨긴다. 상태 변경(코드 보냄·오류)은 알림 영역(`aria-live` 계열)으로 읽고, 입력칸 오류는 입력칸과 연결한다.
- **코드 입력.** 칸 1개이고 붙여넣기를 받는다. 칸 여러 개로 쪼개지 않는다(스크린리더·자동 완성 호환, 후보). 숫자 키보드를 요청한다.
- **색에만 의존하지 않는다.** 강조 단추는 채움 + 위치로 구분하고 오류는 아이콘 + 문구로 알린다.
- **대비.** 라이트·다크 두 테마에서 텍스트·단추 외곽선 대비는 공통 원칙(`01_화면설계_공통원칙.md`)의 기준을 따른다. 수치를 이 문서에서 새로 정하지 않는다.
- **시간 제한.** 코드 유효 시간(`auth.email_code.ttl_minutes`)이 끝나기 전에 남은 시간을 알린다. 재발송은 `auth.email_code.resend_seconds` 가 지난 뒤 활성화되고 남은 초를 읽어 준다. 두 키의 기본값은 `../10_API설계/iam.md` 설정 키 절에 있다.

## 11. 다국어·테마

- 모든 문자열은 언어 팩이다. 제목·부제·약관 문구는 번역 길이가 달라 카드 높이가 자라도 레이아웃이 깨지지 않게 한다(안 맞으면 카드 안 스크롤).
- 오른쪽에서 왼쪽으로 쓰는 언어(RTL)에서는 아이콘·텍스트 배치가 거울처럼 뒤집힌다. 상세는 27 정본이다.
- 외부 제공사 단추의 문구·아이콘 사용 규정(구글·Apple 브랜드 가이드)은 제공사 문서를 따른다. 그 규정은 미확인이고 확인할 목록은 21l 의 '확인 필요' 항목에 모은다(§13).
- 다크·라이트 테마를 모두 지원한다. 로고·제공사 아이콘은 테마별 자산이다. 시스템 테마를 따르는 것이 기본이다.

## 12. 시험 관점

- 단추 노출: 회사 층 값 조합별 노출·순서·강조 단추가 맞는지, 등록 행을 더하면 문서·코드 수정 없이 그 수단이 노출 방식대로 그려지는지.
- 다중 소속: 정책이 다른 두 테넌트에 속한 계정이 느슨한 테넌트 경로로 로그인한 뒤 엄격한 테넌트에 들어갈 때 그 테넌트의 정책이 다시 판정되는지.
- 열거 방지: 있는 계정·없는 계정·SSO 미등록 도메인 입력에서 화면·문구·응답 시간이 같은지.
- 상태 전이: §2 표의 모든 상태(비밀번호 입력·패스키 등록 권유 포함) 전이와 뒤로 가기·Esc·외부 창 닫기·재발송·시간 초과.
- 폼팩터: 데스크톱 480×560, 웹 창 크기 변경, 스마트폰 키보드 가림, 태블릿 회전.
- 접근성: 키보드만으로 완주, 스크린리더 낭독 순서.
- 단계 게이트: M1~M2 에서는 S3·S4·S5 와 외부 계정 단추가 나오지 않는지.
