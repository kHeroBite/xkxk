# 23. 창 콘텐츠 불러오는 중 표시 설계

> 상태 설계 정본(결정 143, ADR-127) · 요구 REQ-114(원문은 `../00_요구사항/01_사용자요구사항_원문.md` REQ 표가 가리키는 결정 143 절) · D 행 `../90_결정관리/01_결정대기_부록/d569_결정143.md` · 계약·키 이름과 수치는 모두 후보다

> 관련: 화면 공통 규칙 `01_화면설계_공통원칙.md` §2-1(새 화면의 계약 구현 의무), 성능 기준 `../04_기술스택/03_PoC_UI_합격기준_Mars실측.md` §6.4(PERF-14).

## 1. 요구 해석

- 창 안 콘텐츠를 100% 불러오기 전까지 그 창 아이콘을 스피너로 바꿔 보이고, 다 불러오면 원래 아이콘으로 되돌린다.
- 처음 열 때뿐 아니라 창 안에서 검색·새로고침 같은 불러오기가 생길 때마다 같게 동작한다.
- '100% 불러오기 완료'는 화면이 붙은 순간이 아니라 콘텐츠가 첫 데이터를 다 받아 그린 순간이다. 그래서 완료는 콘텐츠가 직접 알린다(§2.2).

## 2. 계약

### 2.1 문서 단위 유일 진입점

- 창 콘텐츠 불러오는 중 상태는 문서마다 하나의 계약(구현 `WindowLoadState`)만 갖는다. 기존 진행 표시(오버레이·커서, 구현 `BusyService`)는 이 계약이 부르는 하위 표시 정책 부품으로 남기고, 문서 스코프를 직접 부르던 곳은 모두 이 계약 경유로 바꾼다. 같은 개념을 두 곳에 두지 않는다(대원칙 13).
- 2단계 시작. 열기 요청 순간(문서 생성 전) `BeginRequest(요청 키, 사유)` 로 토큰을 받고, 문서가 생기면 `Bind(요청 키, 문서)` 로 묶는다. 열기가 실패해 문서가 생기지 않으면 그 토큰은 실패로 끝난다. 이미 있는 문서의 작업은 `Begin(문서, 사유)` 다.
- 토큰은 완료·실패·취소·해제 중 어느 것이든 한 번만 감소시킨다(이중 호출 무시). 겹친 작업은 수를 합산하고, 수가 0보다 크면 불러오는 중이다.
- 실행 묶음 `RunAsync(문서, 사유, 작업, 취소)` 는 완료·실패·취소 모두에서 끝을 낸다(예외는 다시 던진다). 문서 단위는 이것만 쓰고, 기존 진행 표시의 실행 묶음은 메인 범위 전용이다.
- 스레드. 끝내기·상태 변경은 UI 스레드로 넘겨 처리하고, 상태 읽기는 UI 스레드에서만 한다.
- 상태는 불러오는 중(수 > 0), 지연 중(가장 오래된 진행 작업이 `ui.shell.busy_icon.slow_seconds` 를 넘음), 변경 통지 셋이다.
- 닫힘 해제. 문서가 닫히면 토큰을 모두 무효로 하고 수를 0으로 두며 통지한다. 하위 표시 부품의 문서 스코프(오버레이·커서·한 프레임 뒤 예약)도 함께 정리한다. 닫힌 뒤 늦게 끝난 작업은 무시한다.

### 2.2 완료 정의

- 시작은 창 열기 요청 순간이다. 셸 열기 명령이 문서를 만들기 전에 시작하고, 토큰을 문서에 붙여 콘텐츠에 넘긴다.
- 끝은 콘텐츠 뷰모델의 명시 완료다. 콘텐츠는 보고 계약(구현 `IContentLoadReporter`)으로 열기 토큰과 작업 시작 함수를 받고, 첫 데이터 조회가 끝나면 열기 토큰을 완료한다.
- 검색·새로고침은 작업 시작 함수에 사유 `search`·`refresh` 를 넘겨 같은 계약을 쓴다.
- **새 화면은 보고 계약 구현이 필수다**(01 §2-1). 계약을 구현하지 않은 콘텐츠는 뷰가 붙은 순간을 완료로 본다. 이 경우 '100%' 가 아니라 '뷰 표시'까지라는 한계가 있고, PoC 의 간트·폼 샘플이 지금 여기에 해당한다. 그리드 샘플은 계약을 구현한다.

## 3. 표시

- 창 아이콘(22 §2.3 의 모든 자리)은 이 계약의 불러오는 중 상태만 따른다. 기존 진행 표시의 표시 여부와는 무관하다(UI 스레드가 막히면 그쪽 표시가 꺼지는 문제를 피한다).
- 스피너는 아이콘과 같은 글자색이다. 불러오는 중에 창·탭의 활성 상태나 테마가 바뀌면 따라 바뀐다(강조색은 활성 제목줄·선택 탭 바탕과 같아 보이지 않는다).
- `ui.shell.busy_icon.enabled` 를 끄면 스피너로 바꾸지 않는다.
- `ui.shell.busy_icon.show_delay_ms`(기본 0)는 시작 뒤 스피너를 보이기까지의 지연이다. 원문대로 완료 전까지 늘 보이도록 기본은 0이다.
- `ui.shell.busy_icon.min_visible_ms` 는 깜박임 방지 최소 표시 시간이다. 짧게 끝난 작업도 이 시간만큼은 스피너가 남는다.
- 지연. 시간이 오래 걸려도 스피너를 내리지 않는다. 지연 중이면 시계 표지를 덧그리고 툴팁에 '오래 걸리는 중'을 보인다. 원래 아이콘 복귀는 완료·실패·취소·닫힘 때만이다.
- 실패. 원래 아이콘에 오류 표지를 `ui.shell.busy_icon.error_badge_seconds` 동안 덧그린다.
- 접근성 이름은 '불러오는 중'(지연이면 '오래 걸리는 중')이다.

## 4. 회전 수단과 대체 표시

- 회전은 렌더 스레드 컴포지션 시각물(구현 `IconSpinnerVisual`, 기존 간트 스피너와 같은 방식)이다. 보이는 동안만 렌더 스레드 애니메이션이 돈다.
- 열기 경로. 시작 직후 아이콘을 스피너로 바꾸고, 무거운 뷰 생성은 스피너를 먼저 그린 뒤 한 프레임 뒤에 시작한다.
- 근거 수준. '렌더 스레드에서 돈다'는 기존 코드 주석이며, UI 스레드가 막혀도 계속 도는지는 데스크톱·Android 에서 **미검증**이다(웹은 아래 실측). 시험은 진단 인자로 UI 스레드를 막고 0.2초 간격 캡처 3장의 회전각 차이로 판정한다. 막힘 구간에 멈추면 그 한계를 이 절에 사실로 적고 사용자에게 보고하며, 합격 기준을 완화하지 않는다.
- 웹(WASM 단일 스레드)은 UI 스레드가 막힌 동안 회전이 멈추고 마지막 모양이 남는다(2026-11-22 브라우저 230552 판 실측: headless Chromium 소프트웨어 GL, 비활성 창, 막힘 9초 중 5초 이후 화면 갱신 0·모양 93px 유지). 막히기 전에 낸 프레임이 수 초 늦게 올라올 수 있어(관측) 시험은 그 구간을 빼고 판정한다(`window_load_judge.py`).
- 대체 표시.
  - 제목 탭 표시 방식이 `title`(22 §3)이면 아이콘 자리가 없으므로 `ui.shell.busy_icon.title_only`(`inline` 제목 앞 작은 스피너·`underline` 탭 아래 진행 줄·`none`)를 쓴다.
  - 움직임 수준 `reduced`·`off`, 소프트웨어 렌더, 실효 `motion=none`(효과 단계 낮음 포함, 21 §5.2)이면 회전하지 않는 정지 글리프(`PdIconBusyStatic`)를 보인다. 기능 표시라 효과 단계로 끄지 않는다.

## 5. 진단(키 등록부에 넣지 않음)

- 진단 빌드 인자 `--sample-load-delay-ms`(비동기 지연)·`--sample-ui-block-ms`(UI 스레드 차단)와 원격 명령(그리드 검색·창 불러오는 중 상태·자기시험)으로 시험한다. 화면 차이가 없는 진단 스위치라 설정 키가 아니다(01a §3 과 같은 규칙).
- 자기시험은 기존 앱 내장 자기시험 방식(진단 빌드 원격 명령, 응답 JSON 기계 판정)을 확장한다. 케이스는 완료·예외·취소·이중 호출·닫힘 해제·다른 스레드 완료·지연 표시다.

## 6. 한계

- 보고 계약을 구현하지 않은 콘텐츠는 '뷰 표시'까지만 보인다(§2.2).
- UI 스레드 막힘 중 웹은 회전이 멈춘다(§4 실측). 데스크톱·Android 의 회전 지속은 미검증이다.
- OS 독립 창(SDI)의 작업 표시줄 아이콘은 OS 가 그리므로 스피너로 바꾸지 않는다. 독립 창 안 제목줄 아이콘만 바꾼다.

## 7. 시험 케이스

`load_first_open`(열기 요청 → 콘텐츠 완료까지 스피너), `load_search`·`load_refresh`, `load_overlap`(겹친 작업 합산), `load_fail`(오류 표지), `load_cancel`, `load_close_release`(닫힘 해제·늦은 완료 무시), `load_double_call`, `load_other_thread`, `load_slow`(지연 표지·스피너 유지), `load_min_visible`, `load_ui_block_spin`(UI 차단 중 회전각 차이), `load_title_only`(대체 표시), `load_reduced_static`, `load_no_reporter`(뷰 부착 완료 한계).

## 8. 개정 이력

- 2026-11-22. 신설(결정 143).
- 2026-11-22. §3 스피너 색을 아이콘과 같은 글자색으로 명시(강조색이 활성 자리 바탕과 겹쳐 보이지 않던 결함).
- 2026-11-22. §4·§6 웹 UI 스레드 막힘 실측(회전 멈춤) 반영, 미검증 범위를 데스크톱·Android 로 좁힘. 근거 판은 원자료가 남은 230552 판이다(늦은 프레임은 관측으로만 적음).
