## 1. 목적·근거·신뢰도

- 목적: 일정 막대만으로는 답하지 못하는 "왜 이 날짜인가", "무엇이 이 작업을 결정하는가"에 답하도록 차트뷰 계획을 보강한다(사용자 요구 2026-11-05).
- 결론: 새 CV·기능 ID·화면을 더하지 않는다. 뷰·기능·화면의 수는 뷰 등록부(`08_차트뷰_설계_2.md` §2)와 `../06_기능목록/21_Pd_기능요건상세_공통_색인.md` 가 갖는다. CV-01·CV-09·CV-10 의 모드와 일정 근거 패널로 흡수한다(U-CV-12).
- 가장 큰 실익: SCH-02 의 AI 활용 칸은 지연 원인 설명을 약속하지만, 그 입력이 될 결정적 근거(어떤 선행이 날짜를 결정했는가)가 엔진 응답에 없다. 이 빈칸을 ADR-081 로 메운다.
- 자료 성격: python-docx 로 만든 제품 설계 참고서다. 조사 범위 표기는 Project 데스크톱 2016~2024 계열이다. 그림 11장은 새로 그린 개념 재구성이고, 기간·날짜는 예시다. 수치와 그림은 근거로 쓰지 않는다.
- 제품 동작의 근거는 자료가 아니라 Microsoft 공식 문서다(§2.1). 화면과 용어는 복제하지 않고 동작 개념만 참고한다.
- 재결정하지 않는 것: ADR-005, O8, D-51, ADR-047, SCH-07 보기 규칙. 정본 데이터 모델·API·WBS 는 이 문서에서 고치지 않는다(§5·§7).
- 원문 안의 권고문은 자료로만 다룬다.

## 3. 모드 설계 (후보)

### 3.1 CV-01 — 선행 입력과 Task Path 오버레이

- 선행 입력: `<대상>[유형][±<n>d]` 를 쉼표로 잇는다. 유형을 생략하면 FS, 지연을 생략하면 0 이다(MSP-03). 대상은 `wbs_path` 표시 번호를 쓰는 안이 후보다. 정본 `wbs_path` 는 `1.2.3` 형식이라 자료의 정수 ID 와 다르다.
- 파서는 UI·컨트롤 레이어에 두고 API 는 구조 필드(선행·후행·유형·지연일)만 받는다. 없는 대상·자기 참조는 셀 오류로 보이고, 순환은 서버의 409 `sch.dependency_cycle` 을 따른다.
- 체크 목록 선택은 구문 입력의 다른 입구이며 같은 구조 필드로 저장한다(MSP-06).
- 오버레이 모드는 네 가지다. 선행, 일정 결정 선행(Driving), 후행, 영향 후행(Driven)이다. 색만으로 구분하지 않고 범례와 선 모양을 함께 쓴다.
- 오버레이는 저장 데이터를 바꾸지 않는다. 선택이 바뀌면 `ViewContext` 선택만 갱신한다.
- 폼팩터는 08 §3.10 값을 넘지 않는다. 스마트폰은 간트가 △ 이므로 선택 작업의 근거 목록만 조회하는 안이 후보다.
- **끌어서 선행 연결(M1, 사용자 요구 2026-11-05):** 사용자 원문은 "네트워크 다이어그램 처럼 간트에서도 작업을 끌어 선행관계 연결편집이 가능해야한다" 이다. 선행 구문 입력·체크 목록과 같은 입구의 하나로 간트 막대를 끌어 의존을 만든다. 규칙 8개(연결 만들기, 유형·lag 수정, 순환·무효 거부, 권한, 실행 취소, 일정 반영, 태블릿·터치, 범위)는 [`08a`](08a_차트뷰_카탈로그_일정_자원.md) CV-01 카드가 정본이며 여기서 반복하지 않는다.
  - 설정 키: 관계 유형 기본값·터치 길게 누르기 진입·저장 전 `dryRun` 미리보기는 키 `sch.gantt.link.default_type`·`sch.gantt.link.touch_long_press`·`sch.gantt.link.dry_run_preview` 이고 회사 기본값 + 사용자 재정의다(D-119·D-132). 선언과 기본값은 10 `sch.md` 설정 키 절이다. 서버 판정·순환 거부·권한 검사는 데이터 무결성·보안 고정 예외라 옵션이 아니다(ADR-089).
  - 저장 대상은 같다. 끌기·구문·체크 목록 모두 구조 필드(선행·후행·유형·지연일)만 API 로 보낸다(MSP-02·06 과 같은 원칙).
  - 연결 직후의 근거 패널과 Task Path 오버레이는 새 연결을 바로 반영한다. 근거 값은 엔진 응답만 쓴다(§4).
  - 요약 작업 대상은 거부한다(D-84). 오류 코드는 10 `sch.md` 의 의존 경로에 둔다(§5).
  - 추정 인일은 근거가 없어 산정하지 않는다(§7 묶음 G).

### 3.2 CV-09 — 전체 모드와 국소 모드

- 전체 모드는 계획 전체 그래프다. 검색·범위 필터·단계별 접기·자동 배치를 쓴다(MSP-13).
- 국소 모드는 선택 작업에서 키 `sch.network.local_hop_max` 의 홉 수까지만 보인다. CV-01 하단 분할 또는 CV-09 안의 모드로 열며 화면은 `SCR-SCH-01` 그대로다. 새 CV 가 아니다.
- 노드 상세는 담당(작업 본체 모듈의 요약 조회), 진척(`progress_pct`), 의존 유형·지연일, 일정 근거를 보인다. 의존 이유 열은 §5 다.
- 일정 영향은 `reschedule` 의 `dryRun` 으로 본다. 비용 영향은 MSP-31 결정 전에는 표시하지 않는다.
- 네트워크 화면의 편집은 M4 다(U-CV-16, D-82). M1 은 CV-01 간트에서 의존을 편집하며 막대 끌어서 연결을 포함한다(§3.1). 사용자 요구는 "네트워크 다이어그램 처럼" 간트에서 끌어 연결하는 것이므로 그 동작은 간트에서 M1 이고, 네트워크 화면 자체의 편집 시점만 M4 다.
- 자동 배치 후보는 MSAGL 이다(MIT, `ref/analysis/automatic-graph-layout.md`). 채택이 아니며 웹 WASM 동작과 성능은 미확인이다.

### 3.3 CV-10 — 산식 후보

- 현행 산식은 '총여유 0 인 작업의 연결 경로'다. FNLT 가 이미 M1 에 있어 총여유가 음수가 될 수 있고, 그러면 0 만 보는 산식이 놓칠 수 있다(추정, 확인 필요).
- 후보 산식은 '총여유 ≤ 임계 인 작업의 연결 경로'다. 임계는 카드의 여유 임계 필터이고 기본값은 키 `sch.critical_path.float_threshold_days` 다.
- 경로가 여럿이면 모두 보이고 경로별로 구분한다(MSP-23).
- 마감일 열을 도입하면 총여유 계산도 함께 정해야 한다. 공식 문서는 Deadline 이 Total Slack 계산에 영향을 줄 수 있다고만 적어 방식은 미확인이다. Pd 규칙은 M4 설계 때 정한다(U-CV-14).
- 회귀 기준: 제약 없는 계획에서 AC-SCH-03-1(5일·8일 경로) 결과가 그대로여야 한다. 수용 기준은 바꾸지 않는다.

### 3.4 일정 근거 패널

CV-01 의 오른쪽 패널이다(배치는 후보). 새 화면이 아니며 "왜 이 날짜인가"에 답한다. 요인은 공식 문서의 8종을 기준으로 정본에 대응시켰다. 화면은 요인 값을 모두 `sch` 엔진 응답(§4)으로 받고 다른 모듈을 직접 부르지 않는다. 다른 모듈이 원천인 요인은 `sch` 가 포트로 읽어 응답에 싣는다.

| 공식 요인 | 정본 대응 | 원천 모듈·계약 | 원천이 테넌트 허용에 없을 때 | 단계 |
|---|---|---|---|---|
| 실제 시작 | `actual_start` | `sch` | 해당 없음 | M1 |
| 평준화 지연 | SCH-09(제안만, 자동 적용 없음) | `sch` | 해당 없음 | M4 |
| 제약 | `constraint_type`·`constraint_date` | `sch` | 해당 없음 | M1 |
| 요약 작업 | `is_summary`, 요약 날짜는 하위에서 계산 | `sch` | 해당 없음 | M1 |
| 선행 | `task_dependency` | `sch` | 해당 없음 | M1 |
| 하위 작업 | 작업 본체 계층 | 작업 본체 모듈(지금 `iss`, 이전 예정 → `task`, D-538)의 작업 요약 조회 | 작업 본체가 없으면 `sch` 도 작업을 갖지 않으므로 해당 없음 | M1 |
| 달력 | 근무 달력·예외일 | 근무 달력 모듈 `wcal`(D-489) — `sch` 가 포트 `sch.port.work_calendar` 로 읽는다 | 달력일 기준으로 계산하고 패널에 '근무 달력 없음(달력일 기준)'을 보인다(키 `sch.calendar.fallback_workweek`) | M1 |
| 수동·자동 | `plan.scheduling`·`schedule_mode` | `sch` | 해당 없음 | M1 |

패널의 근거 값은 §4 엔진 응답만 쓰고 클라이언트가 다시 추론하지 않는다. AI 설명은 이 값을 입력으로 삼으며 날짜 확정은 사람이 한다(MSP-19). 근거·일정 결정 선행의 단계는 D-189 를 따른다.

## 4. 엔진 응답 (ADR-081)

- 전진 계산 중 작업마다 날짜를 결정한 요인을 함께 기록한다. 결과는 결정적이며 AI 가 개입하지 않는다.
- 후행 날짜를 묶는 값이 가장 늦은 의존이 일정 결정 선행(Driving)이다. FS·SS 는 시작을, FF·SF 는 종료를 묶으므로 어느 쪽을 묶었는지 함께 기록한다.
- 동률이면 모두 일정 결정 선행이다. 제약이나 실제 시작이 더 늦게 묶으면 일정 결정 선행이 없을 수 있고, 그때는 그 요인을 근거로 돌려준다.
- 수동 작업은 전파 대상이 아니므로 `schedule_mode=manual` 요인만 돌려준다.
- 영향 후행(Driven)은 같은 기록의 역방향이다.
- 응답 필드(요인 종류·묶은 쪽·일정 결정 선행 표지 등)와 근거 조회 경로의 정본은 10 `sch.md` 다. 이 문서는 화면이 그 응답으로 무엇을 그리는지만 적는다. 요인 종류는 위 §3.4 표의 여덟이다.
- 단계: 근거·일정 결정 선행과 총여유·주공정 경로는 D-189, ALAP 는 M4 다(U-CV-13·14).
- 보완할 점: 요인 기록이 엔진 비용을 얼마나 늘리는지 측정하지 않았다(추정 불가). 응답 크기를 줄이려 요청할 때만 돌려주는 안을 §5 에 둔다.

## 6. 일정 의존 대 착수 허가 (ADR-080)

새 의존 유형을 만들지 않는다. O8·ADR-005 는 건드리지 않는다.

| 구분 | 일정 의존 | 착수 허가 |
|---|---|---|
| 뜻 | 일정 계산 조건 | 실제 업무를 시작해도 되는지의 조건 |
| 정본 | `sch.task_dependency` | ISS-07 전이 조건 `{permission, requiredFields[], approvalRequired}` |
| 승인 | 관여하지 않는다 | M1 은 승인 대기 상태로만 이동, 결재선은 M2(APR-03) |
| 산출물 제출·검증 조건 | 관여하지 않는다 | 현재 전이 조건에 없다. 필요하면 별도 결정 후보다 |
| OR 조건 | 없다 | 정본에 표현이 없어 미정이다 |
| 간트 표시 | 막대·연결선 | 착수 차단 표지를 읽기 전용으로 겹친다(후보). 일정 계산에는 넣지 않는다 |

- 착수 차단 표지는 간트 화면의 화면 확장 자리다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7 5번). 자리의 소유는 `sch` 화면 모듈, 기여는 전이 조건을 가진 작업 본체 모듈(지금 `iss`, ISS-07)과 결재선 모듈 `apr`(APR-03)이다. 기여 모듈이 테넌트 허용에 없으면 그 표지만 숨긴다. 자리 목록의 정본은 50 §3.2 화면 조립 표다.
- 예: Lead 는 선행과 일정을 겹치는 값이다. 선행 진행률이 실제로 그 값이 됐는지 평가하지 않는다(MSP-11).
- 자동화가 일정 가능만 보고 착수시키면 잘못된 착수가 생길 수 있으므로 전이는 ISS-07 조건을 그대로 검사한다.

## 8. 사용자 결정 U-CV-12~18 (2026-11-05)

| ID | 질문 번호 | 질문 | 결정 |
|---|---|---|---|
| U-CV-12 | D-78 | 의존·일정 분석을 새 뷰·ID 없이 CV-01·09·10 모드로 흡수할까? | 기존 뷰 모드로 흡수(CV-01·09·10, 새 CV·ID 없음) |
| U-CV-13 | D-79 | 일정 근거 패널·Driving 표시 시점은 언제인가? | 전진분 M1, 후진분(총여유·주공정 경로·ALAP) R2 |
| U-CV-14 | D-80 | 제약 4종 추가·마감일 열 시점은 언제인가? | 마감일만 M1, 나머지 제약 R2(권고와 다름). 마감일 열은 M1 데이터 모델 추가이고 총여유 규칙은 R2 |
| U-CV-15 | D-81 | 일정 의존과 착수 허가를 분리할까(ADR-080)? | 분리, 새 의존 유형 없음 |

| U-CV-17 | D-83 | 작업 단위 지연→손익 시뮬레이션 범위는 어디까지인가? | PRJ-11 확장 후보, 앞당기지 않음 |
| U-CV-18 | D-84 | 음수 lag·퍼센트 lag·요약 작업 의존을 어떻게 할까? | 음수 허용, 퍼센트 보류, 요약 의존 M1 금지 |

- 현행 단계(D-189): 결정 111 Q-YT-04 가 SCH-03 전체(작업 종속성·중요경로, CPM 계산)를 M2 로 당겼다(`../06_기능목록/21_기능요건상세_부록/a08_SCH.md` SCH-03 릴리스 줄). 그래서 ① SCH-03 계산(전진·후진·총여유·중요경로)은 M2 다. ② CV-10 크리티컬 패스 오버레이와 일정 근거 패널 후진분도 M2 다. ③ CV-09 네트워크 화면 편집은 D-82 대로 M4 다. ④ ALAP·제약 4종·마감일의 총여유 영향 규칙(U-CV-14)은 M4 다.
- 결정 기록: ADR-080 일정 의존과 착수 허가 분리, ADR-081 일정 근거 데이터(Driving·요인)를 엔진 결과에 포함한다. 본문은 `../90_결정관리/02_결정기록_부록/b10_ADR-080_081.md` 에 있다.
- 요구: REQ-59(부모 REQ-58).
