## 1. 진척 계열 (CV-14~CV-17)

### CV-14 번다운·번업
- 목적: 스프린트 남은 양이 계획선을 따라가는지 보고 범위 변경을 구분한다.
- 사용자: PM·스크럼 팀.
- 관리 동작: 스프린트 선택, 번다운↔번업 전환, 범위 변경 표시 켜기(필수 표시), 이슈 목록 이동.
- 분석 지표(산식): 남은 양_t=약속량+추가량−완료량_t. 정본 ISS-10 수용 기준 사례 20+3−5=18. 닫힌 스프린트는 캐시.
- 필요 데이터: `iss` — `GET /api/v1/iss/sprints/{sprintId}/burndown`, `GET /api/v1/iss/boards/{boardId}/burnup`.
- 권한: 조회 `iss.issue.read`@project.
- 기능 영역: ISS(ISS-10).
- 화면 ID: SCR-ISS-03.
- 우선순위: 필수(정본이 보고서보다 앞섬).
- AI 활용: 보조 — 이상 추세(범위 급증 등)의 설명 요약만 제안한다. 사람 확인: 스크럼 마스터가 원 수치와 대조 후 회고에 사용.

### CV-15 누적흐름도(CFD)
- 목적: 날짜별 상태 범주 누적 면적으로 병목을 찾는다.
- 사용자: PM·스크럼 팀.
- 관리 동작: 기간·보드 선택, 상태 범주 표시 선택, 면적→이슈 목록 드릴다운.
- 분석 지표(산식): 날짜×상태 범주별 누적 건수. 병목=특정 상태 범주 폭이 기간에 걸쳐 증가.
- 필요 데이터: `iss` — `GET /api/v1/iss/boards/{boardId}/cumulative-flow`(이슈 이력으로 조회 때 계산). 대시보드 위젯으로 볼 때는 `rpt` 프로젝션(원천 `iss` 가 지표 원천 포트 `rpt.port.metric_source` 로 등록하는 일별 이슈 집계)을 쓴다.
- 권한: 조회 `iss.issue.read`@project.
- 기능 영역: ISS(ISS-10), DSH.
- 화면 ID: SCR-ISS-03.
- 우선순위: 높음.
- AI 활용: 해당 없음 — 결정적 집계 유형: 일별 누적 건수 집계이며 AI 입력이 없다.

### CV-16 속도(Velocity)
- 목적: 최근 스프린트의 약속 대비 완료로 팀 처리량을 가늠한다.
- 사용자: PM·스크럼 팀.
- 관리 동작: 최근 N 스프린트 범위 조정(N 의 기본값은 키 `iss.velocity.window_sprints`), 막대→스프린트 리포트 이동.
- 분석 지표(산식): 완료율=완료 포인트÷약속 포인트, 이동 평균=최근 N 개 완료 포인트 평균.
- 필요 데이터: `iss` — `GET /api/v1/iss/boards/{boardId}/velocity`(약속·완료 포인트), `GET /api/v1/iss/sprints/{sprintId}/report`.
- 권한: 조회 `iss.issue.read`@project.
- 기능 영역: ISS(ISS-10).
- 화면 ID: SCR-ISS-03.
- 우선순위: 높음.
- AI 활용: 해당 없음 — 결정적 집계 유형: 포인트 합과 평균이며 AI 판단이 없다.

### CV-17 S-Curve
- 목적: 누적 계획 대비 누적 실적을 곡선으로 비교해 진행 편차를 본다.
- 사용자: PM·PMO.
- 관리 동작: 단위 전환(진행률·공수·원가), 기준선 비교선 켜기, 기간 선택.
- 분석 지표(산식): 편차=누적 실적−누적 계획. SPI(t)=EV÷PV 연동은 CV-21. 현재 계획 기준으로 시작하고 기준선 비교는 SCH-04 와 함께 연다(U-CV-4, D-70).
- 필요 데이터: 누적 시계열은 `rpt` 프로젝션(원천 `sch`·`tim`·`fin` 이 지표 원천 포트 `rpt.port.metric_source` 로 등록, 읽기는 `GET /api/v1/rpt/metrics`). 원본은 `sch` — `GET /api/v1/sch/plans/{planId}/tasks`, `tim` — `GET /api/v1/tim/entries`, `fin` — `GET /api/v1/fin/projects/{projectId}/cost-actuals`. `fin` 이 테넌트 허용에 없으면 원가 단위를 숨긴다.
- 권한: 조회 `rpt.metric.read`@tenant 와 원천 권한(`sch.plan.read`@project·`tim.entry.read`@project). 원가 단위는 `fin.cost.read`@project 가 있어야 보인다.
- 기능 영역: SCH(SCH-04), TIM(TIM-01), FIN.
- 화면 ID: SCR-DSH-04.
- 우선순위: 필수. 기준선 비교는 SCH-04 의 단계를 따른다.
- AI 활용: 보조 — 편차 원인 후보의 설명 초안만 제안한다. 사람 확인: PM 이 일정·공수 원자료와 대조 후 보고에 사용.

## 2. 원가 계열 (CV-18~CV-22)

### CV-18 예산 대비 실적
- 목적: 프로젝트 예산과 실적 원가의 차이와 소진 속도를 본다.
- 사용자: PM·재무 담당·PMO.
- 관리 동작: 읽기 중심, 기간·원가 분류 필터, 막대→원가 명세 이동.
- 분석 지표(산식): 차이=예산−실적원가, 소진율=실적원가÷예산. 진행 중 프로젝트는 EAC·진척과 함께 해석(보고서 §3.3 제안).
- 필요 데이터: `fin` — `GET /api/v1/fin/projects/{projectId}/budgets`(확정 예산 판), `GET /api/v1/fin/projects/{projectId}/cost-actuals`(월·구분별 실적 원가).
- 권한: 예산 `fin.budget.read`@project, 원가 `fin.cost.read`@project. 원가 권한이 없으면 원가 열을 뺀다.
- 기능 영역: FIN(FIN-01·FIN-02).
- 화면 ID: SCR-FIN-01.
- 우선순위: 필수.
- AI 활용: 해당 없음 — 결정적 계산 유형: 차이와 소진율은 사칙연산이다.

### CV-19 수익성·ROI 추이
- 목적: 기간별 영업이익률과 ROI 추이를 본다.
- 사용자: 경영진·재무 담당·PMO.
- 관리 동작: 기간·프로젝트·부서 필터, 지표 선택. 두 지표는 별도 계열로 표시한다.
- 분석 지표(산식): 영업이익률=(매출−원가)÷매출, ROI=(투자수익−투자비용)÷투자비용. 정의는 FIN-05 표준 지표 계층으로 단일화한다(ADR-078, U-CV-5·D-71).
- 필요 데이터: `fin` — `GET /api/v1/fin/projects/{projectId}/profit`(월별 매출·원가·이익률·ROI), 부서 집계는 `GET /api/v1/fin/profit/summary`. 표준 지표는 `fin` 이 지표 원천 포트 `rpt.port.metric_source` 로 등록하고 `rpt` 지표 조회(`GET /api/v1/rpt/metrics`)로 읽는다.
- 권한: 조회 `fin.profit.read`@project(부서 집계는 @dept). 권한이 없으면 숨긴다.
- 기능 영역: FIN(FIN-03·FIN-05).
- 화면 ID: SCR-FIN-02.
- 우선순위: 높음.
- AI 활용: 해당 없음 — 결정적 계산 유형: 비율 산식이며 정의를 FIN-05 에서 고정한다.

### CV-20 손익 Waterfall
- 목적: 계약 매출에서 비용 항목을 차감해 공헌이익에 이르는 과정을 본다.
- 사용자: 재무 담당·경영진·PM.
- 관리 동작: 프로젝트·기간 선택, 항목 접기·펼치기.
- 분석 지표(산식): 공헌이익=계약매출−(인건비+외주비+인프라비+기타 직접비). 항목 정의는 FIN-02 원가 분류를 따른다.
- 필요 데이터: `fin` — `GET /api/v1/fin/projects/{projectId}/profit`(매출), `GET /api/v1/fin/projects/{projectId}/cost-actuals`(원가 구분별 합계).
- 권한: 조회 `fin.profit.read`@project·`fin.cost.read`@project.
- 기능 영역: FIN(FIN-02·FIN-03).
- 화면 ID: SCR-FIN-02.
- 우선순위: 높음.
- AI 활용: 해당 없음 — 결정적 계산 유형: 항목 합산·차감이며 판단 요소가 없다.

### CV-21 EVM
- 목적: 계획 가치·획득 가치·실제 원가로 일정·원가 성과와 완료 시점 전망을 본다.
- 사용자: PM·PMO·재무 담당.
- 관리 동작: 주 단위 스냅샷 시점 선택, 기준선 선택, 지표 임계 강조(임계 값은 키 `fin.evm.alert_thresholds`, 회사 기본값에 하위 범위(프로젝트)가 덮어쓴다).
- 분석 지표(산식): CPI=EV÷AC, SPI=EV÷PV, EAC·ETC 는 FIN-04 정의를 따른다. 일정 기준선이 있어야 그린다.
- 필요 데이터: `fin` — `GET /api/v1/fin/projects/{projectId}/evm`(주별 PV·EV·AC·EAC·ETC·SPI·CPI, 기준선 ID 를 받는다). 기준선 목록은 `sch` — `GET /api/v1/sch/plans/{planId}/baselines`.
- 권한: 조회 `fin.evm.read`@project, 기준선 목록 `sch.plan.read`@project.
- 기능 영역: FIN(FIN-04), SCH(SCH-04).
- 화면 ID: SCR-FIN-02.
- 우선순위: 필수(D-69).
- AI 활용: 보조 — 지표 악화 원인 후보의 설명 초안만 제안한다. 사람 확인: PM·재무가 스냅샷 원자료와 대조 후 보고.

### CV-22 Cash Flow
- 목적: 월별 예상 유입·유출과 누적 순현금, 미수 연령을 본다.
- 사용자: 재무 담당·경영진.
- 관리 동작: 월·기간 선택, 유입(청구·수금 일정)·유출(경비·인건비) 계열 전환, 미수 건 드릴다운.
- 분석 지표(산식): 월 순현금=유입−유출, 누적 순현금=월 순현금 누적합, 미수 연령 구간은 키 `fin.receivable.age_bucket_days` 를 따른다.
- 필요 데이터: `fin` — `GET /api/v1/fin/contracts/{contractId}/billing-schedules`(청구 일정), `GET /api/v1/fin/receivables`(미수 목록), 경비는 `GET /api/v1/fin/projects/{projectId}/expenses`. 월별 유입·유출 합계 계약은 없다 — `fin` 이 지표 원천 포트로 현금 흐름 지표를 등록할지 착수 전에 정한다.
- 권한: 조회 `fin.billing.read`·`fin.payment.read`(범위는 10 `fin.md`).
- 기능 영역: FIN(FIN-08·FIN-09).
- 화면 ID: SCR-FIN-04.
- 우선순위: 높음. 데이터(FIN-08·09)와 차트의 단계는 다르다(뷰 등록부).
- AI 활용: 해당 없음 — 결정적 집계 유형: 청구·수금 일정의 월별 합산이다.

## 3. 경영 계열 (CV-23~CV-26)

### CV-23 포트폴리오 버블
- 목적: 프로젝트 포트폴리오를 매출·이익률·투입공수·위험도로 한 장에서 비교한다.
- 사용자: 경영진·PMO.
- 관리 동작: 부서·PM·범주·기간 필터, 버블→프로젝트 상세 드릴다운(상세→간트→이슈 이동, ViewContext 유지).
- 분석 지표(산식): x=매출, y=이익률(CV-19 정의), 크기=투입공수, 색=위험도(CV-24 점수 구간).
- 필요 데이터: 포트폴리오 표는 `rpt` 프로젝션(원천 `prj`·`fin`·`iss`·`tim` 이 지표 원천 포트 `rpt.port.metric_source` 로 등록하는 프로젝트 상태·손익·위험·공수 지표). 포트폴리오 조회 경로는 계약 없음 — DSH-02 설계 때 10 `rpt.md` 에 둔다. 손익 값의 원본은 `fin.q.project_metric` 이다. `fin` 이 테넌트 허용에 없으면 손익 축을 고를 수 없다.
- 권한: 조회 `rpt.metric.read`@tenant 와 원천 권한. 손익 열은 `fin.profit.read` 가 없으면 필드 인가로 뺀다(DSH-02 수용 기준). 기능 게이트는 `lic` 권리 묶음이 정한다.
- 기능 영역: DSH(DSH-02), PRJ(PRJ-04), FIN.
- 화면 ID: SCR-DSH-02.
- 우선순위: 높음.
- AI 활용: 보조 — 이상치 버블의 설명 요약만 제안한다. 사람 확인: PMO 가 원 수치로 확인 후 경영 보고에 사용.

### CV-24 리스크 매트릭스
- 목적: 리스크를 확률×영향 격자에서 본다.
- 사용자: PM·PMO.
- 관리 동작: 칸 선택→이슈 목록, 프로젝트 범위 전환, 점수 임계 강조.
- 분석 지표(산식): 점수 계산 방식은 키 `iss.risk.score_method`(기본값 확률 순위 × 영향 순위)다. 격자 칸 수는 확률·영향 코드 묶음의 값 수로 정해진다(10 `iss.md` 리스크 경로). 강조 임계는 키 `iss.risk.highlight_score` 다. 칸별 건수·이슈 키.
- 필요 데이터: `iss` — `GET /api/v1/iss/spaces/{spaceId}/risk-matrix`, `GET /api/v1/iss/spaces/{spaceId}/risks`.
- 권한: 조회 `iss.issue.read`@project.
- 기능 영역: ISS(ISS-02).
- 화면 ID: SCR-ISS-04.
- 우선순위: 높음(이미 정본).
- AI 활용: 해당 없음 — 결정적 계산 유형: 점수는 입력된 확률·영향의 곱이다.

### CV-25 AI 예측 타임라인
- 목적: 완료 예상일·지연 가능성·추가 비용 예측을 근거와 함께 본다.
- 사용자: PM·PMO·경영진.
- 관리 동작: 예측 기준 시점 선택, 근거 항목 펼치기, 예측 승인·반려 기록(사람 확정).
- 분석 지표(산식): 예측값과 신뢰구간 표시 의무. 결정적 통계 모형(진척 추세·EVM 지수 기반)과 LLM 예측 모형을 둘 다 구현하고 회사가 키 `ain.forecast.method` 로 고른다(기본값 통계, D-73·D-215). 두 모형은 교체 가능한 포트 뒤에 둔다. LLM 예측을 고르면 AI 사용량 과금(결정 88·94 산식) 대상이라 선택 화면에 비용 발생 안내를 띄운다. 근거는 ADR-078(지표는 결정적 로직)·ADR-073(사람 확인)·REQ-39(외부 전송 정책)이다.
- 필요 데이터: `ain` — `POST /api/v1/ain/forecasts`(실행), `GET /api/v1/ain/forecasts/{runId}`(예측값·신뢰구간·근거·방식 표시), `POST /api/v1/ain/forecasts/{runId}/decision`(승인·반려), 방식 설정 조회 `GET /api/v1/ain/forecast-settings`.
- 권한: 조회 `ain.forecast.read`, 실행 `ain.forecast.run`, 승인·반려 `ain.forecast.approve`(범위는 예측 대상의 범위 종류).
- 기능 영역: AIN(AIN-02·AIN-03), AIP.
- 화면 ID: SCR-AIN-01.
- 우선순위: 차별화. 원인 설명·조치 제안(AIN-03)은 그 기능의 단계를 따른다.
- AI 활용: 보조 — 완료일·지연 가능성·추가 비용을 예측하고 근거·신뢰구간을 함께 표시하며 외부 전송은 REQ-39 정책을 따른다. 사람 확인: PM 이 근거를 검토해 승인해야 일정·보고에 반영하고 효과 수치는 주장하지 않는다.

### CV-27 대시보드 위젯 허브
- 목적: 위 차트들을 대시보드 격자의 위젯으로 모아 보는 단일 진입점이다.
- 사용자: 전 역할(역할별 기본 대시보드).
- 관리 동작: 위젯 추가·이동·크기 조정(격자 열 수는 키 `rpt.dashboard.grid_columns`), 위젯 설정 저장, 역할별 기본 배치 편집.
- 분석 지표(산식): 위젯별 지표는 각 카드의 산식을 따른다. 위젯 갱신 최소 간격은 키 `rpt.widget.refresh_min_seconds` 다. 위젯은 `rpt` 프로젝션과 지표만 읽는다(원천 모듈이 지표 원천 포트 `rpt.port.metric_source` 로 채운다, DSH-01 규칙·D-504). 위젯 목록은 원천 모듈이 등록하는 등록형이다.
- 필요 데이터: `rpt` — `GET /api/v1/rpt/widgets`, `GET /api/v1/rpt/widgets/{widgetId}/data`, `GET /api/v1/rpt/dashboards/home`, `PUT /api/v1/rpt/dashboards/{dashboardId}/layout`.
- 권한: 본인 대시보드 `rpt.dashboard.read`·`rpt.dashboard.write`@self, 역할 기본 대시보드 `rpt.dashboard.admin`@tenant. 위젯 데이터는 각 원천 권한을 다시 거른다.
- 기능 영역: DSH(DSH-01).
- 화면 ID: SCR-DSH-01.
- 우선순위: 필수.
- AI 활용: 해당 없음 — 결정적 배치 유형: 위젯 배치와 표시이며 판단 로직이 없다.

## 5. 추적 단위 승격 (사용자 결정 2026-11-05, U-CV-6 재검토)
- 결정 요지: 새 기능 ID(SCH-10 등)는 만들지 않는다(기존 ID 확장 유지, SCH-10 불채택). 대신 모든 CV 카드를 WBS·시험·권한의 추적 단위로 승격한다. 카드 문서 넷(08a·08c·08e·08f)의 카드가 모두 대상이다(영업 카드는 D-101·D-102). 근거는 사용자 지시(2026-11-05) "어떤방식이 더 원칙에 가깝고, 앞으로 확장하기가 용이한가? … 개발기간보다 앞으로 변경이나 추가기능이 필요한 경우 더 빠르고 안전한 대응이 가능한 방법으로 해달라"이다.
- 규칙 1 — 카드 하나가 추적 단위 하나다. CV 번호는 불변이며 삭제한 번호는 다시 쓰지 않는다. 다음 번호와 삭제 번호는 CV 번호 대장(`08f_차트뷰_추가_PERT_할일.md` §4)이 갖는다.
- 규칙 2 — WBS는 카드마다 작업 행(`WBS-CV-NN`, `../03_개발범위/30_Pd_WBS_기반_M1.md`·`30a_Pd_WBS_M2_M3_확장.md`)을 따로 가진다. 행의 단계는 뷰 등록부의 값을 쓰고 카드에는 단계를 적지 않는다. 소속 기능 ID(카드의 `기능 영역`)는 참조로만 둔다. 단계를 바꿀 때는 뷰 등록부를 먼저 고친다.
- 규칙 3 — 시험은 카드마다 시험 묶음 하나를 갖는다. 묶음 이름 형식 `TC-CV-NN` 은 후보다. 묶음에는 카드의 `분석 지표(산식)` 값 대조와 `권한` 칸 대조를 반드시 넣는다.
- 규칙 4 — 뷰는 귀속 기능의 권한 코드로 판정한다. 카드의 `권한` 칸은 그 권한 코드를 가리키고 뷰 고유의 표시 차이(핸들 숨김·열 제거 등)만 적는다. 권한 코드의 정본은 소유 모듈 10 문서의 권한 코드 절이다. 뷰는 원천 모듈 권한을 넘는 데이터를 보여 주지 않는다.
- 규칙 5 — 카드의 필요 데이터 칸에 '계약 없음'이 남은 카드는 시험 묶음을 그 계약이 소유 모듈 10 문서에 생긴 뒤 작성한다. 그 전에는 WBS 행에 `설계 선행` 표기를 둔다.
- 규칙 6 — 보류 카드(CV-26)는 WBS 행을 만들되 보류(D-74·D-190)로 두고 구현 작업·시험 묶음은 만들지 않는다.
