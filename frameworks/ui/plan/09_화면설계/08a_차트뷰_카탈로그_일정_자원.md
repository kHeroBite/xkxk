## 1. 일정 계열 (CV-01~CV-10)

### CV-01 간트
- 목적: 다중 프로젝트의 작업 일정과 선후행 의존을 한 시간축에서 관리한다.
- 사용자: PM·PMO·구성원.
- 관리 동작: 막대 드래그·리사이즈로 일정 변경(서버 엔진 재계산, D-51 직접 그리기), 다중 선택 일괄 변경(건수 상한은 키 `sch.task.bulk_max`), 의존 연결(막대를 끌어 선행관계를 잇는 연결 편집, 아래 "끌어서 선행 연결" 줄), 기준선 막대 비교, 필터·그룹·줌.
- 끌어서 선행 연결(M1, 사용자 요구 2026-11-05): 사용자 원문은 "네트워크 다이어그램 처럼 간트에서도 작업을 끌어 선행관계 연결편집이 가능해야한다" 이다. 규칙은 다음과 같다.
  1. 연결 만들기: 선행 막대의 끝점 핸들에서 후행 막대 위로 끌어 놓는다. 놓은 위치(시작 쪽·완료 쪽)로 유형 FS·SS·FF·SF 를 정하는 규칙은 후보다. 값을 못 정하면 키 `sch.gantt.link.default_type` 의 유형에 지연 0 을 쓴다(MSP-03, D-119). 간트 막대 끌기 연결의 제품 사례는 이번에 확인하지 못했다(미확인). Network Diagram 에서 끌어 연결은 공식 확인이다(`08d` §2.1).
  2. 관계 유형·지연일 수정: 연결선을 선택해 패널에서 유형과 지연일을 고친다. 저장은 의존 경로(`PATCH /api/v1/sch/dependencies/{depId}`)로 하고 선행 열 입력과 같은 경로를 쓴다. 음수 지연은 허용한다(D-84).
  3. 순환·무효 거부: 서버가 순환·자기 참조·같은 쌍 중복·요약 작업 의존(D-84)을 거부하고 서버 판정이 최종이다(D-51). 오류 코드는 10 `sch.md` 의 의존 경로가 정본이다. 화면은 끌던 연결선을 취소하고 오류 코드의 사유 문구를 보인다.
  4. 권한: 연결 추가·삭제·수정은 `sch.plan.write`@project 다. 그 권한이 없으면 연결 핸들을 보이지 않는다. 연결 양 끝 작업이 속한 프로젝트마다 따로 판정한다.
  5. 실행 취소: 연결 추가·삭제·유형/지연 수정은 각각 하나의 명령으로 컨트롤 레이어 명령 이력에 쌓고 실행 취소·다시 실행한다. 서버 반영은 반대 요청으로 하며 다른 사용자가 먼저 바꿔 412 면 취소하지 못하고 최신 상태로 갱신한다고 알린다(`rowVersion`·`If-Match`).
  6. 일정 반영: 저장 즉시 서버가 후행 일정을 다시 계산한다(자동 예약 작업에 한함, MSP-04). 놓기 전에 `reschedule` 의 `dryRun` 으로 영향 일정을 미리 보일지는 키 `sch.gantt.link.dry_run_preview` 가 정한다(D-119).
  7. 태블릿·터치: 핸들은 터치 크기를 확보하고(08 §3.10) 막대 스크롤과 구분한다. 핸들을 길게 눌러 연결 모드로 들어간 뒤 후행 막대를 누르는 방식을 쓸지는 키 `sch.gantt.link.touch_long_press` 가 정한다(D-119). 스마트폰은 간트가 기간 막대 목록(△)이므로 연결 편집을 제공하지 않고 조회만 한다(08 §3.10 값을 넘지 않음). 웹은 마우스 드래그를 쓴다.
  설정 키: 위 1·6·7 의 키 셋은 회사 기본값 + 사용자 재정의다(D-132). 선언과 기본값은 10 `sch.md` 설정 키 절이다.
  8. 범위: CV-01 간트 위 연결 편집만 M1 이다. CV-09 네트워크 화면의 연결 편집은 M4 다(D-82).
- 분석 지표(산식): 일정 지연일=실제(또는 예측) 종료일−기준선 종료일, 진척률=`progress_pct`. M2 확장으로 막대에 계획공수·실제공수·원가 오버레이를 둔다(후보).
- 필요 데이터: `sch` — `GET /api/v1/sch/gantt`(작업·의존·기준선 막대·달력 예외), `GET /api/v1/sch/plans/{planId}/tasks`, `POST /api/v1/sch/plans/{planId}/reschedule`. 달력 예외는 `sch` 가 포트 `sch.port.work_calendar` 로 읽어 응답에 싣는다.
- 권한: 조회 `sch.plan.read`@project, 편집 `sch.plan.write`@project.
- 기능 영역: SCH(SCH-02·SCH-04), 연동 ISS·PRJ.
- 화면 ID: SCR-SCH-01.
- 우선순위: 필수(이미 정본 기능, 이 카드는 뷰 카탈로그 기준점). 기준선 막대 비교는 SCH-04 의 단계를 따른다.
- 보강(U-CV-12, 세부 값은 후보): 선행 열 구문 입력(`4FS,5FS`·`3SS+2d`, 유형 생략=FS, 지연 생략=0)과 체크 목록 입력, Task Path 오버레이(선행·일정 결정 선행 Driving·후행·영향 후행), 일정 근거 패널("왜 이 날짜인가"). 근거 값은 엔진 응답(ADR-081)만 쓴다. 상세 `08d` §3.1·§3.4. 근거·Driving 과 총여유·주공정 경로의 단계는 D-189 를 따른다(U-CV-13). 마감일 열 표시와 초과 경고는 M1 이다(U-CV-14, D-80).
- AI 활용: 보조 — 지연 원인 설명: 일정 계산은 결정적 엔진이 하고, AI 는 엔진이 기록한 날짜 결정 근거를 입력으로 지연 원인을 풀어 설명한다. 사람 확인: PM 이 설명을 참고만 하고 날짜 변경 확정은 사람이 한다.

### CV-06 로드맵
- 목적: 분기·연 단위 사업 계획과 프로젝트 단계를 경영 시야로 본다.
- 사용자: 경영진·PMO.
- 관리 동작: 프로젝트·단계 막대 이동은 PRJ 단계 전이·SCH 마일스톤과 연동(직접 날짜 입력은 금지 후보), 부서·고객 그룹, 기준선 비교.

- 기능 영역: SCH(SCH-07 `roadmap`), PRJ(PRJ-04·PRJ-12).

- 우선순위: 높음.
- AI 활용: 해당 없음 — 결정적 표시 유형: 단계 날짜 배치이며 판단은 사람이 한다.

### CV-08 이벤트 타임라인

### CV-09 의존성 네트워크(PERT/CPM)
- 목적: 선후행 관계를 그래프로 보고 병목 경로를 찾는다.
- 사용자: PM·PMO.
- 관리 동작: 노드 선택→간트 이동, 의존 추가·삭제(SCH-02 API 와 동일), 접기·필터(큰 계획에서 필수).
- 보강(U-CV-12): 전체 모드(검색·범위 필터·단계별 접기·자동 배치)와 국소 모드(선택 작업에서 키 `sch.network.local_hop_max` 의 홉 수까지, 간트 하단 분할 또는 CV-09 안 모드, 화면은 SCR-SCH-01 그대로). 노드 상세에 담당·진척·의존 유형·지연일·일정 근거를 보이고 일정 영향은 `reschedule` `dryRun` 을 쓴다. 네트워크 화면의 연결 편집은 M4 다(U-CV-16, D-82). 간트 위 끌어서 연결은 M1 이다(CV-01 카드). 제품에 Relationship Diagram 보기가 있음은 공식 확인이다(`08d` §2.1). 상세 `08d` §3.2.
- 분석 지표(산식): ES·EF·LS·LF, 총여유=LS−ES. 자유여유 계산은 후보.
- 필요 데이터: `sch` — `GET /api/v1/sch/gantt`(작업·의존). 근무일 계산은 `sch` 가 포트 `sch.port.work_calendar` 로 한다. 그래프 배치용 응답(노드·간선·계산 결과 묶음)은 계약 없음 — 10 `sch.md` 에 보기 종류로 둘지 착수 전에 정한다.
- 권한: 조회 `sch.plan.read`@project, 의존 편집 `sch.plan.write`@project.
- 기능 영역: SCH(SCH-03).
- 화면 ID: SCR-SCH-01.
- 우선순위: 보통.
- AI 활용: 해당 없음 — 결정적 계산 유형: ES·EF·LS·LF 는 정해진 전진·후진 계산이다.

### CV-10 크리티컬 패스 뷰
- 목적: 완료일에 영향을 주는 작업 경로를 간트 위에 겹쳐 보인다.
- 사용자: PM·PMO.
- 관리 동작: 간트 오버레이 켜기·끄기, 경로 위 작업 선택, 여유 임계 필터.
- 분석 지표(산식): 총여유 0 인 작업의 연결 경로, 경로 길이=경로 작업 기간 합. 정본 SCH-03 수용 기준의 8일 경로 사례와 일치해야 한다.
- 보강(U-CV-12): 산식을 "총여유 ≤ 임계(키 `sch.critical_path.float_threshold_days`, 카드의 여유 임계 필터 값) 인 작업의 연결 경로"로 바꾸는 안이다(후보). 마감일 열은 M1 에 두되 마감일이 총여유 계산에 주는 영향 규칙은 M4 에서 정한다(U-CV-14). 제약(FNLT 등)이 있으면 총여유가 음수일 수 있어 0 만 보는 산식이 놓칠 수 있다(음수 여유 동작은 추정, 확인 필요). 경로가 여럿이면 모두 보이고 경로별로 구분한다. 제약 없는 계획에서 AC-SCH-03-1 결과는 그대로여야 하며 수용 기준은 바꾸지 않는다. 상세 `08d` §3.3.
- 필요 데이터: `sch` — SCH-03 계산 결과를 싣는 `GET /api/v1/sch/gantt` 응답(총여유·경로 표지 필드는 10 `sch.md` 의 엔진 응답 정본).
- 권한: 조회 `sch.plan.read`@project.
- 기능 영역: SCH(SCH-03).
- 화면 ID: SCR-SCH-01.
- 우선순위: 높음. 오버레이의 단계는 D-189 를 따른다.
- AI 활용: 해당 없음 — 결정적 계산 유형: 경로는 총여유 0 이라는 규칙으로 정해진다.

## 2. 자원 계열 (CV-11~CV-13)

### CV-11 리소스 스케줄러
- 목적: 사람별 배정 기간과 충돌을 보고 조정한다.
- 사용자: PM·자원 담당.
- 관리 동작: 배정 이동·분할, 충돌 경고, 평준화 제안 수락(SCH-09). 무거운 재계산은 작업 큐 비동기 후보.

- 필요 데이터: `sch` — 배정(SCH-06, 08 `sch.md` 의 `resource_assignment` 는 정의 전 후보)과 가동률 계산. 가용공수는 `sch` 가 포트 `sch.port.member_availability`(구현 `wcal`, D-541)로 읽고 근무일은 `sch.port.work_calendar` 로 읽는다. 배정 조회·수정 경로는 계약 없음 — SCH-06 설계 때 10 `sch.md` 에 둔다.
- 권한: 조회 `sch.plan.read`@project, 배정 변경 `sch.plan.write`@project. 개인 가용성의 범위 판정은 `wcal.availability.read` 의 범위를 따른다.
- 기능 영역: SCH(SCH-06·SCH-08·SCH-09), TIM(TIM-06).
- 화면 ID: SCR-SCH-03.
- 우선순위: 높음.
- AI 활용: 보조 — 평준화 후보안을 제안하고 적용은 하지 않는다. 사람 확인: PM 이 제안을 검토해 수락해야 반영.

### CV-12 자원 히트맵
- 목적: 조직·개인별 기간 가동률을 색으로 보고 과부하·유휴를 찾는다.
- 사용자: PMO·자원 담당·조직 관리자.

- 분석 지표(산식): 가동률=배정공수÷가용공수(조직 단위 분모는 단일 정의, U-CV-5). 휴가·공휴일 반영. 성능 시험 규모 예시 500명×52주=26,000셀(성능 시간은 추정).
- 필요 데이터: 가동률 집계는 `rpt` 프로젝션(원천 `sch`·`tim` 이 지표 원천 포트 `rpt.port.metric_source` 로 등록, 읽기는 `GET /api/v1/rpt/metrics`). 가용공수는 `sch` 가 포트 `sch.port.member_availability`(구현 `wcal`)로 읽는다. 집계 프로젝션의 키는 원천 모듈 선언서가 정한다(계약 없음 — SCH-06 설계 때 정한다).
- M2 데이터 출처(결정 86, TODO-94): PRE-06 역할 슬롯·SCH-01 작업 담당자·TIM-01 실적 공수로 구성하고, SCH-06 배정이 들어오면 대체한다(릴리스 이동 없음).
- 권한: 조회 `rpt.metric.read`@tenant 와 원천 권한(`sch.plan.read`@project·`tim.entry.read` 의 조직 범위 `@dept`·`@subtree`). 개인 가동률은 조직 범위 안만 보인다.
- 기능 영역: SCH(SCH-06), TIM(TIM-06), ORG.
- 화면 ID: SCR-SCH-03.
- 우선순위: 필수(U-CV-2, D-68).
- AI 활용: 보조 — 과부하·유휴 패턴의 설명 요약만 제안한다. 사람 확인: 팀장이 배치 조정 전 요약과 원 수치를 대조.
