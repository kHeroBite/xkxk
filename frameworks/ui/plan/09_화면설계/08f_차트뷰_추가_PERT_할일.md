## 1. 일정 계열 추가 (CV-35·CV-36)

### CV-35 PERT 3점 추정·완료 확률
- 목적: 작업 기간을 낙관·보통·비관 3점으로 넣어 기대 완료일과 목표일 안 완료 확률을 본다. 불확실성이 큰 R&D·신규 업종 프로젝트의 일정 약속 근거로 쓴다.
- 사용자: PM·PMO·경영진(조회).
- 관리 동작: 작업별 3점(a 낙관·m 보통·b 비관) 입력, 목표일 입력 → 확률 표시, 3점 미입력 작업은 단일 기간을 a=m=b 로 본다(산식 정의라 옵션이 아니다 — 미입력은 불확실성 0 으로 계산하고 화면에 '3점 미입력 n건'을 함께 보인다). CV-09 네트워크·CV-10 경로 오버레이 위에 기대 기간과 표준편차를 겹쳐 보인다. 입력은 표 편집과 노드 상세 패널 두 곳이다.
- 분석 지표(산식): 기대 기간 te=(a+4m+b)÷6, 표준편차 σ=(b−a)÷6. 경로 기대 길이 Te=Σte(크리티컬 패스 작업), 경로 분산 σ²_path=Σσ². 완료 확률 P(완료일 ≤ 목표일)=Φ((목표일−Te)÷σ_path), Φ 는 표준정규 누적분포다. 날짜는 근무 캘린더 기준 근무일로 센다.
- 산식 한계(표시 필수): 위 식은 단일 크리티컬 패스만 보고 작업 간 독립을 가정한다. 거의 같은 길이의 경로가 여럿이면 실제 확률보다 높게 나올 수 있다. 화면에 '근사값' 표지와 경로 수를 함께 보인다. 몬테카를로 모의는 이번 범위에 넣지 않는다(YAGNI, 재검토 조건은 근사 오차 민원 발생 때).
- 필요 데이터: `sch` — `GET /api/v1/sch/gantt`(작업·의존), 작업 수정 `PATCH /api/v1/sch/tasks/{taskId}`. 근무일은 `sch` 가 포트 `sch.port.work_calendar` 로 센다. 3점 추정 열(후보 이름 `estimate_optimistic`·`estimate_most_likely`·`estimate_pessimistic`)과 확률 계산 응답은 08·10 `sch.md` 에 없다(계약 없음 — 설계 과업은 TODO-81 에 더한다). 계산은 SCH-03 일정 엔진이 하고 뷰는 결과만 그린다(레이어 분리).
- 권한: 조회 `sch.plan.read`@project, 3점 입력 `sch.plan.write`@project. 확률·기대 완료일만 보이는 요약 보기는 조회 권한으로 연다.
- 기능 영역: SCH(SCH-03), 연동 SCH-04(기준선 대비 표시).
- 소속 기능: SCH-03.
- 화면 ID: SCR-SCH-01(CV-09·CV-10 과 같은 화면 안 모드).
- 우선순위: 보통(CV-09 와 함께).
- AI 활용: 보조 — 3점 초안 제안: 같은 회사의 비슷한 작업(유형·규모) 실적 분포에서 a·m·b 초안을 제안하고, 확률 계산은 결정적 엔진이 한다. 사람 확인: PM 이 초안을 고쳐 확정해야 계산에 들어간다(제안 → 승인 경로, `../05_아키텍처/28_Pd_에이전트_자동화_설계.md` §3).

### CV-36 WBS 트리도
- 목적: 프로젝트 범위를 상위에서 하위로 분해한 계층을 조직도처럼 펼쳐 보고, 빠진 분해와 구조 균형을 찾는다.
- 사용자: PM·구성원·PMO.
- 관리 동작: 노드 접기·펼치기, 수준(깊이) 필터, 노드 끌어 부모 바꾸기(SCH-01 계층 변경과 같은 API, `wbs_path` 재계산), 노드에서 간트·이슈 상세로 이동. 가로 트리·세로 트리·들여쓰기 목록 3가지 배치를 전환한다(기본 배치는 키 `sch.wbs_tree.default_layout`). 1인·소규모 규모 모드에서는 들여쓰기 목록이 기본이다(`12_간편입력_규모적응_화면설계.md` §2).
- 분석 지표(산식): 수준별 노드 수, 잎 노드 수, 노드 진척=SCH-01·SCH-11 이 계산한 값 그대로 표시(뷰는 롤업을 다시 계산하지 않는다). WBS 100% 규칙 검사(하위 합이 상위 범위를 덮는가)는 DOC-06 확장 옵션의 검사 결과를 경고 표지로만 보인다.
- 필요 데이터: `sch` — `GET /api/v1/sch/plans/{planId}/tasks`(`includeTask=true` 로 작업 본체 요약: 키·제목·상태·담당자·상위), 부모 바꾸기 `POST /api/v1/sch/tasks/{taskId}/move`. WBS 100% 규칙 검사 결과를 주는 계약은 없다(DOC-06 은 이전 예정 → `scoping`, D-517 — 그 모듈 문서 쌍이 생길 때 정한다). 검사 결과를 주는 모듈이 테넌트 허용에 없으면 검사 표지만 숨긴다.
- 권한: 조회 `sch.plan.read`@project, 구조 변경 `sch.plan.write`@project. 구조 변경(부모 바꾸기·추가·삭제)은 범위 변경이라 에이전트 제안으로 들어온 경우 승인이 기본이다(28 §5).
- 기능 영역: SCH(SCH-01), 연동 ISS·DOC(DOC-06).
- 소속 기능: SCH-01.
- 화면 ID: SCR-SCH-01.
- 우선순위: 높음.
- AI 활용: 보조 — 분해 누락 후보 제안: 자료 투입 생성(DOC-06)이나 사람이 만든 WBS 에서 같은 업종 팩 템플릿 대비 빠진 하위 항목 후보를 제안한다. 사람 확인: PM 이 제안함에서 승인해야 구조에 들어간다.

## 2. 매트릭스 계열 (CV-37·CV-38)

두 매트릭스는 같은 2축 4사분면 컴포넌트를 쓴다. 축 정의·사분면 이름·카드 필드만 소속 기능 플러그인이 정하고, 카드 끌기·가상화·사분면 합계는 컴포넌트가 한다(08 §3.11 공통 차트 컴포넌트 원칙과 같은 방식, 결정 54).

### CV-37 아이디어 매트릭스(가치×노력)
- 목적: 접수된 아이디어를 가치와 노력 두 축에 놓고 먼저 할 것과 버릴 것을 고른다. 생애주기 앞단 아이디어 단계를 시각화한다(REQ-66).
- 사용자: 아이디어 평가자·PMO·경영진·제안자(본인 아이디어 조회).
- 관리 동작: 점 클릭 → 아이디어 상세, 점수 수정(평가자), 사분면 필터, '프로젝트로 승격' 단추(PRJ-19 승격 규칙, 승격은 PMO 승인), 기간·출처·부서 필터.
- 분석 지표(산식): 가치 점수=Σ(가치 항목 점수×가중치), 노력 점수=Σ(노력 항목 점수×가중치). 항목·가중치·척도·사분면 경계와 이름은 `prj` 소유 테넌트 데이터(아이디어 점수 항목, 관리 권한 `prj.config.admin`)이고 등록형이다. 기본 시드는 가치 1~5·노력 1~5 각 1항목, 경계는 척도 중앙값, 사분면은 빠른 성과(가치 높음·노력 낮음)·큰 투자(높음·높음)·채우기(낮음·낮음)·보류(낮음·높음)다.
- 필요 데이터: `prj` — `GET /api/v1/prj/ideas`(점수·사분면), `PUT /api/v1/prj/ideas/{ideaId}/scores`, `POST /api/v1/prj/ideas/{ideaId}/promote`(08 `prj.md` 의 아이디어 테이블).
- 권한: 조회 `prj.idea.read`@tenant(공개 범위 안), 점수 `prj.idea.evaluate`@tenant, 결정 `prj.idea.approve`@tenant, 승격 `prj.idea.promote`@tenant. 승격 단추는 승격 권한이 있을 때만 보인다.
- 기능 영역: PRJ(PRJ-19), 연동 PRJ-10(우선순위 점수)·PRJ-12(생애주기).
- 소속 기능: PRJ-19.
- 화면 ID: 아이디어 화면(ID 는 메뉴 정본이 부여).
- 우선순위: 높음.
- AI 활용: 보조 — 중복·유사 아이디어 묶음과 가치·노력 점수 초안 근거 요약을 제안한다. 사람 확인: 평가자가 점수를 확정하고 AI 초안은 자동 반영하지 않는다.

### CV-38 아이젠하워 매트릭스(긴급×중요)
- 목적: 할 일을 긴급과 중요 두 축으로 나눠 지금 할 것·일정 잡을 것·맡길 것·뺄 것을 정한다(REQ-74 GTD·아이젠하워).
- 사용자: 구성원(개인 할 일)·팀 구성원(팀 할 일).
- 관리 동작: 카드를 사분면으로 끌기(= 긴급·중요 표시 갱신), '일정 잡기' 사분면 카드를 캘린더 칸으로 끌기(COL-13), '맡기기' 사분면 카드 담당 바꾸기(팀·그룹·프로젝트 범위 할 일만), 완료 체크. 개인 범위 할 일은 본인만 본다.
- 분석 지표(산식): 긴급=기한까지 남은 날 ≤ 키 `col.todo.urgent_days` 또는 사용자가 긴급 표시. 중요=사용자가 중요 표시 또는 우선순위가 키 `col.todo.important_min_priority` 의 값 이상. 사분면별 건수, 기한 초과 건수. 사분면 이름은 `col` 소유 테넌트 데이터의 기본 시드(지금 할 것·일정 잡을 것·맡길 것·뺄 것)다.
- 필요 데이터: 할 일 본체는 이전 예정(→ `task`, D-538)이고 그 문서 쌍이 생기기 전까지 `col` 경로를 쓴다. `col` — `GET /api/v1/col/todos`(범위·보기·기간), `PATCH /api/v1/col/todos/{todoId}`(긴급·중요·담당), 캘린더로 끌기는 `POST /api/v1/col/todos/schedule-proposals`(제안으로 올라감), 승격은 `POST /api/v1/col/todos/{todoId}/promote`(대상 종류 등록 코드).
- 권한: 조회 `col.todo.read`@할 일 범위, 수정 `col.todo.write`@할 일 범위. 개인 범위 할 일은 회사 관리자 권한으로도 보이지 않는다(보안 고정 예외, COL-16 부록 업무 규칙이 정본).
- 기능 영역: COL(COL-16), 연동 COL-13(캘린더)·ISS(할 일 → 이슈 승격).
- 소속 기능: COL-16.
- 화면 ID: 할 일 화면(ID 는 메뉴 정본이 부여).
- 우선순위: 높음.
- 다른 모듈로 건너가는 동작: 이슈 승격은 대상 종류 등록 코드로 부르고(`col` 할 일 승격 경로), 대상을 만드는 모듈이 테넌트 허용에 없으면 그 종류가 승격 목록에 나오지 않는다.
- AI 활용: 보조 — 캘린더 빈칸 배치 제안(UX-25 제안형)과 긴급·중요 분류 초안을 제안한다. 사람 확인: 사용자가 배치·분류를 고르거나 끌어 옮겨야 반영된다.

## 3. 진척 계열 추가 (CV-39)

### CV-39 Hill Chart(확신도 진행)
- 목적: 숫자 공정률로 나타내기 어려운 초기·탐색 단계의 진행을 '파악 중(오르막)·실행 중(내리막)' 언덕 위치로 보인다(UX-26). R&D·신규 업종·아이디어 승격 직후 프로젝트에 쓴다.
- 사용자: PM·팀장·구성원(담당 범위).
- 관리 동작: 범위 묶음(요약 작업) 점을 언덕 위에서 끌어 위치 갱신, 위치 갱신 때 한 줄 메모(선택), 날짜 슬라이더로 과거 위치 비교, 오래 멈춘 점 강조.
- 분석 지표(산식): 위치 0~100(0~50 오르막=파악, 50~100 내리막=실행)은 사람이 정하는 주관 값이다. 정체=위치 변화 없는 기간 ≥ 키 `sch.hill_chart.stale_days`. 숫자 공정률(SCH-11)과 합산하지 않고, 개인 평가(EVA) 입력으로 쓰지 않는다.
- 필요 데이터: `sch` — `GET /api/v1/sch/plans/{planId}/tasks`(요약 작업). 확신도 위치와 날짜별 이력은 08·10 `sch.md` 에 없다(계약 없음 — 설계 과업은 TODO-81 에 더한다).
- 권한: 조회 `sch.plan.read`@project, 점 위치 갱신 `sch.plan.write`@project.
- 기능 영역: SCH(SCH-01), 연동 SCH-11(숫자 공정률과 나란히 표시만).
- 소속 기능: SCH-01.
- 화면 ID: SCR-SCH-01(화면 안 모드). 대시보드 위젯은 CV-27 허브로 노출한다.
- 우선순위: 보통.
- AI 활용: 보조 — 정체 점의 원인 후보 요약: 해당 범위의 일지·이슈·회의 액션아이템을 근거로 정체 사유 후보를 요약한다. 사람 확인: 담당자가 점 위치를 직접 정하고, AI 는 위치를 바꾸지 않는다.

## 3-1. 지식·협업 계열 추가 (CV-40·CV-41, 결정 118-7)

두 카드의 번호는 `13_UX패턴_카탈로그.md` §5 CV 표에서 왔다. 화면은 `메뉴구조.csv` 의 SCR-KMS-02(메뉴 1086)·SCR-COL-08(메뉴 1087)이다(화면 ID 값은 후보). 기능 게이트는 `lic` 권리 묶음이 정본이다.

### CV-40 지식 그래프(로컬 그래프)
- 목적: 이슈·문서·위키 페이지·회의록·교훈 사이의 연결을 연결 패널 목록만으로는 보기 어려울 때, 활성 객체를 중심으로 한 관계 그림으로 한눈에 본다(UX-44, D2-16).
- 사용자: 전원(볼 수 있는 객체 범위)·객체 편집자.
- 관리 동작: 활성 객체 기준 로컬 그래프 기본, 깊이 선택(기본값은 키 `kms.link_panel.graph_depth`, 상한은 키 `kms.link_panel.graph_depth_max`), 노드 hover 미리보기 카드(PLT-01 공통 카드), 노드 클릭으로 그 객체 상세 이동, 종류·기간·프로젝트 필터, 연결 안 된 언급·고아 객체 보기 전환. 전역 그래프는 노드 수 상한 안에서만 연다(상한 값은 PoC 실측 전 값 없음). NAV 는 연결 패널 목록형으로 대체한다.
- 분석 지표(산식): 노드 수, 간선 수, 객체별 연결 건수(들어오는·나가는), 고아 객체 수(연결 0건). 권한 밖 출처는 건수와 노드에 넣지 않는다. 의미 유사 연결 후보는 점선 후보로만 그리고 승인 전에는 연결 건수에 합산하지 않는다.
- 필요 데이터: `kms` — `GET /api/v1/kms/link-panel/{objectKind}/{objectId}`(연결·로컬 그래프, `depth`), `.../unlinked-mentions`, `GET /api/v1/kms/orphans`(08 `kms.md` §3.5). 링크 자체는 `plt` 객체 링크 한 벌이다(`GET·POST /api/v1/plt/object-links`, 계약 `plt.q.object_links`·`plt.c.link_objects`, D-523). 그래프에 들어오는 연결 원천은 닫힌 목록이 아니다. 대상을 가진 모듈(위키·회의록·교훈·이슈·계약·발주·기회 등)이 자기 선언서로 대상 종류 코드를 등록하고 `plt` 객체 링크 명령으로 링크를 낸다. 경로의 `{objectKind}` 는 등록된 대상 종류 코드다(D-509). 대상 종류를 등록한 모듈이 테넌트 허용에 없으면 그 종류의 노드만 빠진다.
- 권한: 조회 `kms.link.read`(볼 수 있는 객체 범위, 권한 밖 출처는 넣지 않는다), 링크 바꾸기 `plt.object_link.write`·`plt.object_link.delete`. 패널 켜기·고아 공개 범위는 키 `kms.link_panel.enabled`·`kms.link_panel.orphan_visibility`(쓰기는 공통 설정 경로).
- 기능 영역: KMS(KMS-04), 연동 COL-12(위키)·COL-15(회의록)·KMS-01(교훈)·ISS·DOC.
- 소속 기능: KMS-04.
- 화면 ID: SCR-KMS-02(메뉴 1086). 이슈·문서·회의록·교훈 상세 세부 창의 연결 패널(UX-44)에서도 로컬 그래프 보기로 연다.
- 우선순위: 보통(KMS-04 와 같은 단계).
- AI 활용: 보조 — 의미가 비슷한 객체를 붙일 만한 연결 후보로 제안한다. 사람 확인: 제안함(AIN-08)에서 객체 편집자가 승인해야 링크가 생기고 승인 전에는 어떤 객체도 바뀌지 않는다.

### CV-41 화이트보드 캔버스
- 목적: 회고·브레인스토밍 결과를 자유 배치 캔버스에 모아 투표로 고르고 이슈·할 일로 이어 회의 결과가 작업이 되게 한다(UX-66·67·68·98).
- 사용자: 보드 참여자·진행자·PM(담당 프로젝트로 변환).
- 관리 동작: 스티키·도형 추가·이동·묶음, 투표 세션(1인당 표 수·비공개 투표), 공용 타이머, 스티키 묶음 → 이슈·할 일 일괄 변환(미리보기 → 승인 2단계), 변경 이력. 동시 편집은 요소별 판 번호가 높은 쪽을 남기고 삭제는 묘비 표시 뒤 정리하며 실행 취소는 내 변경만 되돌린다(기본값은 D 후보). NAV 는 카드 목록에 표 단추를 두고 보기와 스티키 추가만 지원한다.
- 분석 지표(산식): 투표 집계=스티키(요소)별 득표 수 합, 비공개 투표는 진행자가 끝내기 전 개별 선택을 누구도 볼 수 없다. 묶음별 스티키 수, 변환 승인율=승인 항목÷미리보기 항목. 스티키 500개 렌더 지연은 PoC 실측 전 값 없음.
- 필요 데이터: `col` — `GET·POST /api/v1/col/boards`, `PATCH /api/v1/col/boards/{boardId}/elements`(요소별 `version`, 충돌 412), `POST .../votes`, `POST .../timer`, `POST .../convert`(미리보기 → 승인 항목만)(08 `col.md` 의 보드 테이블). 요소 병합 방식은 10 `col.md` 가 정한다.
- 권한: 조회 `col.board.read`@보드 범위, 요소·투표 `col.board.write`@보드 범위, 타이머·변환 `col.board.admin`@보드 범위. 변환으로 만들어지는 대상의 생성 권한은 대상을 만드는 모듈이 다시 판정한다. 일괄 변환 승인은 기본값이 필수이고 회사 옵션이다(D-261, ADR-089). 감사 기록은 끌 수 없다.
- 기능 영역: COL(COL-17), 연동 COL-13·COL-15(회의)·COL-16(할 일)·ISS(이슈)·KMS-01(교훈)·CV-37(아이디어 매트릭스 입력).
- 다른 모듈로 건너가는 동작: 스티키 묶음 → 이슈·할 일·교훈·아이디어 변환은 `col` 보드 변환 경로 하나로 하고, 만들 대상은 대상 종류 등록 코드로 고른다(10 `col.md` 머리의 `{target}` 규칙). 변환 대상 목록은 화면 확장 자리(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7 5번, 소유 `col`, 기여는 대상을 만드는 모듈)다. 대상을 만드는 모듈(`iss`·`kms`·`prj` 등)이 테넌트 허용에 없으면 그 변환 단추를 숨긴다.
- 소속 기능: COL-17.
- 화면 ID: SCR-COL-08(메뉴 1087).
- 우선순위: 보통(COL-17 과 같은 단계).
- AI 활용: 보조 — 스티키 묶음 분류와 묶음 제목 다듬기를 제안한다. 사람 확인: 진행자가 묶음을 고쳐 확정하고 이슈·할 일 변환은 미리보기에서 승인한 항목만 만들어진다.
