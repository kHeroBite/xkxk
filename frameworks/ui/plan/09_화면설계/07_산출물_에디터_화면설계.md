## 1. 공통 전제

| 항목 | 내용 |
|---|---|
| 프로그램 | 클라이언트 프로그램 `pd` 의 테넌트 사용자 화면이다. 운영사 콘솔(`pd-admin`) 화면은 없다. |
| 화면 ID | `SCR-DOC-01`~`05`. 정본은 `../_build/menu_data.py` 이고 이 문서는 인용만 하며 새 ID 를 만들지 않는다. 화면 ID 는 불변이다(D-496). 화면의 채택 단계는 설계 등재다. |
| 열림 방식 | 한 화면 = 한 문서 창(탭)이다(20 §3). DOCK·NAV 에서는 같은 내용을 패널·밀어 넣기 화면으로 바꾼다. 화면 유형(20 §3 8종) 대응은 아래 §2 표이다. |
| 레이어 분리 | UI/UX(배치·상호작용), 컨트롤(화면 상태·명령 처리), 데이터(서버 API·엔터티)를 나눈다. 화면은 데이터 레이어를 직접 만지지 않고 컨트롤 레이어의 명령만 호출한다. 서버 규칙(필수 섹션·잠금·권한)은 서버가 판정하고 화면은 결과를 표시한다. 시각 상태(비활성·배지)는 UI 레이어가 컨트롤 상태 값만 보고 그린다. |
| 표시 판정 | 화면·명령을 보일지는 테넌트 허용(모듈이 조립에 있는가) → 기능 게이트(요금제) → 권한 코드 순서로 가른다. 판정 순서의 정본은 `../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §8, 화면 표시 판정식은 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §3 이다. 허용에 없는 모듈의 화면은 메뉴에 두지 않는다. 기능 게이트가 닫힌 화면은 잠금 아이콘으로 보인다. 권한 판정 결과가 거부면 메뉴에서 숨기고, 읽기 전용이면 편집 컨트롤을 비활성으로 보인다(20 §3, 01 §6). '모듈 없음'과 '요금제 부족'은 표시가 다르다(숨김 대 잠금, 키 `ui.screen.not_entitled_display`·`ui.screen.gate_closed_display`, 선언 `../10_API설계/plt_2.md` §12.1). |
| 다국어 | 화면 문자열은 다국어 키로 둔다(01 §10). 이 문서의 한국어 라벨은 기본 문구 후보이다. |
| 오류 표시 | 서버 오류 code 로 분기하고 문구는 다국어 키로 그린다. 오류 코드의 정본은 `../10_API설계/doc.md` §8 과 공통규약 §9 다. 412 는 "다른 곳에서 바뀜" 안내 후 최신 판 다시 읽기를 권한다. |
| 공통 컴포넌트 | 그리드, 저장 필터, 댓글·멘션, 첨부, 활동 이력, 결재 상신 버튼은 20 §3 의 공통 컴포넌트를 같은 모양으로 쓴다(PLT-01). |
| 폼 항목 | 템플릿 메타·임의 문서 첨부 메타의 필수·선택은 항목 정책(`../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §4)의 대상이다. 이 문서에 적은 필수·선택은 기본값이다. 항목 카탈로그 등재는 기능 부록 a18 의 '항목 정책' 줄이 한다. |

## 3. SCR-DOC-01 산출물 템플릿 카탈로그 (DOC-01)

목적: 문서 유형별 기본 서식을 보고, 업체 서식으로 복제·게시·폐기한다.

```
┌ 산출물 템플릿 ──────────────────────────────────────────────┐
│ [유형 ▾ 전체] [정본 형태 ▾] [상태 ▾]  검색[........]  [+ 복제] │
├───────────────┬──────────────────────────────────────────────┤
│ 유형 트리      │ 템플릿 목록(그리드)                             │
│  ▸ 계획(C)    │  이름 | 유형 | 출처 | 정본 형태 | 변환 | 판 | 사용 │
│  ▸ 분석·설계  │  ─ 기본 요구사항정의서 | C-01 | 기본 | 구조화 …   │
│  ▸ 개발·시험  │  ─ ○○사 요구사항정의서 | C-01 | 업체 | 구조화 …   │
│  ▸ 관리(M)    ├──────────────────────────────────────────────┤
│               │ 미리보기 / 섹션 정의 / 판 이력(탭)               │
└───────────────┴──────────────────────────────────────────────┘
```

| 영역 | 동작 |
|---|---|
| 유형 트리 | 산출물 카탈로그에 등록된 유형을 단계별로 묶어 보인다. 카탈로그 행은 PMS 몫 전수표(`../03_개발범위/05_전주기_산출물_요구.md` §3)와 모듈 선언서·팩이 등록한 행이다(D-509). 화면은 행을 추가하지 않는다. |
| 목록 | 출처 배지 `기본`(수정 불가)·`업체`. 정본 형태 배지. 변환 형식은 그 템플릿 판에 등록된 형식 칩이다. |
| 상세 탭 | 미리보기 · 섹션 정의(제목·필드·표 열) · 판 이력 · 사용 중 문서 수. |
| 명령 | `복제`(기본→업체 서식 초안), `필드 추가·삭제`, `게시`(판 +1), `폐기`(소프트). 게시된 판은 수정 불가이며 새 판에서만 고친다. |

상태별 허용 명령은 컨트롤 레이어가 서버 상태 값으로 계산해 UI 에 전달한다. 템플릿 상태 값과 전이의 정본은 `../08_데이터모델/doc.md` §3.2 다.

| 조건 | 화면 반응 |
|---|---|
| 기본 템플릿 선택 | 편집 컨트롤 비활성, `복제`만 활성(DOC-01 규칙) |
| 정본 형태가 원본+메타 | 변환 형식 영역을 숨기고 "변환 형식 없음(원본 그대로 관리)" 안내(V-4) |
| 사용 중 판 삭제 거부 | 폐기만 권하는 안내 |
| 섹션 정의 오류 | 해당 섹션에 오류 표시 |
| 권한 판정이 읽기 전용 | 목록·미리보기만 보이고 명령은 비활성 |

PRJ-03 프로젝트 템플릿과는 별개이며 연결 링크만 둔다. 원본 보관 기간은 설정 키 `doc.original.retention_days`(허용 층 회사, 선언 `../10_API설계/doc.md` §11)의 해석 값을 읽기 전용으로 보인다. 값 층 해석은 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §5 를 따른다.

## 4. SCR-DOC-02 산출물 에디터·내보내기 (DOC-02·03)

목적: 템플릿 판에서 문서를 만들어 섹션·표·첨부를 편집하고, 저장하면 버전을 더하며, 문서 버전을 등록된 형식으로 내보낸다.

```
┌ 요구사항정의서 v3 [초안] ─────── [저장] [결재 상신] [내보내기 ▾] ┐
│ 목차(섹션)        │ 본문 편집 영역                     │ 우 패널  │
│  1. 개요          │  ## 1. 개요                        │ 버전 이력 │
│  2. 요구 목록 ●   │  본문 텍스트 …                      │  v3 현재  │
│  3. 제약          │  ┌ 표: 요구 목록 ──────────────┐   │  v2 …    │
│  (필수 섹션 *)    │  │ ID | 요구 | 우선순위 | …    │   │ [비교]   │
│                   │  └─────────────────────────────┘   │ 결재 상태 │
│                   │  첨부: [파일 참조 추가]              │ 활동·댓글 │
└───────────────────┴────────────────────────────────────┴─────────┘
```

| 영역 | 동작 |
|---|---|
| 목차 | 템플릿 섹션 정의를 따른다. 필수 섹션은 표시(*)하고 비어 있으면 저장 시 경고한다. 현재 편집 섹션 점(●). |
| 본문 | 텍스트·표·첨부 참조 편집. 에디터 형식(블록 문서 대 서식 문서)과 저장 포맷은 설계 단계 결정이며 이 문서는 정하지 않는다. |
| 저장 | 덮어쓰지 않고 새 버전을 추가한다. 변경 사유는 선택 입력이다. 수정 요청에는 `If-Match`(공통규약 §7)를 쓴다. |
| 버전 이력 | v 번호·작성자·시각·변경 사유 목록, 두 버전 비교(변경 섹션·표 행 강조), 이전 버전 열람. 저장 버전은 PRJ-06 산출물 버전과 공유한다. |
| 결재 | 연결 시 상신 버튼으로 APR 요청을 만들고 승인 전 버전을 잠금 표시한다. |
| 내보내기 | 메뉴에서 형식과 변환 서식을 고른다. 형식 목록은 변환기 포트가 등록한 형식 가운데 템플릿 판에 지정된 것이다(D-509). 화면은 등록된 형식을 그리며 형식 이름을 고정하지 않는다. 템플릿 판에 없는 형식은 비활성이다. |

문서 상태 값과 전이의 정본은 `../08_데이터모델/doc.md` §3.3 이다. 승인된 버전은 읽기 전용 배너("승인됨 — 새 판에서 수정")를 보이고 `새 판 만들기`만 제공한다.

### 4-1. 내보내기 진행

변환은 비동기 작업이다. 작업 상태 값의 정본은 `../08_데이터모델/doc.md` §3.4 다.

| 단계 | 화면 표시 |
|---|---|
| 요청 | 진행 줄을 우 패널 하단에 둔다. 같은 버전·형식이 진행 중이라는 거부를 받으면 기존 진행 줄을 가리킨다. |
| 완료 | 파일 크기와 `다운로드` 버튼(사전 서명 URL). 파일에는 문서 ID·버전·내보낸 시각이 식별 메타로 들어감을 한 줄 안내한다(DOC-04 왕복 기준). |
| 실패 | 같은 버전·형식으로 `다시 요청`. |
| 형식 없음 | 형식 메뉴 항목에 비활성 사유를 표시한다. |

소요 시간 수치는 실측 전이라 화면에 약속하지 않는다. 내보내기는 열람 권한이 있는 필드만 담는다. 정본 형태가 원본+메타인 유형은 이 에디터 대상이 아니며 열면 SCR-DOC-03 의 원본 목록으로 안내한다.

### 4-2. 오류와 충돌

| 상황 | 화면 반응 |
|---|---|
| 필수 섹션 누락 | 섹션 강조 |
| 동시 편집 충돌 | 내 변경 보존, 최신 판 열기·비교 제안(병합 방식은 설계 단계 결정) |
| 승인 버전 수정 거부 | '새 판 만들기' 안내 |
| 권한 판정이 읽기 전용 | 편집 컨트롤 비활성, 열람·비교만 |
| 외부 참여자 | 외부 참여 경로(교차 테넌트·게스트 계정·공유 링크)별 열람 범위는 `iam` 권한 판정을 따르고 화면은 그 결과만 그린다(`15_외부참여_공유링크_화면설계.md`) |

## 5. SCR-DOC-03 가져오기 미리보기·변환 손실 보고 (DOC-04·05)

목적: Word·Excel 파일을 올려 pd 문서로 되가져오고, 원본을 보관하며, 변환 중 잃은 항목을 보고한다.

해석 고정(03/05 해석 행 H-2): pd 템플릿으로 내보낸 파일은 왕복을 보장 대상으로 한다. 임의 서식도 왕복을 **목표**로 하며 어려운 구조 해석에는 AI(LLM)를 쓸 수 있다. 목표이지 보장이 아니므로 화면은 임의 서식 경로에서 "완전 복원" 같은 문구를 쓰지 않고, 원본 보관과 변환 손실 보고(§5-2 왕복 실패 보고)로 못 미친 부분을 드러낸다. 카탈로그에 없는 **임의 문서**는 일반 첨부로 받아 원본+메타로 보관한다(H-1, §5-3).

```
 ① 업로드 → ② 판정 → ③ 매핑(임의 서식만) → ④ 미리보기 → ⑤ 확정
┌ 가져오기 ──────────────────────────────────────────────────┐
│ 파일: 요구사항_고객.xlsx  [pd 템플릿 파일 ✔ | 임의 서식]       │
├────────────────────────┬───────────────────────────────────┤
│ 원본 열·섹션            │ 대상 필드 (템플릿 판 ▾)             │
│  A열 번호  ───────────▶│  요구 ID                           │
│  B열 내용  ───────────▶│  요구 내용                         │
│  C열 비고  ─── 미대응   │  (대응 없음)                       │
├────────────────────────┴───────────────────────────────────┤
│ 미리보기: 대응 38 / 미대응 3        [손실 보고 보기] [취소]    │
│                                        [확정하고 문서 만들기] │
└────────────────────────────────────────────────────────────┘
```

| 단계 | 동작 |
|---|---|
| ①업로드 | 첨부 업로드가 완료·확정된 파일만 받는다. 미확정 파일과 손상·암호 파일은 거부 사유를 보인다. |
| ②판정 | 식별 메타로 pd 템플릿 파일인지 가른다. pd 템플릿 파일은 ③을 건너뛰고 자동 대응한다. |
| ③매핑 | 임의 서식은 원본 열·섹션을 템플릿 필드에 끌어 놓거나 목록에서 고른다. 이 마법사 UI 는 IMP-06 과 공유할 후보이며 IMP-06 은 이번에 바꾸지 않는다. |
| ④미리보기 | 필드별 대응·미대응을 보인다. 확정 전에는 문서가 바뀌지 않는다. |
| ⑤확정 | 새 문서 버전을 만들고 SCR-DOC-02 로 이동 링크를 준다. |

가져오기 작업 상태 값과 전이의 정본은 `../08_데이터모델/doc.md` §3.5 다. 화면은 분석 중에는 진행 표시, 미리보기 준비가 되면 ④로 이동, 실패면 사유와 `다시 올리기`, 취소면 목록으로 돌아간다. 분석은 비동기(I-14)이며 소요 시간은 라이브러리 선정·실측 전이라 수치를 두지 않는다.

### 5-1. 원본 보관·손실 보고 탭

| 영역 | 내용 |
|---|---|
| 원본 목록 | 파일 이름·해시·크기·버전·보관 시각. 추가 전용이며 수정·삭제 명령이 없다. 해시가 같으면 다시 받지 않는다(ADR-050). |
| 손실 보고서 | 변환마다 1건. 항목 종류·위치·건수·심각도를 표로 보인다. 손실이 없어도 "손실 없음"을 기록해 보인다. 항목 종류는 변환기 포트가 등록한 종류이고 분류 세부 기준은 라이브러리 선정 뒤 설계가 정한다(미정). |
| 확인 | `확인함` 표시(되돌리기 불가). 심각도 높음은 요청자에게 앱 내 알림. |
| 재변환 | `새 매핑으로 다시 변환`(같은 원본에서 새 가져오기 작업). 이전 보고서는 남긴다. |
| 원본+메타 유형 | 정본 형태가 원본+메타인 유형은 메타(제목·버전·단계·작성자·결재)와 함께 이 탭이 유일한 관리 화면이다. |

화면 반응은 권한 판정 결과로만 가른다. 허용이면 생성·확인·재변환 명령을 보이고, 읽기 전용이면 목록과 보고서만 보이며, 거부면 탭을 숨긴다. 권한 코드는 `doc.original.read`·`doc.original.write`(`../10_API설계/doc.md` §12)이고 역할별 기본 대응은 `iam` 역할 시드가 정본이다.

### 5-2. 임의 서식 왕복 시도와 실패 보고 (H-2 화면 요소)

새 화면 ID 는 만들지 않고 SCR-DOC-03 안의 요소로 둔다.

| 요소 | 동작 |
|---|---|
| 왕복 시도 배지 | 판정 단계에서 `pd 템플릿 파일 ✔` 또는 `임의 서식 — 왕복 목표(보장 아님)` 로 구분해 보인다. |
| AI 지원 토글 | 임의 서식 매핑 단계에 `AI 로 매핑 후보 제안` 스위치. 켜기 전에 외부 전송 정책(REQ-39) 요약(전송 대상·마스킹·감사)과 요금제·토큰 한도를 보이고 `동의하고 보내기`를 눌러야 전송한다. 정책이 막거나 한도가 없으면 스위치는 비활성이며 수동 매핑만 쓴다(크레딧 소진 `lic.credit_exhausted`·기능 게이트 닫힘 `lic.feature_unavailable` 는 사유로 표시). |
| AI 제안 표시 | AI 가 제안한 대응은 `AI 초안` 칩으로 구분하고 사람이 하나씩 확정·수정·삭제한다. 확정 전에는 문서가 바뀌지 않는다. |
| 왕복 실패 보고 | 복원하지 못한 항목(손실 항목 종류, 매핑 실패 열)을 표로 보이고 `AI 가 해석 시도했으나 실패` 와 `처음부터 대응 없음` 을 구분한다. 성공으로 가장하지 않으며 `원본 내려받기`·`새 매핑으로 다시 변환`을 함께 둔다. |
| 달성 수준 안내 | 임의 서식의 복원 수준은 실측 전이라 수치를 두지 않는다. 한 줄 안내 "임의 서식은 복원이 목표이며 보장하지 않습니다." |

변환 라이브러리와 LLM 활용 방식의 확인은 `../90_결정관리/03_향후과제_TODO.md` 의 TODO-63(LLM 활용 포함) 에 연결한다. 화면은 라이브러리 선정에 의존하지 않도록 컨트롤 레이어의 명령(`제안 요청`·`확정`)만 호출한다.

### 5-3. 임의 문서 일반 첨부 (H-1)

카탈로그에 없는 임의 문서(예 고객이 준 참고 자료)도 SCR-DOC-03 의 원본 목록에서 `+ 임의 문서 첨부` 로 올린다.

| 요소 | 동작 |
|---|---|
| 첨부 입력 | 파일 선택 + 제목·유형(기타)·단계·작성자 메타. 카탈로그 번호는 기본값으로 선택 항목이다(§1 폼 항목). |
| 보관 | 일반 첨부로 원본+메타 보관(추가 전용, 해시 기록). 구조화 문서로 바꾸지 않는다. 구조화가 필요하면 `가져오기`로 넘기는 링크를 둔다. |
| 구분 표시 | 목록에 `카탈로그` / `임의 문서` 배지를 보인다. 임의 문서는 SCR-DOC-05 의 점검 대상이 아니다. |

## 6. SCR-DOC-04 RFP 프로젝트 생성 마법사·추정 (DOC-06·07, 영업·수주 전)

목적: 입수한 RFP 에서 요구 후보와 기술·솔루션·공수 후보를 받아, PM 이 확인한 뒤에만 프로젝트로 만든다. 기능은 `scoping` 모듈로 옮길 예정이다(D-517, 08·10 `doc.md` 의 이전 예정 절).

해석 고정(03/05 해석 행 H-3): 공수는 AI **추정**이며 PM 이 확인·수정해 확정하기 전까지 확정값이 아니다. 화면의 모든 후보에 `추정`·`AI 초안` 표기를 붙이고, 확정되지 않은 값은 PRE-04·PRE-06 이나 프로젝트에 반영하지 않는다.

```
 ① 입수 문서 → ② 요구 확인 → ③ 추정 확인 → ④ 프로젝트 정보 → 생성
┌ ③ 추정 확인 ─────────────── [AI 초안 · 추정] ───────────────┐
│ 요구 항목        │ 기술·솔루션 후보 │ 직군별 공수(추정)  │ 상태  │
│ R-01 로그인       │ OIDC 연동 …     │ 개발 5.0 / 시험 2.0 │ 초안  │
│  근거: 요구 R-01 · 단가표 v3 · 유사 사례 2건 · 신뢰도 …        │
│ R-02 …           │ …              │ … (수정 가능)       │ 수정중│
├───────────────────────────────────────────────────────────┤
│ 합계(추정): 개발 …M/D … 확정 2 / 5     [하나씩 확정] [제외]    │
│ ⚠ PM 확정 전에는 어디에도 반영되지 않습니다                    │
└───────────────────────────────────────────────────────────┘
```

| 단계 | 동작 |
|---|---|
| ①입수 문서 | PRE-01 의 입수 문서 버전을 고른다. 요구 후보는 PRE-03 결과를 입력으로만 받고 중복 구현하지 않는다. |
| ②요구 확인 | 요구 후보를 PM 이 확정·수정·삭제한다. 확정된 요구가 없으면 추정 요청을 막고 사유를 보인다. |
| ③추정 확인 | DOC-07 결과 표. 행마다 근거(요구 항목·단가표 버전·유사 사례)와 신뢰도를 보인다. 행 상태는 서버 값을 표시 이름(초안·수정중·확정·제외)으로 그린다(상태 값 정본은 `../08_데이터모델/doc.md` §3.8). 정확도 수치는 실측 전이라 약속하지 않는다. |
| ④프로젝트 정보 | PRJ-01 입력(이름·기간·고객)을 받는다. |
| 생성 | 확정 두 단계(요구·추정)를 마친 뒤에만 활성. 확정한 후보만 반영한다. 생성이 끝난 뒤 마법사에는 되돌리는 명령이 없고, 만든 프로젝트는 프로젝트 화면에서 다룬다. |

생성 한 번은 프로젝트 생성(`prj`)과 견적·투입 계획 반영(`pre`)을 함께 일으키는 여러 모듈 쓰기다. 연결 방식(동기 호출·`orc` 사가·이벤트 연쇄)은 `../05_아키텍처/50_Pd_모듈_의존그래프.md` §1 판정표로 정하고 교차 업무 시나리오(`../05_아키텍처/51_Pd_교차업무_시나리오.md` 계열)에 등재한다. 이 등재는 TODO-504 다. 화면 반응은 연결 방식과 무관하게 같다. 생성 중에는 단계별 진행을 보이고, 일부 단계가 실패하면 실패한 단계·이미 반영된 결과의 링크·`다시 시도`를 보인다. 성공으로 가장하지 않는다.

| 조건 | 화면 반응 |
|---|---|
| PM 확인 없이 생성 요청 | 미확정 단계로 이동 |
| 크레딧 없음(`lic.credit_exhausted`) | 남은 크레딧과 회사의 AI 초과 사용 정책(`lic.ai_overage.policy`) 안내 |
| 요금제 미지원(`lic.feature_unavailable`) | 잠금 아이콘 |
| 같은 세션 추정 진행 중 | 기존 진행 표시를 가리킨다 |
| 추정 대기 | 비동기 큐(I-14)·AIP 게이트웨이(I-23). 완료 시 앱 내 알림. 소요 시간 수치 없음 |

마법사 진행 상태 값은 `../08_데이터모델/doc.md` §3.7 이 정본이다. 건너뛴 항목 목록을 마지막 단계에 보인다. 수동 입력(PRE-04·PRE-06)은 이 화면과 무관하게 유지되며 마법사 안에 수동 입력 진입 링크를 둔다. 문서 원문의 학습 사용 금지는 AIP 정책 확인이 필요하다(추정이며 화면은 이를 약속하지 않는다). 수주 전 단계에서만 연다는 제한은 권한 코드 범위로 판정한다(`doc.rfp.*`·`doc.estimate.*`, 이전 예정 → `scoping`).

## 7. SCR-DOC-05 산출물 커버리지 (DOC-08)

목적: 카탈로그의 모든 문서 유형이 기능과 연결되고 프로젝트별로 빠짐없이 관리되는지 점검한다.

```
┌ 산출물 커버리지 ───────────────────────────────────────────┐
│ 대상 (● 카탈로그 ○ 프로젝트[ ▾ ]) 단계[▾]     [점검 실행]   │
├──────────────────────────────────────────────────────────┤
│ 결과: ✖ 실패(미연결 1)   실행 시각 …   카탈로그 판 …         │
│ 번호 | 문서 유형 | 담당 기능 | 변환 | 판정                    │
│ C-01 | 요구사항정의서 | DOC-01·02 | 등록 형식 | 연결됨         │
│ C-03 | 공수 추정      | (비어 있음) |  —  | 미연결 ✖         │
├──────────────────────────────────────────────────────────┤
│ 프로젝트 단계별 누락(프로젝트 선택 시) · 경보                  │
└──────────────────────────────────────────────────────────┘
```

| 점검 | 근거 |
|---|---|
| 담당 기능 칸 비어 있음 → 미연결 | V-1 |
| 담당 기능 ID 가 기능 목록에 실재 | V-2 |
| 변환 칸에 등록된 변환 형식 코드가 없으면 "원본 그대로"이며 DOC-05 포함 | V-4 |
| 추정 공수 행이 DOC-07 포함 | V-5 |
| 프로젝트 단위 단계별 산출물 존재 | DOC-08 처리 5 |

- "100% 소화"는 카탈로그에 적은 산출물이 구조화 문서 또는 원본 첨부+메타 중 하나로 관리됨을 뜻한다(03/05 해석 행 H-1). 카탈로그 밖 문서는 100% 에 포함하지 않으며 화면도 밖 문서를 세지 않는다. 미연결 행이 있으면 점검 결과는 실패로 표시한다.
- 실행은 매번 새 실행으로 남기고 이전 실행과 비교 링크를 둔다. 점검 결과 값의 정본은 `../08_데이터모델/doc.md` §3.9 다.
- 카탈로그 행 추가·수정 UI 는 이 화면에 없다(카탈로그 등록은 §3 의 등록 주체가 한다). 단계 게이트(PRJ-12) 연결은 후보이며 이번에 바꾸지 않는다.
- 없는 프로젝트는 찾을 수 없음 안내, 권한 판정이 거부면 `점검 실행` 을 숨긴다. 누락 경보는 알림 요청 일반 계약(`doc.NotificationRequested`)으로 담당자에게 간다. 받는 사람은 권한 코드 판정으로 정한다.
