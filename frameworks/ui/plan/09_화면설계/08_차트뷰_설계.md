## 1. 목적과 근거자료

- 목적: 간트 외 다양한 뷰와 관리 동작을 제공해 빠른 프로젝트 관리와 분석을 가능하게 한다(사용자 요구 2026-11-04, REQ-58).
- 범위: 뷰는 계열(일정·자원·진척·원가·경영·허브·영업·매트릭스·지식·협업)로 묶는다. 뷰 수는 뷰 등록부의 행 수이고 이 문서에 적지 않는다.
- 뷰는 새 기능 ID 를 만들지 않는다(D-72). 뷰마다 기존 기능의 확장으로 귀속되고, 뷰 카드가 WBS·시험·권한의 추적 단위다(§6, 규칙은 `08c` §5).
- 영업 단계(계약 전) 칸반·파이프라인 차트는 `08e` 에 사례 조사와 카드가 있다(결정 49~52). 칸반 보드는 하나의 공통 보드 컴포넌트를 쓴다(D-104, §3.11).
- 보고서 성격: python-docx 로 생성한 설계 제안서다. 수치와 그림은 가상 데이터이므로 근거로 쓰지 않고 구조·용어·우선순위 제안만 쓴다. 경쟁 제품 표의 출처 URL 은 열어 확인하지 않았다(미확인). 제품별 기능 유무를 사실로 옮기지 않는다.
- 정본과 다르면 정본을 유지하고, 앞당김은 사용자 결정 후보로만 올린다.
- 보강(D-78): CV-01·CV-09·CV-10 은 선행 구문 입력·Task Path 오버레이, 전체·국소 모드, 총여유 ≤ 임계 산식과 일정 근거 패널을 모드로 흡수한다(기존 뷰 모드로 흡수). 상세·판단표 MSP-01~36 은 `08d` 에 있다.
- 간트 끌어서 선행 연결(사용자 요구 2026-11-05, M1): "네트워크 다이어그램 처럼 간트에서도 작업을 끌어 선행관계 연결편집이 가능해야한다". 규칙은 `08a` CV-01 과 `08d` §3.1 에 있다. CV-09 네트워크 편집과 간트 쪽 끌어 연결의 단계는 뷰 등록부를 따른다(D-82).
- 재결정하지 않는 것: SCH-07 보기 규칙, DSH-01 위젯 규칙, ADR-046 캐시, ADR-047 차트 라이브러리, D-51 간트 직접 그리기. 이 문서는 인용만 한다.
- Mars 코드·화면은 복사하지 않는다(ADR-036).

## 2. 뷰 등록 규격 (등록형, D-509)

- **등록 주체·자리:** 뷰는 소유 모듈이 모듈 선언서의 '화면과 메뉴' 항목에 올린다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §3.1 선언서 표, §7 화면 확장 자리). 새 솔루션이 차트·보드를 더할 때 이 문서와 다른 모듈 문서를 고치지 않는다.
- **뷰 정의:** 번호(CV), 이름, 계열, 소유 모듈, 귀속 기능, 화면 ID, 그리기 구분(공통 차트 `ChartSpec` 값·공통 보드 플러그인·시간축 렌더러 플러그인·예외와 사유), 데이터 원천(모듈과 계약 ID), 폼팩터 값, 단계다. 칸의 뜻은 `08_차트뷰_설계_2.md` §1 이다.
- **보기 대상 종류:** 뷰를 저장 보기로 남기려면 소유 모듈이 보기 대상 종류와 구성 형식을 선언한다(§3.2).
- **뷰 등록부:** 선언에서 모은 파생 표가 `08_차트뷰_설계_2.md` §2 다. 단계·폼팩터 값의 정본은 그 표의 칸이다.
- **허용에 없을 때:** 소유 모듈이 테넌트 허용에 없으면 뷰가 없다. 데이터 원천 모듈 일부가 허용에 없을 때는 §3.9 를 따른다.
- **번호:** CV 번호는 발급 순서대로 붙이고 불변이다. 다음 번호는 `08f` §4 가 관리한다(53_2 §5 의 CV 접두).

## 3. 뷰 공통 구조

### 3.1 레이어 분리

UI 레이어는 그리기와 입력만 맡는다. 컨트롤 레이어는 뷰 상태·명령·선택 동기화를 맡고 Avalonia 에 의존하지 않는 C# 라이브러리로 둔다. 데이터 레이어는 서버 API·읽기 모델·캐시를 맡는다. 차트 라이브러리는 `IChartAdapter` 만 거친다(ADR-047). 시간축 뷰는 같은 시간축 렌더러(줌·가상 스크롤·구간 선택·드래그)를 공유하고 막대 의미만 뷰별 플러그인으로 바꾼다(ADR-077, §3.11·§5). 줌 단계는 설정 키 후보 `ui.timeline.zoom_levels`(목록 값, 기본값 일·주·월·분기(후보), 회사·사용자 옵션, ADR-089)이고, 로드맵의 연 단위는 그 목록에 더할 수 있는 값이다. 저장 보기에는 선택한 확대 단계가 남는다(보고서 RP-37). PoC·시험 코드에도 같은 분리를 적용한다.

### 3.2 뷰 저장·공유

- 저장 보기(개인·공유 보기 설정)는 공통 기반의 일반 계약 한 벌 `plt.saved_view` 를 쓴다(D-523, 데이터 `../08_데이터모델/plt.md` §3.9, API `../10_API설계/plt.md`). 소유 모듈은 보기 대상 종류(`view_target`)와 보기 종류별 구성 형식을 선언서로 등록하고, 뷰 종류 값도 그 모듈이 등록한다(`sch` 는 `../08_데이터모델/sch.md` §3.5). 다른 모듈의 뷰를 더할 때 `sch` 스키마를 고치지 않는다.
- 분석 차트의 위젯 정의는 `rpt.widget_def`(DSH-01)가 갖고, 저장 보기는 위젯을 가리키는 설정만 둔다.
- 공유 보기는 소유자만 고치고 지운다. 저장 필터는 ISS-12 PQL 과 결합한다.
- **외부 참여자:** 외부 참여 세 경로(교차 테넌트·게스트 계정·공유 링크, `15_외부참여_공유링크_화면설계.md`)마다 범위가 다르다. 교차 테넌트 참여자와 게스트 계정은 공유된 프로젝트의 공유 보기만 읽기로 연다(D-76). 공유 링크로 연 사람은 링크가 가리키는 보기 하나만 읽기로 보고 다른 보기로 옮기지 못한다(후보). 판정은 `iam` 권한 코드와 공유 링크 범위가 하고 화면은 결과만 그린다.

### 3.3 필터·기간 공유

컨트롤 레이어에 `ViewContext`(프로젝트·조직·기간·기준선·권한 범위, 후보 — 선택 작업 ID 집합(선택)·의존선(종속성) 표시 여부) 하나를 두고 모든 뷰가 구독한다. 같은 문서 창 안에서 뷰를 바꿔도 이 값은 유지된다(보고서 RP-35). 문서 창(MDI) 단위가 기본이다. 창 사이 공유는 사용자 옵션 후보다.

### 3.4 뷰 간 이동·드릴다운

뷰 안 이동은 `(viewKind, scope, selection)` 을 컨트롤 레이어 상태로 넘긴다. 주소(딥링크) 꼴은 클라이언트 계약이며 `04_웹_화면설계.md` W-05 가 가리키는 자리를 따른다. 차트와 표는 선택을 양방향으로 맞춘다. 경로 예는 포트폴리오 버블 → 프로젝트 상세 → 간트 → 이슈다. 이동해도 `ViewContext` 는 유지한다.

### 3.5 실시간 갱신

일정 뷰는 프로젝트 실시간 그룹으로 받은 작업만 갱신한다(SCH-02). 실시간 그룹 종류와 이름 규칙의 정본은 `../10_API설계/00_공통규약.md` §10 이다. 위젯은 허브 메시지를 받은 것만 다시 읽고 최소 간격은 `rpt.widget.refresh_min_seconds`(운영 값, 선언 `../10_API설계/rpt.md` 설정 키 절)다. 분석 차트는 읽기 모델 프로젝션을 쓰므로 "n분 전 기준"(`asOf`)을 표시한다.

### 3.6 낙관적 잠금

쓰기는 `rowVersion`·`If-Match` 를 쓴다. 412 면 최신 목록을 함께 돌려준다(공통규약). 일괄 변경 상한은 `sch.task.bulk_max`(운영 값, 선언 `../10_API설계/sch.md` 설정 키 절)다. 드래그가 충돌하면 서버 판정이 최종이다(D-51).

### 3.7 내보내기

DSH-04 를 확장한다. DSH-04 의 현행 형식은 `xlsx`·`pdf` 이고 이 둘은 그대로 둔다. 현재 뷰 상태는 PDF·PNG·CSV 에 PPTX 를 더해 내보낸다(D-75). PPTX 생성 방식과 라이브러리는 정해지지 않았고 착수 전에 오픈소스·무료 기준으로 고른다. 승인 시점 스냅샷을 기준선(SCH-04)·APR 과 연계하는 것도 후보이며 TODO-173 으로 추적한다(보고서 RP-40). 권한 밖 열은 파일에서 뺀다(DSH-04 기존 규칙).

### 3.8 AI 활용

지표 계산은 결정적 로직이다. AI 는 설명·이상 징후 요약·예측 제안만 맡고 실행은 사람이 확정한다. 카드의 AI 활용 칸은 ADR-073 규격(`06_AI_활용_전수_요구.md`)을 따르며 보조일 때는 사람 확인 지점을 적는다. 효과 수치는 쓰지 않는다. CV-25 의 예측 모형(통계 대 LLM)은 그 뷰 단계 착수 전에 결정하며(D-73) 외부 전송은 REQ-39 를 따른다.

### 3.9 표시 판정·권한·감사

- 뷰를 보일지는 테넌트 허용 → 기능 게이트 → 권한 코드 순서로 가른다(판정 순서 `../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §8, 화면 표시 판정식 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §3).
- 소유 모듈이 허용에 없으면 뷰를 메뉴·뷰 전환 목록에 두지 않는다.
- 데이터 원천 모듈 가운데 일부가 허용에 없으면 그 원천의 시리즈·열만 빼고 남은 원천으로 그린다. 범례에 빠진 원천을 '사용하지 않는 모듈'로 표시해 빈 값과 구별한다. 모든 원천이 없으면 뷰를 숨긴다. 원천이 있으나 지표 값이 없으면 빈 결과로 그린다.
- 요금제 게이팅은 기능 게이트를 따른다. 등급별 값은 기능 등록부(`../06_기능목록/기능목록.csv` 요금제 열)와 `lic` 권리 묶음 시드가 정본이다(`../03_개발범위/20c_Pd_솔루션기획안_요금_패키징_AI과금.md`).
- 손익 열은 필드 인가로 제거한다(DSH-02). 민감 읽기는 감사한다(DSH-02 손익 열 조회). 뷰를 바꿔도 권한 범위는 같은 원본 모듈 권한으로 다시 거른다(DSH-01).

### 3.10 폼팩터

용어와 규칙은 [`../05_아키텍처/08_지원_폼팩터_용어.md`](../05_아키텍처/08_지원_폼팩터_용어.md) 를 따른다. 스마트폰은 NAV 고정이고 간트는 기간 막대 목록으로 보인다(SCH-02). 태블릿은 DOCK 기본으로 터치 핸들 크기를 확보한다. PC 형(MDI)은 전 기능을 편집한다. 웹은 같은 렌더러(Avalonia.Browser)에 가상화를 필수로 쓰고 브라우저 단축키 제약을 따른다(08 §7-3).

- 뷰별 폼팩터 값은 뷰 등록부(`08_차트뷰_설계_2.md` §2)의 칸이 정본이다. 기호는 `02_메뉴구조.md` 정의와 같다(○ 전체 기능, △ 조회·간단 처리만, ✕ 메뉴에 두지 않음).
- 뷰 값은 그 뷰를 여는 화면의 노출 값(메뉴 생성기 데이터)을 넘지 않는다. 화면 노출 값을 바꿀지는 `06_모바일_화면설계.md` §5.1 의 TODO-503 이다.

### 3.11 공통 차트 컴포넌트와 설정·파라미터 원칙 (결정 54·52, ADR-091)

사용자 원문(결정 54): "차트 대부분은 하나의 공통 컴포넌트를 만들자. 대신 다양하게 변화가 가능하도록 설정이나 파라미터로 조절이 가능하도록 하자". 결정 52(칸반 공통)와 같은 방향이다. 옵션화 대원칙(결정 86, ADR-089)에 따라 아래 값은 기본값이며 회사 설정으로 바꿀 수 있다.

- **공통 차트 컴포넌트 1개:** 차트 종류(막대·선·영역·산점·버블·히트·퍼널·폭포 등)·축·시리즈·색·범례·툴팁·드릴다운·내보내기를 `ChartSpec`(설정 JSON) 하나로 받는다. 뷰마다 새 컴포넌트를 만들지 않고 `ChartSpec` 값과 데이터 바인딩만 바꾼다. 형식은 `rpt.widget_def` 설정 스키마와 같다.
- **UI 레이어 소속:** 컴포넌트는 그리기·입력만 맡는다(3.1). 지표 계산은 서버 읽기 모델·컨트롤 레이어가 하며 컴포넌트는 `IChartAdapter`(ADR-047)만 거친다.
- **파라미터로 바꾸는 것:** 기간·기준선 유무·집계 단위·정렬·임계선·색 규칙·표시 항목. 값 층 해석은 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §5 를 따르고 허용 층은 회사·하위 범위·사용자다. 파라미터 묶음은 설정 키 후보 `ui.chart.params`(구조 값, 대상 열 = 뷰 번호)로 키 등록부에 올린다. 열거할 수 없는 새 차트 종류는 어댑터 확장으로 더한다.
- **칸반 공통 컴포넌트 1개(결정 52, D-104):** 보드를 쓰는 화면은 모두 하나의 보드 컴포넌트를 쓰고 보드마다 다른 것은 보드 플러그인으로 등록한다. 보드를 쓰는 자리는 닫힌 목록이 아니다. 플러그인 규격과 등록 방법의 정본은 `08e` §5 이다.
- **그리기 구분의 판정:** 원칙은 "공통이 기본, 예외는 근거를 적는다"이다. 뷰마다의 구분은 뷰 등록부의 '그리기' 칸이 정본이고 최종 판정은 PoC 실측 뒤 정한다. 예외의 근거는 다음과 같다.
  - 직접 그리기(간트·리소스 스케줄러): 막대 드래그 편집·의존 연결·서버 재계산 왕복이 있다(D-51).
  - 그래프 레이아웃(의존성 네트워크·크리티컬 패스): 노드·간선 배치와 선행 편집이 필요해 일반 차트 시리즈로 표현할 수 없다.
  - 시간축 렌더러: 시간축 줌·가상 스크롤·드래그가 필요해 분석 차트 컴포넌트와 성격이 다르다(ADR-077).
  - 손익 Waterfall: 두 라이브러리에서 전용 Waterfall 시리즈를 못 찾았다(§5). 누적·범위 막대로 대체 구현 가능성은 `../01_시장조사/11_공급자API_차트_조사.md` §D-131 에 있다. 되면 공통, 아니면 직접 그리기다(D-131, 라이브러리 PoC 로 확인).
  - 캘린더는 월·주 격자 위젯(COL-13 공유)이고, AI 예측 타임라인은 시간축 위에 예측 구간을 얹는 시간축 계열이다. 보류 뷰는 판정하지 않는다.
- 예외 뷰도 데이터 경로·권한·내보내기·딥링크(3.2~3.9)는 공통 규칙을 그대로 쓴다. 예외를 줄이는 방향으로 PoC 결과에 따라 등록부를 갱신한다.

## 4. 대량 데이터 방침과 성능 목표

### 4.1 방침

1. 서버 집계를 우선한다. 클라이언트에는 원자료 대신 뷰포트(가시 구간+버퍼) 데이터와 점 수 상한이 있는 집계를 보낸다.
2. 시계열은 서버의 일·주 단위 읽기 모델(rpt 프로젝션·스냅샷)에서 읽고 전체 재계산을 피한다(ISS-10·FIN-04 방식).
3. 점·행이 많으면 구간 다운샘플을 쓴다. 방식은 구현 때 고른다(후보).
4. 행과 막대는 가상화해 가시 영역만 그린다(D-51).
5. 목록은 커서 페이지로 준다.
6. 캐시는 ADR-046 을 따른다. 서버 뒤 cache-aside, 태그 버전 무효화, 인증 응답 앞단 저장 금지다. 닫힌 스프린트처럼 불변인 결과는 오래 둔다(ISS-10).
7. 무거운 재계산(평준화·S-Curve 재생성)은 작업 큐로 비동기 처리하고 진행률을 보인다.
8. 웹 WASM 은 가상화와 점 상한을 더 엄격히 한다.

## 6. 기능 ID·화면·WBS 영향

- **기능 ID:** 차트뷰가 만드는 기능 ID 는 없다(D-72). 후보였던 SCH-10 "일정 뷰 확장 묶음"은 만들지 않는다. 근거는 사용자 기준(원칙·변경 대응 우선)이며 대신 뷰 카드를 추적 단위로 둔다.
- **추적 단위:** 뷰 카드마다 WBS 행·시험 묶음·권한 대조의 단위가 된다. 규칙 1~6 은 `08c` §5 가 정본이고 대조표는 카드 문서(`08a` §3·`08f` §4)에 있다.
- **기존 기능 확장:** 뷰가 확장하는 기능 ID 는 뷰 등록부의 '귀속 기능' 칸이다. 각 기능 부록에는 "차트뷰 연결" 한 줄만 더하고 본문 구조·수용 기준은 바꾸지 않는다.
- **화면:** 차트뷰 전용 화면 SCR-SCH-04(로드맵·스윔레인)와 SCR-DSH-04(분석 차트), "분석" 메뉴 그룹을 둔다(D-67). 화면 수와 화면의 단계·노출 값은 메뉴 생성기 데이터(`../_build/menu_data.py`)와 생성물 `02_메뉴구조.md`·`메뉴구조.csv` 가 정본이다. "분석" 메뉴 그룹은 기존 화면 링크 모음이고 하위 묶음과 링크 화면의 정본은 `02_메뉴구조.md` §2.1(생성원 `../_build/menu_data.py` LINK_GROUPS)이다. 바로가기라 새 메뉴 ID 는 없다(결정 112-16 선례). 영업 차트는 기존 SCR-CRM-01·SCR-CRM-02 안에 둔다.
- **WBS:** 차트뷰 작업의 WBS 행과 추정 인일의 정본은 `../03_개발범위/30_Pd_WBS_기반_M1.md`(WBS-M1-31)·`../03_개발범위/30a_Pd_WBS_M2_M3_확장.md`(WBS-M2-33)·`../03_개발범위/30b_Pd_WBS_M4_출시뒤X_게이트.md`(WBS-M4-26)다. 카드마다 행을 둘지 묶음 행을 둘지는 WBS 쪽에서 하나로 정하며 TODO-506 이다(재산정은 TODO-81). WBS 행은 뷰 등록부의 '단계' 칸을 가리킨다.
- **보고서 단계 환산:** 보고서 1차는 M1·M2 일부, 2차는 M2, 3차는 M3·M4 로 읽는다. 보고서 1차의 스윔레인·리소스 스케줄러를 M1 로 당기면 SCH-06 단계와 충돌하므로 당기지 않는다.
- **ADR:** ADR-076 차트뷰 체계, ADR-077 시간축 렌더러 공통화, ADR-078 지표 사전 단일화, ADR-079 분석 차트 데이터 경로·대량 데이터 방침이다. 본문은 `../90_결정관리/02_결정기록_부록/b9_ADR-076_079.md` 에 있다. 결정 52·54 는 ADR-091(차트·칸반 공통 컴포넌트), 결정 49~51 은 ADR-092(영업 차트 채택·릴리스·예측 범주)이며 본문은 `../90_결정관리/02_결정기록_부록/b14_ADR-091_092.md` 에 있다.
