# 데스크톱 화면 설계 — Windows·macOS 앱

> 공통 규칙은 `01_화면설계_공통원칙.md`, 메뉴·화면 목록은 `02_메뉴구조.md`(생성물), 창 크롬 수치는 `../04_기술스택/05_창크롬_OS디자인_기준.md` 를 따른다. 결정은 ADR-052.
> 와이어프레임은 `img/desktop_shell.svg`(MDI 기본 셸)와 `img/desktop_sdi.svg`(독립 창·분할)다. 크기 1280×800, 한국어 라벨이다.
> 대상 폼팩터는 데스크톱(Windows·macOS)과 같은 셸을 쓰는 태블릿 앱(DOCK 기본)이다. macOS 는 실기가 없어 미검증이다(`../05_아키텍처/08_지원_폼팩터_용어.md` §2).
> 이 문서는 사용자가 보는 동작과 판정 기준만 둔다. 측정 기록은 `../04_기술스택/04_판정보고서_부록/`, 합격 기준 수치는 `../04_기술스택/03_PoC_UI_합격기준_Mars실측.md`, 구현 위치와 진단 도구는 `../../poc/ui/README.md` 에 둔다.
> 설정 키는 이름만 적는다. 선언(값 꼴·기본값·값 분류·허용 층·저장 위치)은 `../10_API설계/plt_2.md` §12.1 이다. 이 문서에서 처음 쓰는 키는 §10(`03_데스크톱_화면설계_2.md`)에 모았다.

## 1. 셸 구성 (MDI 기본 — `img/desktop_shell.svg`)

```
┌ 메뉴 줄 ──────────────────────────────────────────────────────────────┐
│ [로고] 파일 창 보기 시스템 …… [자동][PC형][태블릿형][모바일형] [테마] [_][□][X] │
├ 제목 줄(탭 줄) ─────────────────────────────────────────────────────────┤
│ [홈 대시보드][이슈 목록 ✓][WBS·간트][(최소화) 주간보고] … ▔ 스크롤 선  [◫][◫] │
├──────────┬──────────────────────────────────────────────┬─────────────┤
│ 패널 자리  │  MDI 문서 영역 (떠 있는 문서 창, 그림자)          │ 패널 자리     │
│ (예 탐색기)│   ┌ 이슈 목록 ───────────[핀][위][_][□][X]┐     │ (예 알림)     │
│           │   │ 필터 · 목록 그리드 · 상세 미리보기     │     │             │
│           │   └────────────────────────────────────┘     │             │
├──────────┴──────────────────────────────────────────────┴─────────────┤
│ 하단 패널 자리(예 로그 · 메신저 탭, 1/2 분할 가능)                          │
└──────────────────────────────────────────────────────────────────────┘
```
- 메뉴 줄(호칭 정본 08 용어 §8-1)은 로고·셸 메뉴·빈 공간·UI 방식 아이콘 4칸·테마 아이콘·캡션 버튼을 한 줄에 둔다.
- 테마 아이콘은 최소화 버튼 바로 왼쪽이다. 라이트/다크를 바꾸며 어두우면 해, 밝으면 달 그림이다.
- 테마 아이콘 왼쪽에 [자동]·PC형·태블릿형·모바일형 4칸 아이콘이 온다. 아이콘은 직접 만든 벡터이고 이름은 툴팁으로 보인다.
- [자동]을 켜면 판정된 칸이 옅게 강조되고 창 폭에 따라 방식이 바뀐다(§2). 자동 상태에서 나머지 3칸을 누르면 자동이 풀리고 그 방식으로 바뀐다(공통원칙 §2-1).
- 도구모음 줄과 리본은 두지 않는다. 설정은 시스템(Y) ▸ 설정이고, 문서별 명령은 문서 창 안 도구 영역과 우클릭 메뉴에 둔다. 'Pd' 글자는 두지 않는다.
- 시스템 메뉴의 디버그모드와 메뉴 ID 표시는 dev·staging·qa 채널에만 있고 prod 채널에는 없다(`ui.debug_mode.default_channels`·`ui.menu_id.visible_channels`, ADR-090).
- 제목 줄은 떠 있지 않은 열린 문서를 제목 탭으로 보인다. 줄 높이·탭 높이·탭 폭과 좁을 때 줄이는 규칙의 정본은 공통원칙 §2-1 이다.
- 제목 탭은 활성(강조 배경+반전 글자)·비활성(기본)·최소화(흐린 글자)를 색으로 구분한다. 하단 최소화 표시줄은 없다.
- 탭이 넘치면 얇은 스크롤 선만 보이고 hover 때 굵어진다. 잘린 제목은 말줄임이다.
- 모든 제목 탭은 전체 제목 툴팁을 띄운다. 툴팁을 띄우지 않는 것은 제목이 빈 값일 때뿐이다. 탭 hover 는 탭 전체 사각형에 배경을 칠한다.
- 독립 창(SDI)은 제목 탭에 두지 않고 제목 줄 오른쪽 끝의 작은 아이콘으로 보인다. 활성·비활성·최소화를 구분하고, 툴팁은 창 이름이다.
- 독립 창 아이콘을 누르면 그 창이 활성화된다(최소화면 복원). OS 전경이 그 독립 창으로 바뀌고 독립 창 제목 줄이 활성 색, 메인이 비활성 색이 된다.
- 알림 배지는 알림 패널이 집중 숨김·닫힘일 때 새 알림이 오면 상태 표시줄에 보인다. 누르면 패널이 드러나고 읽으면 0 이 된다.
- 터치 기기(Windows 터치 노트북 포함)에서는 패널 모서리 버튼을 항상 표시한다(공통원칙 §4.4).
- 메인 창 맨 아래에 상태 표시줄 한 줄을 둔다. 문서 수·활성 문서 제목·상태 문구·알림 배지·활성 창 배율·프로젝트 선택을 보이고, 좁으면 항목 단위로 다음 줄에 내린다.
- 상태 표시줄에는 연결 상태·서버군·사용자를 두지 않는다. 이 셋은 시스템(Y) 메뉴의 프로그램 정보에서 본다(§1.2).

### 1.1 패널 자리와 패널 등록

- 셸은 패널 자리만 갖는다. 패널 자리는 상·하·좌·우 가장자리이고 가장자리마다 여러 줄을 둘 수 있다.
- 패널은 두 종류다. 셸 소유 패널은 탐색기(업무 메뉴 트리)와 로그다. 그 밖의 패널은 모듈이 모듈 선언서로 등록하는 기여 패널이다(`../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §3·§8).
- 기여 패널의 예는 알림 센터(SCR-COL-01), 메신저(SCR-COL-02), 사용법 챗봇(AIN-09), 실시간 STT 회의(COL-16), 제안함(AIN-08)이다.
- 기여 패널은 표시 판정(30 §3)이 참일 때만 보인다. 기여 모듈이 테넌트 허용에 없으면 그 패널은 패널 자리와 보기 메뉴에서 빠진다.
- 패널 등록 항목은 불변 패널 ID·표시 이름(번역 키)·기본 가장자리·같은 가장자리 안 순위 값·기본 열림 여부다(항목은 후보).
- 같은 가장자리에 패널이 둘 이상이면 순위 값 순서로 바깥부터 놓는다. 셸 기본 구성은 탐색기 왼쪽, 알림 오른쪽, 로그와 메신저 아래다.
- 레이아웃 저장 파일은 패널을 불변 패널 ID 로 가리키고 형식 판 번호를 갖는다. 새 판은 옛 판 읽기를 유지한다(`../05_아키텍처/52_Pd_계약버전_규칙.md` §1.1).
- 패널은 상·하·좌·우 어디에나 붙고, 문서 창을 끌어 탭으로 합치거나 가장자리에 놓아 1/2 로 나눈다(공통원칙 §4.4). 패널 위치 메뉴는 §7.3 이다.

### 1.2 계정·테넌트와 서버군

- 데스크톱 앱은 서버군을 고르지 않는다. 로그인한 계정의 테넌트로 라우팅 계층이 서버군을 정한다(`../05_아키텍처/06_서버군_리전_라우팅.md` §5·§6.2).
- 서버군 선택은 가입 화면에서 업체관리자가 하는 일이다(06 §5). 로그인 화면에는 서버군 선택이 없다.
- 현재 서버군 이름은 프로그램 정보에 진단용으로 보인다. 표시 문구는 `ui.label.cell` 이다.
- 테넌트가 다른 서버군으로 옮겨지면 클라이언트가 기억한 서버군은 '이동됨' 응답으로 고쳐진다(06 §6.2). 사용자 조작은 없다.
- 한 사용자가 서로 다른 테넌트에 속하면(교차 테넌트 초대, 결정 124) 앱은 한 번에 한 테넌트로 일한다. 테넌트를 바꾸면 그 테넌트의 서버군으로 다시 연결하고 레이아웃은 테넌트마다 따로 복원한다(후보).

## 2. 방식 전환 — MDI·DOCK·NAV (ADR-051)

| 방식 | 문서 표시 | 탐색기 | 기본 대상 | 전환 수단 |
|---|---|---|---|---|
| MDI | 떠 있는 문서 창 + 독립 창(SDI) | 좌측 패널(서랍) | Windows·macOS 앱 | 보기 ▸ 화면 방식, 제목줄 |
| DOCK | 가운데 문서 탭(탭 문서) + 상·하·좌·우 패널 | 좌측 패널(서랍) | 태블릿 앱 | 같음 |
| NAV(대화면) | 좌측 메뉴 + 오른쪽 콘텐츠 1개, 상단 열린 화면 목록 | 좌측 메뉴 | 선택 | 같음 |

- DOCK(태블릿형)에서는 문서 탭이 열린 문서 목록을 맡으므로 제목 줄의 제목 탭을 숨긴다. 문서 탭은 분할·끌기·우클릭 '분할 해제'를 가진다.
- DOCK 에서 독립 창 아이콘이 있으면 제목 줄은 아이콘만 남고, 없으면 줄을 숨긴다. MDI 는 그대로다.
- 전환해도 열린 문서·보던 문서·입력 중 내용·스크롤을 유지하고, 방식별 레이아웃을 따로 저장·복원한다(REQ-46-6·7).
- 창 메뉴 '탭 문서로 전환'과 보기 프리셋('MDI 계단식·탭 문서·MDI 세로 바둑판')은 MDI·DOCK 안의 배치 바꾸기다. 방식 전환과 다르다.
- 데스크톱 앱 창을 좁혔을 때의 방식은 공통원칙 §8 자동 전환 규칙을 따른다. 경계 폭·히스테리시스·디바운스는 `ui.layout.expanded_width_dp`·`ui.layout.compact_width_dp`·`ui.layout.switch_hysteresis_dp`·`ui.layout.switch_debounce_ms` 다.
- 수동으로 고른 방식은 창 폭과 무관하게 유지한다.

## 3. MDI 문서 창·독립 창(SDI)

### 3.1 MDI 문서 창
- 캡션 버튼은 [_ 최소화] [□ 최대화·복원] [X 닫기]다. 핀 고정(위치 고정)과 항상 위는 캡션이 아니라 기능 버튼 줄의 별개 토글이다.
- 아이콘은 직접 만든 벡터다. 호버·누름·켜짐 표현은 공통원칙 §4.2 상태 표를 따른다.
- MDI 문서 창에는 앱 로고가 없고 제목은 왼쪽 여백 8px 에서 시작한다. 이 여백은 창 크롬 수치이며 수치의 정본 자리는 04/05 다.
- 창 메뉴(제목줄 우클릭·로고 클릭·Alt+-)는 §7.2 공통 항목 뒤에 독립 창으로 분리·다른 창 닫기·분할·정렬·문서 배치 항목을 둔다.
- Mars 윈도우 메뉴 13항목은 '창(W)'과 '창 옵션'에 모두 둔다.
- 문서 창을 MDI 영역 밖이나 패널 쪽으로 밀어도 축마다 '잔존 비율 × 창 크기'와 잡을 곳 규칙 중 큰 값만큼은 보인다. 잔존 비율은 `ui.mdi.min_visible_percent` 이고 0 이면 잡을 곳 규칙만 쓴다.
- 잡을 곳(끌 수 있는 제목 구간)은 `ui.mdi.min_grab_dp` 이상 보여야 한다. 기능 버튼·캡션 버튼만 남고 잡을 곳이 없는 상태는 금지한다.
- 위쪽은 제목 줄이 사라지지 않게 멈춘다. 창이 밀려 기능 버튼 줄이 잡을 곳을 가리면 그 줄을 접는다.
- 끌기 경계·잔존·줄 접기의 계산식과 값의 범위는 공통원칙 §4.3 이 정본이다. 값을 바꾸면 왼쪽 한계·줄 접기 경계·독립 창 진단의 잡을 곳 기준이 함께 바뀐다.
- 이 규칙의 합격 판정은 잔존과 잡을 곳 하한을 지키는지다. 기준은 완화하지 않으며, 시험 도구는 고정 수치가 아니라 현재 설정값으로 기대값을 계산한다.
- 독립 창으로 분리한 문서도 잡을 곳 폭과 기능 버튼 줄 접힘 여부를 진단 조회로 읽을 수 있어야 한다. 판정 기준은 MDI 와 같은 `ui.mdi.min_grab_dp` 다. 화면 밖이나 최소화 상태면 마지막 상태를 내고 창 상태로 구분한다.
- 끌기 중 가벼운 크롬의 규칙과 옵션은 `01a_화면설계_공통원칙_끌기경량크롬.md` 가 정본이다.
- MDI 끌기 프레임 성능의 합격 기준은 04/03 의 MDI 창 20개 끌기 행(PERF-02)이고 판정 결과는 판정 보고서 부록에 있다. 측정을 통과시키려고 프레임을 일부러 만드는 변경(렌더 루프 유지 등)은 하지 않는다.
- 비전경 시험 기동(`--bg`)에서는 메인 창도 활성화 없이 떠야 한다. 판정 조건은 판정 보고서 부록 a7 의 비활성 조작 행이 정본이다. 제품 일반 기동은 바꾸지 않는다.
- 하단 로그 패널은 채널에 따라 기본 표시가 다르다. 채널별 표시의 정본은 ADR-090 채널별 표이고, 보기 메뉴의 로그 항목은 지금 표시 상태와 일치해야 한다.
- **MDI 탭 묶음 창.** 공통원칙 §4.4 창 탭 합류로 MDI 창 둘 이상을 묶으면 MDI 창 하나가 된다. 제목 줄은 활성 탭 문서의 제목이고, 제목 줄 아래에 독립 창과 같은 모양의 문서 탭 줄이 생긴다.
- 묶음 창의 캡션 버튼·기능 버튼 줄·끌기 경계·잔존 비율은 보통 MDI 창과 같다.
- 탭 줄의 각 탭 X 는 그 탭 문서만 닫는다. 묶음 창 캡션의 닫기 버튼은 묶음 안의 문서를 모두 닫는다(Windows·브라우저 탭 관례).
- 탭을 닫거나 끌어내 1개만 남으면 묶음이 풀려 같은 위치·크기의 보통 MDI 창이 된다. 탭 클릭으로 활성 문서를 바꾸고, 탭을 묶음 밖으로 끌면 MDI 창이 된다.
- 탭을 끌어내 분리한 창은 활성 창이 되어 맨 위에 온다(공통원칙 §4.4 7항). 창 메뉴 목록과 제목 탭 띠에는 묶음 안 문서가 하나씩 보인다.
- 끄는 동안 합류 표적과 '탭으로 합치기' 아이콘의 표시·강조는 공통원칙 §4.4 와 01a §2 를 따른다. 끄는 창 자신은 합류 표적 위에 있는 동안 반투명(`ui.mdi.tab_join.source_opacity`)으로 보여 아래 표적이 비친다.
- 끌어서 창 배치(상단 막대·가장자리·모서리)는 `11_창배치_스냅레이아웃.md` 를 따른다.

### 3.2 독립 창(SDI) — `img/desktop_sdi.svg`
- 문서 창을 앱 창 밖 OS 창으로 떼어 낸다(창 ▸ 독립 창 ▸ 분리, 또는 탭을 앱 밖으로 끌기). 다른 모니터로 옮길 수 있다. 독립 창도 MDI 방식에 속한다(ADR-051).
- 독립 창은 앱 로고를 표시한다. 로고 클릭은 창 메뉴, 더블클릭은 닫기다(Windows 관례).
- 독립 창에 문서 2개 이상을 합치면 제목줄 아래 문서 탭 줄이 생기고, 1개면 숨긴다.
- **창 탭 합류.** 다른 독립 창을 끌어 이 창의 로고(창 아이콘 칸)나 탭 줄 위에 머문 뒤 놓으면 탭으로 합쳐지고 끌던 창은 닫힌다. 머무름 시간과 판정 규칙의 정본은 공통원칙 §4.4 다.
- 겹치기만 해서는 합쳐지지 않는다. 끄는 동안 머무는 표적이 강조되고, 다른 독립 창 로고 칸에는 앱 로고 대신 '탭으로 합치기' 아이콘이 같은 중심에 보인다.
- 데스크톱 독립 창 끌기는 OS 이동 루프라 앱이 포인터 이벤트를 받지 못한다. 그래서 OS 의 창 이동 알림 때 커서 위치를 읽어 표적을 판정한다. OS 에 묶인 처리는 데스크톱 계층에만 둔다.
- 독립 창은 메인 창을 소유자(owner)로 삼지 않는다. 메인을 최소화해도 독립 창은 그대로 보이고, 작업표시줄에 따로 표시된다.
- 앱은 클라이언트 프로그램 식별자(Windows 는 AUMID)를 명시해 같은 프로그램·같은 채널의 창이 작업표시줄 버튼 하나에 묶이게 한다. 명시하지 않으면 OS 가 휴리스틱으로 정한다(Microsoft Learn AppUserModelIDs, 공식 확인).
- 클라이언트 프로그램 식별자는 제품 표시 이름과 떼어 프로그램 코드와 빌드 채널로 만든다(꼴은 후보). 한 PC 에 dev·qa·prod 채널을 함께 깔아도 채널마다 버튼이 따로 묶인다. 식별자는 배포 뒤 바꾸기 어려운 안정 식별자이며 정본 자리는 `../05_아키텍처/05_제품구성_시스템메뉴.md` 다.
- 설정 **항상 메인 창 위**(기본 켬)는 창별 **항상 위**(OS 최상위)와 별개다. 켜면 메인 창을 활성화해도 메인이 독립 창과 그 그림자 아래에 머물고, 끄면 클릭한 창이 위로 온다.
- 메인이 최소화되면 독립 창은 반응하지 않는다. 앱 종료·트레이 숨기기/보이기 때 독립 창도 함께 처리하며 소유 관계는 되살아나지 않는다.
- 'MDI로 재결합'은 원래 MDI 위치로 돌려보낸다. 독립 창 모두 최소화·복원·닫기·위치 초기화는 창 메뉴에서 한다.

### 3.2.1 기본 창 동작 (메인·MDI·SDI 공통)
- 제목줄 더블클릭은 최대화↔복원이다. 메인·SDI·MDI 모두 같다. MDI 는 두 번째 누름으로 판정해 끌기 시작과 겹치지 않게 한다.
- 최대화한 창의 제목줄을 끌면 이전 크기로 복원된다. 커서는 제목줄의 같은 가로 비율 위치에 남고, 끌기는 놓을 때만 끝난다. 메인·SDI 는 OS 가, MDI 는 앱이 처리한다.
- 최소 크기는 모든 창이 같은 규칙을 쓴다. 폭은 캡션 3버튼·로고 칸·제목 최소 폭·고정 칸·틀의 합이고, 높이는 제목줄과 틀의 합이다(Windows 최소 추적 크기 관례). 크롬 스타일을 바꾸면 다시 계산한다.
- 좁아지면 기능 버튼이 먼저 잘린다. 캡션 3버튼과 제목 최소 칸(첫 글자+줄임표, 끌기·더블클릭 영역)은 항상 남는다. MDI·SDI 제목줄이 같은 순서를 따른다.
- 바둑판 배치도 최소 크기를 지킨다. 최소 크기 아래로 내려가면 최소 크기가 들어가는 열·행 수로 줄여 다시 놓는다. 칸보다 창이 많으면 남는 창은 제목줄 높이씩 오른쪽·아래로 어긋나게 겹친다.
- Win32 TileWindows 공식 문서에는 최소 크기나 넘침 처리 규칙이 없다(공식 확인). 그래서 위 바둑판 규칙은 공식 관례가 아니라 이 앱의 자체 규칙이다.
- Ctrl+0(macOS Cmd+0)은 문서 배율·글자 크기 초기화다. 대상은 포커스가 있는 문서이고, 없으면 마지막으로 Ctrl+휠을 한 창, 그다음 활성 문서 순이다. 메인 창 크롬은 배율이 고정된다.

### 3.3 분할과 합치기
- 패널 가장자리에 놓으면 1/2 분할, 패널 가운데에 놓으면 탭 합류, 패널에서 문서 영역 가운데로 끌면 MDI 떠 있는 창이다.
- 분할 해제는 분할 영역 탭 우클릭 '분할 해제' 또는 분할 창을 주 영역 가운데로 끌어 합류하는 것이다. 빈 분할은 자동으로 없앤다.

### 3.4 차트 뷰 문서 창 (REQ-58)

정본은 `08_차트뷰_설계.md` 다(결정은 ADR-076~081). 아래에 '후보'로 적은 것만 후보다.

- 차트 뷰는 MDI 문서 창으로 열린다. 새 화면 SCR-SCH-04(로드맵·스윔레인)·SCR-DSH-04(분석 차트)와 "분석" 메뉴 그룹을 둔다(D-67). 화면의 단계와 메뉴 표시는 `02_메뉴구조.md` 를 따른다.
- 같은 문서 창 안에서 뷰 종류를 바꿔 보고, 창을 분할해 두 뷰를 나란히 놓을 수 있다. 분할과 합치기는 §3.3 을 따른다.
- 뷰가 보는 프로젝트·기간 등은 문서 창 단위 뷰 맥락으로 맞춘다. 창 사이 공유는 사용자 옵션 후보다(08 §3.3).
- 다중 모니터에서는 독립 창으로 떼어 다른 모니터에 둘 수 있고 §5 의 모니터 규칙을 따른다. PC형(MDI)은 전 기능을 편집하고, 분석·진척·원가·경영 계열 뷰는 조회 중심이다(08 §3.10 표).
- 실시간 갱신의 범위와 간격은 08 §3.5 가 정본이다.

## 5. 다중 모니터
- 창 ▸ 모니터 ▸ 멀티 모니터에 지금 연결된 모니터 전부를 라디오로 보인다. 머리글은 `모니터 1: DISPLAY1  2560×1440 (주 모니터)` 형식이다(이름은 OS 장치 이름, 해상도는 물리 px). 주 모니터가 맨 앞이고 나머지는 왼쪽→오른쪽 순이다.
- 고른 모니터는 `ui.display.selected_monitor` 에 저장돼 재기동 뒤에도 유지된다. 고른 적이 없으면 주 모니터를 고른 것으로 본다.
- 일반 최대화(최대화 버튼·제목줄 더블클릭·Win+↑)는 메인 창과 독립 창 모두 창이 속한 모니터에서 한다(Windows 기본 동작). 속한 모니터는 창과 겹치는 면적이 가장 큰 모니터이고, 그 모니터의 작업 영역(작업표시줄 제외) 전체를 쓴다.
- 고른 모니터 값은 일반 최대화에 쓰지 않는다.
- 50:50 걸침은 Windows 와 같게 주 모니터로 간다(표준 Win32 창 실측). 주 모니터가 끼지 않은 50:50 은 미검증이고 OS 결과를 따른다.
- 고른 모니터로 옮기는 것은 사용자가 그 동작을 명시했을 때뿐이다. 창 ▸ 모니터 ▸ '선택한 모니터로 최대화'를 실행하거나, 메인 창이 최대화된 동안 라디오에서 다른 모니터를 고르면 그 모니터로 옮긴다(메인 창만).
- 저장된 창 위치가 현재 모니터 밖이면 가장 가까운 모니터 안으로 옮긴다. 선택했던 모니터가 없어지면(분리·이름 변경) 주 모니터로 대체하고 저장값은 지우지 않는다. 다시 연결되면 그 모니터로 돌아간다.
- **실행 중 자동 복구.** 모니터 연결·분리·해상도·배치 변경과 메인 창 크기 변경 뒤 조용 시간(`ui.display.change_settle_ms`)이 지나면 한 번 점검한다. 창이 열릴 때의 점검과 같은 기준을 쓴다.
  - 메인 창·독립 창은 창 위쪽 띠(`ui.window.offscreen.strip_height_px`)가 어떤 작업 영역과도 가로 `ui.window.offscreen.min_overlap_x_px`·세로 `ui.window.offscreen.min_overlap_y_px` 이상 겹치지 않으면 안 보이는 창이다.
  - 안 보이는 창만 옮긴다. 메인 창은 주 모니터 작업 영역 가운데·기본 크기로, 독립 창은 §7.2 '기본 위치'의 독립 창 자리로 옮긴다. 보이는 창은 움직이지 않는다.
  - 위치 고정 창도 안 보이면 옮기고 고정 상태는 유지한다. 최대화한 창은 옮기지 않는다. 모니터 정보가 비어 있으면(전환 중) 옮기지 않는다. 비전경 시험 기동은 창을 일부러 화면 밖에 두므로 이 점검을 끈다.
  - MDI 문서 창은 메인 창 크기 변화로 제목 줄을 잡을 수 없게 되면 계단 기본 위치로 옮기고 크기는 유지한다. 판정은 끌기 한계와 같은 구간(제목 줄에서 끌 수 있는 곳)을 재되 문턱은 `ui.mdi.offscreen.min_grab_overlap_dp` 로 낮춘다.
  - MDI 판정 문턱을 끌기 하한보다 낮추는 까닭은 메인 창을 조금 줄인 정도로 사용자가 밀어 둔 창이 돌아가지 않게 하기 위해서다. 최소화·최대화 창은 제외하며 웹·태블릿도 같다.
  - 모니터를 다시 연결해도 창이 원래 자리로 돌아오지는 않는다.
- 독립 창은 메인 창이 어느 모니터에 있든 끌려가지 않고 자기가 놓인 모니터에서 최대화한다. 독립 창은 모니터마다 따로 둘 수 있고, 여러 모니터를 덮는 단일 창은 만들지 않는다.
- 잴 MDI 사각형이 없는 분리(MDI 가 최대화됐거나 아직 그려지지 않은 새 문서)는 독립 창을 메인 창 모니터에 띄운다. 끌어 놓은 자리·레이아웃 복원 좌표는 그대로 둔다.
- 웹은 해당 없다. 브라우저는 모니터를 고를 수 없어 멀티 모니터 목록을 숨기고 '모니터 정보 없음'(비활성)을 보인다. '단일 모니터'·'선택한 모니터로 최대화'는 비활성이며 툴팁은 "웹에서는 모니터 배치에 맞춰 브라우저 창을 옮길 수 없습니다."다.
- 실제 모니터 분리·연결과 배율이 다른 모니터는 사용자 화면과 장치를 바꾸므로 자동 시험하지 않고 사람이 확인한다.

## 7. 우클릭 메뉴 (공통)
- 문서 창 본문 우클릭은 화면 고유 명령 → 구분선 → **글자 크게(+)·글자 작게(−)·기본 크기(Ctrl+0)** 다(공통원칙 §5.3).
- 제목 탭 우클릭은 §7.2 창 메뉴 공통 항목 뒤에 다른 창 닫기·이름 변경·독립 창 전환·핀 고정을 둔다. 탭을 활성화하지 않고 그 탭의 창에 적용한다.
- 문서 탭 우클릭(DOCK 가운데·독립 창 안)은 닫기·다른 탭 모두 닫기·독립 창으로 분리·분할 해제(분할 영역일 때)·이름 변경과 §7.2 창 메뉴 공통 항목(이전 크기로·최소화·최대화·기본 위치로 이동)이다. 탭을 활성화하지 않고 그 탭의 문서에 적용한다.
- 패널 제목 줄·패널 안 탭 우클릭은 §7.3 패널 위치 메뉴다. 패널 숨기기는 제목 줄 ✕·📌 가 맡고, 분할 해제는 문서 탭·MDI 창 메뉴에 있다.

### 7.1 바쁨 표시 커서의 플랫폼 판정
작업이 길어질 때 움직이는 스피너를 보이는 방식은 플랫폼마다 다르다. 동작의 정본은 이 표이고 구현 위치는 `../../poc/ui/README.md` 에 있다.

| 플랫폼 | 판정 | 방식 | 검증 상태 |
|---|---|---|---|
| Windows·macOS 데스크톱 | 움직이는 OS 커서 사용 | 비트맵 프레임 8장을 창 커서로 차례로 바꾼다. 프레임을 못 만들면 시스템 Wait 커서다 | Windows 는 자체 시험만 있다. **macOS 는 미검증**(실기 없음) |
| 웹(브라우저) | **움직이는 커서 불가** — 브라우저는 페이지가 커서를 애니메이션할 수 없다 | **포인터 추적 스피너** — 앱 화면 안에서 포인터를 따라다니고 끝나면 사라진다 | 웹 시험 판정은 포인터 자리 화소 변화·떠난 자리 원복·종료 뒤 제거다 |
| Android·스마트폰 | **커서 해당 없음** — 터치 기기라 마우스 포인터 커서가 없다 | 요건 대상 아님. 코드는 웹과 같은 포인터 추적 경로를 쓰지만 기기에서 그 모양을 합격 기준으로 재지 않는다 | 해당 없음 |

- 같은 판정을 적은 자리는 이 표, 04 웹 W-19, 06 모바일 §4 다. 셋이 다르면 이 표를 따른다.

### 7.2 창 메뉴 (메인·MDI·독립 창 제목 줄과 제목 탭 공통)
창 메뉴는 공통 컴포넌트 하나이고 네 위치에 붙는다. 메인 창 메뉴 줄, MDI 문서 창 제목 줄, 독립 창 제목 줄, 제목 줄의 제목 탭이다.

| 항목 | 접근 키 | 비활성 조건 | 동작 |
|---|---|---|---|
| 이전 크기로 | R | 보통 상태 | 보통 상태로 돌리고 활성화 |
| 최소화 | N | 최소화 상태 | 캡션 버튼과 같은 경로 |
| 최대화 | X | 최대화 상태 | 캡션 버튼과 같은 경로(OS 가 소속 모니터에 최대화) |
| 기본 위치로 이동 | D | 없음(측면 패널 탭·탭 문서 제외) | 대상 창만 복원해 기본 위치로 옮기고 활성화해 맨 앞으로 가져온다 |
| 닫기 | C | 없음 | 표시 단축키: 메인 Alt+F4, 그 외 Ctrl+F4(macOS Cmd+W, 웹·Android 표시 안 함) |

- **기본 위치.** 메인 창은 소속 모니터 작업 영역 가운데이고 크기를 유지하며, 작업 영역보다 크면 맞춰 줄인다.
- 독립 창은 메인 창 소속 모니터 작업 영역의 왼쪽 위에서 `ui.window.cascade.origin_offset_px` 만큼 들어간 자리이고, 겹치면 `ui.window.cascade.step_px` 씩 계단으로 놓는다. 크기는 유지한다.
- MDI 문서 창은 MDI 영역 안 첫 빈 계단 칸이고 크기를 유지한다. 칸을 잡을 수 없으면 왼쪽 위다.
- **자동 복구와 다른 점.** 자동 복구(§5)는 안 보이는 창만 옮기고 주 모니터를 기준으로 한다. 이 명령은 사용자가 지정한 창을 보이는 상태여도 옮기고, 메인 창은 지금 쓰는 모니터에 남긴다.
- **위치 고정 창.** 기본 위치 이동은 허용하고 고정 상태는 유지한다. 사용자가 그 창을 골라 내린 명령이기 때문이다. '위치 고정 중 최소·최대 차단' 옵션을 켜면 이전 크기로·최소화·최대화만 비활성이다.
- **탭 우클릭은 활성화하지 않는다.** 활성화하면 최소화 탭이 복원되고 독립 창이 앞으로 나와, 메뉴가 보여 주는 상태가 틀어진다.
- **넣지 않은 항목.** Windows 시스템 메뉴의 이동·크기 조정은 넣지 않는다. 끌기와 기본 위치로 이동이 대신하고, 키보드 이동 모드는 MDI 문서 창에 없어 위치마다 동작이 달라진다.
- **위치별 추가 항목.** 독립 창은 MDI 로 합치기, MDI 문서 창은 독립 창으로 분리·다른 창 닫기·분할·정렬, 제목 탭은 다른 창 닫기·이름 변경·독립 창 전환·핀 고정이다.
- **OS 시스템 메뉴와의 관계(Windows).** 메뉴 줄의 끌기 빈칸·캡션 버튼을 우클릭하면 OS 시스템 메뉴 대신 Pd 창 메뉴가 뜬다. 두 메뉴는 겹치지 않는다. 작업 표시줄 Shift+우클릭의 OS 메뉴는 그대로이고, Alt+Space 는 앱이 Pd 메뉴를 연다.
- **접힌 창.** 이 제품에는 접기 상태가 없어 해당 없다.
- **제목 줄의 독립 창 아이콘.** 아이콘 우클릭에도 이 창 메뉴를 붙인다. 탭 우클릭과 같이 활성화하지 않고 그 창에 적용하며, 웹·Android 관리형 창도 같은 경로를 쓴다.
- 플랫폼 차이는 웹 `04_웹_화면설계.md` W-20, 태블릿·폰 `06_모바일_화면설계.md` §2 다.
- 실제 우클릭 네 위치·팝업 표시·Alt+Space·실제 다중 모니터에서의 동작은 사람 확인 대상이다.

### 7.3 패널 위치 메뉴 (패널 제목 줄·패널 안 탭)

모든 패널(셸 소유 패널·기여 패널·분할 패널)이 같은 규칙을 따르고 메뉴는 공통 컴포넌트 하나다. 기여 패널은 탭 제목에 건수를 보일 수 있다(예 `알림(5건)`, 건수가 바뀌면 바로 갱신, 0건이면 `알림`).

| 조작 | 메뉴 이름 | 항목 | 동작 |
|---|---|---|---|
| 패널 제목 줄 우클릭 | 패널 위치 | 위·아래·왼쪽·오른쪽, 구분선, 패널 목록(`왼쪽 패널: 탐색기` 처럼 가장자리와 활성 탭) | 가장자리: 패널을 그 가장자리로 옮긴다. 패널: 탭을 모두 합친다. 빈 패널은 접히고 접힌 패널도 목록에 남는다 |
| 패널 안 탭 우클릭(탭이 2개 이상일 때 탭 줄이 보인다) | 이 탭 옮기기 | 같은 항목, 문서 탭은 문서 영역 추가 | 그 탭 하나만 옮긴다. 가장자리를 고르면 새 패널로 나간다. 기존 탭 메뉴 뒤에 덧붙는다 |
| 패널 제목 줄 끌기 | (안내 표시) | 문서 영역 안내·전역 안내의 방향, 다른 패널 가운데·제목 줄, 다른 패널 가장자리 | 안내 방향: 그 가장자리로 이동. 패널 가운데·제목 줄: 탭 합류. 패널 가장자리: 그 옆에 분할(영역 방향만). 문서 영역 가운데: 도구가 있는 패널은 제자리, 문서만 있는 패널은 문서를 문서 영역으로 돌려보낸다. 안내 밖·창 밖: 제자리 |

- **같은 가장자리에 패널이 둘.** 탭으로 합치지 않고 옆 줄에 나란히 둔다. 단이 달라 두께를 따로 맞출 수 있고 합치는 일은 끌기·메뉴로 고를 수 있어서다. 줄 순서는 패널 등록의 순위 값이다(§1.1).
- 줄이 모자라면 그 가장자리 영역 안에 칸을 나눠 넣는다. 그 가장자리에도 영역이 없으면 항목이 비활성이다.
- **분할 패널·탭을 가장자리로.** 비어 있는 영역을 그 가장자리로 옮겨 담는다. 처음에 접혀 있는 빈 자리를 먼저 쓴다.
- **현재 위치.** 체크하고 비활성으로 둔다. 같은 위치로 옮기는 일은 없다.
- **비활성.** 집중 숨김으로 접힌 패널(대상), 집중 숨김 중 새 칸이 필요한 이동이다. 집중 숨김은 모든 패널에 같게 적용하고, 보기 메뉴에서 패널을 고르면 집중을 풀고 그 패널을 드러낸다.
- **패널 기능 끔.** 정본은 공통원칙 §4.4 다. 끔이면 패널 고정(📌)이 되지 않고 버튼이 숨으며, 창을 끌 때 가운데 분할 안내 박스가 보이지 않는다.
- 패널 기능이 끔이어도 같은 탭 영역 안 순서 바꾸기와, 패널 안의 문서를 문서 영역·창 등 원하는 위치로 끌어 빼는 것은 된다. 방향 분할은 끔에서 하지 않는다. 앱·웹, PC형·태블릿형이 같다.
- 패널 기능 자동은 PC형 켬·태블릿형·모바일형 끔이다. 직접 고른 값이 우선하고, UI 형이 바뀌면 다시 판정한다. 끔으로 바뀌면 고정된 패널은 고정이 풀린다.
- **유지한 동작.** 가장자리 이동 때 모서리 소유 초기화, 방향별 몫 기억, 닫힘·핀 패널을 대상으로 고르면 닫힘 해제·핀 유지다.
- **문서 분할과의 관계.** 문서 분할은 문서 칸 안에서만 일어나 패널 단과 섞이지 않는다. 그래서 문서를 나눈 채로도 패널 가장자리를 옮긴다. 모서리 버튼을 문서 분할 중 숨기는 규칙은 그대로다.
- **패널을 잃지 않는다.** 패널째 끌어 놓아도 패널이 트리에서 빠지지 않고 탭만 옮긴다. 놓기 취소·창 밖 놓기·마지막 패널·문서 분할 중 모두 시험 대상이다. 패널이 접혀도 보기 메뉴로 되돌린다.
- **도구 탭에 문서 영역을 내지 않는 이유.** 문서 영역에 들어간 도구는 이 메뉴가 없는 MDI 창이 된다(보기 메뉴로는 돌아온다). 중앙 문서 영역의 문서 탭에는 이 메뉴가 없다(대상은 패널 안 탭이다).
- **저장.** 패널 위치는 레이아웃 저장 파일에 불변 패널 ID 와 가장자리로 저장한다(§1.1). 패널 위치가 없는 옛 판 파일은 셸 기본 구성으로 읽는다.
- **터치 탭 단위 옮기기.** 경로는 패널 제목 줄 ▾ > 패널 위치 > '이 탭 옮기기 — <탭 제목>' > 대상 패널(왼쪽·오른쪽·위쪽·아래쪽 패널로, 떠 있는 패널로)이다.
- 이 항목은 탭이 둘 이상인 패널에만 나온다. '떠 있는 패널로'는 독립 창으로 분리한다. 터치에는 탭 우클릭이 없어 탭 끌어 놓기 외에는 이 경로뿐이다.
- 플랫폼 차이는 웹 `04_웹_화면설계.md` W-21, 태블릿·폰 `06_모바일_화면설계.md` §2 다.
- 좁은 창에서 열 합이 셀 영역을 넘쳐 가로 스크롤이 생겨도 표의 열 끌기 크기 조절은 유지된다.
