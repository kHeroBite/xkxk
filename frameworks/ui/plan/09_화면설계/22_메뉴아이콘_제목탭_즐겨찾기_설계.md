# 22. 메뉴 아이콘·제목 탭 표시·제목 줄 즐겨찾기 설계

> 상태 설계 정본(결정 143, ADR-127) · 요구 REQ-113(원문은 `../00_요구사항/01_사용자요구사항_원문.md` REQ 표가 가리키는 결정 143 절) · D 행 `../90_결정관리/01_결정대기_부록/d569_결정143.md` · 키 이름·글리프 이름·수치는 모두 후보다
> 키의 값 꼴·기본값·값 분류·허용 층은 `../10_API설계/plt_2.md` §12.1 이 정본이다. 즐겨찾기 데이터·권한·대상 종류는 `20_개인화_빠른찾기_설계.md`(REQ-111) 가 정본이고, 이 문서는 그 부품 ①을 제목 줄에 놓는 자리와 동작만 정한다.
> 관련: 메뉴 ID 규칙 `09_메뉴ID_규칙.md`, 메뉴 생성 정본 `../_build/menu_data.py`, 제목 줄 공통 규칙 `01_화면설계_공통원칙.md` §2-1, 자산 규칙 `../../assets/README.md`, 불러오는 중 아이콘 `23_창_불러오는중_표시_설계.md`, 폼팩터 용어 `../05_아키텍처/08_지원_폼팩터_용어.md`.

## 1. 요구 해석

- 메뉴마다 아이콘을 만든다. 제목 줄의 제목 탭에서 제목 앞에 그 창의 아이콘을 보인다.
- 제목 탭을 아이콘만·아이콘+제목·제목만 중 무엇으로 보일지 설정에서 고른다.
- 메뉴(창)를 즐겨찾기하면 메인 창 제목 줄 오른쪽 끝의 별도 영역에 메뉴 이름 없이 아이콘만 보이고, 누르면 그 창이 바로 열린다. 새 창 제목 탭은 지금처럼 왼쪽부터 생기고, 즐겨찾기는 오른쪽부터 생긴다.

## 2. 메뉴 아이콘

### 2.1 정본과 생성

- 아이콘 단위는 **메뉴 ID**(ADR-085 불변 4자리)다. 화면이 메뉴 ID 를 바꾸지 않으므로 아이콘도 따라 바뀌지 않는다. 메뉴 ID 수와 생성된 아이콘 수는 생성기 출력으로만 적는다(문서에 숫자를 박지 않는다).
- 정본 데이터는 `../_build/menu_icon_data.py`(메뉴 ID → 기본 글리프 + 보조 표지)이고, 글리프는 `../_build/icon_glyphs.py`(24 격자 단색 path)다. `../_build/menu_data.py` 는 건드리지 않는다(메뉴 생성 정본 분리, 09 §6).
- 생성기 `../_build/menu_icons.py` 가 누락 0·조합 중복 0·path 문법을 검사한 뒤 아래를 만든다. 생성물은 손으로 고치지 않는다.
  - `assets/icons/menu/m<메뉴ID>.svg`
  - 클라이언트 리소스 사전(StreamGeometry 키 `PdMenuIcon<메뉴ID>`, 셸 키 `PdShellIcon<이름>`·정지 글리프 `PdIconBusyStatic`)
  - 데이터 계층 카탈로그(화면 ID → 메뉴 ID·아이콘 키). 코드 생성이라 리소스 설정이 필요 없고 웹 트리밍에 안전하다
  - `assets/_LICENSES.csv` 멱등 갱신
- 생성기 선택지는 `--check`(검사만)·`--self-test`·`--sheet <경로>`(16·24·32dp × 밝음·어두움 접촉 시트)다. 시험 단계에서 접촉 시트를 이미지로 확인한다.

### 2.2 그리기 규칙

- 기본 도형(사각형·원·선·호)으로 새로 그린다. 외부 아이콘 세트(Material·Lucide·Font Awesome 등)의 path 를 기억으로 재현하거나 복사하지 않는다. 생성 방식(생성기·모델·날짜)을 `_LICENSES.csv` source 칸에 적는다.
- 단색 path 하나로 그리고 색은 테마 글자색 토큰을 따른다. 그래서 밝음·어두움·대비 테마에서 따로 그리지 않는다.
- 같은 업무 그룹은 기본 글리프를 공유하고 보조 표지(작은 덧그림)로 화면을 가른다. 조합이 겹치면 생성기가 실패한다. 16dp 에서 표지만으로 구분되지 않으면 화면 뜻에 맞는 다른 기본 글리프를 쓴다. 즐겨찾기·아이콘만 탭에서는 그룹이 섞이므로 다른 그룹의 아이콘과 상태 글리프(불러오는 중·지연·실패)와도 구분되어야 한다.
- 셸 창(설정·테마 편집기 등)은 셸 메뉴 ID 가 없어 `shell.<이름>` 고정 키를 쓴다. 셸 메뉴 ID 배정은 09 §6 과제에 덧붙이고, 배정 뒤 키를 옮기는 일은 TODO-659 다.
- 아이콘 키가 없으면 종류 기본 글리프 → 제목 첫 글자 원형 표지 순으로 대신한다.
- RTL 에서는 방향을 뜻하는 아이콘만 좌우를 뒤집는다.

### 2.3 표시 자리

모든 자리는 공용 컨트롤 하나(구현 `WindowIcon`)로 그린다. 불러오는 중 스피너도 이 컨트롤이 바꿔 보인다(23 §3).

| 자리 | 폼팩터 |
|---|---|
| 제목 줄의 제목 탭(제목 앞) | MDI·웹 데스크톱 |
| MDI 문서 창 머리(옛 고정 문서 글리프 자리) | MDI |
| 관리형 독립 창 머리·OS 독립 창(SDI) 제목줄의 제목 앞(앱 로고 칸은 그대로) | MDI |
| 제목 줄 오른쪽 독립 창 아이콘 | MDI·DOCK |
| DOCK 문서 탭 | DOCK |
| 탐색기 트리 항목 | MDI·DOCK |
| NAV 메뉴 항목 | NAV |
| 제목 줄 즐겨찾기 영역(§4) | MDI·웹 데스크톱 |

- 앱 로고와 창 아이콘의 관계. 2026-11-01 사용자 지시 "창타이틀 로고는 SDI 일 때만 보여라"(`../04_기술스택/05_창크롬_OS디자인_기준.md` §2.7)와 §1 의 "제목 앞에 그 창의 아이콘"을 둘 다 지킨다. 창 아이콘은 로고를 대신하지 않는다.
  - MDI 문서 창은 앱 로고 없이 왼쪽 아이콘 칸에 창 아이콘을 둔다.
  - 독립 창(관리형·OS)은 왼쪽부터 `앱 로고 칸 → 창 아이콘 → 제목` 순서다. 보이는 문서가 없으면 로고와 제목만 둔다.
  - 독립 창의 로고 칸은 누르면 창 메뉴, 다른 창을 끌어오는 동안은 합치기 표적이다. 창 아이콘은 제목 끌기 영역에 속해 누름을 받지 않는다.
  - macOS 스타일은 제목줄에 아이콘을 두지 않으므로 로고와 창 아이콘을 모두 숨긴다(04/05 §2.7).
- `ui.menu.icon.visible` 을 끄면 탐색기·NAV 메뉴의 아이콘을 숨긴다. 제목 탭은 §3 표시 방식을 따른다.

## 3. 제목 탭 표시 방식

| 값(`ui.shell.title_tab.display`) | 모양 | 폭 |
|---|---|---|
| `icon` | 아이콘만 | 고정 폭 `ui.shell.title_tab.icon_only_width_dp`. 제목은 툴팁과 접근성 이름으로 보인다 |
| `icon_title`(기본) | 아이콘 + 제목 | 01 §2-1 폭 규칙. 아이콘 칸만큼 자연 폭이 는다 |
| `title` | 제목만 | 01 §2-1 폭 규칙(지금과 같다) |

- 기본값 `icon_title` 은 사용자가 요청한 기능을 기본으로 보이게 하는 선택이다(D 행). 탭 폭과 기존 스크린샷 기대값이 바뀌므로 시험 판정기 기대값도 함께 고친다.
- DOCK 문서 탭도 같은 표시 방식을 쓴다.
- `icon` 에서 닫기 × 는 01 §2-1 의 닫기 표시 규칙을 따르되 아이콘 위에 겹쳐 그린다(아이콘을 흐리게).
- `title` 에서 불러오는 중 표시는 23 §4 대체 표시를 쓴다.

## 4. 제목 줄 즐겨찾기 영역

### 4.1 데이터

- 데이터는 REQ-111 부품 ① 즐겨찾기 `plt.personal_favorite` 다. 대상 종류는 `screen`, 대상 ID 는 화면 ID 다. 새 표·새 계약을 만들지 않는다(20 §2 원칙 1·3).
- 개수 상한은 `plt.personal.favorite.max_items`, 권한을 잃은 화면은 20 §5 를 따른다.
- PoC 는 서버가 없어 기기 로컬 저장소(구현 `PersonalFavoriteStore`, 기존 키-값 저장소 위)로 같은 계약을 구현한다. 서버 구현은 plt 개인화 작업에서 같은 계약으로 바꾼다.

### 4.2 배치

```
[제목 탭 →]  …빈칸…  [독립 창 아이콘] | [즐겨찾기 ←]
```

- 제목 탭은 왼쪽부터, 즐겨찾기는 오른쪽 끝부터 쌓인다. 구분선은 독립 창 아이콘과 즐겨찾기 사이에 둔다.
- `ui.shell.favorite_bar.position` 이 `before_sdi` 이면 즐겨찾기를 독립 창 아이콘 왼쪽에 둔다(기본 `end`).
- 즐겨찾기 영역은 제목 줄 폭의 `ui.shell.favorite_bar.max_width_pct` 까지 쓴다. 넘치면 왼쪽 끝에 `»` 단추를 두고 나머지는 팝업 목록으로 보인다. 제목 탭 가용 폭은 즐겨찾기 영역과 독립 창 아이콘 칸을 뺀 폭이다(01 §2-1).
- 아이콘만 보이고(이름 없음) 툴팁·접근성 이름은 화면 이름이다. 크기는 독립 창 아이콘과 같은 16 DIP 이다.
- 즐겨찾기가 0개면 영역과 구분선을 숨긴다. `ui.shell.favorite_bar.visible` 을 끄면 영역을 숨긴다(데이터는 그대로).

### 4.3 동작

- 클릭은 `ui.shell.favorite_bar.click` 에 따른다. `activate_or_open`(기본)은 그 화면 창이 열려 있으면 활성화하고(여러 개면 최근 활성 창), 없으면 새로 연다. `always_new` 는 늘 새로 연다.
- 열기는 일반 창 열기와 같은 경로라 열기 효과(21 §4)와 불러오는 중 표시(23)를 그대로 쓴다. 활성화의 출처는 `window_list` 로 본다(21 §3.2).
- 넣기·빼기 자리. 제목 탭 우클릭 메뉴, 창 메뉴, 탐색기 항목의 별 단추, 즐겨찾기 아이콘 우클릭(빼기). 터치에서는 길게 누르기 메뉴다.
- 끌어서 순서를 바꾼다. 순서 키는 사전순 순서 키(`rank`, 공통규약_2 끌어서 순서 바꾸기 규칙)다.
- 다른 기기의 변경은 20 §4 통지로 목록만 다시 읽는다.

### 4.4 폼팩터

| 폼팩터 | 자리 |
|---|---|
| PC형(MDI)·웹 데스크톱 | 제목 줄 오른쪽 끝(§4.2) |
| 태블릿형(DOCK) | 제목 탭이 없으므로 탐색 패널 맨 위 '즐겨찾기' 구역(20 §4) |
| 모바일형(NAV) | 삼선 메뉴 맨 위 즐겨찾기 화면(20 §4) |

- RTL 에서는 논리적 끝(왼쪽)에 둔다.

## 5. 시험 케이스

`icons_all_menu`(메뉴 ID 전부 SVG·리소스 키 존재, 누락·중복 0 — 생성기 `--check`), `icon_sheet`(접촉 시트 육안), `tab_display_each`(세 값별 탭 모양·폭), `tab_display_dock`(DOCK 문서 탭), `icon_places`(§2.3 자리마다 같은 키), `sdi_logo_and_icon`(독립 창의 로고·창 아이콘 순서, 좁은 폭의 제목 말줄임, 합치기 표적 자리. 폭이 모자라면 기능 버튼부터 잘린다. 한계로, 창 최소 폭 계산은 창 아이콘 몫을 세지 않아 최소 폭에서는 제목 글자가 밀릴 수 있다), `icon_fallback`, `fav_add_remove`(넣기·빼기 네 자리), `fav_order_drag`, `fav_overflow`(`»` 팝업), `fav_click_activate_or_open`, `fav_click_always_new`, `fav_restart_persist`, `fav_lost_access`(20 §5), `fav_dock_nav`(구역 자리).
