# Pd 화면 설계 — 저해상도·소형 화면 폼 대응

> 상태 설계 정본(결정 114)
> 수치는 모두 설정 키의 기본값(후보)이고 근거 수준은 미검증이다(실측하지 않았다). 키 이름과 뜻은 §9 에 있고, 값 꼴·기본값·값 분류·허용 층의 선언 자리는 `../10_API설계/plt_2.md` §12.1 의 `ui.*` 표다.
> 충돌 규칙: 창 크롬 수치(`plan/04_기술스택/05_창크롬_OS디자인_기준.md`), MDI 창 끌기 경계 규칙(`01_화면설계_공통원칙.md` §4.2), 폼팩터별 기본 UI 모드(`../05_아키텍처/08_지원_폼팩터_용어.md` §1-3)와 달라 보이면 그 정본이 우선이다. 이 문서는 그 정본들을 고치지 않고 위에 얹는다.

## 1. 문제와 사용자 진술

- 사용자 진술(2026-11-09, 원문): "지금 mars에서도 발생되는 문제중에 모니터가 너무 작거나 해상도가 낮을때에 내용이 많은 폼을 보여주는 문제가 있다. 스크롤을 잘 활용하거나, 고정창크기라면 적절한 조절이 필요할것 같으니 이도 계획에 넣어라."
- Mars 에서 실제로 그런 문제가 있다는 것은 **사용자 진술**이다(근거 수준 미확인, Mars 코드나 화면으로 확인하지 않았다). Pd 가 같은 문제를 피하도록 설계하는 것이 이 문서의 목적이다.
- 문제 유형 3가지는 다음과 같다. (a) 입력 항목이 많은 폼이 작업 영역보다 커서 아래쪽 버튼·입력란이 안 보인다. (b) 고정 크기로 설계한 창이 작은 화면에서 화면 밖으로 잘린다. (c) 큰 모니터에서 저장한 창 위치·크기가 작은 모니터에서 복원될 때 화면 밖에 놓인다.

## 2. 용어와 기준

용어는 `../05_아키텍처/08_지원_폼팩터_용어.md` 를 따른다(폼팩터는 데스크톱·태블릿·스마트폰, UI 모드는 MDI·DOCK·NAV). 아래 네 낱말의 용어 정본 등재는 53 에 요청했다.

| 용어 | 뜻 |
|---|---|
| 논리 해상도(DIP) | 물리 픽셀 ÷ 화면 배율. 모든 크기 기준은 DIP 로 적는다 |
| 작업 영역 | 화면에서 작업 표시줄·독·시스템 막대를 뺀 사용 가능 영역(모니터별로 다름) |
| 설계 크기 | 폼이 이상적으로 보이는 크기. 창의 '최초 열림 크기' 의 상한 |
| 폼 최소 크기 | 폼을 이 아래로 줄이지 않는 크기. 아래에서 스크롤로 전환한다. 03 §3.2.1 의 창 크롬 최소 크기(창 틀의 최소 크기)와 다른 대상이다 |

## 3. 스크롤 우선 원칙

1. **세로 스크롤을 기본**으로 한다. 내용이 많은 폼은 창을 늘리지 말고 본문을 스크롤한다.
2. **가로 스크롤은 표·그리드·차트·간트 같은 본래 넓은 요소에 한정**한다. 일반 폼 본문에는 가로 스크롤을 만들지 않고 입력 항목이 아래로 줄바꿈되게 한다.
3. **고정 영역**: 제목줄(창 크롬)·화면 머리(제목, 핵심 조회 조건)·하단 버튼 줄(저장·취소)은 스크롤하지 않고 항상 보인다. 본문만 스크롤한다.
4. **긴 폼 구획화**: 항목이 많으면 구획(섹션)으로 접기·펼치기, 또는 탭으로 나눈다. 필수 항목 구획이 먼저 열린다. 접힘 상태를 사용자별로 기억할지는 `ui.form.section_collapse_remember` 가 정한다.
5. **검증 오류 위치 이동**: 저장 시 오류가 화면 밖에 있으면 첫 오류 항목으로 스크롤하고 구획을 자동으로 펼친다.
6. **키보드·포커스**: Tab 이동으로 화면 밖 항목에 포커스가 가면 그 항목이 보이도록 자동 스크롤한다.
7. 스크롤바는 내용이 넘칠 때만 보이고, 터치 환경에서는 관성 스크롤을 따른다(플랫폼 기본 동작).

## 4. 고정 크기 창 규칙

대화상자·설정창·작은 도구창처럼 크기를 고정한 창에 적용한다.

- **최초 열림 크기** = min(설계 크기, 해당 모니터 작업 영역 × 비율). 비율은 `ui.window.initial_size_pct` 다(가로·세로 같은 값).
- 작업 영역이 설계 크기보다 작으면 창을 줄이고, 줄어든 만큼 본문을 §3 방식으로 스크롤한다. 고정 영역(제목줄·하단 버튼)은 항상 유지한다.
- **폼 최소 크기**는 폼마다 화면 메타(§9.2)로 선언한다. 선언이 없는 폼은 `ui.window.form_min_width_dp`·`ui.window.form_min_height_dp` 를 쓴다. 폼 최소 크기 아래로 작업 영역이 줄면 최소 크기를 유지하지 않고 작업 영역에 맞추되, 이때는 가로·세로 스크롤을 모두 허용한다(버튼이 가려지는 것보다 낫다는 판단이다).
- 크기 조절을 막은 고정 창이 작업 영역보다 크면 조절 가능으로 바꾸거나 스크롤로 전환한다(`ui.window.oversize_allow_resize`). '크기 고정' 이 화면 밖 잘림의 이유가 되면 안 된다.
- 모달 대화상자는 부모 창 중앙을 기본으로 하되 §5 보정을 거친다. 높이가 큰 모달은 본문 스크롤 + 하단 버튼 고정을 기본으로 한다.
- 배율 변경, 모니터 연결·해제, 해상도 변경이 일어나면 열린 창에 §4~§5 를 다시 적용한다.

## 5. 화면 밖 위치 보정

창 복원, 새 창 열기, 모니터 구성 변경, 작은 모니터로 이동 때 적용한다.

1. 복원 위치와 크기가 어떤 모니터 작업 영역에도 충분히 걸치지 않으면 가장 가까운 모니터(없으면 주 모니터)의 작업 영역 안으로 옮긴다. '충분히 걸침' 판정은 03 §5 의 MDI-12 규칙을 그대로 쓴다. 수치는 그 절에 있고 이 문서는 다시 적지 않는다.
2. 창이 작업 영역보다 크면 §4 로 줄인 뒤 옮긴다. 옮긴 뒤 제목줄 전체가 작업 영역 안에 있도록 한다.
3. **MDI 창 끌기 경계 보장**: 보정은 01 §4.2 의 MDI 창 끌기 경계 규칙(잡을 곳 최소 너비, 값·값 분류·근거는 그 절)을 어기지 않는 방향으로만 한다. 캡션 버튼만 남고 끌 구간이 없는 상태를 만들지 않으며, 이 문서는 그 규칙을 바꾸지 않는다.
4. 보정은 창이 보이기 전(첫 표시 전)에 한다. 화면이 뜬 뒤에 위치가 튀지 않게 한다.
5. 저장은 논리 좌표(DIP)와 어느 모니터였는지(식별 정보)를 함께 남기고, 복원할 때 모니터가 없으면 위 1을 적용한다.
6. 보정 사실을 사용자에게 알릴지는 `ui.window.position_fix_notice` 가 정한다. 알리지 않을 때도 진단 로그에는 남긴다(창 id, 원래 위치, 보정 후 위치).

## 6. 최소 지원 해상도

실제 보급 해상도는 조사하지 않았다(근거 수준 미확인).

| 구분 | 최소 논리 해상도 | 비고 |
|---|---|---|
| 데스크톱·웹 | `ui.window.support_min_width_dp` × `ui.window.support_min_height_dp` | 이 이상에서 MDI 기본 동작 |
| 데스크톱·웹(그 아래) | `ui.window.scroll_min_width_dp` × `ui.window.scroll_min_height_dp` 까지 '동작은 하되 스크롤 위주' | 완전한 MDI 대신 SDI 권장 |
| 태블릿 | 시험에서 쓰는 가장 작은 태블릿 크기 | DOCK 기본 유지 |
| 스마트폰 | `ui.window.phone_min_width_dp` 너비 | NAV, 스크롤 우선 |

- 최소 해상도 미만은 '동작 보장 안 함' 이 아니라 '스크롤로 접근 가능' 을 목표로 한다. 아무리 작아도 저장·취소 버튼에는 도달할 수 있어야 한다.
- 최소 해상도 값은 Q-LR-01 의 답으로 정했다(D-192·D-228, §10).

## 7. 다른 모드와의 관계

- **MDI**: 자식 창 크기가 작업 영역을 넘으면 §4 로 줄이고 스크롤한다. 끌기 경계 규칙(§5-3)이 우선한다. 창 크롬 수치(모서리·외곽선·제목줄·캡션 버튼)는 04_기술스택/05 를 그대로 쓰며 바꾸지 않는다.
- **DOCK**: 패널·서랍은 독 영역 안에서 스크롤한다. 서랍이 화면을 덮을 때도 닫기 버튼은 고정 영역에 둔다.
- **NAV**: 하단 탭과 상단 막대는 고정, 본문만 스크롤. 가로 스크롤은 §3-2 한정.
- **웹**: 브라우저 창 크기·확대 비율(Ctrl +)에 따라 같은 논리 해상도 규칙을 적용한다. 확대 200%에서도 하단 버튼에 도달해야 한다(WCAG 개념 참고, 근거 수준 미확인).
- 화면 밖 보정과 폼 최소 크기는 UX 동등성 짝(데스크톱↔웹, 스마트폰↔태블릿)이 같은 규칙을 쓴다.

## 8. 시험 방법

### 8.1 해상도 × 배율 매트릭스

| 논리 해상도 | 배율 100% | 125% | 150% | 200% |
|---|---|---|---|---|
| 1920 × 1080 | 기준 | ○ | ○ | ○ |
| 1366 × 768 | ○ | ○ | ● | ○ |
| 1280 × 720 | ● | ● | ○ | ○ |
| 1024 × 600 | ● | ○ | ○ | ○ |

(● 필수, ○ 선택. 시험 해상도는 시험 조건이라 설정 키가 아니다. 어떤 칸이 필수인지는 시험 계획이 정한다.)

### 8.2 항목과 판정 기준

| ID | 시험 | 판정 |
|---|---|---|
| LR-1 | 긴 폼(항목 많음)을 매트릭스 각 칸에서 열기 | 본문 스크롤 가능, 제목줄·하단 버튼 고정 보임 |
| LR-2 | 고정 크기 창을 작은 화면에서 열기 | 창이 작업 영역 안, 버튼 도달 가능 |
| LR-3 | 큰 모니터에서 저장한 위치를 작은 해상도에서 복원 | 창이 작업 영역 안, 제목줄 전체 보임 |
| LR-4 | MDI 창을 화면 밖으로 끌기 | 01 §4.2 끌기 경계 규칙의 잡을 곳이 남음 |
| LR-5 | 저장 오류가 화면 밖일 때 | 첫 오류로 스크롤, 구획 자동 펼침 |
| LR-6 | 모니터 해제·해상도 변경 중 열린 창 | 창이 남은 모니터 작업 영역으로 이동 |
| LR-7 | 웹 확대 200% | 하단 버튼 도달 가능 |

### 8.3 시험 규칙

- 합격 판정은 측정한 위치·크기 값(DIP)과 화면 확인으로 한다. 응답 시간이 걸린 항목은 실제 동작시간(ms·초)으로 판정하고 부하 값으로 시행을 무효 처리하지 않는다.
- 시험 운영 규칙(측정 시점·시험 모니터·브라우저)은 이 문서에 두지 않는다. 시험 계획 정본 자리(`plan/12_시험계획/`, 결정 129)가 갖는다.
- 가상 해상도 시험이 물리 소형 모니터 시험을 대신할 수 있는지는 미확인이다.

## 9. 설정 키와 화면 메타

### 9.1 설정 키

선언(값 꼴·기본값·값 분류·허용 층)은 `../10_API설계/plt_2.md` §12.1 이 갖는다. 이 표는 키 이름과 뜻만 적는다.

| 키 | 뜻 | 쓰는 절 |
|---|---|---|
| `ui.window.initial_size_pct` | 최초 열림 크기의 작업 영역 대비 비율 | §4 |
| `ui.window.form_min_width_dp`·`ui.window.form_min_height_dp` | 화면 메타에 폼 최소 크기 선언이 없을 때 쓰는 값 | §4 |
| `ui.window.oversize_allow_resize` | 작업 영역보다 큰 고정 창을 조절 가능으로 바꿀지 | §4, Q-LR-02 |
| `ui.window.position_fix_notice` | 화면 밖 위치 보정 사실을 사용자에게 알릴지 | §5-6, Q-LR-04 |
| `ui.window.support_min_width_dp`·`ui.window.support_min_height_dp` | MDI 기본 동작을 지원하는 최소 논리 해상도 | §6, Q-LR-01 |
| `ui.window.scroll_min_width_dp`·`ui.window.scroll_min_height_dp` | 스크롤 위주로 동작을 보장하는 최소 논리 해상도 | §6 |
| `ui.window.phone_min_width_dp` | 스마트폰 최소 너비 | §6 |
| `ui.form.section_collapse_remember` | 구획 접힘 상태를 사용자별로 기억할지 | §3-4, Q-LR-03 |

### 9.2 화면 메타와 사용자 창 상태

- 폼의 설계 크기·폼 최소 크기·고정 영역은 그 화면을 소유한 모듈이 모듈 선언서의 '화면과 메뉴' 항목에 화면 ID 별로 선언한다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §3.1·§7). 새 솔루션의 폼도 이 문서나 셸을 고치지 않고 같은 규칙을 받는다.
- 사용자별 창 크기·위치(논리 좌표 + 모니터 식별)와 구획 접힘 상태는 설정 키가 아니라 사용자 상태다. 저장 열쇠는 불변 화면 ID(D-496)이고 소유 모듈은 셸 설정을 가진 공통 기반 `plt` 다.
- 위치 보정 진단 로그(창 id, 이전·이후 좌표)에는 개인정보를 담지 않는다.

## 10. 사용자 결정 질문 (Q-LR) (D-192·D-228)

4건 모두 추천 답으로 정했다(결정 114). 근거는 옵션화 대원칙(ADR-089, plan/README.md 8번)이다. 4건은 법령·보안·데이터 무결성 예외가 아니므로 원칙으로 정하고, 값은 §9.1 의 키로 둔다.

## 11. 한계와 미확인

- Mars 의 문제는 사용자 진술이다. Mars 의 현재 구현을 근거로 삼지 않았다.
- 실제 장비 분포와 사용 비율을 조사하지 않았다. WCAG 확대 기준은 출처를 확인하지 않았다(근거 수준 미확인).
- 기존 화면 설계 문서와의 관계는 이렇다. §5-1 화면 밖 판정은 03 §5 MDI-12 를 따른다. 폼 최소 크기는 03 §3.2.1 의 창 크롬 최소 크기와 대상이 다르다. §7 의 모드 관계는 01 §8 자동 전환 경계를 따른다. 04·06 과의 항목별 대조는 하지 않았다(근거 수준 미검증).
