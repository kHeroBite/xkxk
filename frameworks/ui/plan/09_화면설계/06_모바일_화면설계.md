# 모바일 화면 설계 — 스마트폰·태블릿, Android·iOS

> 상태 설계 정본(ADR-053).
> 근거 조사는 `05_모바일_PMS앱_비교조사.md`(타 PMS 앱 9종 + Mars 모바일), 방식 규칙은 ADR-051·REQ-46, 용어는 `05_아키텍처/08_지원_폼팩터_용어.md` 다.
> 와이어프레임: `img/mobile_phone.svg`(스마트폰 NAV, 400×800), `img/mobile_tablet.svg`(태블릿 DOCK, 1280×800).
> 실기 근거: Galaxy Z Fold5(Android 16) 접힘 약 401dp·펼침 약 805dp 실측(ADR-041). iOS 는 장비가 없어 미검증이다.

## 1. 폼팩터별 방식

| 접속 기기 | 판정(크기+기기 정보, 08 §1-3-1) | 기본 / 선택 | 비고 |
|---|---|---|---|
| 스마트폰(접힌 폴드 포함) | 좁은 폭 경계(`ui.layout.compact_width_dp`) 미만 | 모바일형(NAV)만, 선택 UI 없음 | 자동 전환만. 스마트폰은 모바일형만 쓴다는 고정은 제품 상수다(ADR-051 결정 17, 키의 뜻은 05/08 §1-3) |
| 태블릿(태블릿·펼친 폴드) | 좁은 폭 경계 이상 | 태블릿형(DOCK) 기본 / 자동·PC형·모바일형 선택 | 자동이면 창 폭이 좁은 폭 경계 미만일 때 모바일형으로 부드럽게 전환(ADR-051) |
- 데스크톱 접속은 PC형(MDI) 기본이고 '자동'은 PC형이다(`03_데스크톱_화면설계.md`). 자동 전환 경계·히스테리시스·애니메이션의 규칙은 공통원칙 §8 이고, 키(`ui.layout.*`)의 선언·기본값·값 분류는 `../10_API설계/plt_2.md` §12.1 이다.
- 폴드를 접으면 즉시 스마트폰 규칙으로 바뀌고, 펼치면 직전 방식·레이아웃·문서 상태로 돌아간다. 열린 화면·입력 중 내용·스크롤(첫 행 기준 1행 이내)은 유지한다(REQ-46-7·8).
- 창 움직임 효과(결정 143)는 모바일형(NAV)에서 `fade`·`push*` 부분집합만 쓰고 나머지 효과는 `fade` 로 낮춘다. 태블릿형(DOCK)은 문서 탭 내용 영역에 같은 효과(`tilt3d` 포함)를 쓴다. 규칙은 `21_창_움직임효과_배경_설계.md` §4, 배경 이미지는 앱 로컬 데이터 폴더(21 §6.2), 즐겨찾기 자리는 `22_메뉴아이콘_제목탭_즐겨찾기_설계.md` §4.4 다(D-596).
- 스마트폰을 가로로 돌려 폭이 좁은 폭 경계를 넘어도 모바일형을 유지한다(`ui.layout.phone_landscape_keeps_mobile`, 기본값 켬, 08 용어 §9-4).
- 메뉴 ID·툴팁 표시와 디버그모드는 빌드 채널에 따라 다르다. dev·staging·qa 빌드에만 있고 prod 빌드에서는 빠진다(ADR-090 채널별 표, 결정 55·57·90).

## 2. 스마트폰 — NAV (`img/mobile_phone.svg`)

```
┌ 상단 앱 바 ───────────────────────────────┐
│ [☰ 메뉴]  화면 제목              [🔔] [⋮]  │  ← ☰=탐색기+전체 메뉴, 벨=알림 센터, ⋮=화면 내 기능
├──────────────────────────────────────────┤
│ 콘텐츠(목록 → 상세는 밀어 넣기 화면 전환)       │
│                                    [+]   │  ← 빠른 생성(FAB)
├ 하단 탭 5개 ──────────────────────────────┤
│  홈   프로젝트   이슈(작업)   메신저   더보기   │
└──────────────────────────────────────────┘
```
- 주 메뉴는 상·하단에만 둔다. 하단에 아이콘 탭 몇 개(최대 5)를 두고, 상단 왼쪽 삼선(☰)으로 나머지 전부에 접근한다(팀즈·아웃룩 같은 공통 경험, 사용자 지시 2026-11-01). 삼선 서랍(왼쪽에서 겹쳐 열림)에는 탐색기와 셸 메뉴 전체(파일·창·보기·시스템)가 있다(ADR-051 결정 11). 업무 메뉴 전체 그룹은 서랍과 '더보기'에 있다.
- **도달 100%:** 화면 한계로 하단 탭에 못 넣은 메뉴는 서랍·더보기로 넘기며 숨기지 않는다. 모바일형에서 쓸 수 없는 항목(창 배열·바둑판·계단식·독립 창·모니터 이동)은 숨기지 않고 서랍에 비활성으로 두고 사유(\"PC형·태블릿형에서 사용\")를 보인다. 보이거나 사유와 함께 비활성이면 도달로 센다.
- **제목줄·도구 모음:** 스마트폰의 모바일형에서는 제목 줄(제목 탭·SDI 아이콘 줄)이 없다. 데스크톱 제목줄 메뉴와 도구 모음도 숨기고 위 앱 바만 둔다(제목 줄은 폭이 넓을 때만 보이며 스마트폰 NAV 는 해당 없음). 그 항목은 서랍·하단 탭으로 닿는다. 데스크톱·태블릿에서 모바일형을 고른 경우는 형 전환 스위치와 창 조작 버튼이 있어야 하므로 그대로 둔다.
- **형 전환 안전:** 다른 형에서 모바일형으로 바꿔도 문서를 닫지 않는다. 열린 문서·활성 문서·입력·선택·포커스는 유지하고, MDI 배치·분할은 레이아웃 모델에 남겨 PC형·태블릿형으로 돌아오면 복원한다. 독립 창(SDI)은 그대로 두며, 저장 안 된 입력은 전환으로 사라지지 않는다. 끌기 중이면 끝난 뒤 전환한다.
- **하단 탭·빠른 생성은 등록형이다:** 항목 후보는 모듈 선언서가 올린 화면·메뉴 기여(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7 화면 확장 자리)에서 온다. 테넌트 허용에 든 모듈의 항목만 보이고, 허용에 없는 모듈의 항목은 숨기며 그 자리는 다음 후보가 채운다. 어느 항목을 어떤 순서로 둘지는 설정 값으로 정한다(회사 기본, 사용자 재정의 — 설정 키 후보 `ui.nav.bottom_tabs`·`ui.nav.quick_create`, 목록 값, 허용 층 회사·사용자). 하단 탭 수 상한 5 는 제품 상수다(ADR-051 결정 11).
- 목록 기본, 보드·간트·캘린더는 프로젝트 상세 안의 탭으로 둔다(05 조사 §5 공통 권고 — Jira 프로젝트 탭 사례).
- 빠른 생성 버튼(FAB)은 하단 탭 화면에서 보이고 등록된 빠른 생성 항목을 바로 만든다(05 조사 — Asana 우하단 +, Linear 작성기). PMS 제품의 기본값 예시는 홈·프로젝트·이슈 탭에서 이슈·공수·경비다.
- 창 메뉴(03 데스크톱 §7.2)는 스마트폰 NAV 대상이 아니다. 제목 줄·제목 탭이 없고 창을 옮길 일이 없다. 태블릿 DOCK 도 제목 탭을 숨기는 설계이고 문서가 MDI 창이 아니라, 최소화·최대화·기본 위치 항목은 해당 없음이다. 메뉴 줄에는 창 메뉴를 두지 않는다(앱 전체 화면이라 대상이 없다). 터치 길게 누르기로 여는 동작은 새로 넣지 않았다. Android 동작은 미확인이다.
- 패널 위치(03 데스크톱 §7.3): 모든 패널이 같은 규칙이다. 태블릿 DOCK 은 우클릭이 없어 패널 제목 줄 ▾ 가 같은 메뉴를 연다(측면 패널 ▾ 는 터치 기기에서만 보인다). 제목 줄 끌기도 같은 동작이다. 패널 안 탭 하나만 옮기는 경로는 탭 끌어 놓기와 패널 ▾ > 패널 위치 > '이 탭 옮기기 — <탭 제목>' > 대상 패널 메뉴(탭이 둘 이상인 패널만)다. 끌어 놓기는 그대로 유지한다. Fold5 펼침 진단 빌드에서 한 경로(왼쪽 패널의 탭 하나를 오른쪽 패널로)를 확인했고, 다른 대상·사람 손 터치·Release·iOS 는 미확인이다(원자료 저장소 미수록). 스마트폰 NAV 는 패널이 없어 대상이 아니고, 알림 화면 머리줄에 `알림(5건)` 을 보인다.
- 길게 누름에만 기능을 두지 않는다. 같은 기능을 ⋮·▾ 메뉴에도 둔다(iOS 콜아웃 제약, 08 용어 §7-3 4행). 글자 크게·작게·기본 크기도 ⋮ 메뉴에 둔다(데스크톱 우클릭 메뉴의 대응, 공통원칙 §5.3).
- 셸 메뉴(파일·창·보기·시스템)는 ☰ 서랍 안에 둔다. 창 배열·모니터·독립 창 항목은 스마트폰에서 비활성+사유로 보인다.

## 3. 태블릿 — DOCK 기본 (`img/mobile_tablet.svg`)
- 데스크톱과 같은 Shell 이다(`03_데스크톱_화면설계.md`). 메인 제목줄 한 줄 메뉴, 좌측 탐색기 패널, 가운데 문서 탭, 우측 알림 서랍.
- 중복 탭 제거: 태블릿 DOCK 은 제목 줄에 제목 탭을 두지 않고(제목 탭은 PC형 MDI 에서만 보인다) 문서 영역 탭이 유일한 탭 줄이다. 같은 이름의 탭이 제목 줄과 문서 영역에 둘 다 보이지 않는다(실측 미확인). 독립 창(SDI)이 있으면 제목 줄에는 SDI 아이콘만 둔다.
- 메인 타이틀바 오른쪽 도구는 왼쪽부터 `[라이트/다크 테마 아이콘] [자동][PC형][태블릿형][모바일형] [캡션 버튼]` 순서다. UI 형 네 칸이 캡션 버튼 바로 앞에 오고 테마 아이콘은 그 왼쪽에 붙는다. UI 형 네 칸과 테마 버튼은 글자 없는 직접 그린 벡터 아이콘이고 이름은 툴팁으로 보인다(공통원칙 §2-1). 테마 아이콘은 어두우면 해, 밝으면 달 그림을 보인다(누르면 바뀔 쪽). Android 는 캡션 버튼이 없어 UI 형 칸이 오른쪽 끝이다. 웹은 캡션 버튼이 없어 UI 형 칸이 오른쪽 끝이다. 그 아래 도구 모음 줄(테마·설정 버튼)은 없앴고, 설정은 시스템(Y) > 설정과 보기 메뉴로 연다. 스마트폰 NAV 는 제목 줄이 없어 해당 없고, 테마는 모바일형 메뉴의 테마 전환으로 한다(동등성 유지).
- 제목 줄·제목 탭 높이 값의 정본은 공통원칙 §2-1 이다. 태블릿 DOCK 은 제목 탭을 두지 않아 제목 줄 높이만 영향을 받고, 메뉴 줄 높이는 바꾸지 않는다.
- 패널 기능(핀 고정·끌기 중 도킹 안내) 켬/끔은 시스템 > 설정 '창' 페이지에서 자동·켬·끔으로 고른다. 자동은 PC형 켬, 태블릿형·모바일형 끔이라 이 문서의 태블릿 DOCK 은 **기본이 끔**이다. 끔이면 패널의 📌 핀 버튼과 가운데 분할 표적 안내가 보이지 않고, 같은 탭 영역 안 순서 바꾸기는 남는다. 끔이어도 패널의 문서를 원하는 위치로 끌어 뺄 수 있고(위 패널 ▾ > 패널 위치 > '이 탭 옮기기'의 영역 간 이동도 같다), 숨겨지는 것은 핀과 분할 안내뿐이다. 켬으로 돌려도 핀은 자동 복원하지 않는다.
- 측면 패널은 단일 탭으로 보이고, 문서 창 안은 핀치로 확대한다(ADR-041). 목록 화면은 좁은 폭 경계 이상에서 목록-상세 2열로 연다(05 조사 §5 태블릿 권고, Mars 마스터-디테일).
- 터치 대상 최소 크기는 Android 48dp·iOS 44pt 다. 값 분류는 표준 상수(각 OS 접근성 지침의 값)이고 지침 원문의 출처 URL 은 근거 수준 미확인이다. 캡션 버튼·탭·패널 손잡이 모두 이 크기 이상이다.
- 화면 가장자리에서 시작하는 끌기 동작(도킹·분할선)은 두지 않는다. 막는 가장자리 폭은 설정 키 후보 `ui.touch.edge_drag_exclusion_pt`(기본값 20(후보), 운영 값, 근거 수준 추정)다. 분할선은 안쪽 손잡이로 잡는다(iOS 가장자리 뒤로가기, 08 용어 §7-3 6행).

## 4. Android·iOS 차이

### 5.1 차트 뷰 노출 (REQ-58)

- 뷰별 폼팩터 값의 정본은 `08_차트뷰_설계.md` 의 뷰 등록부다. 이 절은 스마트폰 화면 규칙만 적는다.
- 스마트폰의 뷰별 노출은 그 뷰가 붙은 화면의 노출 값을 넘지 않는다. 화면 노출 값은 메뉴구조 생성물을 따른다. 노출 ✕ 화면으로 가는 링크는 위 안내(대화면에서 열기)를 보인다.
- 칸반·번다운·리스크 뷰가 붙은 화면(SCR-ISS-03·SCR-ISS-04)의 노출 값을 올릴지는 TODO-503 이다.
- 태블릿은 DOCK 기본으로 터치 핸들 크기를 확보하고, 로드맵·스윔레인·리소스 스케줄러 등은 터치 편집 또는 조회 위주다(08 뷰 등록부의 폼팩터 칸).
- 가로 모드: 차트 뷰도 §1 의 스마트폰 가로 규칙(`ui.layout.phone_landscape_keeps_mobile`)을 따른다. 차트 뷰 고유 가로 규칙은 두지 않는다.

## 6. 남은 과제와 판정 규칙
- iOS 생체 인증·QR 스캔 실측은 장비 확보 뒤 한다(TODO-214·TODO-216, 결정 137).
- PMS 제품의 하단 탭 기본값 선택(§2.1)은 TODO-500, iOS 실기 확인은 TODO-502 다.
- Fold5 실측이 남은 항목은 타이틀바 아이콘 배치·제목 줄 높이·패널 기능 끔 기본(§3), 뒤로가기(§4), 패널 ▾ '이 탭 옮기기' 터치 동작·스마트폰 제목 줄 없음(§2), 태블릿 중복 탭 제거(§3)다. 이 실측은 TODO-501 이고, 측정 회차·빌드 식별값·원인 분석은 판정보고서 부록(`../04_기술스택/04_판정보고서_부록/a11_성능_웹_모바일_재측정.md`)과 HISTORY 가 기록한다.
- 접힘 폭에서는 시스템 메뉴가 더보기로 접혀 설정 진입 대상이 없으므로 접힘은 하단 탭 설정을 쓴다.
- **탭 판정 제외 범위(C5·K7, 2026-11-08 사용자 결정):** 앱 창이 화면에 뜨기 전에 주입된 탭은 C5·K7 판정에서 빼고 건수만 보고한다. 앱 코드로 받을 수 없는 플랫폼 동작이기 때문이다. 화면이 뜨는 순간에 걸친 탭은 계속 판정한다(자율 판단). 앱 창에 전달됐다가 사라진 탭과 직접 지연 도달은 판정 대상이다. 판정 기준(앱 창에 전달된 탭은 유실 0)은 낮추지 않는다.
- **'화면 뜨기 전'의 정의(자율 판단):** Android 가 앱 창에 터치를 넘길 수 없는 상태다. 근거는 기기 입력 분배 로그의 줄(입력 채널 없음·닿은 창 없음·다른 프로세스 창)이다. 앱 창 표시 로그 줄 이후라도 입력 채널이 붙기 전이면 포함한다. 판정기는 PC 시계와 기기 시계를 섞지 않고 측정기가 붙인 유실 분류를 쓴다(`poc/ui/test/mobile/judge/c5_splash_judge.py`).
- **접힘(커버 화면) 측정 방법:** 접힘 모드는 기기를 실제로 접지 않고 기기 상태 명령으로 커버 화면으로 옮겨 잰다. 시험 도구는 공용 함수 `poc/ui/test/mobile/measure/retest_android_pcaway_lib.py` 의 `set_closed()`·`set_open()` 이다. 측정이 끝나면 반드시 펼침 상태로 되돌린다. 측정 첫 단계에서 기기 상태가 접힘인지, 활성 화면이 커버 쪽으로 바뀌었는지, 앱 화면 분류가 스마트폰 NAV 인지 확인한다. Android 판에 따라 명령이 무시될 수 있다(추정). 무시되면 펼침 상태에서 좁은 팝업창(폭이 좁은 폭 경계 미만)으로 대신 재고 그 근거를 기록한다.
- 창 배치(스냅 레이아웃)는 스마트폰 NAV 에 해당 없음(창이 하나의 화면 전체라 칸 나눔 대상이 아니다). 태블릿 MDI 로 쓸 때는 `11_창배치_스냅레이아웃.md` 를 적용한다.
