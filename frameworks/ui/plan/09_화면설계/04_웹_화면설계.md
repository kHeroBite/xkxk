# 웹 화면 설계 — 브라우저(데스크톱·태블릿·스마트폰)

> 상태 설계 정본(ADR-052).
> 웹은 데스크톱과 **같은 공용 Shell** 을 브라우저 호스트(Avalonia.Browser, WebAssembly)로 돌린다(ADR-007·037, 판정보고서 §1 웹 L0 6/6). 따라서 화면·메뉴는 `03_데스크톱_화면설계.md` 와 같고, 이 문서는 **차이만** 적는다.
> 와이어프레임: `img/web_shell.svg`(PC 브라우저 MDI, 1280×800). 공통 규칙 `01_화면설계_공통원칙.md`, 브라우저 제약 근거 `05_아키텍처/08_지원_폼팩터_용어.md` §7-3. 결정 ADR-052.

## 1. 셸 구성 (`img/web_shell.svg`)

```
┌ 브라우저 창(브라우저가 그리는 탭·주소창·최소화/최대화/닫기) ───────────────┐
│┌ Pd 메뉴 줄 ─────────────────────────────────────────────────────────┐│
││ [로고] 파일 창 보기 시스템 ………………… [전체화면] [사용자]                 ││ ← 앱 캡션 버튼 없음(W-01)
│├ 제목 줄 ─────────────────────────────────────────── [독립 창 아이콘] ┤│
││ 탐색기 │ MDI 문서 영역(관리형 창 = 앱 화면 안 창)        │ 알림 서랍     ││
│└────────────────────────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────────────────────┘
```
- 화면 방식 규칙은 앱과 같다(공통원칙 §8). PC 브라우저 MDI, 태블릿 브라우저 DOCK 기본, 대화면은 3방식 전환이다. '자동'이면 PC 브라우저는 넓은 폭 경계(`ui.layout.expanded_width_dp`) 이상 PC형, 좁은 폭 경계(`ui.layout.compact_width_dp`)부터 넓은 폭 경계 미만까지 태블릿형, 좁은 폭 경계 미만 모바일형(NAV)으로, 태블릿 브라우저는 좁은 폭 경계 이상 태블릿형·미만 모바일형으로 전환한다(REQ-46-5·8). 키의 선언·기본값은 `../10_API설계/plt_2.md` §12.1 이다. 사용자 에이전트 값은 쓰지 않는다(ADR-051 결정 10).
- PC 브라우저와 태블릿 브라우저의 구분은 폭이 아니라 접속 기기로 정했다(08 용어 §9-4). 웹은 주 포인터 `(pointer: coarse)` 와 정밀 포인터 `any-pointer: fine` 으로 판별한다(판정표 정본 `05_아키텍처/08_지원_폼팩터_용어.md` 8·11·12행). 접힘 상태는 알 수 없으므로 창 폭으로 폴백한다(자율 판단).
- 메뉴 ID·툴팁 표시는 빌드 채널에 따라 다르다. dev·staging·qa 웹판에는 있고 운영(prod) 웹판은 메뉴 이름만 보인다(ADR-090 채널별 표, 결정 55·57·90).

| W-24 | 창 배치(스냅, `11_창배치_스냅레이아웃.md`) | MDI·SDI 창을 끌어 상단 막대·가장자리·모서리로 칸에 맞춰 배치한다. SDI 자동 방식은 OS Snap 에 위임하고, 실기에서 OS 막대가 확인되지 않으면 앱이 막대를 보인다 | **동일**한 칸 규칙을 뷰포트 기준으로 적용한다. 관리형 독립 창도 같은 규칙에 포함한다 | 창 배치 단축키가 브라우저에 전달되는지는 미확인이며 시험(Chrome)에서 확인한다 |
| W-25 | 패널 기능 끔에서 문서 빼기(01 §4.4) | 끔이어도 패널 안 문서를 문서 영역·창으로 끌어 빼고 같은 탭 영역 안 순서 바꾸기도 된다(핀 고정·분할 안내만 숨김). 태블릿형은 패널 기능이 자동에서 끔이라 패널 가장자리 방향 분할(위·아래·왼·오른)이 되지 않고 분할 안내도 숨긴다. 방향 분할을 쓰려면 설정 ▸ 창 ▸ 패널 기능을 '켬'으로 고른다. 직접 고른 값이 자동보다 우선한다 | **웹도 같다**. 웹 펼침 화면의 태블릿형도 같고, 자동 판정(PC형 켬·태블릿형·모바일형 끔, 직접 고른 값 우선)도 같다 | 웹에서 접힘 상태는 알 수 없으므로 UI 형 자동 판별은 창 폭 폴백이다(자율 판단, 판정표 정본 `05_아키텍처/08_지원_폼팩터_용어.md`). 분할 시험은 시작 때 패널 기능을 '켬'으로 두고 끝나면 원래 값으로 되돌린다 |
| W-26 | 창 움직임 효과·배경 이미지·불러오는 중 아이콘(결정 143, `21_창_움직임효과_배경_설계.md`·`23_창_불러오는중_표시_설계.md`) | 전환 효과 출처 `keyboard` 는 Ctrl+Tab·Ctrl+F6. 배경 이미지는 앱 로컬 데이터 폴더에 해시 이름 복사본을 둔다. 스피너는 렌더 스레드 컴포지션 시각물 | 전환 효과 출처 `keyboard` 는 Ctrl+F6 만(Ctrl+Tab 은 브라우저 예약키, W-04). 배경 이미지는 IndexedDB 에 두고, 할당량 초과·축출이면 배경 없음 + 알림 1회 + 저장값 보존. WASM 단일 스레드라 UI 스레드 막힘 구간에 스피너 회전이 멈출 수 있다(추정) | 효과 종류·배치 상태 규칙·즐겨찾기 영역은 앱과 같다(REQ-25). 새로고침 뒤 배경 이미지 유지와 막힘 구간 회전은 웹 시험(Chrome)에서 사실을 기록한다(D-577·D-586·D-596) |
| W-27 | 설정 창 앱 모달·메인 크롬 Ctrl+휠(03_2 §8.2, 01 §5.3) | 설정 창은 별도 OS 창이고 열린 동안 메인·MDI·SDI 가 OS·앱 두 겹으로 막힌다. 메인 크롬 Ctrl+휠은 시스템 글자 크기 | 설정은 화면 가운데 시스템 Flyout 이다. 모달로 열면 바깥 누름으로 닫히지 않고(바깥 누름 닫기 끔) Esc·닫기 단추·뒤로 가기로만 닫힌다. 열린 동안 Flyout 내용과 그 안 팝업 밖의 입력(메인·관리형 창)은 앱 관문이 막는다. 메인 크롬 Ctrl+휠은 시스템 글자 크기로 같다 | 웹은 OS 창이 없어 앱 수준 차단만 쓰며 결과(설정 밖 조작 불가)는 같다(REQ-25). 반투명 덮개는 두지 않는다(후보). 브라우저 자체 Ctrl+휠 확대는 앱이 처리한 입력에서만 막힌다(미확인, 웹 시험에서 기록) |

## 4. 시험 환경 (사용자 지시 2026-10-31 21:06)
- 웹 시험·성능 측정 브라우저는 **Chrome 계열**이다. 시험 도구는 `otest_playwright_bg`(기본, 헤드리스 Chromium)와 `otest_playwright` 스킬을 쓰고, Edge 나 새 브라우저 스크립트는 쓰지 않는다. 모바일 웹은 Fold5 실기 Chrome 이다.
- 헤드리스 소프트웨어 렌더 값은 성능 판정에 쓰지 않는다. 성능 측정은 사용자가 PC 를 쓰지 않을 때만 한다.
- 이 절은 시험 환경 규칙과 판정값 정의만 둔다. 회차별 측정 값·번들 해시·원인 분석은 판정보고서 부록(`../04_기술스택/04_판정보고서_부록/a9_성능_웹_모바일_4_5_6.x.md`·`a10_측정보류_목록.md`·`a11_성능_웹_모바일_재측정.md`)이 기록한다.
- **측정 번들 판본 기록 규칙:** 웹 성능 측정 결과에는 서빙한 번들의 wasm sha256 을 반드시 함께 적는다. 판본을 확인하지 못한 측정은 재측정 대상으로 두고 판정에 쓰지 않는다.
- **W4 공식 판정 조건:** 판정 기준은 끌기 프레임 p95 ≤ 25ms 다. 공식 판정은 제품판 웹(진단 없는 제품 빌드, 프레임 출처 Chrome trace) 기준이다. 조건은 실제 Chrome 창 모드, 끌기 프레임 p95 doc1·doc3·doc5 각각 ≤ 25ms, 문서당 끌기 3회 이상, 열림 p95 grid·form·gantt 각각 ≤ 500ms, 열림 반복 10회 이상이다. 프레임 출처가 Chrome trace 인지, 측정 번들이 AOT 판인지, 앱 대비 비교표(작업별 앱 ms·웹 ms·배율 = 웹 ms ÷ 앱 ms)가 맞는지를 함께 본다. 웹 진단판으로 잰 값은 원인 분석·옵션 판정용 참고값이며 공식 판정이 아니다. 데스크톱 결과는 판정보고서 부록(`../04_기술스택/04_판정보고서_부록/`)이 기록하고, 합격 기준은 `../04_기술스택/03_PoC_UI_합격기준_Mars실측.md` 의 PERF-02 다.
- **웹 끌기 옵션 기본값:** 끌기 중 가벼운 크롬 계열 옵션(가벼운 크롬·영역 다시 그리기 추적·이동 창 비트맵 캐시·정지 아래 창 캐시·정지 창 가벼운 크롬)의 웹 기본값과 판정 근거는 `01_화면설계_공통원칙.md` §4.2 와 `01a_화면설계_공통원칙_끌기경량크롬.md` 가 정본이다. 이 문서는 값을 다시 적지 않는다. 옵션의 설정 키와 값 분류는 아직 키 등록부에 없다(TODO-499).
- **측정 정의의 원칙:** 측정을 통과시키려고 프레임을 만드는 변경은 하지 않는다.
- **웹 끌기 판정값(A15·H-02):** W4 판정값은 무변화 간격을 뺀 끌기 프레임 간격 p95 다(기준 ≤ 25ms 불변, 원래 p95 와 뺀 간격 수를 함께 기록). 정의·판별 규칙은 `../04_기술스택/03_PoC_UI_합격기준_Mars실측.md` §6.3 이 정본이고, 근거 결정은 D-568 이다.

## 5. M1 화면의 웹 노출
- M1 화면은 데스크톱과 같다(`03_데스크톱_화면설계_2.md` §8). pd-admin 화면(SCR-IMP-03·SCR-ADM-05·SCR-ADM-07)은 Pd 웹 메뉴에 없다.
- 회원 가입·홈페이지 같은 공개 페이지는 Pd 앱 화면이 아니라 별도 웹 페이지다(로그인 전 진입은 SCR-IAM-01). 배치는 웹판 제공 결정(`../05_아키텍처/21d_Pd_웹판제공_아키텍처_결정.md`)을 따른다. 통합 진입(4버튼)·이메일 코드·SSO 웹 배치는 `plan/09_화면설계/14_로그인_가입_통합진입_화면설계.md` 를 따른다. 웹 고유 차이로 브라우저 자동완성과 리디렉션 콜백을 쓰고, 팝업이 차단되면 전체 페이지 이동으로 대체한다.
