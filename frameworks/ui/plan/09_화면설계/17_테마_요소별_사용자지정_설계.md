# 17. 테마 요소별 사용자 지정 설계 (REQ-101, 결정 131)

> 상태 설계 정본(ADR-115). D-350~D-355 의 행은 `plan/90_결정관리/01_결정대기_부록/d350_테마사용자지정_확인대기.md` 에 있고 결정 근거는 ADR-115(`plan/90_결정관리/02_결정기록_부록/b37_ADR-115.md`)다. 이 문서는 요소·속성의 의미와 되돌리기·잠금의 화면 규칙을 갖고, 키 선언은 `plan/10_API설계/plt_2.md` §12.1 이 갖는다. 구현 방식·저장 형식은 `plan/09_화면설계/18_디자인테마_설계.md` §9·§13 에 있다.
> 기존 정본: 테마·타이포 두 범위 규칙은 `plan/09_화면설계/01_화면설계_공통원칙.md` §5.1~§5.3, 하드코딩 금지는 REQ-99(`plan/05_아키텍처/05_제품구성_시스템메뉴.md` §1.1), 옵션화는 ADR-089.

## 1. 요구와 범위

사용자 요구 원문은 "기본 테마(템플릿)을 선택후 각 요소마다 색상이나 폰트나 글자크기나 디자인항목들을 사용자가 커스터마이징 가능해야 한다." 이다(REQ-101).

- 내장 테마(템플릿)를 고른 뒤 화면 요소(버튼·입력칸·표 머리·메뉴 줄·상태 줄 등)마다 색·글꼴·글자 크기·디자인 항목(모서리·테두리·안쪽 여백)을 바꾼다.
- 목적은 회사 공통 테마를 그대로 쓰지 않고 사용자가 자기 화면을 읽기 편하게 조정하는 것이다. 바꾼 뒤에도 템플릿 값으로 되돌릴 수 있어야 한다.
- 성공 기준은 값 변경이 즉시 화면에 반영되고, 재시작 뒤 유지되며, 속성·요소·전체 단위로 되돌려지고, 기존 테마와 저장 프로필이 깨지지 않는 것이다.
- 이번 범위는 사용자 계층이다. 회사 계층(REQ-100)은 §4 의 잠금 접점만 설계하고 값 정의는 그 문서를 따른다. 서버 저장·회사 정책 강제는 설계에만 둔다.
- 기존 상태: 내장 템플릿 선택, 사용자 테마 복제·색 토큰 편집·이름·삭제, 테마 내보내기·가져오기(색만), 전역 글꼴·크기(문서·시스템 두 범위)는 이미 있다. 요소별 글꼴·크기·굵기, 요소별 모서리·테두리·여백, 템플릿 값으로 되돌리기는 없다.

## 2. 요소 목록

요소 이름은 소문자 snake_case(`app`·`menu_bar`·`doc_title`·`window_tab`·`button`·`input`·`grid_header`·`grid_cell`·`panel`·`status_bar`)이고 설정 키는 `ui.theme.design.<요소>.<속성>` 이다(§3). 색 속성은 새 색 토큰을 만들지 않고 기존 `PdBrush*` 토큰에 매핑한다(색 토큰 목록은 바꾸지 않는다).

| 요소 | 대상 | 색(매핑 토큰) | 글꼴·크기·굵기 | 디자인 항목 |
|---|---|---|---|---|
| app 전역 | 셸 전체 기본 | Background·Text·Accent | 가능 | 없음 |
| menuBar 메뉴 줄 | 제목줄 안 메뉴(MainMenu) 항목 | MainTitleBar·MainTitleText(메뉴가 제목줄 안에 있어 MenuBar·Text 는 화면에 반영되지 않는다). 활성 창은 제목줄 전체(캡션 단추 영역 포함)의 바탕과 글자에 반영하고, 비활성 창은 제목줄 바탕을 고정한 채 글자색만 반영한다 | 가능 | padding |
| docTitle 문서 창 제목줄 | MDI·SDI 제목 글자 | MdiTitleBar·MdiTitleText | 가능 | 없음 |
| windowTab 창 제목 탭 | 상단 탭 | WindowTabActive·WindowTabActiveText | 글꼴·굵기(글자 크기 해당 없음) | 없음(여백·모서리 해당 없음) |
| button 버튼 | 일반 Button(제목줄·창 크롬 단추 제외) | Button·ButtonBorder·Text | 가능 | cornerRadius·borderThickness·padding |
| input 입력칸 | TextBox·ComboBox·NumericUpDown(복합 입력 NumericUpDown·AutoCompleteBox 는 안쪽 입력 칸에도 적용) | Surface·InputBorder·Text | 가능 | cornerRadius·borderThickness·padding |
| gridHeader 표 머리 | DataGrid 열 머리 | GridHeader·GridHeaderLine·Text | 가능 | padding |
| gridCell 표 칸 | DataGrid 칸 | Surface·GridLine·GridStripe·Text | 가능 | padding(줄 높이) |
| panel 도구 패널 | 패널 머리·본문 | SurfaceAlt·Border | 가능 | 없음(모서리 해당 없음) |
| statusBar 상태 줄 | 하단 상태 줄 | StatusBar·StatusBarText | 가능 | padding |

- 문서 창 제목줄의 모서리·외곽선·그림자는 OS 기준값(`plan/04_기술스택/05_창크롬_OS디자인_기준.md`)이라 사용자 지정 대상에서 뺀다. 그림자는 속성에 넣지 않는다(D-351).
- 문서 창 안 글자는 기존 문서 글꼴·크기(Ctrl+휠 포함)가 계속 우선한다. 요소 글꼴은 셸 요소에 적용되고, gridHeader·gridCell 은 문서 글자 크기를 기준으로 오프셋을 적용한다.
- 버튼 요소 범위에서 제목줄·창 크롬 버튼은 제외한다. 창 크롬은 OS 기준(`plan/04_기술스택/05_창크롬_OS디자인_기준.md`)이다. 제외 대상은 창 크롬 단추와 제목줄 안 버튼이다. 판정 기준은 형식 이름이 아니라 클래스다(구현 대응은 18 §13). 스타일 적용 대상과 시험 측정 대상이 같은 제외 규칙을 쓴다.
- 해당 없음 속성(해당 컨트롤에 로컬 값이 있어 스타일이 이기지 못함). windowTab 글자 크기(탭 글자에 로컬 크기)·여백(제목 단추에 로컬 여백)·모서리(반영 실측 안 됨), panel 모서리(도구 패널 틀이 쓰지 않아 미반영). 이 속성은 편집 목록에서 빼며, 옛 저장본에 키가 있으면 검증에서 거부해 무시한다. 남는 속성은 windowTab 글꼴·굵기, panel 글꼴·글자 크기·굵기이다. 적용되는 것은 windowTab 굵기·statusBar 여백·gridCell 여백이다. 정확한 속성 목록은 구현이 정하며 이 표와 맞춘다.
- 요소 목록 10종은 D-350 이다. 요소 추가는 설정 표에 행만 더하면 되도록 코드에 요소 목록을 박지 않는다(REQ-99).

## 3. 설정 키와 값 형식

모든 값은 설정 키 + 기본값이다(REQ-99). 키 꼴은 `ui.theme.design.<요소>.<속성>` 이고 첫 마디 `ui` 는 횡단 접두, 마디는 snake_case 다(`plan/05_아키텍처/53_Pd_용어_상태어휘_문서규칙.md` §5). 키 선언(값 꼴·값 분류·허용 층·저장 위치)의 정본은 `plan/10_API설계/plt_2.md` §12.1 이고, 이 절은 요소·속성의 의미와 화면 동작, 요소 대응을 갖는다. 아래 표는 그 선언을 읽기 쉽게 옮긴 것이며 어긋나면 plt_2 가 이긴다. 범위도 상수가 아니라 아래 범위 키의 값이며, 숫자 범위 열은 초기 제시값이다. 요소 이름은 §2 의 10종이고 요소마다 해당하는 속성만 연다.

**요소별 키** — 값 분류는 모두 사용자 옵션(허용 층 회사·사용자, 제약원 없음, 결정 D-350)이다.

| 속성 | 설정 키 | 형식 | 범위(초기 제시값) | 기본값 |
|---|---|---|---|---|
| font_family | `ui.theme.design.<요소>.font_family` | 글꼴 이름 | 설치 글꼴 목록(웹은 번들 글꼴만) | ""(상속, 현재 렌더 유지) |
| font_size | `ui.theme.design.<요소>.font_size` | 요소 자기 기본 크기 대비 오프셋(정수) | `font_size_offset_min` ~ `font_size_offset_max` | 0 |
| font_weight | `ui.theme.design.<요소>.font_weight` | Normal·Medium·SemiBold·Bold | 글꼴에 실재하는 굵기 | ""(상속, 현재 렌더 유지) |
| corner_radius | `ui.theme.design.<요소>.corner_radius` | 정수 | 0 ~ `corner_radius_max` | button·input 은 Fluent 리소스 값, 그 외 ""(상속) |
| border_thickness | `ui.theme.design.<요소>.border_thickness` | 정수 | 0 ~ `border_thickness_max` | button·input 은 Fluent 리소스 값, 그 외 ""(상속) |
| padding | `ui.theme.design.<요소>.padding` | 1값·2값·4값 | 0 ~ `padding_max` | button·input 은 Fluent 리소스 값, 그 외 ""(상속) |
| 색 | 기존 `PdBrush*` 색 토큰 | 색 값 | 색 선택기 | 템플릿 값 |

**범위 키** — 값 분류는 운영 값(허용 층 운영 시스템뿐)이다. 값은 초기 제시값이고 범위 밖 값은 저장·가져오기 때 버린다.

| 설정 키 | 값 | 설정 키 | 값 |
|---|---|---|---|
| `ui.theme.design.font_size_offset_min` | −4 | `ui.theme.design.font_size_offset_max` | 8 |
| `ui.theme.design.font_size_min` | 10 | `ui.theme.design.font_size_max` | 24 |
| `ui.theme.design.corner_radius_max` | 16 | `ui.theme.design.border_thickness_max` | 4 |
| `ui.theme.design.padding_max` | 24 |  |  |

- 기본값은 지금 화면과 같은 렌더를 유지하도록 잡아 무변경을 보장한다. 제품 기본값이 ""(상속)인 키(font_family·font_weight, 그리고 Fluent 리소스 키가 없는 요소의 corner_radius·border_thickness·padding — window_tab·panel 등)는 어느 층도 값을 주지 않으면 앱 리소스에서 지워 현재 화면이 그대로 유지된다. corner_radius·border_thickness·padding 은 button·input 만 Fluent 리소스 값을 기본으로 읽는다.
- 굵기는 합성 굵게 금지 규칙(§5.2)을 따른다. 글꼴에 없는 굵기는 가까운 실재 굵기로 대체하고 실효값을 표시한다.
- 글자 크기 실효값 = clamp(요소 자기 기본 크기 + 오프셋, `font_size_min`, `font_size_max`)이다. 요소 기본 크기는 (문서 범위 요소면 문서 글자 크기, 아니면 시스템 글자 크기) + 요소별 기준 토큰 오프셋이다(글자 크기 속성이 있는 모든 요소는 본문 토큰 0, 실제 무지정 렌더 크기와 같게. 글자 크기가 해당 없음인 windowTab 만 캡션 토큰을 기록해 둔다). 상태바 글자도 로컬 크기 없이 본문 크기를 상속하므로 본문 토큰을 쓴다. 이 기본 크기가 시스템 글자 크기를 따르므로 시스템 크기 설정과 겹쳐 동작한다. 시스템 크기가 바뀌면 오프셋은 유지하고 다시 계산한다. 오프셋 0 은 지금 화면과 같다(D-352).
- 적용 규칙. 지정된 (요소, 속성)만 화면에 반영하고, 미지정이면 기존 화면이 그대로다(무변경). 값이 바뀌면 즉시 다시 반영한다. 구현 방식(스타일 묶음 생성·전환형 규칙·안전 폴백)과 그 실측 근거는 `plan/09_화면설계/18_디자인테마_설계.md` §7·§13 에 있다. 요소별 적용 대상 선택 기준은 코드에 박지 않고 요소 표(데이터)에 둔다(REQ-99).
- 설정 키 밖 값·모르는 요소·속성, 형식·범위 밖 값(음수·NaN·빈 글꼴)은 저장·가져오기 때 버린다.

**대비 경고 기준 키** — 값 분류는 제품 상수(D-354, 접근성 고정이라 회사 재정의 없음, 운영 시스템 층에서만 바뀜)다. 법령·보안·무결성 예외가 아니라 사용자 방침으로 고정한 제품 정책이다.

| 설정 키 | 기본값 | 뜻 |
|---|---|---|
| `ui.theme.design.contrast_min` | 4.5 | 본문 글자 대비 기준 |
| `ui.theme.design.contrast_min_large` | 3 | 큰 글자 대비 기준 |
| `ui.theme.design.large_text_size` | 24 | 큰 글자로 보는 기준 크기 |
| `ui.theme.design.contrast_min_high` | 7 | 높은 기준(대비 템플릿) |
| `ui.theme.design.contrast_template` | pd-contrast | 높은 기준을 쓰는 템플릿 |

별도의 잠금 목록 키는 두지 않는다. 잠금은 §4 의 항목 상태로 표현한다.

## 4. 설정 계층과 저장

값 층의 이름과 순서는 `plan/05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §5 가 정본이다(제품 기본 → 운영 시스템 → 회사 → 하위 범위 → 사용자, 가장 아래 지정 값이 유효값).

```
실효값 = 사용자 값 ?? 회사 값(REQ-100) ?? 제품 기본 층 값(템플릿 값 ?? 키 선언 기본값)
```

- 제품 기본 층: 키 선언 기본값은 §3 표의 기본값이다. 템플릿 값은 이 층 안의 값 묶음이다(05/30 §5 에서 팩이 기본값 공급원으로 이 층의 값을 달리 주는 것과 같은 방식이며 층을 더 만들지 않는다). 내장 템플릿의 요소 값 묶음은 지금 7종 모두 비어 있어 키 선언 기본값을 따른다. 내장 색 표와 색 토큰 목록은 바꾸지 않는다.
- 회사 값·잠금(설계만): 정본은 REQ-100 문서(`plan/05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md`)다. 회사 값은 같은 키 체계로 회사 층에 둔다. 잠금은 별도 목록이 아니라 05/30 §4 항목 상태로 표현한다. 회사가 키(또는 한 요소의 키 묶음)의 상태를 '읽기 전용'으로 정하면, 곧 그 키의 허용 층에서 사용자를 빼면, 그 키는 편집 화면에서 비활성·자물쇠로 표시한다. 저장된 사용자 값은 삭제하지 않고 무시하며 잠금이 풀리면 복귀한다. 회사 층 공급자가 없는 PoC 에서는 모든 키의 허용 층이 사용자·회사라 잠금이 없다(D-355).
- 사용자 값은 바꾼 키만 저장한다(희소 저장). 바꾸지 않은 키는 저장되지 않아 이후 제품 기본이 바뀌어도 따라간다. 색은 기존 색 사전을 그대로 쓴다.
- 사용자 테마는 복제 원본 내장 템플릿 Id 를 함께 기억하며 이것이 되돌리기 기준이다. 옛 저장본은 요소 값이 비어 있어 화면이 변하지 않고, 원본 Id 가 없으면 기반(Light·Dark)에 맞는 내장(pd-light·pd-dark)을 기준으로 한다.
- 기반 Light·Dark 를 바꾸는 이름 변경 뒤에도 되돌리기 기준은 원본 Id 가 우선이다. 사용자 테마를 삭제하면 같은 기반 내장으로 복귀하고 요소 값도 함께 사라진다.
- 저장 경로는 기존 하나(테마 변경 → 설정 저장)다. 저장 형식(필드 이름·직렬화)은 `plan/09_화면설계/18_디자인테마_설계.md` §9 에 있다. 서버 저장(사용자 설정 서버 동기화)은 TODO-170 이다.

## 5. 동작

- 템플릿 선택: 기존 콤보·편집기 목록에서 내장 템플릿을 고른다.
- 자동 사용자 지정: 내장 템플릿이 선택된 채 요소 값을 바꾸면 그 템플릿의 사용자 사본(`<템플릿 이름> 사용자 지정`, 복제 원본 = 그 내장 템플릿)을 한 번 만들어 선택하고 변경을 거기에 넣는다. 묻지 않는다. 내장은 그대로이고, 같은 원본의 사본이 이미 선택 중이면 새로 만들지 않는다(D-353).
- 즉시 반영: 변경마다 지정된 요소·속성의 반영을 다시 한다(같은 값이면 생략). 재시작이 필요 없다. 숨은 컨트롤(예 모바일형의 메뉴 줄)도 다시 보일 때 최신 값이 반영돼야 하므로 반영 뒤 전체 컨트롤을 다시 평가한다(구현 대응과 실측은 18 §13).
- 언어 전환 시 요소·속성 표시명이 즉시 갱신된다.

## 6. 되돌리기

세 단계다.

| 단계 | 효과 | 확인 |
|---|---|---|
| 속성 | 그 키 1개 삭제(색 속성은 기준 템플릿 값으로) | 없음 |
| 요소 | 그 요소 키 전부 삭제 + 그 요소 매핑 색 토큰을 기준 템플릿 값으로 | 없음 |
| 전체 | 요소 값 사전 비움 + 색 전체를 기준 템플릿 값으로 | 확인 대화상자 1회 |

기준 템플릿은 사용자 테마의 복제 원본 내장 템플릿이다(§4).

## 7. 편집 화면 위치와 미리보기

- 위치는 기존 테마 편집기(보기 ▸ 테마 편집기, 설정 ▸ 모양 ▸ 테마 편집기 열기) 안의 '요소별 디자인' 영역이다. 기존 색 토큰 표는 그대로 두고, 요소 목록 → 속성 행(값 편집기 + 되돌리기 단추) 구조다.
- 셸 화면이라 새 메뉴 ID 를 쓰지 않는다(`plan/09_화면설계/09_메뉴ID_규칙.md` 셸 구간 미배정). 합의 구간의 메뉴 ID 1090 은 발급하지 않았다(정본은 `plan/_build/menu_data.py`).
- 속성 행은 덮어쓴 값이면 표시(점), 잠금이면 자물쇠, 대비 경고면 경고 아이콘을 보인다.
- 미리보기: 편집 패널에 표본(버튼·입력칸·표 머리 1줄)을 두고 변경이 즉시 보인다. 표본은 보조이며, 실제 반영은 셸의 실제 요소에서 확인한다.

## 8. 폼팩터

용어는 `plan/05_아키텍처/08_지원_폼팩터_용어.md` 를 따른다. 기능은 모든 폼팩터에서 같다(REQ-25 동등성).

| 폼팩터 | 배치 |
|---|---|
| PC형(MDI·SDI)·데스크톱 웹 | 편집기 창 안 2열(요소 목록 \| 속성 행) |
| 태블릿형(DOCK) | 같은 2열, 폭이 좁으면 1열 |
| 모바일형(NAV, 스마트폰·모바일 웹) | 1열, 요소 선택 → 속성 화면으로 이동, 터치 대상 44 이상 |

- 웹은 글꼴 목록이 번들 글꼴만이다(§5.2 기존 한계). 데스크톱 전용 글꼴 이름을 가져오면 번들 글꼴로 대체하고 실효값을 표시한다.

## 9. 접근성과 대비 경고

- 요소의 글자색 대 바탕색 대비가 4.5:1(본문)·3:1(18pt 이상) 미만이면 경고를 표시한다. 차단하지 않고 저장된다(사용자 선택 존중, ADR-089). 경고는 끌 수 없다(접근성, 제품 상수 — 사용자 방침으로 고정, §3 대비 경고 기준 키).
- 기준 템플릿이 `pd-contrast` 면 7:1 기준으로 경고한다(WCAG 2.1 SC 1.4.6, https://www.w3.org/WAI/WCAG21/Understanding/contrast-enhanced.html). 기준 값은 §3 의 설정 키다(D-354).
- 속성 행은 키보드로 모두 조작할 수 있고, 값·덮어씀·잠금·경고 상태는 보조 기술에 이름으로 전달한다.

## 10. 내보내기·가져오기

- 기존 테마 JSON 내보내기·가져오기에 요소 값과 복제 원본 템플릿이 함께 실린다. 옛 JSON(요소 값 없음) 가져오기도 동작한다.
- 가져오기는 §3 의 검증으로 모르는 키·범위 밖 값을 버린다. 가져온 테마는 새 사용자 테마로 추가되며 실효값이 원본과 같아야 한다.
- 웹: 브라우저에는 파일 경로가 없으므로 내보내기는 경로 대신 내용(JSON)을 내려받기로 처리한다. 재시작(페이지 다시 읽기) 뒤 유지는 웹 설정 저장소에 사용자 테마와 요소 값을 함께 저장해 보장한다.

## 11. 시험

원격 자동화(진단 빌드 전용)로 셸의 실제 컨트롤에서 읽은 계산값(글꼴·크기·굵기·모서리·테두리·여백·바탕색·글자색)으로 판정한다. 표본 미리보기 값으로 판정하지 않는다.

| 케이스 | 판정 |
|---|---|
| 템플릿 선택 | 선택한 템플릿 색 계산값 = 템플릿 표 값 |
| 자동 사용자 지정 | 내장 선택 중 값 변경 → 새 사용자 테마 선택됨, 복제 원본이 선택했던 내장과 일치, 내장 템플릿의 요소 값 비어 있음 |
| 색·글꼴·크기·굵기·모서리·테두리·여백 각 변경 | 해당 요소 실제 컨트롤 계산값이 지정 값(글자 크기는 시스템 크기 + 오프셋) |
| 즉시 반영·재시작 유지 | 같은 세션 다음 프레임 반영, 재기동(웹은 페이지 다시 읽기) 뒤 값 유지 |
| 되돌리기 3단 | 속성·요소·전체 각각 제품 기본값·템플릿 색으로 복귀 |
| 희소 저장 | 저장 JSON 의 요소 값에 바꾼 키만 있음 |
| 편집형 ComboBox | 대상 없음(제품 소스에 편집 가능한 ComboBox 가 없다). 생기면 `input` 요소 시험 항목에 추가한다 |
| 팝업 상속 | 팝업(컨텍스트 메뉴·콤보 드롭다운)에서도 요소 지정이 같은 값으로 적용됨(첫 프레임 표식 맞음 ≥1·어긋남 0, 18 §11) |
| 내보내기·가져오기 | 가져온 새 테마의 실효값 동일 |
| 대비 경고 | `pd-contrast` 기반 사본에서 글자색≈바탕색 → 경고, 7:1 기준 |
| 옛 저장본 | 요소 값 없는 프로필로 기동 → 사용자 테마·선택 Id 유지, 화면 계산값 불변 |
| 내장 불변 | pd-light·pd-dark·pd-contrast 선택 시 색 계산값 = 내장 표 |
| 회귀 | 기존 창 끌기·스냅·창 크롬·테마 동기화 시험 통과 |

- 데스크톱은 격리 진단판에서 원격 명령만 쓰므로 화면 캡처·실입력이 필요 없다. 웹은 번들 정적 서버 + headless Chromium, 모바일은 헤드리스 에뮬레이터로 기능 7케이스(템플릿 선택·요소 변경·재시작 유지·되돌리기 3단·가져오기)를 본다. 성능 재측정은 하지 않는다(끌기·열기 경로를 바꾸지 않음).
- 위험: 로컬 값이 스타일보다 우선하는 컨트롤은 요소 지정이 먹지 않는다. 실측해 §2 에 '해당 없음 + 근거'로 적었다. 새 요소를 더할 때도 대상별로 실측한다.
