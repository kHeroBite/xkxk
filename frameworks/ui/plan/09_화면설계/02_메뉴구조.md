# 메뉴 구조 — 셸 메뉴와 업무 메뉴(화면 목록)

> 자동 생성 파일 — 정본은 `plan/_build/menu_tree.py`(데이터 `plan/_build/menu_data.py`). 고칠 때는 정본을 고치고 `cd plan && python3 -B _build/menu_tree.py` 로 다시 만든다.
> 기능별 상세 행은 `메뉴구조.csv`(UTF-8 BOM)다. 화면 원칙은 `01_화면설계_공통원칙.md`, 결정은 ADR-052 다.

생성기 계산 — 화면 100개(참조형 8·배치 후보 9·화면 후보 1), 배치한 현행 기능 238건, 화면 없는 기능 1건(AIN-10), 현행이 아닌 기능 3건(AIN-05·AIN-06·LIC-07)은 메뉴에서 뺀다, 화면 릴리스 {'M1': 34, 'M2': 34, 'M3': 15, 'M4': 17}.

## 1. 셸 상단 메뉴 (모든 화면 공통)

제품 셸 메뉴의 정의다. 창 관리 명령은 '창(W)' 한 메뉴에 둔다. 메인 제목줄에는 제품 이름 글자를 두지 않고 접근성 이름만 둔다. 파일 메뉴의 '새 …' 항목은 업무 화면 모듈이 셸 등록 경로로 기여하는 확장점이다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7). 시스템 메뉴의 동작은 `../05_아키텍처/05_제품구성_시스템메뉴.md` 가 갖는다. 셸 메뉴 항목의 메뉴 ID 는 셸 구간(0001~0999)에서 배정하며 항목별 배정 표는 아직 없다.

```
[로고] [파일(F)] [창(W)] [보기(V)] [시스템(Y)]  …빈 공간(끌기·더블클릭)…  [_][□][X]
파일(F)
  새 ▸ (업무 화면 모듈이 기여한 문서 종류) · 새 독립 창 ▸ (같은 기여 목록)
  ─ 레이아웃 저장 / 레이아웃 복원 / 레이아웃 관리…
  ─ 화면 캡처
  ─ 종료(Alt+F4)
창(W)
  계단식 배열 / 가로 바둑판 배열 / 세로 바둑판 배열 / 탭 문서로 전환
  ─ 최소화 / 최대화·이전 크기 / 이전 크기로 / 핀 고정(항상 위) / 이름 변경 / 크기·위치 초기화
  ─ 전체 최소화 / 전체 복원 / 최근 최소화 창 복원
  ─ 다음 창(Ctrl+Tab·Ctrl+F6) / 이전 창(Ctrl+Shift+Tab·Ctrl+Shift+F6)
  ─ 독립 창 ▸ MDI↔독립 창 전환 / 독립 창으로 분리 / MDI로 재결합 / 위치 초기화 / 모두 최소화 / 모두 복원 / 모두 닫기
  ─ 모니터 ▸ 모니터 1: 이름 해상도 [주] / 모니터 2: … (라디오, 선택 모니터로 최대화)
  ─ 메인 창 크기·위치 초기화
  ─ 닫기(Ctrl+F4) / 다른 창 모두 닫기 / 모두 닫기
  ─ 창 옵션 ▸ 자동저장 / Esc 창닫기 / 자석 / 자석 범위… / 탭 더블클릭으로 닫기 / 주의 환기(반짝임) / 트레이 상주
  ─ 열린 창 목록 1~9 (활성 ✓)
보기(V)
  프리셋: MDI 계단식 / 탭 문서 / MDI 세로 바둑판
  ─ 탐색기 / 로그 / 알림
  ─ 빠른 찾기(즐겨찾기·최근, 팔레트 홈) / 즐겨찾기·최근 패널 (09/20 개인화 빠른 찾기)
  ─ 화면 방식 ▸ MDI / DOCK / NAV (대화면만, 스마트폰은 자동 NAV)
  ─ 문서 글자 기본 크기(Ctrl+0)
  ─ 라이트/다크 전환 / 다음 테마 / 설정… / 테마 편집기…
시스템(Y)
  디버그모드 · GPU 가속모드 · 프로그램 중복모드 | 모니터링 ▸ · 로그 ▸ | 문의하기 · 문의목록 | 업데이트 확인 · 변경이력 · 도움말 · 프로그램 정보
```

- 웹은 같은 메뉴를 쓰되 브라우저가 가로채는 키(Ctrl+Tab·Ctrl+F4·Alt+F4)는 메뉴로만 제공하고, 앱 창 캡션 버튼은 두지 않는다(브라우저 기능 사용, `04_웹_화면설계.md`).
- 스마트폰 NAV 는 셸 메뉴를 상단 앱 바의 더보기(⋮)로 축약한다(`06_모바일_화면설계.md`).

## 2. 업무 메뉴 — 그룹별 화면

MDI·DOCK 은 탐색기 패널(서랍) 트리, 대화면 NAV 는 좌측 메뉴, 스마트폰 NAV 는 하단 탭과 더보기로 같은 그룹을 보여 준다. 화면이 보이는지, 숨기는지, 잠금 표시로 두는지는 표시 판정식(`../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §3, 판정 순서 정본 `../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §8)을 따른다. 숨김·잠금 표시 방식은 설정 키 `ui.screen.not_entitled_display`·`ui.screen.gate_closed_display` 이고 선언은 `../10_API설계/plt_2.md` §12.1 이다.

메뉴ID 는 불변 4자리 숫자다(`09_메뉴ID_규칙.md`). 셸·업무 두 구간으로 배정하고 pd 는 접두 없음, pd-admin 은 a 접두, 오케스트레이터는 o 접두다. 업무 구간 1001~9999·셸 구간 0001~0999 이고(D-156·D-157) R-3 불변을 적용한다. 화면에는 개발·STG·QA 빌드에서만 `[1001] 이름` 으로 보이고 운영 빌드는 이름만 보인다(키 `ui.menu_id.visible_channels`, ADR-090).

## 4. 범례

- 프로그램: 실행 단위다(`pd`·`pd-admin`, 뜻은 `../05_아키텍처/53_Pd_용어_상태어휘_문서규칙.md` §1.1). pd-admin 화면은 pd 메뉴에 나오지 않는다.
- 이용 구분: 사용자·회사 관리·운영사로 메뉴 그룹과 프로그램을 가르는 표시이고 권한이 아니다. 화면 권한 코드는 `iam.screen.read`·`iam.screen.write` 이고 화면 ID 는 대상 열이다(`../10_API설계/iam.md`). 역할별 기본 부여는 `iam` 역할 시드(`../06_기능목록/20_Pd_상세기능설계_공통_권한_화면.md` §2)가 갖는다.
- 소유 모듈·기여 모듈: 화면마다 소유 모듈 하나와 기여 모듈을 둔다(`../05_아키텍처/32_Pd_모듈화_조립구조_설계.md` §7). 값은 모듈 등록부(`../05_아키텍처/48_Pd_연동설계_총괄_계약등록부.md` §3) 이름이고, 기여 모듈이 테넌트 허용에 없을 때 영역 동작은 `../05_아키텍처/50_Pd_모듈_의존그래프.md` §3.2 가 갖는다. 생성기는 두 칸의 모듈이 등록부에 있는지, 기능 등록부에 소유 모듈 칸이 있으면 화면의 기능이 소유·기여 모듈 안에 드는지 검사한다.
- 데스크톱 열림: MDI = 문서 창(DOCK 에서는 문서 탭, NAV 에서는 콘텐츠 영역), 모달 = 대화 상자, 전용 창 = 로그인 전 단독 창, 패널 = 도구 패널(서랍), 셸 = 메인 창 자체.
- 스마트폰: ○ 전체 기능, △ 조회·간단 처리만(편집은 대화면 안내), ✕ 메뉴에 두지 않음. 이 칸은 화면 선언의 기본값이고, 회사는 화면·폼팩터별로 바꿀 수 있다(표시 판정 `../05_아키텍처/30_Pd_회사별_항목정책_옵션화_설계.md` §3). 태블릿은 데스크톱과 같은 화면이다(DOCK 기본).
- 릴리스: 화면에 묶인 현행 기능 가운데 가장 이른 단계다(M1<M2<M3<M4, 출시 뒤 X). 참조형 화면은 화면 데이터의 릴리스 값을 쓴다. 기능ID 칸의 괄호는 화면 릴리스와 단계가 다른 기능의 단계이고, 화면 안 그 영역이 그 단계에 켜진다.
- 후보 표시: 화면 ID·메뉴 ID 는 발급되면 확정이다(D-496). '(배치 후보)'는 화면은 있고 그룹·화면명·배치가 후보인 화면, '(화면 후보)'는 화면을 둘지 자체가 후보인 화면이다. 참조형 화면은 다른 화면에 배치된 기능을 참조만 한다(중복 배치가 아니다).
- PMO 묶음 바로가기: 직군 권한 템플릿(IAM-05)은 SCR-IAM-02(역할·권한) 탭에 두고 PMO 묶음에는 그 탭으로 가는 바로가기만 둔다. ISS-19 는 전용 화면 SCR-ISS-08 이고(D-223) PMO 묶음에는 그 화면으로 가는 바로가기만 둔다. 바로가기에는 새 화면 ID·메뉴 ID 가 없다.
- 메뉴ID: 불변 4자리 숫자이고 재사용하지 않는다(정본 `menu_data.py` 의 MENU_ID). '0000' 는 미배정 표시다. 생성기는 프로그램 접두·4자리 형식·업무 구간·중복·폐기 번호 재사용·미배정 화면과 직전 생성물 대비 메뉴 ID 변경을 검사한다.
