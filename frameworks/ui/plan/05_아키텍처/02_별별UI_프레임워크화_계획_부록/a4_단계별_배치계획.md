## 1. 공통 끝 조건

코드를 바꾸는 batch(B02~B23)는 아래를 모두 지켜야 끝난다.

- 빌드 3축(데스크톱·웹·Android) 성공(`tools/check_build_rc.sh`).
- `python3 -B tools/check_layers.py` 와 `python3 -B tools/classify_layers.py --check` 가 rc=0 이다.
- 계약 시험(B02 신설) rc=0 이다.
- 공개 API 검사(`test/framework/judge/api_surface_check.py`) rc=0 이다(B02 부터).
- 비전경 판정기 회귀 0 이다. F 단계 끝 batch 는 포그라운드 판정기와 Fold5 실기기 시험을 포함한다(PC 비움·접지 않음 원칙).
- 새로 만들거나 바꾼 층 파일은 300줄 이하이고 첫 줄에 한국어 헤더 주석이 있다.
- 성능 항목은 PC 비움 때만 실제 ms 로 판정한다. PC 사용 중이면 성능 항목만 대기로 두고 나머지는 진행한다.
- 공개 API·문서 대상이 바뀌면 `python3 -B tools/gen_api_docs.py` 로 명세(`docs/api/`)를 다시 만들고 수기 문서(`docs/`)를 갱신하며 `bash test/framework/verify_framework.sh --stage docs` 가 rc=0 이다(B07b 신설, UADR-0015).

## 3. 의존

- B01→B02→…→B23 직렬이다. 각 batch 가 앞 batch 결과(공개 계약·폴더 구조)를 입력으로 쓰므로 batch 사이 병렬은 두지 않는다. batch 안에서는 파일 소유자 1명 원칙으로 나눠 병렬로 한다.
- B04·B05 의 대상 파일 목록은 대표값이다. 착수 전에 `rg -l` 결과로 다시 확정한다.
- B11 은 실행 파일 이름·경로를 한곳(`test/common/_paths.py`·`tools/pdctl.py` 상수)에서 읽게 먼저 바꾼 뒤 옮긴다.
- 질문·사용자 조치가 걸린 batch 는 그 항목만 대기로 두고 다른 항목은 진행한다. B18 은 저장소 이전·러너 등록·INFRA 기재가 끝나지 않았으면 로컬 피드 단계까지만 하고 게시 항목을 이월한다.

## 5. ohoops 알림

- 조건은 B18 끝 조건 전부다. F5 에서 첫 사전판(0.x) 패키지를 사내 피드에 게시하고 피드 소비 시험이 PASS 해야 한다.
- 그때 team-lead 가 사용자에게 "ohoops UI 개발 가능"을 알린다. 추적은 UTODO-0025 다.
- 알림에는 소비자 문서 진입점 `frameworks/ui/docs/README.md` 링크를 함께 적는다. 문서는 B07b 에서 만들고 이후 batch 마다 §1 공통 끝 조건으로 갱신한다.
- 그 전까지 ohoops UI 개발은 보류한다.
