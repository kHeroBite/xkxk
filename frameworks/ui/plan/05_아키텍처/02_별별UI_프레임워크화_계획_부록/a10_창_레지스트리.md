# 부록 a10 — 창 레지스트리

> 상태: 계획 확정(B09 구현 끝, B10 창 문맥·강타입 뷰모델·시험대 이전 구현 진행 중) · 최종 갱신일: 2026-11-27 · 본문: `../02_별별UI_프레임워크화_계획.md`
> 근거: 결정 UADR-0016(창 레지스트리·문서 종류 문자열 ID·저장 형식 6)·UADR-0017(시험대 모듈·강타입 창 등록), 원칙 UADR-0009(8원칙), 레지스트리 모양 UADR-0013·부록 a8, 메뉴 부록 a9, 강타입 등록 부록 a11, 배치 부록 a4 B09·B10.

## 1. 목적

문서 종류를 열거형 `DocumentKind`(Grid·Gantt·Form)에서 **등록식 문자열 ID** 로 열어 솔루션이 자기 창 종류를 더할 수 있게 한다(본문 §5 `ui.Windows`). 그 과정에서 옛 레이아웃 저장본을 하나도 잃지 않는다(본문 §9 위험 표 "저장 형식 버전 올림 + 옛 값 읽기 변환").

- 창 종류 등록·조회·열기·내용 생성 함수까지가 B09 범위다. 창 문맥·강타입 뷰모델·뷰 등록은 B10 에서 열었다(§2 I6·I7, 등록 상세는 §13 → a11).
- 열거형은 소스에서 없앤다(계획 시점 `src/` 28파일 67줄 사용, 문자열 변환 7곳 별도).
- 레이아웃 저장 형식을 Version 5 에서 6 으로 올리고 v1~v5 는 읽을 때 변환한다.
- 완료 판정은 `DocumentKind` 0 과 읽기 변환 고정 시험 PASS 다(a4 B09).

조회와 열기 규칙은 다음과 같다.

- `Contains`·`TryGet`·`Remove` 는 ID 만 Ordinal 로 비교하고 별칭은 받지 않는다. `Items` 는 등록 순서다.
- `TryResolve`·`Open` 은 아래 순서로 찾고 먼저 맞는 창을 쓴다.
  1. ID(Ordinal).
  2. 별칭(OrdinalIgnoreCase).
  3. 옛 이름·옛 숫자. `LegacyWindowKinds.ToId(값)` 이 ID 를 주면 그 ID(Ordinal)로 다시 찾는다. 창 정의의 `Aliases` 와 무관하다(§3). 옛 이름·숫자는 예약어(§4)라 셸 밖의 창이 1·2번에서 가로채지 못한다.
- `Open(id)` 는 `TryResolve` 로 정의를 찾아 셸의 `OpenDocument`(정규 ID)를 부르고 true 를 돌려준다. 제목은 지정하지 않고(자동 제목), 분리창 여부는 정의의 `Placement`, 중복 허용은 아래 규칙을 따른다. 못 찾으면 false 와 XKUI0505, 셸이 아직 없으면 false 와 XKUI0506 이다.
- `Open(id, configure)` 는 `UiWindowOpenOptions` 를 만들어 `configure` 를 적용한 뒤 `OpenDocument(정규 ID, options)` 를 부른다.
- `configure` 가 null 이면 `ArgumentNullException` 이고, 그 밖에는 예외를 던지지 않는다(진단 + false).
- 중복 허용 유효값은 `options.AllowDuplicate` 이며 null 이면 현재 설정이다. 현재 설정의 처음 값은 정의의 `AllowDuplicate` 이고, 저장본의 켬·끔 목록(§5.3)과 제목줄 '중복 허용' 버튼이 바꾼다.
- `UiWindowOptions.CreateContent` 의 반환값은 Avalonia `Control` 이어야 한다. `Framework/` 는 Avalonia 를 모르므로 `object?` 로 받고 화면 층이 검사한다(아니면 XKUI0507).
- `CreateContent` 를 비워도 등록은 된다. 다만 B10 부터 화면 층이 내용을 대신 만들어 주는 창은 없으므로 `CreateContent` 없는 창은 전부 자리표시와 XKUI0507 이다(§7).
- 등록 뒤에 옵션 객체를 바꿔도 정의는 바뀌지 않는다.

```csharp
// 모듈 Configure 안 — B09 의 등록 모양(내용 함수가 Control 을 돌려준다).
ui.Windows.Add("acme.project.editor", o =>
{
    o.TitleKey = "acme.project.editor";
    o.Icon = "acme.icon.project";
    o.CreateContent = context => new ProjectEditorView();
});
```

뷰모델·뷰를 형식으로 등록하는 강타입 모양(화면 층 확장 메서드 `Register<TViewModel, TView>`·`Register<TViewModel, TView, TArgs>`)은 §13 → a11 이다.

## 3. ID 와 별칭

창 ID 는 명령·메뉴·아이콘과 같은 문자열 키 체계다. 형식 규칙은 명령 ID 와 같고(빈 값·공백 거부), 위반은 XKUI0501 이다.

| 창 | ID | 영구 별칭 | 옛 숫자 | 제목 키 | 설명 키 |
|---|---|---|---|---|---|
| 그리드 | `xkxk.demo.grid` | `Grid` | 0 | `shell.kind.grid` | `chrome.help.grid` |
| 간트 | `xkxk.demo.gantt` | `Gantt` | 1 | `shell.kind.gantt` | `chrome.help.gantt` |
| 입력폼 | `xkxk.demo.form` | `Form` | 2 | `shell.kind.form` | 없음 |

- 데모 창 3종은 B10 부터 시험대 모듈(모듈 ID `xkxk.frameworks.ui.testbed`)이 **같은 ID** 로 등록한다. Owner 는 모듈 ID, `AllowDuplicate=false`, 별칭 없음이고 `CreateContent` 를 채운다. 아이콘은 기존 메뉴 아이콘 키(그리드·간트·폼)다. 셸은 등록하지 않는다(B09 의 내부 `ShellDefaultWindows` 는 삭제).
- 옛 이름(대소문자 무시)과 옛 숫자는 **영구 별칭**이다. 저장본 읽기, 명령 `xkxk.demo.open` 의 파라미터, `Open`·`TryResolve`, 원격 `kind=`, 자동화 인자(`--open Grid:3`)에서 계속 받는다.
  - 해석의 마지막 단계(§2 의 3번)가 늘 데모 ID(`xkxk.demo.*`)로 풀기 때문에 정의의 `Aliases` 에 기대지 않는다. 데모 창을 `Aliases` 없이 등록·`Replace` 해도 옛 이름·숫자는 그 정의로 풀린다.
  - 옛 이름 `Grid`·`Gantt`·`Form` 과 문자열 `"0"`·`"1"`·`"2"` 는 **영구 예약어**다. 셸 주체(`xkxk.shell`) 밖의 등록은 이를 창 ID·별칭으로 쓸 수 없다(§4). 데모 창을 등록·교체하는 쪽(시험대 모듈 포함)은 옛 이름 별칭을 넣지 않는다(넣을 필요가 없고, 넣으면 버려진다).
  - 데모 창이 등록돼 있지 않거나(시험대 없는 앱) `Remove` 되면 풀 정의가 없으므로 XKUI0505 다(열기·복원은 자리표시).
  - 자동화 인자 `--open` 은 옛 이름·숫자·창 ID·별칭을 받는다. 모르는 이름은 자리표시 문서 + XKUI0505 다(B09 이전에는 무시했다).
- 변환표는 `src/xkxk.frameworks.ui.shell/Docking/` 의 public `LegacyWindowKinds` 다. `Grid`·`Gantt`·`Form` 상수, `ToId(string?)`(대소문자 무시, "0"·"1"·"2" 포함), `ToId(int)`, `NameOf(string?)`(옛 이름 또는 null)를 준다. B10 이 데모 창을 시험대 모듈로 옮긴 뒤에도 데이터 무결성 때문에 셸에 남는다. 공개 계약(`Framework/`)은 아니다.
- ID 와 별칭은 **한 이름공간**이다.
  - 새 ID 가 다른 창의 ID·별칭과 대소문자 무시로 같으면 등록하지 않는다(XKUI0502, `Add` 는 false). 기존 창은 그대로다. 예를 들어 어떤 창의 별칭이 `acme.editor` 이면 ID `ACME.Editor` 는 등록되지 않는다.
  - 같은 ID(Ordinal)를 `Replace=true` 로 교체할 때는 교체 대상 자신의 ID·별칭을 비교에서 뺀다. 대소문자만 다른 ID 는 교체가 아니라 새 ID 이므로 `Replace` 와 무관하게 거부한다.
  - 별칭이 다른 창의 ID·별칭과 겹치면 그 별칭만 버리고 등록은 한다(XKUI0504).

## 4. 예약 접두어와 등록 정책

a8 §5·§6 의 예약 접두어 `xkxk.` 와 정책 P1~P4 를 창에 그대로 적용하고, 창에는 옛 이름·숫자 예약을 더한다.

| 번호 | 창 적용 |
|---|---|
| 예약 ID | 프레임워크 아닌 주체가 아직 없는 `xkxk.*` 창 ID 를 새로 만들면 XKUI0503 이고 등록하지 않는다(false). 이미 있는 `xkxk.*` 창의 `Replace=true` 재정의는 허용한다. 접두어 판정은 대소문자를 구분한다 |
| 예약 별칭 | 프레임워크 아닌 주체가 `xkxk.*` 별칭을 더하면 **그 별칭만 버리고 창은 등록**하며(true) XKUI0503 을 남긴다. 접두어 판정은 대소문자를 무시한다(별칭 해석이 무시하므로) |
| 옛 이름 ID | 셸 주체(`xkxk.shell`) 밖의 등록이 `Grid`·`Gantt`·`Form`·`0`·`1`·`2`(대소문자 무시)를 창 ID 로 쓰면 XKUI0502 이고 등록하지 않는다(false). `Replace` 와 무관하며 `xkxk.` 모듈도 같다 |
| 옛 이름 별칭 | 셸 주체 밖의 등록이 같은 값을 별칭으로 더하면 예약 별칭처럼 **그 별칭만 버리고 창은 등록**하며(true) XKUI0503 을 남긴다. 대소문자 무시. 별칭 충돌(XKUI0504)보다 먼저 판정한다 |
| P1 | `Replace=true` 인데 기존 등록이 없으면 새로 등록한다(Added). 예약 ID·옛 이름 ID 규칙과 ID 충돌 검사(§3)가 우선한다 |
| P2 | `Remove` 는 등록 주체만 한다. 다른 주체의 창은 XKUI0508 이고 지우지 않는다. `Replace=true` 교체는 주체와 무관하며 Owner 가 옮겨 간다 |
| P3 | `Replace` 는 목록 안의 자리를 유지한다 |
| P4 | Build 뒤 붙잡아 둔 모듈 레지스트리로 등록하면 실행 중 등록과 같고, 진단은 앱 Diagnostics 에 쌓는다 |

같은 ID 를 `Replace=false` 로 다시 등록하면 XKUI0502 이고 첫 등록이 남는다. 새 ID 가 예약 ID 규칙과 ID 충돌에 함께 걸리면 XKUI0503 하나만 남기고, 옛 이름 ID 가 충돌에도 걸리면 XKUI0502 하나만 남긴다.

**열린 문서가 있는 창의 `Remove`·`Replace`.** 이미 열린 문서는 닫거나 바꾸지 않는다. 그 뒤의 새 열기와 레이아웃 복원부터 `Replace` 는 새 정의를, `Remove` 는 자리표시(XKUI0505)를 쓴다.

```json
  "DuplicateWindowIds": ["xkxk.demo.gantt", "acme.project.editor"],
  "DuplicateOffWindowIds": ["xkxk.demo.grid", "xkxk.demo.form"],
  "Documents": [
    { "Id": "Gantt-1", "Kind": "Gantt", "WindowId": "xkxk.demo.gantt" },
    { "Id": "acme.project.editor-1", "WindowId": "acme.project.editor" } ] }
```

(예시는 관련 필드만 적었다.)

### 5.2 읽기 변환

`LayoutSerializer.Deserialize` 가 해석한 뒤 `LayoutMigration.Normalize` 가 v1~v5 를 메모리에서 6 의 뜻으로 채운다. 손상 JSON 은 지금처럼 null 이다.

| 저장본 상태 | `WindowId` 결정 |
|---|---|
| `WindowId` 있음 | 그 값(`Kind` 와 달라도 `WindowId` 우선) |
| `WindowId` 없고 `Kind` 가 옛 이름·숫자 0~2 | 변환표의 `xkxk.demo.*` |
| `WindowId` 없고 `Kind` 도 없음(v1 모양) | `xkxk.demo.grid`(옛 기본값과 같다) |
| 모르는 문자열·범위 밖 숫자 | 원래 값을 창 ID 로 본다(복원 때 자리표시) |

- `DuplicateWindowIds` 는 저장본 값과 `DuplicateKinds` 를 변환한 값의 합집합이다. 모르는 ID 도 보존한다.
- `DuplicateKinds` 의 원소는 문자열과 숫자를 모두 읽는다(목록 원소용 변환기, 문서 `Kind` 와 같은 방식). 숫자 원소 때문에 저장본 전체를 잃지 않게 하기 위해서다. null 원소와 변환표에 없는 값은 합집합에서 빠지고, 문자열·숫자가 아닌 원소는 손상 JSON 이다.
- `DuplicateOffWindowIds` 는 저장본 값을 그대로 읽는다. 키가 없으면 빈 목록과 같으며, `DuplicateKinds` 로부터 만들지 않는다.
- 읽고 쓰기를 반복해도 결과가 같다(멱등).
- 등록 안 된 창은 복원 때 **자리표시 문서**로 열어 ID·제목·위치를 보존한다. 다시 저장해도 사라지지 않는다(XKUI0505).

### 5.3 중복 허용 저장·복원

저장할 때 두 목록을 다음과 같이 채운다.

- 켬(`DuplicateWindowIds`)은 현재 설정이 켜진 창 전부다.
- 끔(`DuplicateOffWindowIds`)은 현재 설정이 꺼진 **등록 창 전부**(정의의 `AllowDuplicate` 값과 무관)와, 등록 안 됐지만 꺼짐으로 정해 둔 창(저장본의 끔 목록에서 읽었거나 사용자가 끈 것)이다.
- `Serialize` 는 끔 목록에서 빈 항목·중복·켬 목록에도 있는 항목을 뺀다.

복원할 때는 두 목록의 별칭을 정규 ID 로 바꾼 뒤 창마다 위에서 아래로 처음 맞는 줄을 적용한다.

| 조건 | 결과 |
|---|---|
| 켬 목록에 있음 | 켬(두 목록에 모두 있으면 켬) |
| 끔 목록에 있음 | 끔. 이미 꺼져 있거나 등록 안 된 창이어도 정한 값으로 기억해 다음 저장에 남긴다 |
| 둘 다 없고 `Version` 5 이하이며 옛 3종 | 끔(옛 저장본은 목록에 없으면 꺼짐) |
| 그 밖 | 바꾸지 않는다 |

형식 6 저장본은 저장 시점의 등록 창을 두 목록 중 하나에 담는다. 따라서 둘 다 없는 창은 저장 뒤에 추가된 창이며, 복원이 그 설정(정의 값 또는 사용자가 바꾼 값)을 덮지 않는다.

### 5.4 대안 비교

| 안 | 내용 | 실현×가치/위험 | 판단 |
|---|---|---|---|
| A(채택) | `Kind` 옛 이름 유지 + `WindowId`·`DuplicateWindowIds` 추가, 읽기 변환 | 5×5/2=12.5 | 옛 판 앱도 새 저장본을 읽는다. 저장 크기가 조금 늘어난다 |
| B | `Kind` 를 문자열 ID 로 바로 바꿈 | 5×3/3=5 | 옛 판 앱이 열거형 해석에 실패해 레이아웃 전체를 잃는다 |
| C | 열거형 유지 + 문자열 ID 병행 | 4×2/2=4 | a4 끝 조건(열거형 0)에 어긋난다 |

점수는 계획 시점의 상대 평가(추정)다. 옛 판 앱의 동작은 코드의 직렬화 방식(열거형 문자열 변환)에서 판단한 것이며 옛 판 앱을 실제로 띄워 확인한 결과가 아니다. 한계는 §11 ②다.

## 7. 셸 내부 모델

아래는 `Framework/` 밖이라 공개 API 고정 대상이 아니다.

| 대상 | 변경 |
|---|---|
| `PocDocument` | `Kind` 삭제. `string WindowId`(init, 기본 빈 문자열)·`object? Parameter`(init) |
| `IShellCommands.OpenDocument` | 첫 인자 `string windowId`(ID·별칭·옛 이름·숫자, `TryResolve` 로 해석). 4인자 모양(`title`·`sdi`·`allowDuplicate`)은 유지한다. 모르는 ID 는 자리표시 문서 + XKUI0505 |
| `IShellCommands` 추가 | `OpenDocument(string windowId, UiWindowOpenOptions options)` 오버로드 |
| 중복 허용 | `DuplicateWindowIds`·`DuplicateOffWindowIds`(§5.3)·`IsDuplicateAllowed(id)`·`SetDuplicateAllowed(id, allowed)` |
| `WindowDisplay` | `DisplayName(id)`(정의 `TitleKey` 문구 → `Title` → ID)·`IconKeyOf(doc)`·`LegacyOrId(id)`·`InvokeContent(doc, out failed)`. `DocumentKindNames` 를 대신한다 |
| 문서 Id | `{LegacyOrId(id)}-{일련번호}`. 데모 3종은 `Grid-1` 형식 그대로다 |
| `DocumentWindowContext`(B10, `Docking/`) | 문서 하나의 `IUiWindowContext` 구현. `SetTitle` 은 문서 제목 갱신(자동 제목 고정 해제), `Close` 는 기존 닫기 경로(`IShellCommands.CloseDocument`), `BeginBusy` 는 `BusyService.Begin` 위임이다. 닫기 경로가 여럿(DockableClosed 처리기·`CloseAll`·`LayoutRestorer.CloseExcept`)이라 열린 문서 목록의 변경을 구독하고, 자기 문서가 빠지면 Dispatcher 한 바퀴 뒤 다시 확인해 `Closed` 를 1회 낸다 |

- 4인자 호출은 `Title=title`, `Placement=sdi ? Sdi : Default`, `AllowDuplicate=allowDuplicate ? true : null` 로 오버로드에 위임해 기존 동작과 같다.
- 분리창 여부는 `Placement == Sdi` 이거나, `Default` 이고 정의가 `Sdi` 일 때다. 중복 허용은 `AllowDuplicate ?? IsDuplicateAllowed(id)` 다.
- 화면 층 내용 생성은 `DefaultDocumentViewFactory` 가 `WindowDisplay.InvokeContent` 를 부른다. 셸이 창 문맥(`DocumentWindowContext`)을 넣은 `UiWindowContentContext` 를 만들고 `CreateContent` 예외를 잡아 XKUI0507 을 남긴다.
  - 정의가 없으면 자리표시 문구(`shell.window.missing`, `{0}`=창 ID)만 보인다. 화면 층은 XKUI0505 를 내지 않는다. 진단은 셸 입구인 열기(`Open`·`OpenDocument`)와 복원이 낸다.
  - `CreateContent` 결과가 `Control` 이면 쓴다.
  - 예외(셸이 보고)·null·`Control` 아님(화면 층이 보고)이면 같은 자리표시와 XKUI0507 이다.
  - `CreateContent` 가 없으면 창 ID 와 무관하게 같은 자리표시와 XKUI0507(화면 층, 내용 함수 없음)이다. B10 에서 화면 층의 그리드·간트·폼 분기를 없앴고, 데모 화면은 시험대 모듈의 `CreateContent` 가 만든다.
- 복원 지연 로딩의 계측 키는 `LegacyOrId` 소문자라 `grid`·`gantt`·`form` 값이 그대로다.

## 8. 원격 진단과 판정

진단 빌드(`PD_DIAGNOSTICS`)에만 있고 제품 빌드에는 라우트가 없다. 문서 열기·문서 목록 명령은 기존 `docs.open`(별칭 `window.open`)·`docs.list` 다. `windows.list` 는 최상위 OS 창 목록이며 문서 항목은 Id 만 담는다.

| 명령 | 내용 |
|---|---|
| `layout.apply json=<base64 UTF-8 레이아웃 JSON>` | 신규. 저장하지 않고 적용. 응답 `{applied, version_read, docs}` |
| `docs.open` | `kind=<옛 이름 또는 ID>` 유지. `window=<ID 또는 별칭>`·`param=<문자열>` 추가. `kind`·`window` 둘 다 없으면 명령 오류. `param` 은 `UiWindowOpenOptions.Parameter` 로 간다 |
| `docs.list` | 항목에 `windowId` 와 `parameter`(문자열이면 값, 아니면 null) 추가. `kind` 는 `LegacyOrId` 소문자라 기존 값 그대로다 |
| `registry.dump` | `windows` 배열(`id`·`owner`·`aliases`·`placement`·`allowDuplicate`·`hasContent`) 추가 |

- 원격 문서 라벨은 `doc{일련번호}{LegacyOrId}` 다.
- 기존 판정기는 고치지 않고 통과해야 한다. 예외는 저장 Version 을 5 로 고정 비교하던 2곳이며 '6 이상' 비교로 바꾼다.

## 9. 등록 시점과 모듈

- 모듈은 `Configure` 안에서 `ui.Windows.Add` 를 부른다. 실행 중에는 `XkxkUi.Current.Windows` 로 더하고 뺀다.
- 저장소는 앱 컨텍스트가 하나 소유하고 모듈 컨텍스트는 같은 저장소를 등록 주체만 바꿔 본다(a8·a9 와 같다).
- 변경은 `Changed`(Added·Removed·Replaced)로 알리고 잠금 밖에서 발생한다.

## 11. 한계

- ① `UiWindowOpenOptions.Parameter` 는 저장본에 남지 않는다. 레이아웃을 복원한 문서의 `Parameter` 는 null 이다. 인자가 꼭 필요한 창은 `CreateContent` 에서 null 을 처리해야 한다.
- ② 옛 판 앱이 v6 저장본을 읽을 수는 있지만, 다시 저장하면 `WindowId`·`DuplicateWindowIds`·`DuplicateOffWindowIds` 가 사라진다. 옛 이름이 없는 창은 `Kind` 도 없어 새 앱에서 Grid 로 굳는다(문서 수는 유지되고 종류만 잃는다).
- ③ 열린 문서가 있는 창을 `Remove`·`Replace` 해도 열린 문서는 그대로다. 새 정의나 자리표시는 다음 열기·복원부터 적용된다.
- ④ (해소, B10) 강타입 `Register`·`UiWindowViewModel<TArgs>`·`IUiWindowContext` 는 B10 에서 열었다. 남은 예약 확장은 §10 표다. 화면 층 `Register` 는 PublicAPI 추적 밖이라 명세는 수기 문서(`docs/04_확장_창.md`)에 적고, 생성 명세 확대는 B16 이다.
- ⑤ `IShellCommands.OpenDocument` 첫 인자가 `DocumentKind` 에서 `string` 으로 바뀌어 B09 이전 판과 **바이너리 비호환**이다. `IShellCommands` 는 PublicAPI 추적 밖의 형식이며(`docs/01_시작하기.md` 의 '공개 계약 밖' 서술과 같다) 옛 판으로 컴파일한 소비 코드는 다시 컴파일하고 인자를 창 ID 로 바꿔야 한다.
- ⑥ (해소, D-V2) 다른 창이 옛 이름·숫자를 ID·별칭으로 가로채 영구 별칭이 깨지거나 문서 Id(`Grid-1`)가 겹치는 문제는 예약어 규칙(§4)으로 막는다.
- 레지스트리는 프로세스 전역이고 리셋이 없으며, P2 는 실수 방지 수준이지 보안 경계가 아니다(UADR-0013 한계와 같다).
- 성능(PERF-12, 등록 창 열기)은 B20 판정이며 B09 는 측정하지 않는다.
- 데스크톱 런타임 확인이 사용자 파일 가드에 막히면 가드를 풀지 않고 대기(UTODO-0031)로 둔다.

## 12. B10 결과

B09 가 넘긴 인계를 B10 에서 다음과 같이 처리한다(UADR-0017).

- 데모 창 3종·데모 열기 명령(`xkxk.demo.open`·`xkxk.demo.openSdi`)·벤치 열기 명령(`xkxk.bench.open`)은 **같은 ID 로** 시험대 모듈(`xkxk.frameworks.ui.testbed`)이 등록한다. 셸 등록(`ShellDefaultWindows`, `ShellDefaultCommands.Menu` 의 3명령)은 없앤다. `ShellCommandIds.DemoOpen`·`DemoOpenSdi`·`BenchOpen` 상수는 남긴다(UADR-0009 추가만).
- 시험대가 `CreateContent` 를 채우고, 화면 층 `DefaultDocumentViewFactory` 의 그리드·간트·폼 분기는 없앤다. 데모 문서 소스의 시험대 이동은 batch 2 다(예열 일반화 `UiWindowPrewarm` 와 함께, §10).
- Owner 만 바뀌고 ID·옛 이름 해석·저장본은 그대로다. 시험대 모듈 ID 가 `xkxk.` 로 시작해 같은 예약 ID 를 등록할 수 있다.
- 시험대는 셸 주체가 아니므로 옛 이름 별칭을 넣지 않는다(§4). 옛 이름·숫자는 해석의 마지막 단계(§2)가 푼다. 옛 이름 변환표(`LegacyWindowKinds`)는 셸에 남는다.
- 강타입 등록의 첫 소비자는 시험대 표본 창 `xkxk.testbed.typed` 다.
- 셸 메뉴 표의 데모 7행(명령 6 + SDI 묶음 1)은 조건 키 `cmd`(명령이 등록됐을 때만 보임, 묶음은 자식 하나라도 등록이면 보임, XKUI0405 검사 제외)로 두고 행 이전은 B11 이다(UTODO-0049). 시험대 없는 앱은 데모 창이 0개라 데모 메뉴가 숨고, 옛 저장본의 데모 문서는 자리표시(XKUI0505)로 보존된다.
