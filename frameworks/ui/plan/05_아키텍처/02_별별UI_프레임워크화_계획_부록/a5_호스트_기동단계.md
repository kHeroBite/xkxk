# 부록 a5 — 호스트 기동 단계

> 상태: 확정(B03) · 최종 갱신일: 2026-11-26 · 본문: `../02_별별UI_프레임워크화_계획.md`
> 근거: 결정 UADR-0010(호스트 값은 빌더 옵션 `Host` 로 받고 `UseXkxkUi` 가 App 에 1회 연결한다), 현행 진단 부록 a2 G2, 배치 부록 a4 B03. 결정 본문은 `../../90_결정관리/02_결정기록_ADR.md` 에 있다.

## 1. 목적

부록 a2 의 장애 G2("호스트 주입 순서가 코드 순서에 묻힘")를 푼다. B02 까지는 호스트 3종(데스크톱·웹·Android)이 `App.StartupArgs = …`·`App.LayoutStore = …` 같은 정적 대입을 코드 순서에 맞춰 흩어 놓았다. 어느 값이 언제 읽히는지는 코드를 따라가야만 알 수 있었다.

B03 은 이 대입을 모두 빌더 옵션으로 옮긴다. 호스트는 `XkxkUiBuilderOptions.Args`·`Host`(`UiHostOptions`)에 값을 담고, `UseXkxkUi` 가 `Setup` 전에 한 번 App 에 연결한다. 이 문서는 그 단계 순서와 규칙, 남은 한계를 한곳에 적는다.

## 2. 기동 단계표

순서가 중요한 이유는 `App.Initialize`(XAML 로드) 중에 `TrExtension` 이 `StartupArgs` 를 읽기 때문이다. 그래서 연결은 `Setup` 전에 끝나야 한다.

| 단계 | 주체 | 하는 일 | 근거 소스 |
|---|---|---|---|
| 1. 호스트 전처리 | 각 호스트 `Program`·`AndroidApp` | 명령줄·파일 인자 정리, 그래픽 모드(`--gpu`) 판정, 저장소 객체 생성 | `Program.cs`(데스크톱·웹), `AndroidApp.cs` |
| 2. 옵션 구성 | 호스트 어댑터 `*UiHost.Build` | `Args`·`ApplicationId`(`xkxk.frameworks.ui`)·`HostKind` 를 채우고 `configureHost(options.Host)` 로 `Host.*` 를 채운다 | `DesktopUiHost.cs`·`BrowserUiHost.cs`·`AndroidUiHost.cs` |
| 3. Build | 프레임워크 | 모듈 등록·진단 수집 뒤 `XkxkUiApplication` 을 돌려준다. 옵션은 `app.Options` 로 보존된다 | `Framework/XkxkUiBuilder.cs` |
| 4. UseXkxkUi | 프레임워크 | `App.BindHost(application)` 를 Avalonia `Setup` 전에 부른다 | `Framework/XkxkUiAppBuilderExtensions.cs` |
| 5. App.Initialize | Avalonia | XAML 로드. `TrExtension` 이 `StartupArgs` 를 읽는다(그래서 4가 앞선다) | `App.cs`, `TrExtension` |
| 6. AfterSetup | 프레임워크 | `application.IsAttached = true` 를 남긴다 | `XkxkUiAppBuilderExtensions.cs` |
| 7. OnFrameworkInitializationCompleted | App | 아래 순서로 진행한다. ① `ParseStartupArgs` ② `FreshGuard` 감싸기 ③ `ModalScope` ④ `SettingsInput` ⑤ `MainViewModel` ⑥ `ApplyStartupArgs()` ⑦ `Layouts` ⑧ `AutoSaver` ⑨ `MainView` ⑩ 창 생성 ⑪ `ConfigureMainWindow` 호출 | `App.cs` |
| 8. (Android) 늦은 인자 | `MainActivity` | 인텐트로 늦게 온 인자를 `App.ApplyStartupArgs(args)` 로 넘긴다 | `MainActivity.cs` |
| 9. 기동 복원 직전 재판정 | `MainView` | 기동 복원 직전에 `ApplyStartupArgs` 를 다시 판정한다 | `App.cs`·`MainView` |

- 4단계는 두 번 불려도 된다. 뒤 호출의 비 null 값이 이긴다.
- 6·9단계의 `ApplyStartupArgs` 는 같은 판정을 다른 시점에 반복한다. 결과는 같아야 하며 8단계의 인자는 9단계에서도 반영된다.

## 3. 이전 대응표

옛 `App.X =` 정적 대입 8개가 새 옵션 경로로 옮겨졌다. 사용 여부는 호스트마다 다르다.

| 옛 정적 대입 | 새 옵션 경로 | 데스크톱 | 웹 | Android |
|---|---|:---:|:---:|:---:|
| `App.StartupArgs` | `Args` | ✅ | ✅ | ✅ |
| `App.LayoutStore` | `Host.LayoutStore` | ✅ | ✅ | ✅ |
| `App.SettingsStore` | `Host.SettingsStore` | ✅ | ✅ | ✅ |
| `App.LayoutLibraryStore` | `Host.LayoutLibraryStore` | ✅ | ✅ | ✅ |
| `App.ConfigureMainWindow` | `Host.ConfigureMainWindow` | ✅ | — | — |
| `App.VisibleFrameOf` | `Host.VisibleFrameOf` | ✅ | — | — |
| `App.CreateHostWindow` | `Host.CreateHostWindow` | ✅ | — | — |
| `App.WindowHost` | `Host.WindowHost` | ✅ | ✅ | — |

- 데스크톱의 `MonitorFitService.Register(h)` 는 `h.ConfigureMainWindow` 를 이어 붙인다(앞 대리자를 먼저 부르고 `Attach(w)`). 이 연쇄 순서(Program 람다 → Attach)는 그대로 유지한다.
- Android 의 인텐트 인자는 `Args` 로 올 수 없어 8단계의 `App.ApplyStartupArgs(args)` 로 넘긴다. 파일 인자가 인텐트 인자보다 우선하는 기존 규칙은 바뀌지 않는다.

## 4. 호스트별 host-options 키

호스트 어댑터는 기동 로그 한 줄에 어떤 값이 채워졌는지 남긴다. 형식은 `ui builder host=<종류> modules=0 diagnostics=0 app=xkxk.frameworks.ui host-options=<키 목록>` 이다. 키는 null 이 아닌 값만 아래 순서로 쉼표로 이은 것이다.

| 순서 | 키 | 대응 속성 |
|---|---|---|
| 1 | `layout` | `LayoutStore` |
| 2 | `settings` | `SettingsStore` |
| 3 | `library` | `LayoutLibraryStore` |
| 4 | `mainwindow` | `ConfigureMainWindow` |
| 5 | `visibleframe` | `VisibleFrameOf` |
| 6 | `sdihost` | `CreateHostWindow` |
| 7 | `windowhost` | `WindowHost` |

| 호스트 | 기대하는 host-options |
|---|---|
| 데스크톱 | `layout,settings,library,mainwindow,visibleframe,sdihost,windowhost` |
| 웹 | `layout,settings,library,windowhost` |
| Android | `layout,settings,library` |

## 5. 범위 밖

B03 이 일부러 건드리지 않은 것이다. 각각 맡을 batch 를 적는다.

- App 밖 정적: `DesignEffectsApplier.BlobStore`·`SdiDocumentIcon`·`AppWindowIcon`·`Win32ModalBlock`·`SystemHost.Restart`·`DesktopDiagHooks`. 호스트 진입부에 그대로 남는다.
- `DocumentViews` 등 화면 조립 층의 정적 등록은 이 batch 의 대상이 아니다.
- 정적 setter 제거는 B21(1.0)이다. 예고용 `[Obsolete]` 표시는 B16 에서 단다.
- `App.ApplyStartupArgs(IReadOnlyList<string>)` 는 셸 루트 공개 메서드라 PublicAPI 분석기가 서명을 고정하지 않는다. B21 정리 대상이다.
- 공개 호스트 확장(`UseDesktopHost` 등)은 hosting 분리인 B11 이다.
- B11 batch 2 결과(공개 호스트 확장, 2026-11-28 계획 확정·구현 진행 중): 공개 형식 7개만 둔다(UADR-0018, 그 밖 public 0·`InternalsVisibleTo` 0). `DesktopHost.Run(string[])`·`Run(string[], DesktopHostOptions)`, `BrowserHost.RunAsync(string[])`·`RunAsync(string[], BrowserHostOptions)`, Android 는 상속 전용 기반 클래스 `XkxkAndroidApplication<TApp>`·`XkxkMainActivity`(abstract)와 `AndroidHostOptions` 다. 옵션 3개는 `sealed`·`init`·기본값 null 이라 속성 추가가 하위 호환이다(UADR-0009). 확장은 `ConfigureUi`(모듈 등록, null 이면 모듈 0)부터 연다. 호스트 3종은 위 §4 의 host-options 키·§6 연결 규칙을 그대로 지키고, 정적 시작 상태(Android `ArgsFromFile`·`s_startupArgs`)는 비제네릭 `internal static class AndroidHostStartup` 에 둔다(공개 목록 밖). 데이터 폴더·단일 인스턴스 이름 옵션(`DataFolderSegments`·`InstanceName`)과 `AppDataFolder.UseSegments` 는 batch 3(B11-3)에서 더한다. `UseSegments` 우선순위는 `--data-dir`(`PD_DATA_DIR`) > `UseSegments` > 기본값이다.

## 6. 연결 규칙(계약 C23)

`App.BindHost` 는 아래 규칙으로 옵션 값을 정적 주입점에 옮긴다.

1. 비 null 값만 대입한다. `Args` 는 1개 이상일 때만 대입한다.
2. null 이면 기존 정적 값을 그대로 둔다. 정적 setter 로 먼저 넣은 값은 지워지지 않는다.
3. 정적 값과 옵션이 둘 다 있으면 옵션이 이긴다.
4. 연결은 `UseXkxkUi` 때 한 번이다. 그 뒤 옵션을 바꿔도 App 에는 반영되지 않는다.
5. `UseXkxkUi` 를 쓰지 않는 경로는 정적 setter 로 계속 동작한다(하위 호환).

계약 시험은 C22(8개 값이 App 공개 getter 와 같다)와 C23(비 null 만 연결·옵션 우선)이 맡는다.

## 7. 한계

- 연결 뒤 옵션 변경은 반영하지 않는다(규칙 4).
- 정적 setter 가 B21 까지 남으므로 컴파일러는 옛 경로 사용을 막지 못한다. 옛 `App.X =` 대입은 판정기 `test/framework/judge/host_injection_check.py` 로만 검출한다.
- 판정기는 `using static` 이나 형식 별칭으로 `App` 을 우회한 대입을 잡지 못한다. 한정 이름 대입(`xkxk.frameworks.ui.shell.App.LayoutStore = x;`)과 복합 대입(`+=` 등)은 잡는다.
- `App.ApplyStartupArgs(args)` 호출은 대입이 아니라 메서드 호출이라 판정 대상이 아니다.
- Dock 형식(`IHostWindow`)과 Avalonia 형식(`Window`·`PixelRect`)이 고정 계약(Framework) 표면에 들어간다. 소비자가 구현하는 인터페이스(`ILayoutStore`·`IKeyValueStore`·`IWindowHostCommands`)도 같다. 이들은 분석기 범위 밖이고 원칙 4 의 대상이다. B16 공개 API 고정 확대 때 동결 또는 추상 기반 전환을 검토하고, B11 에서 위치를 다시 본다. 지금은 Unshipped 라 바꿀 수 있다.
- Fold5 실기기가 연결되지 않으면 Android 늦은 인자 경로(8·9단계)는 실측 없이 대기로 남는다. 코드상 확인만 했다.
- `--fresh` 는 `UseXkxkUi` 재호출로 꺼지지 않는다(기존 동작).
