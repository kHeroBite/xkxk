# 부록 a7 — 컨텍스트 서비스 이전 대응

> 상태: 계획 확정(B05, 구현 진행 중) · 최종 갱신일: 2026-11-26 · 본문: `../02_별별UI_프레임워크화_계획.md`
> 근거: 결정 UADR-0012(설정·테마·투어·모니터 상태를 앱 컨텍스트가 소유, DesignThemeResolver 는 정적 조회 함수로 유지, 웹·Fold5 성능 기준선은 B12 로 이관), 앞 batch 부록 a6(UADR-0011), 현행 진단 부록 a2 §3, 배치 부록 a4 B05·B12·B16·B21. 결정 본문은 `../../90_결정관리/02_결정기록_ADR.md` 에 있다.

## 1. 목적

부록 a6 이 4종(메인 뷰모델·셸 명령·화면 층 등록부·문구 서비스)을 앱 컨텍스트로 옮긴 데 이어, B05 는 a2 §3 에 남은 정적 전역 상태 중 아래를 컨텍스트 소유로 옮긴다. B05 는 F1(공개 계약 기반) 의 끝 batch 라서 판정기 전수 회귀와 성능 기준선도 함께 남긴다.

- 사용자 설정(`UiSettings`)
- 테마 목록(`ThemeCatalog`)
- 투어 카탈로그(`TourCatalog`)
- 모니터 메뉴(`MonitorMenuViewModel`)
- 디자인 테마 해석 상태(`DesignThemeResolver` 의 가변 상태)

프레임워크 안 코드는 `XkxkUi.Current` 만 거치고, 옛 정적 접근자는 외부 호환용 위임으로만 남긴다(B16 예고, B21 제거).

## 2. 공개 계약

모두 셸 `src/xkxk.frameworks.ui.shell/Framework/` 에 둔다. 공개 API 분석기가 서명을 고정하고 원칙은 UADR-0009(추가만, 선택 파라미터 금지)를 따른다.

| 형식 | 추가 내용 |
|---|---|
| `IUiAppContext` | 기존 5멤버·순서를 유지하고 4멤버를 더한다. 모두 비 null 이다 |
| `UiHostOptions` | `public IMonitorProvider? MonitorProvider { get; set; }` 를 더한다. 기본 null, null 이면 모니터 정보 없음이다 |

`IUiAppContext` 에 더하는 4멤버는 다음과 같다.

| 멤버 | 형식 | 경로 |
|---|---|---|
| `Settings` | `UiSettings` | `XkxkUi.Current.Settings` |
| `Themes` | `ThemeCatalog` | `XkxkUi.Current.Themes` |
| `Tour` | `TourCatalogData` | `XkxkUi.Current.Tour` |
| `Monitors` | `MonitorMenuViewModel` | `XkxkUi.Current.Monitors` |

- 구현체 `UiAppContext`(internal)가 지연 생성(스레드 안전)으로 소유한다. 투어는 소스(기본 내장 소스)와 캐시를 컨텍스트가 갖고, 읽기 실패는 빈 데이터로 처리한다(지금과 같음).
- `MonitorMenuViewModel` 에는 현재 공급자를 읽는 `CurrentProvider` 를 더한다. 옛 `Provider` 정적 속성은 get·set 위임으로 남긴다.
- 내부 전용 `DesignThemeState`(internal)가 디자인 테마 해석 상태를 보관한다(§4).

## 3. 옛 정적 접근자 → 새 경로 대응표

| 옛 접근자 | 새 경로 | 옛 접근자의 새 모습 |
|---|---|---|
| `UiSettings.Current` | `XkxkUi.Current.Settings` | 읽기 위임 속성. 공개 생성자는 바이너리 호환으로 남는다 |
| `ThemeCatalog.Current` | `XkxkUi.Current.Themes` | 읽기 위임 속성. 생성자는 private 에서 internal 로 바꾼다 |
| `TourCatalog.Current`·`TourCatalog.All` | `XkxkUi.Current.Tour`(`.Steps`) | 정적 상태를 지우고 위임한다. `UseSource(source)` 서명은 그대로이고 컨텍스트의 소스 교체로 위임한다 |

- 호출부(계획 시점 UiSettings 79파일 196곳, ThemeCatalog 17파일, TourCatalog 3파일, 모니터 3파일, 합계 87파일)는 결정적 치환 스크립트 1명이 한 번에 이전하고, 손 수정 대상 9파일과 axaml 4파일은 따로 고친다.
- axaml 12줄은 `Source={x:Static fw:XkxkUi.Current}` 와 `Settings.` 접두 경로로 바꾼다(B04 의 DocumentDockMode 형식과 같다).
- 이전 뒤 옛 한정 이름을 쓰는 곳은 위임 접근자 정의 자신뿐이어야 한다. 판정기 `test/framework/judge/context_services_check.py` 의 `refs=0` 과 독립 `rg` 대조로 확인한다.

## 4. DesignThemeResolver — 정적 조회 함수로 유지하는 예외

a2 §3 표는 `DesignThemeResolver.Current` 를 정적 전역 상태로 나열한다. B05 는 이 심볼을 `Loc.Tr` 와 같은 **정적 조회 함수**로 유지하고 옛 접근자 위임 목록에 넣지 않는다. 이것은 a2 §3 표 대비 **예외**이며 UADR-0012 가 결정으로 남긴다.

- 근거 — `DesignThemeResolver.Current` 는 단일 인스턴스를 돌려주는 접근자가 아니라 실효 테마 ID 를 계산하는 함수다. 소비자 호출부(계획 시점 5파일 10곳)가 바뀔 이유가 없다.
- 이전 대상은 함수가 아니라 그 함수가 읽는 **가변 상태 전부**(필드 6·정적 속성 5, 정적 이벤트의 대리자)다. `DesignThemeState` 에 같은 이름·초기값으로 옮기고 resolver 는 컨텍스트 소유 상태를 읽고 쓴다. 공개 서명은 바뀌지 않는다.
- 상태 소유가 이전의 본질(a2 §3 의 문제는 "프로세스에 숨은 상태")이므로 목적은 달성된다. 정적 조회 표면은 B21 제거 대상이 아니다.
- `ElementThemeOverride`(`.Elements.cs`)는 같은 방식으로 위임한다. 화면 층 대리자 등록 지점 `WindowOverviewHost` 는 범위 밖이다(§6).

## 5. 데스크톱 호스트 합성과 MonitorProvider

- 합성 지점(데스크톱 Program 의 호스트 구성)이 `DesktopMonitorProvider` 와 `DesktopWindowHost` 를 1회 만든다. 모니터 공급자는 `h.MonitorProvider` 로 넣고 `UseXkxkUi` 가 비 null 이면 컨텍스트의 `Monitors` 에 1회 연결한다(B03 값 연결 규칙, UADR-0010).
- 호스트 내부 도우미 `MonitorFitService` 는 internal `Monitors` 속성으로 같은 인스턴스를 공유한다. 정적 `Provider` 대입 줄은 삭제한다.
- 웹·Android 호스트는 공급자가 없다. `MonitorProvider` 가 null 이면 `HasMonitors=false` 로 지금과 같다.
- 호스트의 나머지 정적 상태는 B11(호스팅 라이브러리 분리)이 맡는다.

## 8. 시험과 회귀

- 계약 시험 C28~C32(`test/framework/contract/ContextServiceChecks.cs`)는 구현 전에 red 를 남기고 구현 뒤 green 이 된다. 투어 소스·모니터 공급자를 바꾼 시험은 반드시 원복한다.
- 판정기 `context_services_check.py` 는 refs(옛 6종 + `Provider`)·defs(위임 정의·공개 생성자 0·정적 가변 상태 0·호스트 `Instance` 0)·인벤토리를 본다. `verify_framework.sh` 에 `services` 단계로 묶는다.
- 회귀 묶음 R-F1(정적 5·앱 없는 2·비전경 원격 9·웹 1, 합계 17)을 전 회차(기준판 복사본)와 후 회차(B05 판)로 두 번 돌려 `logs/b05_regress.json` 에 남긴다. 실행 사본은 끝나면 지운다.
- 스모크는 데스크톱·웹·Fold5(접지 않음)로 하고, F 끝 batch 라서 포그라운드 시험(PC 비움)을 포함한다. 대기가 남으면 a4 B05 진척은 "대기(사유)" 로 적고 UTODO 로 이월한다.

## 9. 성능 기준선과 /mnt/c 임시 예외

기준 커밋은 25c31b6(B05 직전 성능 기준)이고 측정은 데스크톱(PERF-01 첫 화면·문서 열기 지표)만 이번에 한다. 판정은 PERF-01 ≤2000ms·중앙값 +5% 이내이며 PC 비움 때만 실측 ms 로 한다(참고 부하는 기록만).

기준판은 같은 소스 트리가 필요하다. 이 batch 는 임시 폴더 금지(/mnt/c 에 임시 파일을 두지 않는다) 규칙의 **예외**를 하나 둔다.

- **사유**: 빌드 도구인 Windows `dotnet.exe` 가 Windows 경로를 요구하므로 세션 ext4 경로에는 기준판을 풀어 빌드할 수 없다. 그래서 Windows `%TEMP%`(`cmd.exe` 로 얻어 `wslpath` 변환) 아래에 고유 폴더 `xkxk_b05_base_<8자>` 를 만든다.
- **방법**: `git archive` 로 25c31b6 의 `frameworks/ui` 만 풀어 쓴다. `git worktree` 는 쓰지 않는다(다중 세션 git 정책, 정리 책임 분산 방지).
- **삭제 소유자**: `test/framework/measure/perf_baseline.py` 한 프로세스가 `try/finally` 로 생성·빌드·측정·삭제를 소유한다. 폴더를 만든 직후 `logs/b05_perf.json` 에 RUNNING·폴더 위치·`base_tree_removed:false` 를 먼저 쓰고, 끝에 부재를 확인한 뒤 `base_tree_removed:true` 로 바꾼다. 강제 종료로 남은 폴더는 기록된 위치로 team-lead 가 정리한다.
- PC 비움이 아니면 트리를 만들지 않고 WAIT 로 기록해 이월한다.

## 10. 웹·Fold5 성능 기준선은 B12 로 이관

웹·Fold5 성능 기준선은 B05 에서 재지 않고 F3 끝 batch(B12)로 넘긴다. 앞 계획 판의 "웹 기준판 번들은 패치판 Avalonia.Browser 재구성이 필요하다" 는 **틀렸다**. `vendor/feed/Avalonia.Browser.12.1.4-pd.1.nupkg` 는 git 추적 파일이라 25c31b6 트리에 있고 기준판 웹 번들은 그대로 빌드할 수 있다. 실제 이관 사유는 다음과 같다.

1. a4 B12(F3 끝 3호스트 회귀·Fold5 재설치·성능 +5%)가 웹·Fold5 성능 판정 batch 로 이미 정의돼 있다.
2. 웹 첫 화면 교대 비교에는 두 번들을 따로 서빙하고 headless Chrome 으로 교대 측정하는 도구가 아직 없다(기존 웹 측정기는 Fold5 기기 Chrome 용).
3. Fold5 기준판은 기준판 APK 를 설치해 사용자 기기의 앱을 두 번 바꿔 넣어야 하는데, F1 은 셸 내부 상태 소유만 바꿔 호스트 고유 경로를 건드리지 않으므로 그 비용을 B12 한 번으로 모으는 것이 낫다.

이 결정은 UADR-0012 에 있고 a4 B12 행에도 문구를 둔다.

## 11. 한계

① **구체 형식 노출** — `UiSettings`·`ThemeCatalog`·`TourCatalogData`·`MonitorMenuViewModel` 이 공개 계약 표면에 들어온다. 인터페이스 추출은 영구 표면을 크게 늘려 B14·B16 에서 확장점 설계와 함께 재검토한다(a6 한계 ④와 같은 줄기).

② **전역·리셋 없음** — `XkxkUi.Current` 는 프로세스 전역이다. 계약 시험은 투어 소스·모니터 공급자를 바꾼 뒤 원복해야 한다.

③ **공개 생성자 잔존** — `UiSettings` 의 공개 생성자는 바이너리 호환으로 남는다. 소비자가 만든 인스턴스는 컨텍스트와 무관하다.

④ **정적 조회 표면 유지** — `DesignThemeResolver.Current` 등은 상태가 컨텍스트로 옮겨진 정적 조회 함수로 남고 B21 제거 대상이 아니다(§4).

⑤ **호스트 정적 참조** — `MonitorFitService.Monitors` 는 합성 지점 공유용 정적 참조다. 전면 제거는 B11 이다.

⑥ **x:Static 1회 평가** — a6 한계 ②와 같다. 서비스는 생성 뒤 바뀌지 않으므로 영향이 없다.

⑦ **판정기 한계** — 정의 형식 안에서 한정 없이 쓰는 `Current` 는 판정기가 잡지 못한다. 정의 파일 안은 손으로 이전하고 defs 검사가 정의 형태를 본다.

⑧ **기준선 범위** — 이번 기준선은 데스크톱만이다. 웹·Fold5 는 B12 이며, PC 비움이 아니면 측정이 이월된다.

## 12. 범위 밖

- 설정·테마 인터페이스 추출, 컨텍스트 변경 알림, DI 생성자 주입은 하지 않는다.
- `WindowOverviewHost`·`FontResolver`·`PerfProbe` 이전은 §6 의 batch 가 맡는다.
- 사용자 결정이 필요한 항목은 없다.
