## 2. 층 규칙과 계약

- 층 참조 규칙은 `AGENTS.md` §5 와 `../../04_기술스택/02_소스구조_분할규칙.md` §11 이 정본이고, `tools/check_layers.py`(규칙 `tools/check_layers_rules.json`)가 검사한다. views→shell→ui·data 방향만 허용한다.
- 셸이 화면 층을 모른 채 쓰는 계약은 `src/xkxk.frameworks.ui.shell/IViewRegistry.cs` 다(메인 화면 생성·문서 뷰 생성기·시스템 창·입력 설치·테마 편집기·진단 명령 등록 등 13개 멤버). 구현은 화면 층 `PdViewRegistry.cs` 가 기동 때 `ViewRegistry.Current` 에 넣는다.
- 문서 뷰 생성 계약은 `src/xkxk.frameworks.ui.shell/Docking/IDocumentViewFactory.cs` 의 `Control Create(PocDocument document)` 하나다.
- 셸 명령 표면은 `src/xkxk.frameworks.ui.shell/Docking/ILayoutStore.cs` 안의 `IShellCommands` 다. 문서 열기는 `OpenDocument(DocumentKind kind, string? title, bool sdi, bool allowDuplicate)` 이다.

## 4. 메뉴·명령·문서 종류·다국어·테마

- 메뉴: 데스크톱 상단 메뉴는 `src/xkxk.frameworks.ui.views/Menus/FileMenu.axaml`·`WindowMenu.axaml`·`ViewMenu.axaml`·`SystemMenuItem.axaml` 에 항목이 고정돼 있다. 항목은 `MainViewModel` 의 명령에 바인딩되고 `AutomationProperties.AutomationId`(예 `shell.mnuOpenGrid`)를 갖는다. 모바일형 메뉴는 데이터 층 `data/Navigation/NavMenuCatalog.cs` 가 따로 들고 있다(데스크톱 AutomationId 1:1 대응표 포함). 즉 같은 메뉴가 axaml 과 C# 카탈로그 두 곳에 있다.
- 아이콘: 생성기 `plan/_build/menu_icons.py` 가 `views/Themes/MenuIcons.axaml`(`PdMenuIcon*`·`PdShellIcon*`, 사이클27 에 `PdCmdIcon*` 추가)과 `data/Navigation/MenuIconCatalog.Generated.cs` 를 만든다. 솔루션이 아이콘을 더하는 공개 경로는 없다.
- 문서 종류: `shell/Docking/ILayoutStore.cs` 의 `enum DocumentKind { Grid, Gantt, Form }` 이 14개 파일 23곳에서 쓰인다. 문서 모델 `shell/Docking/PocDocument.cs` 는 Dock `Document` 를 상속하고 `Kind`·`Seq` 를 가진다. 레이아웃 저장본에도 이 종류 값이 들어간다(추정 — 저장 형식 세부는 F3 착수 때 확인).
- 다국어: `shell/Localization/Loc.cs` 가 셸 어셈블리에 내장된 `<영역>.<언어>.json`(chrome·common·doc·dock·host·log·notify·panel·shell·system·sysview·theme × ko·en, 24개 파일)을 읽는다. 외부 사전을 병합하는 API 는 없다.
- 테마·토큰: 앱 리소스 `views/PdApp.axaml` 과 셸 `Theming/`(색 테마·디자인 테마·사용자 지정)이 담당한다. 시스템 글자 크기 `UiSettings.ShellFontSize` 를 `UiSettingsApplier.ApplyShell` 이 앱 전역 `PdFont*` 토큰에 쓴다.
- 진단: 원격 제어·성능 계측은 `#if PD_DIAGNOSTICS`(198개 파일 347곳)로 제품 빌드에서 빠진다. 속성 `PdDiagnostics`(루트 `Directory.Build.props`)로 켠다.
