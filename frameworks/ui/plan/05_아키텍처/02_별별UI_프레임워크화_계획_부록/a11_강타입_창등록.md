# 부록 a11 — 강타입 창 등록

> 상태: 계획 확정(B10, 구현 진행 중) · 최종 갱신일: 2026-11-27 · 본문: `../02_별별UI_프레임워크화_계획.md`
> 근거: 결정 UADR-0017(시험대 모듈·강타입 창 등록), 창 레지스트리 UADR-0016·부록 a10 §10(예약 확장)·§12(B10 인계), 원칙 UADR-0009(8원칙).
> 이 부록은 옛 a10 §13 으로 쓰려던 내용을 줄 수 한도(300줄) 때문에 분리한 것이다. a10 은 이 부록을 가리키는 안내 1줄만 둔다.
> 표기: 파일 수 같은 수치는 계획 시점(2026-11-27, 기준 커밋 f061c15) 실측이며 구현 결과와 다를 수 있다. 확정값은 판정기 출력과 `HISTORY.md` 가 정본이다.

## 1. 목적

- 창 한 종류를 `뷰모델 + 뷰 + 인자 형식` 한 줄로 등록하게 한다. 소비자는 `CreateContent` 를 손으로 쓰지 않고, 뷰모델이 열림·닫힘·제목·바쁨 표시를 창 문맥으로 다룬다.
- 시험대 모듈(`xkxk.frameworks.ui.testbed`)이 첫 소비자다. 데모 창 3종과 벤치를 이 경로로 옮긴다(a10 §12).
- 만든 동작만 멤버로 노출한다. 닫기 거부(`CanClose`)는 셸 닫기 경로 전부를 바꿔야 해 이번에 만들지 않고 a10 §10 예약 표에 남긴다.

## 2. 이름 확정 근거

사용자 원요구와 a10 §10 의 목표 이름은 `IWindowContext`·`WindowViewModel<TArgs>` 였다. B10 에서 아래처럼 확정했고, 원래 이름과 다르다.

| 원래(a10 §10 목표 이름) | 확정 이름 | 확정 위치 |
|---|---|---|
| `IWindowContext` | `IUiWindowContext` | 셸 `Framework/` |
| `WindowViewModel<TArgs>` | `UiWindowViewModel<TArgs>` | 셸 `Framework/` |
| (비제네릭 기반) | `UiWindowViewModel` | 셸 `Framework/` |
| `Register<TViewModel,TView,TArgs>` | 이름 그대로 | 화면 층 `Windows/` 확장 메서드 |

- 근거(가정 1): `Framework/` 의 공개 형식이 `IUi*`·`Ui*` 관례를 따른다(예 `IUiWindowRegistry`·`UiWindowOptions`). 기존 스타일을 유지한다.
- 근거(가정 2): `IUiWindowContext`·`UiWindowViewModel`·`UiWindowViewModel<TArgs>` 는 Avalonia 가 필요 없어 `Framework/`(PublicAPI 추적)에 둔다. Avalonia 형식 제약 `TView : Control, new()` 가 필요한 `Register` 만 화면 층에 둔다.
- 화면 층 공개 API 는 PublicAPI 추적 밖이라 명세는 수기 문서(`docs/04`)에 적는다. 생성 명세 확대는 B16(새 UTODO)이다.
- a10 §10·본문 §4 예시 주석의 옛 이름은 이 확정 이름으로 고친다. a4 B10 행에는 옛 이름과 확정 이름을 함께 적는다.

## 3. 공개 계약

### 3.1 창 문맥 `IUiWindowContext`(프레임워크만 구현, 멤버 추가 허용)

| 멤버 | 설명 |
|---|---|
| `WindowId` | 창 종류 ID(a10 §3) |
| `DocumentId` | 열린 문서 Id(`Grid-1` 형태) |
| `Title` | 현재 제목 |
| `Parameter` | 열기 때 넘긴 인자(object?) |
| `IsOpen` | 문서가 열려 있으면 true |
| `SetTitle(string)` | 문서 제목 갱신(자동 제목 고정 해제). 닫힌 뒤에는 무시 |
| `Close()` | 기존 닫기 경로 호출. 닫힌 뒤에는 false |
| `BeginBusy()` · `BeginBusy(string reason)` | 바쁨 표시 시작(IDisposable). 기존 `BusyService.Begin` 위임 |
| `event EventHandler? Closed` | 문서가 닫힐 때 1회 |

### 3.2 뷰모델 기반

- `UiWindowViewModel`(추상, `INotifyPropertyChanged`)
  - `Window`(IUiWindowContext) — 연결 전 접근은 InvalidOperationException.
  - `Parameter`, `protected virtual Task OnOpenedAsync(CancellationToken)`, `protected virtual void OnClosed()`.
  - `protected void OnPropertyChanged(string)`, `protected bool SetProperty<T>(ref T field, T value, string propertyName)`.
  - 생성자는 protected 1개(public 0).
- `UiWindowViewModel<TArgs> : UiWindowViewModel` — `TArgs? Args` 하나를 더한다. 파라미터가 null 이면 default, `TArgs` 가 아니면 XKUI0509.
- `UiWindowContentContext.Window`(IUiWindowContext, 셸이 부를 때 비 null)와 `UiCommandContext.Windows`(= `App.Windows`)를 추가한다.

### 3.3 프레임워크 전용 공개 진입점(영구 공개 표면)

연결·수명 호출은 뷰모델 기반의 `AttachWindow(IUiWindowContext, object?)`·`NotifyOpenedAsync(CancellationToken)`·`NotifyClosed()` 가 한다.

- 가시성은 public 이고 `[EditorBrowsable(EditorBrowsableState.Never)]` 를 붙인다. 문서에 '프레임워크 전용, 소비자 호출 금지'를 적는다.
- 화면 층 바인더가 `InternalsVisibleTo` 없이 부르려고 public 으로 연다. 한 번 공개하면 뺄 수 없는 **영구 공개 표면**이다.
- 소비자가 직접 부르면 수명 호출이 중복될 수 있다. 중복 방지는 프레임워크가 하지 않으며 문서가 금지로 안내한다.

## 4. 등록 6 오버로드

화면 층 `Windows/UiWindowViewRegistration.cs` 의 정적 확장 클래스다. 제약은 `TView : Control, new()`, `TViewModel : UiWindowViewModel`(인자 있는 판은 `UiWindowViewModel<TArgs>`)이다. 선택 파라미터는 쓰지 않는다(C16). 반환값은 `Add` 결과(bool)다.

| # | 서명 | 인자 |
|---|---|---|
| 1 | `Register<TViewModel,TView>(this IUiWindowRegistry, string id)` | 없음 |
| 2 | `Register<TViewModel,TView>(…, string id, Action<UiWindowOptions> configure)` | 없음 |
| 3 | `Register<TViewModel,TView>(…, string id, Action<UiWindowOptions> configure, Func<UiWindowContentContext,TViewModel> create)` | 없음 |
| 4 | `Register<TViewModel,TView,TArgs>(…, string id)` | `TArgs` |
| 5 | `Register<TViewModel,TView,TArgs>(…, string id, Action<UiWindowOptions> configure)` | `TArgs` |
| 6 | `Register<TViewModel,TView,TArgs>(…, string id, Action<UiWindowOptions> configure, Func<UiWindowContentContext,TViewModel> create)` | `TArgs` |

- 생성 함수가 없는 판은 `TViewModel : new()` 제약이다.
- `Add` 위에 얹고 `CreateContent` 를 채운다. `configure` 가 `CreateContent` 를 설정해도 이 등록이 덮어쓴다(덮어쓴 사실은 진단 없이 문서에만 적는다).

## 5. 흐름

1. 뷰모델을 만든다(생성 함수가 있으면 그것, 없으면 `new()`).
2. `AttachWindow` 로 문맥·파라미터를 연결한다. 형식이 맞지 않으면 XKUI0509 와 자리표시 내용이다.
3. `new TView { DataContext = vm }` 로 뷰를 만든다.
4. 뷰가 처음 시각 트리에 붙을 때 `NotifyOpenedAsync` 를 **1회** 부른다(SDI 이동·탭 재부착으로 다시 붙어도 1회).
5. 문맥의 `Closed` 때 토큰을 취소하고 `NotifyClosed()`(→ `OnClosed()`)를 1회 부른다.

연결부는 화면 층 `Windows/WindowViewModelBinder.cs`(내부 형식)다. 문서 하나에 대한 셸 구현은 `Docking/DocumentWindowContext.cs`(내부)다.

## 6. 오류 규칙

| 상황 | 동작 |
|---|---|
| 파라미터 null(레이아웃 복원) | `Args` 는 default, 오류 아님 |
| 파라미터가 `TArgs` 아님(`AcceptParameter` 가 false) | `AttachWindow` 가 `ArgumentException` 을 던지고 연결하지 않는다. 바인더가 잡아 XKUI0509 WindowArgumentMismatch(Error)와 자리표시 내용으로 처리한다 |
| 두 번째 `AttachWindow`, 연결 전 `NotifyOpenedAsync` | `InvalidOperationException`(소비자가 프레임워크 전용 진입점을 직접 부른 경우) |
| `OnOpenedAsync` 예외 | XKUI0510 WindowViewModelFailed(Error), 뷰는 그대로 둔다 |
| `OnClosed`·닫힘 처리 예외 | 바인더가 감싸 XKUI0510 으로 남기고 앱은 멈추지 않는다 |
| 생성 함수가 null 반환·예외, 내용이 `Control` 아님 | XKUI0507 WindowContentFailed, 자리표시 |
| 닫힌 뒤 `SetTitle`·`Close` | 무시·false |

## 7. 시험대 지원용 공개 형식(공개 계약 아님)

B10 은 데모·벤치 소스를 시험대 모듈로 옮기며 views 의 `internal` 형식·멤버를 public 으로 바꾼다. 이는 **빌드를 통과시키기 위한 시험대 지원용**이며 공개 계약이 아니다.

### 7.1 공개 형식 변경 목록(M3, 호환 영향)

- `BenchEntry` 삭제 — 시험대가 `TestbedBench.Open` 을 직접 부른다.
- (batch 2) `GridViewPool.TryTake` 반환형 `GridDocumentView?` → `Control?` — **바이너리·소스 비호환**. views 는 PublicAPI 추적 밖이라 소비 코드는 다시 컴파일한다.
- `GridDenseTarget` public 전환(batch 1, 벤치가 사용).
- `RemoteCommandRouter.AddExtension(Action<RemoteCommandRouter>)` 공개 — 시험대 모듈이 자기 진단 명령을 공용 라우터에 더한다. 라우터 생성 전이면 등록 순서대로 보관했다가 기본 명령 뒤에 호출하고, 생성 뒤면 즉시 호출한다.
- 시험대 표본 창의 `TArgs` 는 `string` 이다(`TypedSampleArgs` record 대신). 원격 `docs.open` 이 param 을 문자열로만 넘기기 때문이다.

### 7.2 B16 생성 명세 제외 후보

아래는 `[EditorBrowsable(Never)]` 와 '시험대 지원용·공개 계약 아님' 주석을 붙이고, B16 생성 명세에서 **제외 후보**로 둔다. `docs/04` 에는 소비자 영향만 적는다.

| 형식·멤버 | 전환 시점 | 전환 이유 |
|---|---|---|
| `GridDenseTarget` | batch 1 | 벤치 `GridBenchView` 가 사용 |
| `GridColumnDrafts` | batch 2 | 이동한 그리드 문서 뷰가 사용 |
| `GridCellStrokes` | batch 2 | 이동한 그리드 문서 뷰가 사용 |
| `GridLayoutProbe` | batch 2 | 이동한 그리드 문서 뷰가 사용 |
| `GridViewPool.NoteSize`·`Keep` | batch 2 | 이동한 그리드 문서 뷰가 사용 |
| `GridDocumentViewModel.RunTrackedAsync` | batch 2 | 이동한 그리드 문서 뷰가 사용 |

- 결합 해소 과제: views 의 `internal` 결합을 풀어 이 공개 전환을 되돌리는 과제를 odone 이 UTODO 로 등록한다(시험대 지원용 internal→public 결합 해소).
- 멤버 단위 `internal` 은 빌드(CS0122)가 판정한다. 빌드 소유자가 team-lead 에 보고해 해당 views 파일 소유자를 다시 띄운다.

## 8. 한계

- ① 앱 종료 때는 열린 문서가 목록에서 빠지지 않아 `OnClosed` 가 불리지 않는다. 종료 시 정리가 필요한 뷰모델은 이 호출에 기대지 말고 앱 종료 이벤트를 따로 쓴다.
- ② 내용 생성 전에 닫힌 문서는 문맥이 없다. 그 문서의 뷰모델은 만들어지지 않으므로 `OnClosed` 도 불리지 않는다.
- ③ 닫힘 검출(D3): 닫기 경로가 한 곳이 아니다(DockableClosed 처리기·`CloseAll` 의 Clear·`LayoutRestorer.CloseExcept` 의 잔여 Remove). 문맥이 열린 문서 목록의 `CollectionChanged`(Remove·Reset·Replace)를 구독하고, 자기 문서가 목록에 없으면 Dispatcher 한 바퀴 뒤 다시 확인해 `Closed` 를 낸다.
- ④ `CanClose`(닫기 거부)는 없다. 닫기는 거부할 수 없다.
- ⑤ 프레임워크 전용 공개 진입점(§3.3)은 영구 공개 표면이라 제거할 수 없다.
- ⑥ `UiWindowViewModel`·`IUiWindowContext` 는 UI 스레드 전제이며 별도 스레드 호출 보호는 하지 않는다.
