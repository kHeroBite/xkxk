# 부록 a6 — 앱 컨텍스트 이전 대응

> 상태: 확정(B04) · 최종 갱신일: 2026-11-26 · 본문: `../02_별별UI_프레임워크화_계획.md`
> 근거: 결정 UADR-0011(프로세스 전역 상태 4종을 앱 컨텍스트 한 개가 소유하고 옛 정적 접근자는 위임으로만 남긴다), 현행 진단 부록 a2 §3, 배치 부록 a4 B04·B16·B21. 결정 본문은 `../../90_결정관리/02_결정기록_ADR.md` 에 있다.
> 표기: 줄 수·파일 수 같은 수치는 계획 시점(2026-11-26) 실측이며 구현 결과와 다를 수 있다. 확정값은 판정기 출력과 `HISTORY.md` 가 정본이다.

## 1. 목적

부록 a2 §3 의 정적 전역 상태 가운데 아래 4종은 프로세스에 한 벌씩 숨어 있어 소비자 솔루션이 바꾸거나 시험에서 대체하기 어렵다.

- 메인 뷰모델(`App.MainViewModel`)
- 셸 명령(`App.Shell`)
- 화면 층 등록부(`ViewRegistry.Current`)
- 문구 서비스(`Loc.Instance`)

B04 는 이 4종을 앱 컨텍스트(`IUiAppContext`) 한 개가 소유하게 하고, 프레임워크 안 코드는 컨텍스트만 거치게 한다. 옛 정적 접근자는 외부 호환용 위임 접근자로만 남긴다. 그래서 B16 의 `[Obsolete]` 예고와 B21 의 제거를 호출부 수정 없이 할 수 있다. a4 의 끝 조건은 "직접 참조 0건(위임 접근자만)"이다.

## 2. 공개 계약

모두 셸 `src/xkxk.frameworks.ui.shell/Framework/`(네임스페이스 `xkxk.frameworks.ui.shell.Framework`)에 둔다. 공개 API 분석기(`PublicAPI.Unshipped.txt`)가 서명을 고정한다. 8원칙은 UADR-0009 를 따른다.

| 형식 | 역할 |
|---|---|
| `XkxkUi.Current` | 진입점. `public static IUiAppContext Current { get; }`. 비 null 이고 처음 접근 때 만들어진다. 대입은 불가하다 |
| `IUiAppContext` | 프레임워크만 구현하는 계약(소비자 구현 금지, 멤버 추가 허용). `Localization`(`IUiLocalizer`, 비 null)·`Views`(`IViewRegistry`, 미등록이면 지금과 같은 `InvalidOperationException`)·`RegisterViews(IViewRegistry)`(null 이면 `ArgumentNullException`, 재호출은 교체)·`MainViewModel`(`MainViewModel?`)·`Shell`(`IShellCommands?`) |
| `IUiLocalizer` | 문구 서비스 계약. `INotifyPropertyChanged` 를 잇는다. 프레임워크 구현, 멤버 추가 허용(§4) |
| `UiLanguage` | 언어 한 항목. `Code`·`Name`·`Deconstruct`. 확장 가능한 sealed 클래스(§4) |

`IUiAppContext` 의 구현체 `UiAppContext` 는 internal 이라 소비자가 만들거나 상속할 수 없다. 처음 쓸 때 만들어지는 단일 인스턴스를 `XkxkUi.Current` 가 돌려준다.

## 3. 옛 정적 접근자 → 새 경로 대응표

| 옛 접근자 | 새 경로 | 옛 접근자의 새 모습 |
|---|---|---|
| `App.MainViewModel` | `XkxkUi.Current.MainViewModel` | 읽기만 하는 위임 속성. App 안에는 대입이 없다 |
| `App.Shell` | `XkxkUi.Current.Shell` | 읽기만 하는 위임 속성. App 안에는 대입이 없다 |
| `ViewRegistry.Current` | `XkxkUi.Current.Views`(읽기)·`XkxkUi.Current.RegisterViews`(쓰기) | 같은 이름의 정적 속성이 get·set 으로 위임한다. 정적 필드는 없다 |
| `Loc.Instance` | `XkxkUi.Current.Localization` | `Loc` 가 `IUiLocalizer` 를 구현하고 `Instance` 가 컨텍스트의 같은 인스턴스를 돌려준다 |
| `Loc.Instance.AllKeys`·`MissingKeys`(진단 전용) | `UiAppContext.Instance.CoreLoc.*` | 공개 계약에 넣지 않고 셸 내부 경로(internal)로 쓴다 |
| `Loc.Tr(key)`·`Loc.Tr(key, args)` | 그대로 유지 | 정적 편의 함수라 옮기지 않는다(§5) |

- 프레임워크 안 호출부(계획 시점 92파일, 164줄 안팎)는 결정적 치환 스크립트로 한 번에 이전한다. 규칙은 위 표의 4행과 진단 멤버 1행이며, 필요하면 `using xkxk.frameworks.ui.shell.Framework;` 한 줄을 더한다.
- 이전 뒤에는 옛 한정 이름을 쓰는 곳이 위임 접근자 정의 자신뿐이어야 한다. 이 상태는 판정기 `test/framework/judge/app_context_check.py` 의 `refs=0` 과 독립 `rg` 대조로 확인한다.
- 동작은 바뀌지 않는다. 반환값·예외 문구·null 이 되는 시점이 옛 접근자와 같다. `Loc` 생성 시점만 "`Loc` 형식을 처음 접근할 때"에서 "문구를 처음 쓸 때"로 늦어지며, 눈에 보이는 차이가 없는지는 스모크로 확인한다(추정 단계의 판단).

## 4. IUiLocalizer 최소 표면과 UiLanguage

프레임워크가 구현하는 인터페이스는 멤버를 더하는 것은 호환이지만 빼는 것은 소비자를 깨뜨린다. 그래서 영구 계약에는 소비자에게 필요한 것만 넣는다.

| 멤버 | 설명 |
|---|---|
| `string Language { get; set; }` | 현재 언어 코드 |
| `event Action? LanguageChanged` | 언어가 바뀌면 발생 |
| `IReadOnlyList<UiLanguage> Languages { get; }` | 지원 언어 목록 |
| `string this[string key] { get; }`·`string Get(string key)` | 문구 조회 |
| `string Format(string key, params object?[] args)` | `{0}` 형식 문구 |
| `bool HasKey(string key)` | 키 존재 여부 |
| `IObservable<string> Observe(string key)` | 언어가 바뀔 때마다 값을 내는 관찰 |

- 진단 전용 `AllKeys`·`MissingKeys` 는 넣지 않는다. 한 번 공개하면 빼지 못하는 반면 쓰는 곳이 원격 진단 명령뿐이라 셸 내부 경로로 충분하다.
- 언어 목록은 지금의 튜플 대신 `UiLanguage` 로 낸다. 튜플은 항목을 더할 수 없지만 클래스는 표시 방향·원어 이름 같은 속성을 나중에 더할 수 있다. `Deconstruct` 를 두어 `foreach (var (code, name) in …)` 형태의 기존 호출부는 그대로 컴파일된다.
- `Loc` 의 기존 튜플 `Languages` 는 그대로 두고 `IUiLocalizer.Languages` 는 명시적 구현으로 낸다.

## 5. Loc.Tr 을 유지하는 근거

- `Loc.Tr` 는 상태를 갖지 않는 편의 함수다. 옮길 상태가 없으므로 위임으로 바꿀 이유가 없다.
- 호출부가 계획 시점 303곳(92파일)이다. 이것까지 지우면 변경량이 3배가 되고 소비자 API 가 장황해진다(대안 C 기각, UADR-0011).
- 그래서 B16 의 `[Obsolete]` 예고와 B21 의 제거 대상에서 `Loc.Tr` 은 빠진다. 대상은 상태 접근자(`Loc.Instance` 등)뿐이다.

## 6. 기동 시점

부록 a5 §2 의 단계에서 컨텍스트가 채워지는 시점은 아래와 같다.

| 시점 | 일 |
|---|---|
| 처음 접근 | `XkxkUi.Current` 가 `UiAppContext` 단일 인스턴스를 만든다 |
| 문구 첫 사용 | `Loc` 를 만든다(사전 로드·문화권 설정). 스레드 안전한 지연 생성이라 지금의 정적 초기화와 같은 1회 생성을 보장한다 |
| `PdApp` 생성 | `RegisterViews` 로 화면 층 등록부를 넣는다 |
| 기동 단계 7 | `OnFrameworkInitializationCompleted` 가 메인 뷰모델을 컨텍스트에 넣고 → 기존 `ApplyStartupArgs()` → 셸 명령을 넣는다. 순서는 B03 이전과 같다 |

## 7. 위임 접근자 일정

| 단계 | 일 |
|---|---|
| B04 | 호출부를 새 경로로 이전하고 옛 접근자는 위임으로 남긴다 |
| B16 | 옛 접근자에 `[Obsolete]` 를 달아 예고한다. 호출부가 이미 새 경로라 프레임워크 내부 경고는 생기지 않는다 |
| B21 | 위임 접근자를 제거한다. 단 `Loc.Tr` 은 제외한다(UADR-0011) |

## 8. App 위임 검증의 대체

`App.MainViewModel`·`App.Shell` 의 값이 컨텍스트와 같은지를 계약 시험으로 직접 비교하려면 앱을 기동해 값을 넣어야 한다. 그러나 공개 경로로는 값을 넣을 수 없고(`InternalsVisibleTo` 금지, 원칙 8), 시험 프로세스에 Avalonia 앱을 띄우지 않는 것이 계약 시험의 규칙이다. 그래서 값 일치 실증은 아래 둘로 대신한다.

- 계약 시험 C27 의 구조 검사 — `App` 의 두 속성에 공개 setter 가 없음(`CanWrite == false`, 공개 리플렉션만 사용), `IUiAppContext`·`IUiLocalizer` 의 공개 멤버 목록 대조, `IUiAppContext` 공개 구현 형식 0.
- 판정기 `app_context_check.py` 의 `defs` 검사 — App 두 속성이 위임으로 정의돼 있고 App 안에 대입이 없으며, `ViewRegistry` 에 정적 필드가 없고 `Loc.Instance` 가 위임으로 정의돼 있음.

실제 값이 흐르는 모습은 데스크톱 스모크(언어 전환 포함)가 확인한다. 정적 필드 0 검사는 판정기 정규식과 계약 시험 C25·C26 의 동작 실증이 맡는다.

## 9. 한계

① **한정 없는 이름은 판정 밖** — `PdApp : App` 안에서 `MainViewModel`·`Shell` 을 한정 없이 쓰면 판정기가 잡지 못한다. 계획 시점에 해당 줄은 0건이다.

② **x:Static 은 한 번만 평가** — `DocumentDockMode.axaml` 의 `{x:Static}` 은 로드 때 한 번 평가된다. 컨텍스트에는 변경 알림이 없어 로드 때 값이 null 이면 이후 갱신되지 않는다. 지금과 같은 한계다.

③ **DI 미적용** — 컨텍스트는 단일 앰비언트 접근자(`XkxkUi.Current`)이고 생성자 주입은 하지 않는다. 범위 밖이며 B16 의 DI 재검토 결과에 따른다.

④ **고정 계약 표면이 넓어진다** — `IUiAppContext` 를 통해 `IViewRegistry`(13개 멤버, 동결 인터페이스도 추상 기반도 아님)·`MainViewModel`(구체 형식)·`IShellCommands` 가 공개 계약 표면에 들어온다. 지금은 Unshipped 라 바꿀 수 있지만, 소비자가 구현하거나 의존할 수 있어 B16(공개 API 고정 확대) 때 동결 또는 추상 기반 전환을 재검토한다.

⑤ **프로세스 전역이고 리셋이 없다** — `XkxkUi.Current` 는 한 프로세스에 하나이며 되돌릴 수단이 없다. 그래서 계약 시험이 실행 순서에 의존한다. 상태를 남기는 `ViewRegistry` 등록 시험(C26)은 맨 마지막에 두고, `Language` 를 바꾸는 시험(C25)은 원복해야 한다. 순서를 바꾸거나 시험을 추가할 때 이 의존을 깨지 않도록 주의한다.

⑥ **계획서 한계** — `Loc` 정적 초기화 순서(문화권·경고 설정)를 유지하고 `UiAppContext` 경유로 순환 초기화가 생기지 않는지는 구현에서 확인할 항목이다. 이름 충돌이 생기면 별칭 using 으로 푼다. 앱 없는 콘솔에서 `Language` 를 바꾸면 UI 스레드 전달 호출이 일어나므로 계약 시험은 시간 제한 안에서 먼저 시험해 보고, 막히면 언어 전환은 스모크가 맡는다.

## 10. 범위 밖

- `UiSettings.Current`·테마·투어·모니터 싱글톤 등 그 밖의 정적 상태는 B05 가 맡는다.
- 컨텍스트 변경 알림, `UiModuleContext` 노출, 문구 병합, DI 생성자 주입은 하지 않는다.
- `[Obsolete]` 표시는 B16, 위임 접근자 제거는 B21 이다.

## 구현 메모(B04 완료)
- `Loc` 생성자는 internal 이다. `Loc.Get` 은 public 이고 `Format` 을 더했다.
- `KeyObservable`·`Unsubscriber` 는 `Localization/LocObservable.cs` 로 분할했다.
- 300줄 상한 3파일은 using 1줄 대신 정규화된 이름을 쓴다.
- 호출부는 91파일 164줄을 일괄 치환했고, 네임스페이스 한정 이름 앞부분 수정 6파일 10곳과 `DocumentDockMode.axaml` 을 더했다.
