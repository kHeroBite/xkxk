# 부록 a8 — 아이콘·명령 레지스트리

> 상태: 계획 확정(B06, 구현 진행 중) · 최종 갱신일: 2026-11-26 · 본문: `../02_별별UI_프레임워크화_계획.md`
> 근거: 결정 UADR-0013(아이콘·명령을 같은 키 체계의 레지스트리 2종으로 연다, 예약 접두어 `xkxk.`, 등록 정책 P1~P4), 원칙 UADR-0009(8원칙), 아이콘 키 체계 UADR-0006, 앞 batch 부록 a6(UADR-0011)·a7(UADR-0012), 현행 진단 부록 a2 G4, 배치 부록 a4 B06·B07.
> 표기: 개수·줄 수 같은 수치는 계획 시점(2026-11-26, 기준 커밋 6222b69) 실측이며 구현 결과와 다를 수 있다. 확정값은 판정기 출력과 `HISTORY.md` 가 정본이다.

## 1. 목적

솔루션이 아이콘과 명령을 같은 키 체계로 등록·교체·제거하고, 셸 기본 명령을 이름으로 실행하게 한다. 지금은 아이콘 키를 그림으로 바꾸는 곳이 `TryFindResource(key)` 직접 조회 2곳(`WindowIcon.FindGeometry`·`MenuIconBitmap.Create`)뿐이고, 명령은 메인 뷰모델의 `RelayCommand` 가 `IShellCommands` 를 직접 부른다. 소비자가 아이콘을 더하거나 명령을 이름으로 부를 공개 경로가 없었다(a2 G4).

- B06 은 레지스트리 2종과 기본 생성 공급자·기본 명령 23개·등록 규칙 진단을 만든다.
- B07(메뉴 레지스트리·셸 4메뉴 이관)이 이 위에서 메뉴를 명령 ID 로 묶는다. 그래서 B06 에서는 메뉴 axaml 을 바꾸지 않는다.
- 메뉴 아이콘은 그리는 경로가 레지스트리 해석으로 바뀌므로 메뉴 아이콘 판정기가 회귀 검증을 겸한다.

## 2. 공개 계약

모두 셸 `src/xkxk.frameworks.ui.shell/Framework/`(네임스페이스 `xkxk.frameworks.ui.shell.Framework`)에 둔다. 선택 파라미터는 쓰지 않고 새 입력은 옵션 속성·오버로드로만 더한다(UADR-0009).

| 형식 | 역할 |
|---|---|
| `IUiIconRegistry` | 아이콘 레지스트리. 프레임워크만 구현, 멤버 추가 허용. `Add`·`AddGeometry`·`Remove`·`Contains`·`TryGet`·`Keys`·`Providers`·`AddProvider`·`RemoveProvider`·`Changed` |
| `UiIconOptions` | 아이콘 등록 옵션 객체. `PathData`·`ResourceKey`(정확히 하나)·`Description`·`Replace`(기본 false) |
| `UiIconDefinition`·`UiIconKind` | 해석된 아이콘. 정의는 공개 생성자 없이 팩터리 `FromPathData`·`FromResource` 로 만든다. 종류는 `PathData`·`Resource` |
| `UiIconProvider` | 소비자가 상속하는 추상 기반. `Id`·`Keys`·`TryGetIcon`. 앞으로 멤버는 기본 구현이 있는 virtual 로만 더한다 |
| `UiRegistryChangedEventArgs`·`UiRegistryChangeKind` | 변경 알림. 종류는 Added·Removed·Replaced·ProviderAdded·ProviderRemoved |
| `UiRegistryOwners` | 등록 주체 상수. `Shell`(`xkxk.shell`)·`Generated`(`xkxk.generated`)·`App`(`app`)·`ReservedPrefix`(`xkxk.`) |
| `IUiCommandRegistry` | 명령 레지스트리. `Add`·`Remove`·`Contains`·`TryGet`·`Commands`·`CanExecute`·`Execute`(각각 매개변수 없는 것과 있는 것)·`Changed` |
| `UiCommandOptions`·`UiCommandDefinition`·`UiCommandContext` | 명령 옵션·정의·실행 문맥. 옵션은 TitleKey·Title·Icon·Gesture·Category·DescriptionKey·Execute·CanExecute·Replace |
| `ShellCommandIds` | 셸 기본 명령 ID 상수 23개와 표 순서의 `All` 목록 |
| `UiDiagnosticIds` 추가 | 02xx 아이콘 7개·03xx 명령 9개(§7) |
| `IUiAppContext` 추가 3멤버 | `Icons`·`Commands`·`Diagnostics`. 기존 9멤버·순서 유지 |
| `IUiModuleContext` 추가 2멤버 | `Icons`·`Commands`. 앱 컨텍스트와 같은 저장소를 보고 Owner 는 모듈 ID |

- `IUiAppContext.Diagnostics` 는 앱 수준 진단 모음이다. B06 에서는 빌더 Build 뒤의 등록·실행 진단이 쌓이고, 다른 출처의 진단이 이후 판에서 합류할 수 있다. 항목이 늘어나는 것은 호환 변경이다.
- `UiIconKind`·`UiRegistryChangeKind` 에는 값이 추가될 수 있다. 구독자는 모르는 값을 받으면 전체가 바뀐 것으로 보고 다시 읽는다.
- `Changed` 는 잠금 밖에서 발생하며 구독자 예외는 삼키지 않는다(기존 `UiDiagnostics.Reported` 와 같다).
- 내부 구현은 `UiIconStore`·`UiCommandStore`(internal)이고 앱 컨텍스트가 지연 생성으로 소유한다. 모듈 컨텍스트의 레지스트리는 같은 저장소의 보기(`ViewFor`)다.
- 등록 규칙 위반은 예외 대신 진단을 남기고 false 를 돌려준다. 빌드 중 위반은 기존 `UiErrorPolicy` 를 따른다(Collect 면 모으고 Throw 면 `UiConfigurationException`).

## 3. 아이콘 해석 순서

`TryGet`·`Contains` 는 아래 순서로 첫 일치를 돌려준다.

1. 명시 등록(`Add`·`AddGeometry`).
2. 공급자(`Providers` 순서). 나중에 더한 공급자가 앞에 오고, 기본 생성 공급자 `xkxk.generated` 가 맨 끝이다.

- 명시 등록이 공급자 키를 가리는 것은 정상 재정의이며 진단이 없다. 명시 키를 `Remove` 하면 공급자 값이 다시 보인다.
- 공급자가 돌려준 정의의 Owner 는 그 공급자 Id 로 맞춘다.
- `Keys` 는 해석 가능한 전체 키 사본(명시+공급자, 중복 제거, Ordinal 정렬)이다.
- 화면은 `UiIconGeometry.Find(host, theme, key)` 하나로 해석한다(§6). 레지스트리가 모르는 키는 지금처럼 리소스 조회로 떨어져 호환된다.

## 4. 기본 생성 공급자 xkxk.generated

- 생성기·axaml 은 바꾸지 않는다. 이미 있는 생성 상수에서 키 목록을 만들고 리소스 키로 해석한다. 그림은 그대로 `views/Themes/MenuIcons.axaml` 의 StreamGeometry 에 있다.
- 키 집합은 `CmdIconKeys.All` + `MenuIconCatalog.IconKeyByMenuId` 값 + 셸 아이콘 이름 + 특수 3(`BusyStaticKey`·`BadgeSlowKey`·`BadgeErrorKey`)이다. 계획 시점 169개이고 axaml 의 StreamGeometry 169개와 같은 집합이다.
- `TryGetIcon(key)` 는 `UiIconDefinition.FromResource(key, key)` 를 돌려준다. Owner 는 `xkxk.generated` 다.
- 프레임워크는 아이콘을 명시 등록하지 않고 공급자로만 더한다. 이 약속이 §5 의 아이콘 키 비예약 근거다.

## 5. 예약 접두어 xkxk.

프레임워크 예약 접두어는 `UiRegistryOwners.ReservedPrefix` = `xkxk.`(Ordinal, 대소문자 구분)다. 프레임워크 주체는 Owner 가 이 접두어로 시작하는 주체(`xkxk.shell`·`xkxk.generated`와 프레임워크가 내는 모듈 ID)다.

| 대상 | 규칙 |
|---|---|
| 명령 ID | 프레임워크 아닌 주체가 아직 없는 `xkxk.*` ID 를 새로 만들면(Replace false·true 모두) XKUI0308 Error, 등록 안 함. 이미 있는 `xkxk.*` 명령을 Replace=true 로 바꾸는 것은 허용(재정의 경로). Replace=false 로 같은 ID 를 다시 등록하면 기존대로 XKUI0302 |
| 공급자 Id | 프레임워크 아닌 주체의 `xkxk.*` Id 는 XKUI0206 Error, 등록 안 함 |
| 아이콘 키 | 예약하지 않는다 |
| 모듈 ID | 문서상 예약이지만 검사하지 않는다(§11 한계 d) |

아이콘 키를 예약하지 않는 근거는 둘이다. 명시 등록이 공급자 키를 가리는 것은 정상 재정의라 프레임워크가 새 생성 키를 더해도 소비자 등록이 깨지지 않는다. 프레임워크는 아이콘을 명시 등록하지 않고 공급자로만 더하므로 명시 키 충돌(XKUI0202)이 생기지 않는다.

효과는 프레임워크가 다음 판에 `xkxk.*` 기본 명령·공급자를 더해도 소비자 등록과 충돌하지 않는 것이다. 추가만으로 호환된다.

## 6. 등록 정책 P1~P4

고른 기준은 "나중에 동작을 바꾸지 않아도 되는 쪽"이다. 넓게 허용했다가 막으면 깨짐이고, 좁게 시작해 넓히는 것은 옵션·오버로드 추가로 할 수 있다.

| 번호 | 정책 |
|---|---|
| P1 | `Replace=true` 인데 기존 등록이 없으면 새로 등록하고 true·`Changed(Added)` 다. 호출자가 `Contains` 를 먼저 볼 필요가 없다. 예약 ID 는 §5 가 우선한다 |
| P2 | `Remove`·`RemoveProvider` 는 그 항목을 등록한 주체(Owner 동일, Ordinal)만 할 수 있다. 다른 주체의 항목(셸 기본 명령·생성 공급자 포함)을 지우려 하면 아이콘 XKUI0207·명령 XKUI0309 Error 후 false 이고 지우지 않는다. `Replace=true` 교체는 주체와 무관하게 허용하며 Owner 는 교체한 주체로 옮긴다 |
| P3 | `Replace` 는 `Commands` 안의 자리를 유지한다. `Remove` 뒤 다시 `Add` 하면 맨 뒤에 붙는다. 아이콘 `Keys` 는 정렬이라 해당 없고, `Providers` 는 새 공급자가 앞이다 |
| P4 | Build 가 끝난 뒤 모듈이 붙잡아 둔 `ui.Icons`·`ui.Commands` 로 등록하면 실행 중 등록과 같다. 아이콘을 즉시 검사하고 진단은 `XkxkUi.Current.Diagnostics`(앱)에 쌓으며 Owner 는 모듈 ID 를 유지한다. 예외와 `UiErrorPolicy` 는 적용하지 않는다(진단 + false) |

- 모듈의 명령이 가리키는 아이콘 검사(XKUI0304)는 모듈 순서의 영향을 받지 않도록 Build 끝에 한 번에 한다(`UiBuildSession.Complete`). Build 도중에는 빌더 Diagnostics·`UiErrorPolicy` 를 따른다.
- 숨김·권한 조건은 B07 메뉴 층에서 명령을 지우지 않고 다룬다.

## 8. 단축키 문법

`UiCommandOptions.Gesture` 는 별별UI 자체 문법이다. 공개 문서는 Avalonia 문법을 인용하지 않는다.

- 앞뒤 공백을 뺀 문자열을 `+` 로 나눈 구간들이다. 마지막 구간이 키 1개이고 앞 구간들은 수정자 0개 이상이다.
- 수정자는 Ctrl·Shift·Alt·Meta(대소문자 무시, 각 1회, 순서 무관)다.
- 키는 A~Z, D0~D9, F1~F24, NumPad0~NumPad9, Tab, Enter, Escape, Space, Back, Delete, Insert, Home, End, PageUp, PageDown, Left, Up, Right, Down, OemPlus, OemMinus, OemComma, OemPeriod, Add, Subtract, Multiply, Divide 다.
- 무효 사례는 빈 문자열, 빈 구간(`Ctrl++`), 수정자만(`Ctrl`·`Ctrl+Shift`), 목록 밖 키(`Nope`·`999`), 키 2개(`A+B`), 수정자 중복(`Ctrl+Ctrl+A`), 구간 안 공백이다.
- 구현(`Platform/UiGestureText.IsValid`)은 위 문법을 문자열로 먼저 검사하고, 통과하면 Avalonia `KeyGesture.Parse` 로 다시 해석해 Key 와 수정자 정의 값까지 확인한다. 둘 다 통과해야 유효하다.
- 키 목록 확장은 추가만 한다. 이미 유효한 문자열이 무효로 바뀌는 변경은 하지 않는다.
- B06 은 메타데이터(문법 검사)만 둔다. 실제 키 연결은 B07 이후다.

| LayoutPresetMdiTileVertical | `xkxk.layout.preset.mdiTileVertical` | 없음 | 셸 있음 |

- 제목 문구 키(예 `menu.window.cascade`)와 아이콘 키(`CmdIconKeys.*`)는 판정기가 `shell.ko.json`·`shell.en.json`·생성 상수와 맞는지 확인한다.
- 저장·복원 같은 비동기 명령은 이어 붙인 continuation 에서 예외를 XKUI0306 으로 남긴다.
- 앱 없음(셸 null)에서는 `xkxk.window.overview` 외의 명령이 `CanExecute` false 이고 `Execute` 는 예외 없이 false 다.
- **잔여 8종은 B07 에서 판단한다.** 최대화 전환·이전 크기·이름 변경·MDI↔SDI 전환(뷰모델 부가 로직)과 확대·축소·데모 문서 열기(B10 시험대 모듈)·종료다.

## 10. 창 전체 보기와 화면 층 소비자

- a7 §6 이 `WindowOverviewHost` 를 B06 몫으로 배정했다. 기본 명령 `xkxk.window.overview` 가 `WindowOverviewHost.Request()` 를 부르고, 열기 요청 호출 2곳(MainView 단축키·WindowMenu 클릭)은 `XkxkUi.Current.Commands.Execute(ShellCommandIds.WindowOverview)` 로 바뀐다. 진단 대리자(Open·Select·State·SelectAt)는 그대로 두고 B16 에서 다시 본다.
- `UiIconGeometry`(`Platform/`, public static)가 `Find(host, theme, key)` 로 그림을 해석한다. 키가 비면 null 이다. 레지스트리가 PathData 를 주면 `StreamGeometry.Parse` 결과를 (키, 경로) 로 캐시하고, 실패하면 XKUI0204 를 한 번 남기고 null 이다. 리소스를 주면 호스트 리소스 조회다.
- `WindowIcon` 은 붙을 때 `Icons.Changed` 를 구독해 알림이 오면 UI 스레드에서 다시 그리고, 떨어질 때 해제한다. `MenuIconBitmap` 은 첫 `Create` 때 1회 지연 구독해 알림이 오면 캐시를 비운다(정적 생성자 사용 안 함).
- `UiIconGeometry` 는 public 이지만 `Framework/` 밖이라 공개 API 고정 대상이 아니다. 문서 주석에 "프레임워크 화면 층 전용, B16 공개 범위 재검토" 를 적는다.

## 11. 한계·비권장

- (a) 소비자가 생성 아이콘과 같은 이름 꼴 키(프레임워크 생성 공급자가 내는 키)를 먼저 명시 등록하면 새로 생기는 생성 아이콘이 조용히 가려지므로 비권장이다.
- (b) `Replace=true` 로 Owner 를 가져온 뒤 `Remove` 하면 다른 주체의 항목도 지워진다. P2 는 실수 방지 수준일 뿐 보안 경계가 아니다.
- (c) 셸 기본 명령을 교체한 뒤 `Remove` 하면 같은 `xkxk.*` ID 는 XKUI0308 로 그 프로세스에서 다시 만들 수 없다.
- (d) 모듈 ID 의 `xkxk.*` 는 예약 검사 밖이다. 진단 추가는 B03 계약 변경이라 이번 범위 밖이며, 그 모듈은 프레임워크 주체로 취급된다.
- (e) `registry.dump` 의 명시 등록 목록(explicit)은 전체 개수에서 공급자별 개수를 뺀 값으로 간접 계산한다. 키 목록을 직접 열거하지 않으므로 공급자가 키를 중복해 내면 어긋날 수 있다(2026-11-26 B06 odone 기록).
- (f) 판정기 AC-007(`Icons.Changed` 구독·해제 정적 확인)은 구독이 실제로 동작하는지 실행으로 확인하지 않는다. 실행 검증은 B07 후보다.
- 레지스트리는 프로세스 전역이고 리셋이 없다(B04 한계와 같다). 계약 시험은 시험마다 고유 키·ID 를 쓴다.
- 실행 중 진단은 앱 컨텍스트 하나(`XkxkUi.Current.Diagnostics`)에 쌓이고 빌더 진단과 합치지 않는다.
- `PathData` 의 좌표 격자는 지금 그리기 기준(24)이다. 다른 격자가 필요하면 `UiIconOptions` 에 속성을 더한다.
- `KeyGesture.Parse` 는 콘솔 계약 시험에서 동작함을 실측으로 확인했다(Avalonia 12.1.4 콘솔 탐침, `dotnet.exe` rc=0). 사례는 `Ctrl+Enter`=Return(6)·`Ctrl+PageUp`=Prior(19)이고, `Ctrl` 은 Key.None, `Ctrl+999` 는 `Enum.IsDefined`=false 로 2단 검사가 막는다. `A+B` 는 Parse 가 예외 없이 통과하므로 1단 문법 검사가 막는다. 문법 1단 검사는 Avalonia 없이 돈다.

## 13. registry.dump 와 시험

- 원격 진단(진단 빌드 `PD_DIAGNOSTICS` 만)에 `registry.dump [keys=1]` 과 `command.run id=<명령 ID>` 를 더한다. `registry.dump` 는 아이콘(개수·명시 등록·공급자별 개수)·명령(제목·아이콘 해석 여부·단축키·Owner·활성 여부)·진단·실행 중 Error 수를 돌려주고, `command.run` 은 `{id, canExecute, executed}` 를 돌려준다. a3 §4 가 `registry.dump` 를 B06 부터 계약 시험으로 쓰기로 했다.
- 계약 시험 C33~C45(`test/framework/contract/`)가 §3~§9 를 확인한다. 구현 전에 먼저 써서 컴파일 실패(red)를 남긴 뒤 구현한다.
- 판정기 `test/framework/judge/icon_command_registry_check.py` 가 생성 키 집합·리터럴·명령 23개·문구 키·직접 조회 잔존을 정적으로 확인하고, `verify_framework.sh` 의 registry 단계에서 돈다.
- 비전경 회귀는 데스크톱 스모크(`registry.dump`·`command.run` 계단식·창 전체 보기), 메뉴 아이콘·제목 탭 아이콘 판정기, 웹 headless 스모크다. B06 은 F 끝 batch 가 아니라 포그라운드·Fold5·성능 항목이 없다.
