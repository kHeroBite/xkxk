# 부록 a9 — 메뉴 레지스트리

> 상태: 계획 확정(B07, 구현 진행 중) · 최종 갱신일: 2026-11-27 · 본문: `../02_별별UI_프레임워크화_계획.md`

## 1. 목적

솔루션이 셸 메뉴를 추가·숨김·순서 바꾸기·대체할 수 있게 한다(본문 §4·§5 메뉴 확장점, §8 dogfooding 전제). 지금은 셸 4메뉴(파일·창·보기·시스템)가 axaml 에 고정돼 있고, 모바일형 메뉴는 `NavMenuCatalog` 가 자체 행 목록을 따로 가져 출처가 둘이다(a2 진단).

- 메뉴 레지스트리를 공개하고, 셸 기본 메뉴는 데이터 표 1곳에서 같은 레지스트리로 등록한다.
- 데스크톱·웹 화면 메뉴와 모바일형 메뉴가 같은 레지스트리를 읽는다. 4메뉴 axaml 의 고정 항목은 0개가 되고 기존 `AutomationId`(계획 시점 108개)는 보존한다.
- a8 의 B07 이월 항목(메뉴 이관, 단축키 실제 연결, 잔여 명령 판단, `Icons.Changed` 실행 검증)과 `registry.dump` 명시 등록 목록 문제를 함께 끝낸다.

## 2. 공개 계약

모두 셸 `src/xkxk.frameworks.ui.shell/Framework/`(네임스페이스 `xkxk.frameworks.ui.shell.Framework`)에 둔다. Avalonia 를 참조하지 않고, 선택 파라미터는 쓰지 않으며, 새 입력은 옵션 속성·오버로드로만 더한다(UADR-0009).

| 형식 | 역할 |
|---|---|
| `IUiMenuRegistry` | 메뉴 레지스트리. 프레임워크만 구현, 멤버 추가 허용. `Add`·`Remove`·`Contains`·`TryGet`·`Items`·`GetChildren`·`Move`·`SetHidden`·`GetState`·`Changed` |
| `UiMenuItemOptions` | 등록 옵션. `Parent`·`Kind`(기본 Command)·`CommandId`·`CommandParameter`·`TitleKey`·`Title`·`Icon`·`AutomationId`·`InsertAfter`·`InsertBefore`·`IsVisible`·`ToolTip`·`Section`·`Mobile`(항상 null 아님)·`Replace` |
| `UiMenuMobileOptions` | 모바일형 투영 힌트. `InDrawer`(기본 true)·`Available`(기본 true)·`UnavailableReasonKey`·`EntryId`·`TitleKey`·`CommandId`·`CommandParameter`·`TabOrder`(기본 -1)·`TabTitleKey`·`TabIcon`·`CoveredAutomationIds` |
| `UiMenuPlacementOptions` | 이동 옵션. `Parent`(null 이면 지금 부모 유지)·`ToRoot`(true 면 `Parent` 를 무시하고 최상위)·`InsertAfter`·`InsertBefore` |
| `UiMenuItemKind` | 항목 종류. Command=0·Submenu=1·Separator=2·Section=3. 값은 끝에만 더하고 화면은 모르는 값을 그리지 않는다 |
| `UiMenuItemDefinition` | 등록 시점 사본(공개 생성자 없음, get 전용). 옵션 값에 `Id`·`Owner`·`IsHidden`·`HasVisibilityCondition`·`HasToolTip` 을 더한다 |
| `UiMenuMobileDefinition` | `UiMenuMobileOptions` 의 읽기 사본(공개 생성자 없음) |
| `UiMenuContext` | `IsVisible`·`ToolTip` 대리자 인자. `App`·`Item`·`Surface`(공개 생성자 없음, 속성 추가로만 넓힌다) |
| `UiMenuItemState` | `GetState` 결과. `IsVisible`·`IsEnabled`·`Title`·`Icon`·`Gesture`·`ToolTip`(공개 생성자 없음) |
| `UiMenuSurface` | 보는 화면. Desktop=0·Mobile=1. 값은 끝에만 더한다 |
| `ShellMenuIds` | 셸 메뉴 ID 상수(구분선·섹션 포함)와 `Roots`·`All`(셸 메뉴 표 행 순서) 목록 |

기존 형식에는 아래를 더한다.

| 대상 | 추가 |
|---|---|
| `IUiAppContext` | `IUiMenuRegistry Menus`(기존 12멤버 뒤) |
| `IUiModuleContext` | `IUiMenuRegistry Menus`(기존 6멤버 뒤, Owner 는 모듈 ID). 앱 컨텍스트와 같은 저장소를 본다 |
| `UiRegistryChangeKind` | Moved=5·VisibilityChanged=6 |
| `UiDiagnosticIds` | XKUI0401~0411·XKUI0310(§8) |

- 규칙 위반은 예외 대신 진단을 남기고 false 를 돌려준다. 빌드 중 위반은 기존 `UiErrorPolicy` 를 따른다.
- `Changed` 는 잠금 밖에서 발생하며 구독자 예외는 삼키지 않는다(a8 레지스트리와 같다).
- `Items` 는 트리 깊이 우선 순서의 사본이고, `GetChildren(null)` 은 최상위 목록이다.
- 등록 뒤에 옵션 객체를 바꿔도 등록된 정의는 바뀌지 않는다.

```csharp
// 파일 메뉴의 '입력폼 열기' 뒤에 솔루션 명령을 넣는다.
ui.Menus.Add("acme.project.new.menu", o => { o.Parent = ShellMenuIds.File; o.InsertAfter = "xkxk.file.openForm"; o.CommandId = "acme.project.new"; });
```

## 3. 메뉴 ID 와 AutomationId

- 셸 메뉴 ID 는 `xkxk.<루트>.<이름>` 이다. 이름은 소문자로 시작하는 camelCase 이고, `AutomationId` 의 `shell.mnu` 뒤 이름에서 루트와 겹치는 접두를 뺀 것이다. 예를 들어 `shell.mnuOpenGrid` 항목은 `xkxk.file.openGrid` 다.
- 최상위는 `xkxk.file`·`xkxk.window`·`xkxk.view`·`xkxk.system` 이다. 구분선은 `xkxk.<루트>.sep<n>` 이다.
- 명령 ID 와 같은 문자열이어도 레지스트리가 달라 충돌이 아니다.
- `AutomationId` 를 주지 않으면 `menu.<id>` 다. 화면 `MenuItem` 과 모바일 서랍 항목의 자동화 이름 근거다.
- 구분선·섹션이 아닌 셸 항목의 `AutomationId` 는 `shell.mnu` 로 시작하고 중복이 없다.

## 4. 셸 메뉴 표 — 단일 출처

셸 기본 메뉴의 유일한 출처는 데이터 층 `src/xkxk.frameworks.ui.data/Navigation/ShellMenuTable.cs` 다. UI 에 의존하지 않는 순수 데이터이며 항목 1개가 행 1줄이다.

| 행 형식 | 필드 |
|---|---|
| `ShellMenuRow` | Id·Parent·Kind(`ShellMenuRowKind` Command·Submenu·Separator·Section)·CommandId·Param·TitleKey·Icon·AutomationId·Section·VisibleWhen·ToolTipWhen·Mobile |
| `ShellMenuMobileRow` | InDrawer·Available·ReasonKey·EntryId·TitleKey·CommandId·Param·TabOrder·TabKey·TabIcon·Covers |

- 줄마다 `AutomationId` 를 문자열 리터럴로 적어 판정기가 정적으로 읽는다.
- `VisibleWhen`·`ToolTipWhen` 은 조건 키 문자열이다. 표시 조건 키는 bench·gpuRestartPending·logTool·desktopWindow·monitors·noMonitors 이고, 툴팁 키는 snap·singleMonitor·monitorMaximize·resetMain·logFolder 다.
- 실제 대리자는 내부 `ShellDefaultMenus` 가 메인 뷰모델에 연결해 `ShellMenuTable.Rows` 순서대로 `Add` 한다. 앱(메인 뷰모델)이 없으면 표시 조건은 false, 툴팁은 null 이고 예외가 없다.
- 셸 항목의 Owner 는 `xkxk.shell` 이다.
- 메뉴가 쓰는 명령은 셸 기본 명령으로 등록한다. 기존 23개 뒤에 38개를 더해 61개이며 목록과 판단은 a8 §9 에 있다.
- 글자 초기화(`xkxk.view.fontReset`)는 명령 1개로 합치되 경로별 기존 동작을 유지한다. 메뉴가 붙은 TopLevel(데스크톱 메인 창, 웹·Android 단일 뷰의 TopLevel)을 얻을 수 있으면 `SettingsInput.ResetFromMenu(TopLevel)`(Ctrl+0 과 같은 경로)을 타고, 모바일형 화면이거나 TopLevel 을 얻을 수 없을 때만 `SettingsPanel.ResetFontCommand` 를 실행한다(옛 모바일 메뉴가 쓰던 경로라 모바일형에서는 그대로 보존한다). 셸이 없거나 TopLevel 과 메인 뷰모델이 둘 다 없으면 실행할 수 없다.

## 5. 삽입·이동·숨김

| 동작 | 규칙 |
|---|---|
| 삽입 | `InsertAfter`·`InsertBefore` 가 둘 다 있으면 `InsertAfter` 가 우선한다. 둘 다 없으면 부모 아래 맨 뒤다. 같은 부모 아래에 대상이 없으면 맨 뒤에 붙이고 XKUI0404 경고를 남기며 true 다 |
| 부모 | `Parent` 가 없거나 Submenu 종류가 아니면 XKUI0403 이고 등록하지 않는다 |
| 종류 | Command 인데 `CommandId` 없음, Section 인데 `Section` 없음, Separator 에 `CommandId` 같은 조합은 XKUI0406 이고 등록하지 않는다 |
| 명령 연결 | `CommandId` 가 명령 레지스트리에 없으면 항목은 유지하고 비활성으로 보이며 XKUI0405 다. 실행 중 `Add` 는 true 다 |
| 모듈 빌드 | 모듈 메뉴의 XKUI0405 검사는 Build 끝에 한 번 한다. 뒤 모듈이 등록한 명령을 가리켜도 진단이 없다. 끝까지 없으면 Collect 정책은 빌더 진단, Throw 정책은 `UiConfigurationException` 이다 |
| 이동 | `Move` 는 부모·앵커를 바꾸고 Moved 를 낸다. 대상 없음, 자기 자손 아래로 옮기는 순환, 새 부모가 Submenu 가 아니면 XKUI0410 이고 옮기지 않는다 |
| 숨김 | `SetHidden(id, true)` 는 `GetState` 의 `IsVisible` 을 false 로 만들고 VisibilityChanged 를 낸다. false 로 되돌릴 수 있다 |

`Move`·`SetHidden` 은 비파괴라 등록 주체와 무관하게 허용하며 Owner 는 바뀌지 않는다. 숨김과 순서 바꾸기가 본문 §5 메뉴 확장점의 핵심 용도이기 때문이다.

## 6. 표시 상태 — 메뉴를 열 때 평가

표시 조건·툴팁·활성은 `GetState(id, surface)` 로 **메뉴를 열 때** 평가한다. 지금 메뉴도 열 때 툴팁을 갱신하므로 시점이 같다.

| 값 | 계산 |
|---|---|
| IsVisible | 숨김이 아니고 `IsVisible` 대리자가 true. 대리자 예외면 false 이고 XKUI0411 경고(항목·키당 1회) |
| IsEnabled | Command 는 명령 `CanExecute(id, 파라미터)`, Submenu·Section 은 true, 명령이 없으면 false |
| Title | `Title` → `TitleKey` 문구 → 명령 제목 순서의 첫 값 |
| Icon | `Icon` → 명령 `Icon` |
| Gesture | 명령 `Gesture` |
| ToolTip | `ToolTip` 대리자 결과. 예외면 null 이고 XKUI0411 |

- 없는 ID 는 예외 없이 `IsVisible` 이 false 인 빈 상태를 돌려준다.

## 7. 예약 접두어와 등록 정책 P1~P4

a8 §5·§6 의 정책을 메뉴에 그대로 적용한다.

| 번호 | 메뉴 적용 |
|---|---|
| 예약 | 프레임워크 아닌 주체가 아직 없는 `xkxk.*` 메뉴 ID 를 새로 만들면 XKUI0407 이고 등록하지 않는다. 이미 있는 `xkxk.*` 항목의 `Replace=true` 재정의는 허용한다 |
| P1 | `Replace=true` 인데 기존 항목이 없으면 새로 등록하고 Added 를 낸다. 예약 ID 규칙이 우선한다 |
| P2 | `Remove` 는 등록 주체만 한다. 다른 주체의 항목은 XKUI0408 이고 지우지 않는다. 하위 메뉴는 자손 전원이 같은 주체일 때만 자손째 지우고, 다른 주체의 자손이 하나라도 있으면 아무것도 지우지 않는다. `Replace=true` 교체는 주체와 무관하며 Owner 가 교체 주체로 옮겨 간다 |
| P3 | `Replace` 는 `Parent` 가 같으면 제자리를 유지하고, `Parent` 가 다르면 새 부모의 `InsertAfter`·`InsertBefore` 자리로 옮긴다(앵커가 없으면 XKUI0404 와 맨 뒤). 교체한 정의는 숨김이 풀린 상태이고, 자식이 있는 하위 메뉴를 다른 종류로 바꾸면 XKUI0406 이다. 같은 ID 를 `Replace=false` 로 다시 등록하면 XKUI0402 이고 첫 등록이 남는다 |
| P4 | Build 뒤 붙잡아 둔 모듈 레지스트리로 등록하면 실행 중 등록과 같다. 즉시 검사하고 앱 진단에 쌓으며 예외와 `UiErrorPolicy` 는 적용하지 않는다 |

## 9. 화면 구성과 Section

화면 층 `MenuBuilder` 가 레지스트리의 최상위 항목으로 제목줄 `MenuItem` 을 만든다(`MoreMenu` 앞). 메뉴 막대에는 Submenu·Command 종류만 그리고, 구분선·Section·모르는 종류의 최상위는 그리지 않는다.

- 자식과 Section 칸은 최상위를 만들 때 **동시에 전부 만든다**. 지연 생성하지 않는다. 원격 `menu.list`·`menu.icons` 와 `shell.mnu*` 를 쓰는 기존 UIA·웹 시험이 닫힌 메뉴의 자식을 읽기 때문이다.
- 메뉴를 열 때는 항목을 새로 만들지 않고 `GetState` 로 보임·활성·제목·툴팁·단축키 표시·아이콘만 다시 맞춘다. 구분선은 Avalonia `Separator`(자동화 이름 없음)이며 표시 조건(`desktopWindow` 등)만 같은 방식으로 맞춘다.
- Section 칸은 `GetState` 대상이 아니다. 최상위가 열리면 `MenuBuilder` 가 열린 창 목록·사유 툴팁을 새로 계산하고 `GetState` 를 맞춘 뒤 `ShellMenuSections.RefreshOnOpen` 을 부른다. 섹션 갱신(스냅 칸 활성, 켜진 배치 0개면 하위 메뉴 숨김, 열린 창 ✓)이 마지막에 덮는다. 섹션은 화면에 붙을 때도 사유 툴팁을 Background 로 다시 계산한다. 열린 창 칸과 모니터 항목 값은 바인딩 대신 `PropertyChanged` 구독과 `ContainerPrepared` 로 옮기며(리플렉션 바인딩 트리밍 경고 회피), 구독은 논리 트리에 붙어 있는 동안만 유지한다.
- `Changed` 가 오면 UI 스레드에 한 번으로 모아 해당 최상위만 다시 만들고(모르는 변경 종류는 전체), 제목줄의 좁은 폭 재배치 순서를 갱신한다.
- 항목 실행은 `RegistryMenuCommand`(ICommand)가 `Dispatcher.UIThread.Post` 로 `XkxkUi.Current.Commands.Execute(id, 파라미터)` 를 불러 메뉴가 닫힌 뒤에 한다. 명령의 실행 가능 여부 변경 알림은 없어 메뉴를 열 때 다시 묻는다. `xkxk.view.fontReset` 의 단축키 표시는 플랫폼 명령 수정키(macOS 는 Cmd)로 바꿔 보인다.
- 4메뉴의 axaml·코드 비하인드 8파일은 삭제한다. 코드 비하인드에만 있던 동작은 명령(종료·글자 초기화·다음 테마)과 섹션 훅(스냅·열린 창·툴팁 갱신)으로 옮긴다.

동적 영역은 Section 항목과 화면의 채우기 표(`ShellMenuSections`)로 그린다. 셸 섹션은 3종이다.

| `ShellMenuIds` 상수 | 키 | 내용 | 자동화 이름 |
|---|---|---|---|
| SectionSnap | `xkxk.window.snap` | 스냅 배치 6종의 칸 | `shell.mnuWinSnap*` |
| SectionMonitors | `xkxk.window.monitor.list` | 모니터 라디오 목록과 없음 안내 | `shell.mnuWinMultiMonitor`·`shell.mnuWinMonitorNone` |
| SectionOpenWindows | `xkxk.window.openList` | 열린 창 칸 1~9 와 더 보기 | `shell.mnuWinList1`~`9`·`shell.mnuWinListMore` |

- 스냅 칸은 하위 메뉴 `xkxk.window.snap` 안의 섹션 행 `xkxk.window.snap.cells` 가 21칸(배치 종류 6개와 칸 15개)을 채우고, 켜진 배치가 0개면 섹션 갱신이 하위 메뉴를 숨긴다. 모니터 섹션은 하위 메뉴 `xkxk.window.monitor` 안에서 모니터 목록 하위 메뉴와 없음 안내를 만들며 모니터 유무 조건은 섹션이 판정한다. 열린 창 섹션은 앞의 조건부 구분선까지 직접 그린다(표에 구분선 행이 없다).
- 소비자가 자기 Section 키를 쓰려면 그 키를 채우는 화면이 필요하다. 모르는 키는 XKUI0409 다.

## 10. 모바일 투영과 NavMenuCatalog 파생

- `NavMenuCatalog.Entries` 는 `ShellMenuTable` 에서 파생하고 자체 행 목록은 지운다. 기존 공개 멤버는 유지하고 상태 함수를 받는 `ToJson` 오버로드와 `NavGroup.Custom` 값을 더한다. 이 목록은 셸 기본 메뉴만의 정적 덤프다.
- 실행 중 소비자 항목까지 포함한 모바일 목록은 셸 내부 `MobileMenuProjection` 이 레지스트리에서 만든다. 모바일 뷰모델·투어·원격 진단이 이 목록을 쓴다. 모바일 뷰모델은 메뉴 `Changed` 때 서랍과 하단 탭(`TabOrder` 0 이상 항목을 순서대로, 끝에 '더보기')을 다시 만들고, 명령 `Changed` 때 활성 상태를 다시 맞춘다. 탭을 눌러도 같은 레지스트리 명령을 실행하며, `TabTitleKey` 가 없으면 항목 문구를, `TabIcon` 이 없으면 더보기 아이콘을 쓴다.
- 모바일 항목 ID 는 `Mobile.EntryId` 이고, 없으면 `AutomationId` 가 `shell.mnu` 로 시작할 때 그 뒤 이름, 아니면 메뉴 ID 다.
- 소비자 항목도 셸 항목과 같은 규칙으로 서랍에 넣는다. 레지스트리 순서대로 트리를 전위 순회해 `Mobile.InDrawer` 항목만 바꾸며, 구분선·Section 은 `EntryId` 가 있을 때만 항목이 된다. 모르는 `Kind` 값은 그 하위까지 그리지 않는다.
- `SetHidden(true)` 인 항목은 그 하위까지 서랍에서 뺀다. 반면 `Mobile.InDrawer=false` 는 그 항목만 빼고 자식은 계속 순회한다.
- 최상위 `xkxk.file`·`xkxk.window`·`xkxk.view`·`xkxk.system` 아래 항목은 `NavGroup` File·Window·View·System 이고, 그 밖의 최상위 아래는 Custom 이다. Custom 묶음은 별도 머리글을 만들지 않으며 소비자 최상위 항목이 깊이 0 줄(하위 메뉴면 그룹 제목, 명령이면 실행 줄)이다. 순서는 레지스트리 순서라 기본으로는 셸 4메뉴 뒤다.
- 문구는 `Mobile.TitleKey` → `TitleKey` → `Title` → `GetState(id, Mobile).Title` → 메뉴 ID 순서의 첫 값이다.
- 실행 명령은 `Mobile.CommandId` 가 있으면 그것, 없으면 `CommandId` 다. 파라미터도 모바일 명령이 있으면 모바일 값만 쓰며, 원래 객체를 그대로 넘긴다. `xkxk.nav.openPanel` 이 아니면 실행 뒤 서랍을 닫는다. 이 명령은 모바일 뷰모델이 `NavPanelOpener` 에 건 대리자로 실행된다(menu·explorer·docs 는 서랍 패널, notify 는 알림, settings 는 설정 시트).
- `Mobile.Available=false` 는 서랍에 비활성과 사유(`UnavailableReasonKey`, 없으면 `nav.reason.pcTablet`)로 보인다.
- 표시 조건이 false 인 항목(벤치 없음·재시작 필요 없음 등)은 숨기지 않고 지금처럼 비활성과 `nav.reason.unavailable` 로 보인다.
- 셸 소유 항목(Owner `xkxk.shell`)은 기준 커밋처럼 명령 `CanExecute` 로 막지 않는다. 그 밖의 소유 항목(소비자, 셸 항목을 `Replace` 한 경우 포함)은 `CanExecute` 가 false 면 비활성과 `nav.reason.unavailable` 이다. 하위 메뉴 제목 줄은 표시 조건이 참이면 활성이다.
- 기본 상태의 원격 `nav.menu` JSON(하단 탭, 서랍의 id·활성·사유·대응 AutomationId)은 기준 커밋과 같아야 한다(계획 시점 서랍 행 63개).

## 11. 소비자 단축키 연결

B06 은 단축키를 메타데이터와 문법 검사까지만 두었다. B07 은 **소비자 명령만** 실제 키에 연결한다.

- 화면 층 `RegistryGestureInput` 이 `MainView` 가 속한 TopLevel 하나(`OnLoaded` 에 붙이고 `OnUnloaded` 에 뗌, 독립 SDI 창에는 붙이지 않음)의 아직 처리되지 않은 `KeyDown` 에서, Owner 가 `xkxk.` 로 시작하지 않는 명령 중 `Gesture` 가 맞고 지금 실행할 수 있는 첫 명령을 파라미터 없이 실행하고 처리 표시를 한다. 맞지만 `CanExecute` 가 false 인 명령은 건너뛰며, 실행할 수 있는 것이 없으면 처리 표시를 하지 않는다. 형식이 틀린 단축키는 조용히 건너뛴다(등록 때 XKUI0305 로 알림).
- 셸 기본 단축키는 기존 경로(`ShortcutBindings`·`WindowKeyGestures`) 그대로라 동작이 바뀌지 않는다. `xkxk.layout.save` 의 `Gesture` 는 메뉴 표시와 같게 `Ctrl+S` 로 적지만 키 처리 경로는 기존 그대로다.
- 프레임워크 아닌 주체가 `Add`·`Replace` 한 명령의 `Gesture` 가 정규화(수정자 Ctrl·Shift·Alt·Meta 순서 + 키) 비교에서 기존 명령과 같으면 XKUI0310 경고를 남기고 등록은 한다. 문법 무효(XKUI0305)를 먼저 보고 유효할 때만 충돌을 검사한다.
- 겹치면 등록 순서상 먼저이면서 실행할 수 있는 쪽이 키를 받는다. 셸 기본 단축키와 겹치면 셸 경로가 먼저 처리해 소비자 명령은 그 키를 받지 못한다.

## 13. 한계

- (a) 표시 조건은 열 때 평가한다. 열린 채로 있는 메뉴에서 바뀐 상태는 다음 열기 때 반영되며, 옛 `IsVisible` 바인딩보다 늦을 수 있다.
- (b) 레지스트리는 프로세스 전역이고 리셋이 없다(B04·B06 한계와 같다). 계약 시험은 시험마다 고유 ID 를 쓴다.
- (c) `NavEntry.Command` 의 값은 옛 모바일 명령 문자열(`Open`·`Panel` 등)에서 레지스트리 명령 ID 로 **의미가 바뀐다**. 데이터 층이라 공개 API 고정 대상은 아니지만 옛 문자열에 의존한 코드는 깨진다.
- (d) 메뉴를 axaml 컴파일 대신 코드로 만들어 구성 시간이 늘 수 있다. 측정은 B08 이다. 측정 수단은 B08 의 `ui.menu.build`(구성·재구성)·`ui.menu.refresh`(최상위 열림 갱신)·`ui.menu.open.firstframe`(원격 열기 명령 → 팝업 첫 프레임)이고 정의는 부록 a3 §7.1 이다. 열기 지표는 실입력 클릭 지연을 포함하지 않는다.
- (e) 셸 기본 단축키와 같은 `Gesture` 를 쓴 소비자 명령은 그 키를 받지 못한다(XKUI0310 으로 알린다).
- (f) 소비자 단축키는 `MainView` 가 속한 TopLevel 에서만 연결한다. 독립(SDI) 창 등 별도 창에서의 동작은 이 batch 범위가 아니다.
- (g) 모바일 서랍의 소비자 항목·숨김 규칙은 §10 이다. `SetHidden` 은 하위까지 빼지만 `Mobile.InDrawer=false` 는 자식을 빼지 않으므로, 하위 메뉴를 통째로 서랍에서 빼려면 `SetHidden` 을 쓰거나 자식마다 `InDrawer=false` 를 준다. `SetHidden` 은 데스크톱 메뉴에서도 숨기므로 모바일에서만 하위 묶음을 한 번에 빼는 수단은 아직 없다.
- (h) `ShellMenuIds` 는 구분선·섹션 상수까지 공개하므로 셸 메뉴 구성의 ID 를 유지해야 하는 부담이 생긴다.
- (i) 확대·축소 메뉴 항목과 명령은 만들지 않는다. 데모 문서 열기 2개 명령은 셸의 임시 등록이며 B10 에서 같은 ID 로 시험대 모듈에 옮긴다.
- (j) 도움말 투어의 메뉴 줄은 깊이 0 항목마다 같은 `NavGroup` 의 하위를 모은다. 그래서 Custom 최상위가 둘 이상이면 각 Custom 줄에 모든 Custom 하위가 섞인다. 같은 묶음에 하위가 하나도 없으면 그 최상위는 투어 줄을 만들지 않는다.
- (k) 원격 `nav.menu` 의 목록은 투영 목록이지만 `enabled`·`reason` 은 지금처럼 `Applicable` 기준(정적)이다. 런타임 판정이 반영된 덤프는 `MobileNavViewModel.ToJson` 이다.
- (l) 하단 탭의 활성 표시는 탭 ID 가 패널 이름과 맞지 않아 늘 '더보기' 판정을 탄다. 기준 커밋부터 같은 동작이라 이번에 고치지 않았다.

필요해지면 `IUiMenuRegistry` 재평가 요청 멤버, 위치를 이어 쓰는 확장 메서드, 옵션 속성, 열거형 값, Section 키를 추가만으로 연다. 메뉴 매니페스트는 B22 다.
