## 2.4 플랫폼별 창 제어 버튼(닫기·최소화·최대화) 규칙과 Pd 설계값

> 사용자 요청(2026-10-29): "맥이나 아이폰에서 닫기 최대화 최소화 등의 버튼 스타일은 고유 os 스타일을 따라가도록 해달라." 아래 Pd 처리는 그 요청에 따른 자율 판단이다.

| 플랫폼(폼팩터) | OS 규칙(공식 근거) | Pd 처리 |
|---|---|---|
| macOS(데스크톱) | 신호등은 창 왼쪽 위에 닫기·최소화·확대 순서로 놓인다. key 창은 컬러이고, inactive 창과 key 가 아닌 main 창은 회색이다([HIG Windows](https://developer.apple.com/design/human-interface-guidelines/windows)). 초록 버튼은 전체화면이고, 포인터를 올리면 Fill·Arrange 메뉴가 뜨며, Option+클릭은 이전 크기로 돌린다. Cmd+M 은 최소화, Cmd+W 는 닫기다([Mac 사용 설명서 — 창 이동·정렬](https://support.apple.com/guide/mac-help/move-and-arrange-app-windows-mchlp2469/mac), [전체화면](https://support.apple.com/guide/mac-help/use-apps-in-full-screen-mchl9c21d2be/mac)). | 메인 창과 SDI 창은 OS 신호등을 쓰고, 앱이 그린 캡션은 숨긴다. MDI 내부 창만 신호등을 닮게 직접 그린다. 창 스타일의 기본과 선택은 09/01 §4.2 를 따른다. |
| iOS(모바일 = iPhone) | 앱 창 크롬이 없다. | 스마트폰 NAV 에는 최소화·최대화가 원래 없고 닫기(×)만 있다. 바꾸지 않는다. |
| iOS(태블릿 = iPad) | 창 모드에서는 시스템이 툴바 앞쪽에 window controls 를 그린다. 앱은 겹치지 않게 피해야 한다(HIG). 스타일은 `preferredWindowingControlStyle(for:)`(iPadOS 26.0+)로 고른다([UIKit 문서](https://developer.apple.com/documentation/uikit/uiwindowscenedelegate/preferredwindowingcontrolstyle(for:))). | 태블릿의 MDI 내부 창은 macOS 스타일이다. 시스템 컨트롤과 겹치는지는 미확인이다(iOS 헤드 없음). |
| Android | 일반 화면에는 창 컨트롤이 없다. 데스크톱 창 모드에서는 시스템이 caption bar 를 항상 그리고, 앱은 `captionBar` inset 을 피한다([edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge)). 버튼 배치·순서는 미확인이다. | MDI 내부 창은 Windows 스타일을 유지한다. |
| 웹 | 페이지는 브라우저 창 크롬을 바꿀 수 없다. | 브라우저가 도는 OS 를 navigator(userAgentData.platform → platform)로 판별한다. Mac·iPhone·iPad 면 macOS 스타일, 판별에 실패하면 Windows 스타일이다. |
| Windows | §1 | §1 을 따른다. |

- **HIG 와 부딪치는 점과 예외 이유.** HIG 는 "Avoid creating custom window UI … don't try to replicate the system-provided appearance"라고 권고한다(사용자 정의 창 UI 를 만들지 말고 시스템 외형을 흉내 내지 말라). 그래서 OS 가 그릴 수 있는 최상위 창(메인·SDI)은 OS 신호등을 쓴다. MDI 내부 창은 OS 창이 아니라 앱 화면 안의 요소여서 OS 가 신호등을 그려 줄 수 없다. 사용자 요청(고유 OS 스타일)을 지키려면 직접 그릴 수밖에 없으므로 이것만 예외로 둔다. Apple 아이콘 자산은 쓰지 않고 벡터로 직접 그린다.
- **Avalonia 근거.** Avalonia 12.1.4 macOS 백엔드는 `WindowDecorations=Full` 일 때만 신호등을 보인다(`hasTrafficLights = (_decorations == SystemDecorationsFull)`, [WindowImpl.mm](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/12.1.4/native/Avalonia.Native/src/OSX/WindowImpl.mm)). 메인 창(Full + 확장 제목줄)은 신호등이 제목줄 위에 겹치고, SDI(BorderOnly)는 신호등이 숨는다. 그래서 macOS 에서는 SDI 를 Full 로 바꾼다. 실기 동작은 Mac 장비가 없어 미검증이다.
- **Pd 설계값(공식값 아님, Mac 실기 미검증).** 신호등 지름 12px, 간격 8px(중심 간 20px), 제목줄 28px, 왼쪽 8px, 창 모서리 10px, 네이티브 신호등 자리 78px(2차 출처: Zed 편집기 소스), 색 #FF5F57·#FEBC2E·#28C840, 비활성 #CDCDCD 가 여기에 해당한다. 코드는 `Docking/CaptionLayout.cs`·`Docking/ChromePlatform.cs`·`Themes/MacCaptionResources.axaml` 이다.

## 2.5 Mars 실행 화면 실측과 클래식 스타일

- Mars MDI 창의 입체감은 그림자가 아니라 **명암 3단 계단**(MDI 배경 #778899 → 진한 띠 #40568D → 흰 본문)에서 나온다. 그림자·베벨·그라데이션은 없다. 근거는 판정보고서 부록 `04_판정보고서_부록/a8_Mars실측_3.3_3.6.md` §3.3.1 과 `poc/ui/logs/odev1/mars_capture/`(저장소 미수록, 근거 수준 미확인)다.
- 이 띠 구조는 클래식 스타일의 모양이다. 기본 창 스타일은 Windows 11 이다(09/01 §4.2). Windows·macOS 스타일은 둥근 모서리와 약한 그림자(§1 의 OS 기준)를 쓴다.
- 창 스타일 표시명은 **'클래식'(영문 Classic)** 이다(사용자 요청 2026-11-01, 옛 이름 'Mars 클래식'). 내부 값 `ChromeStyleKind.MarsClassic` 과 저장값은 바꾸지 않는다.

## 2.6 문서 창 버튼 아이콘·상태 표시·간격 Pd 설계값

> 사용자 요청(2026-11-01): "창 버튼이 선택되었을 때 배경색 대신 아이콘색을 변경하라. 최소화 버튼의 _ 가 상단에 붙어 있다", "창 버튼들의 텍스트 글리프를 의미에 맞는 아이콘으로 대체하라", "캡션 버튼 간 거리가 너무 넓다. Windows 11 만 유독 넓다". 적용 범위는 MDI·SDI 문서 창이다. 메인 창 제목줄은 표면색 위라 바탕 반응을 쓴다.

| 항목 | Pd 설계값 | 근거 |
|---|---|---|
| 아이콘 | 모든 문서 창 버튼 기호는 Pd 가 직접 그린 벡터(`Themes/ChromeIcons.axaml`)다. 캡션 3버튼은 10×10 격자(최소화 = 아래 1px 막대, 최대화·복원 = 모서리 1.5 둥근 사각 외곽선, 닫기 = 두께 약 1px ×), 기능 버튼은 16×16 격자(항상 위 = 비스듬한 압정, 위치 고정 = 세운 압정 외곽선/채움, MDI·SDI, 동기화 고리/끊긴 고리, 중복 허용 자물쇠 잠김/열림, 새로고침 두 화살표, 도움말 원 안 물음표, 도구 메뉴 꺾쇠, 문서, 알림 종, 도킹, 분리)다. | 기호 위치 | 모든 기호 경로에 격자 두 모서리 점(면적이 0 에 가까운 삼각형)을 넣는다. Avalonia `Path`·`PathIcon` 의 `Stretch=Uniform` 은 기호의 실제 범위를 기준으로 늘리고 왼쪽 위에 붙인다. 격자 전체를 범위로 만들면 최소화 막대는 격자 맨 아래(기준선)에 오고, 기호마다 배율이 달라지지 않는다. | 사용자 요청 |

## 2.7 MDI 자식 창 제목줄 아이콘과 제목 여백 조사와 Pd 설계값

> 사용자 요청(2026-11-01): "창타이틀 로고는 SDI 일 때만 보여라. MDI 일 때는 다른 애플리케이션의 가장 흔한 사례로 처리하라."

- **Win32 MDI(가장 널리 쓰인 MDI 구현).** MDI 자식 창은 자기 제목줄에 **창 메뉴 아이콘**을 가진다. 자식 창을 최대화하면 시스템이 자식 제목줄을 숨기고, 자식의 창 메뉴 아이콘과 복원 버튼을 프레임 메뉴줄로 옮긴다([About the Multiple Document Interface — Microsoft Learn](https://learn.microsoft.com/en-ie/Windows/Win32/winmsg/about-the-multiple-document-interface), [WM_MDIMAXIMIZE — Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-mdimaximize)). MFC 도 `CMDIChildWndEx::GetFrameIcon` 으로 MDI 자식 창 아이콘을 따로 얻는다([MFC CMDIChildWndEx — Microsoft Learn](https://learn.microsoft.com/en-us/previous-versions/visualstudio/visual-studio-2008/bb983560(v=vs.90))).
- **확인한 범위와 한계.** 위 문서는 자식 창이 "자기 창 메뉴 아이콘"을 가진다는 점까지 확인된다. 그 아이콘이 앱 로고인지 문서 종류 아이콘인지는 자식 창 클래스가 정한다(MDICREATESTRUCT 에는 아이콘 칸이 없고 창 클래스 아이콘을 쓴다는 점은 1차 문서로 확인하지 못했다 — 추정). WinForms 탭 MDI 라이브러리(DevExpress `UseFormIconAsPageImage`, [DevExpress 문서](https://docs.devexpress.com/WindowsForms/DevExpress.XtraTabbedMdi.XtraTabbedMdiManager.UseFormIconAsPageImage))도 자식 폼 아이콘을 따로 다룬다. Visual Studio·Photoshop 의 떠 있는 문서 창 제목줄 아이콘은 이번 조사에서 1차 출처를 찾지 못했다 — 미확인.
- **Pd 설계값.** 가장 흔한 방식(Win32·MFC MDI)을 따라 MDI 자식 창 제목줄 왼쪽에는 **앱 로고가 아니라 문서 기호**(`PdIconDocument`, 귀퉁이 접힌 문서)를 둔다. 기호를 누르면 창 메뉴가 열리는 동작(§1 제목줄 동작 행 "아이콘 클릭 시 창 메뉴")은 유지한다. **앱 로고는 SDI 창 제목줄에만** 둔다. macOS 스타일은 제목줄 아이콘이 없으므로 그대로 숨긴다.
- **MDI 문서 창 제목 왼쪽 여백.** 앱 로고가 없는 MDI 문서 창의 제목은 왼쪽 여백 **8px** 에서 시작한다. 창 크롬 수치라 이 문서가 정본이고 `../09_화면설계/03_데스크톱_화면설계.md` §3.1 이 이 값을 가리킨다. 값 분류는 제품 상수다(창 크롬은 테마 요소별 사용자 지정 대상이 아니다, D-351).

> 사용자 요청(2026-11-01): "창 하단 양쪽 모서리가 라운드인데 내용 부분은 각져 어색하다. 내용 부분도 라운드로 해서 창틀 두께가 항상 같게 하라. 불가능하면 하단 모서리를 각지게 하라." 같은 날 요청: "창의 하단 양쪽 라운드가 어색하다. 창틀이 전체적으로 억지로 입체적으로 만든 느낌이다. 자연스럽게 해달라."

- '미정' 칸은 이 문서가 아직 값을 정하지 않은 자리이고, 코드의 현재 값은 확인하지 않았다(미확인).
- 최대화 창은 모든 스타일에서 모서리 0 이다(§1).
- Windows MDI 는 바깥 층(반경 8, 외곽선 1px) → 안쪽 잘라냄(반경 7) → 제목줄 + 본문(반경 없음)이다. 본문에 따로 반경을 주면 잘라냄 곡선(MDI 7·SDI DWM 8)과 어긋나 제목색 틀 바탕이 초승달로 비친다. 크기 조절은 투명 손잡이(`PdResizeGrips`)와 SDI 의 OS 테두리가 맡아 히트 영역 손실이 없다. 강조 제목줄 색은 제목줄에만 남는다.
- 클래식은 옆 띠(2)와 아래 띠(3)가 달라 원 하나로 정확히 동심을 만들 수 없어(타원 반경이 필요하다) 모서리를 각지게 둔다.
- SDI 는 OS(DWM)가 바깥 모서리를 8 로 둥글리므로 본문에만 같은 규칙을 쓰고, 최대화 SDI 는 0 이다. SDI Windows 스타일의 외곽선은 OS DWM 기본 테두리 1px(frame 가장자리, 모서리 r=8, 활성·비활성 색은 OS 동작)다. 앱의 Dock 문서 본문 테두리(DocumentControl `PART_Border`)는 SDI·Windows 스타일에서 0 이다(`Themes/MdiChrome.axaml` `.pdWinChrome`). 두 선이 겹치면 외곽선이 2px 가 된다. `DWMWA_BORDER_COLOR`=`DWMWA_COLOR_NONE` 으로 DWM 테두리를 끄면 남은 앱 선이 frame 보다 1px 안쪽 직선이라 모서리에서 끊긴다(반경 3.8~4.75)([DWMWINDOWATTRIBUTE — Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)).
- MDI 그림자는 2겹이고 활성 0 4 12 다. 활성 그림자가 비활성보다 진하다.
- 판정보고서(`04_PoC_UI_판정보고서.md` §6.2 UI-10 행)의 결정 값은 2026-10-28 기록이다. 현행 값은 이 문서다. 대조 결과(2026-11-19, PoC 소스 grep)는 다음과 같다. 제목줄 높이(Windows 32px·클래식 23px)와 외곽선 1px 은 이 문서와 같다. 활성 그림자 0 4 16 은 이 문서와 현 PoC 의 2겹 그림자(`ChromeResources.axaml` `PdMdiShadow` — 0 1 3, 0 4 12)로 바뀌었다. 활성 외곽선 #22325A 와 비활성 제목 영역 투명도 0.7 은 현 PoC 소스에 없고 이 문서도 값을 정하지 않았다(미정, 색은 테마 토큰이 정한다).
- 내용 잘라냄은 `Views/ClipBorder.cs` 가 `ClipToBounds` 로 한다. Avalonia 12.x `Border` 의 `ClipToBounds` 는 모서리 반경을 따른다(`CompositionBorderVisual` 이 `CornerRadius` 를 보고 둥근 사각형 클립 `ClipRoundRect` 를 건다). 확인 수준은 Avalonia 12.1.4 디컴파일과 캡처 육안 확인이다(실측).
- 최소 크기는 `PdChromeFramePadding` 을 읽어 계산한다(§2.9).

- **창 폭이 모자랄 때.** 문서 창 제목줄은 **기능 버튼 → 제목(최소 칸까지)** 순서로 잘리고, 캡션 3버튼(최소·최대·닫기)은 항상 보인다(MDI·SDI 같은 규칙, 자율 판단). 제목 최소 칸은 WindowMinSize 의 제목 항("W…" 측정 + 8, `PdTitleMinReserve`)이다. 최소 폭에서도 제목 자리가 남아 그 자리를 더블클릭하면 최대화된다. MDI 는 캡션 3버튼(도구 창이면 도구 버튼)을 머리줄 끝에 겹쳐 고정하고, 나머지 줄(로고·제목·기능 버튼)은 캡션 폭(`PdCaptionReserve` — Windows 108·클래식 54·macOS 왼쪽 68px)만큼 비운 뒤 잘라낸다. 기능 버튼 줄은 제목 최소 칸 오른쪽 자리에만 놓이고 머리줄 바탕으로 제목 글자를 가린다(`Themes/MdiDocumentWindowTheme.axaml`, `Docking/CaptionLayout.cs`). Grid 의 `*` 칸에 함께 두는 방식은 MDI 창이 폭 제한 없이 측정된 뒤 좁게 배치되어 `*` 칸이 줄지 않으므로 쓰지 않는다. SDI 제목줄도 같은 규칙이다(`Views/SdiTitleBar.axaml`).
- **최소 크기.** MDI·SDI 는 같은 계산값을 쓴다(`Docking/WindowMinSize.cs` → 앱 리소스 `PdWindowMinWidth`·`PdWindowMinHeight`, MDI 는 문서 MinWidth/MinHeight, SDI 는 `Themes/SdiHostWindowTheme.axaml` 창 MinWidth/MinHeight).
  - 폭 = 캡션 3 × (버튼 폭 + 좌우 여백) + 캡션 묶음 여백 + 로고 칸(보일 때) + 제목 최소 폭("W…" 측정 + 8) + 틀 좌우 여백
  - 높이 = 제목줄 높이 + 틀 위아래 여백
  - 근거: Windows 최소 추적 크기(SM_CXMINTRACK·SM_CYMINTRACK)를 "제목줄 버튼·아이콘·제목 몇 글자가 보이는 크기"로 두는 관례([GetSystemMetrics — Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getsystemmetrics)). 크롬 스타일·글자 크기가 바뀌면 다시 계산한다.
  - 실측(2026-11-01): Windows 스타일 MDI 최소 = 198×35(산식 캡션 108 + 로고 48 + 제목 32 + MDI 고정 6 + 틀 4), SDI 1×1 요청 뒤 = 198×42 에서 멈춘다. 이 값은 액자 띠를 0 으로 바꾸기 전 값이고, 지금 Windows 최소 크기는 폭 4px·높이 3px 작다(계산, 미측정). 클래식 스타일은 미측정이다. 근거 `poc/ui/logs/odev_c2/ux/web_check.md`·`poc/ui/logs/odev_c2/chrome/desk_extra_criteria.md`(저장소 미수록, 근거 수준 미확인).
- Apple HIG [Windows](https://developer.apple.com/design/human-interface-guidelines/windows) 는 스크립트로 그리는 페이지라 이번 조사에서 본문 인용을 확보하지 못했다. 그래서 Apple 지원 문서(위 1·7행)로 대신했다.

## 2.10 SDI 창 그림자 DWM/Win32 분석

> 요구는 모든 창에 hairline 과 그림자가 있고 활성 창이 더 진한 것이다(§1·§3, 판정보고서 `04_PoC_UI_판정보고서.md` §6.2). 활성·비활성 그림자 차이의 수치는 공식 문서에 없어 Win11 메모장 실측을 기준으로 삼았다. SDI 그림자의 활성 구분은 아직 해결하지 않았고 아래 선택지를 남은 과제로 둔다.

같은 조건(같은 바탕, 창 500×300, 위치 400,160, CopyFromScreen)에서 잰 결과다. 지표는 창 바깥 16px 밝기 감소 합(왼쪽/아래쪽)과 바깥 1px 대 30px 채널 차다.

| 대상 | style / exStyle | 활성 | 비활성 | 바깥 1px 차(활성/비활성) |
|---|---|---|---|---|
| Win11 메모장 | 0x14CF0000(CAPTION·SYSMENU 포함) / 0x110 | 440.1 / 481.4 | 239.3 / 324.2 | 50 / 36 |
| Pd SDI 기준 | 0x16870000(BORDER·THICKFRAME·MIN·MAX·CLIP*) / 0x00240100 | 111.5 / 162.1 | 111.5 / 162.1(같음) | 16 / 16 |
| DwmExtendFrameIntoClientArea 사방 1px + DWMWA_BORDER_COLOR 활성별 | 같음 | 111.5 / 162.1 | 같음 | 효과 없음 |
| 확장 없음(zero)·아래 1px+정책(bottom1,ncr) | 같음 | 111.5 / 162.1 | 같음 | 효과 없음 |
| WS_SYSMENU 단독(sys) | 0x168F0000 | 111.5 / 162.1 | 같음 | 16 |
| WS_DLGFRAME 추가(cap) 계열 4종 | 0x16C70000·0x16CF0000 | **0.0 / 0.0** | 0.0 / 0.0 | 그림자·투명 테두리 소멸, DWM frame = window |
| 투명 여백 + 앱 그림자 시험 구현(PD_SDI_SHADOW=app) | 투명 힌트 | 여백 16px 가 흰색 255, DWM 그림자 그대로라 2중 | 앱 그림자 차 미세(223 대 234) | — |

- Pd SDI 는 WS_DLGFRAME·WS_SYSMENU 가 없다. 메모장은 둘 다 있다. 기준 창은 DWM frame 이 창보다 사방 약 7px 작다(window 500×300, frame 486×293). 이 보이지 않는 크기 조절 테두리 안팎에 DWM 기본 그림자가 걸린다.
- **cap(DLGFRAME)을 켜면 그림자가 0 이 된다.** WS_CAPTION 이 Avalonia 확장 클라이언트(WM_NCCALCSIZE 로 클라이언트가 창 전체)와 맞물려 DWM 이 프레임과 그림자를 모두 그리지 않는 것으로 보인다. 이 해석은 추정이다(비공식 근거 window_manager PR #110·rossy/borderless-window, 공식 문서 미확인).
- DWMWA_BORDER_COLOR 는 로그상 활성별로 바뀌었다(#7A9BDD/#6C6C6C). 그러나 그림자와 1px 차는 그대로였다. 공식 문서는 테두리 색 갱신이 앱 책임이라고만 적고, 활성별 그림자 조건은 적지 않는다([DWMWINDOWATTRIBUTE — Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute), [Custom Window Frame — Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe)).
- 원인 추정은 다음과 같다(공식 문서 미확인). SDI 는 WindowDecorations=BorderOnly + ExtendClientAreaToDecorations 라 WS_DLGFRAME 이 없고, DWM 은 이런 창에 활성 구분 없는 고정 약한 그림자를 그린다.
- 시험 구현의 흰 여백은 Avalonia 시각 트리의 모든 레이어가 Transparent 인데도 생겼다. 그래서 Win32 합성 표면(WS_EX_NOREDIRECTIONBITMAP 창의 스왑체인 알파) 쪽 문제로 추정한다(미확인). Avalonia 문서는 Windows 에서 모든 TransparencyLevelHint 를 지원한다고 적는다([Window management — Avalonia Docs](https://docs.avaloniaui.net/docs/app-development/window-management)). 시험 구현 코드는 제품 코드에 남기지 않았다.
- 남은 선택지는 셋이다(TODO-627). 첫째는 투명 합성 경로를 규명하고 WS_THICKFRAME 을 빼 앱이 크기 조절을 맡는 앱 그림자 방식이다(자석·화면 안 보정·레이아웃 좌표 마이그레이션·시험 도구 기대값 갱신이 따라온다). 둘째는 SDI 를 OS 크롬(Full)으로 두어 OS 가 활성별 그림자를 그리게 하는 방식이다(제목줄 통일과 충돌해 결정이 필요하다, §3 마지막 항). 셋째는 현 상태 유지다.

## 3. Pd 시사점 (설계값 — 위 공식 값에서 끌어낸 것)

- "완성도"의 공통 요소는 다음과 같다. 둥근 모서리(8px, 최대화 시 0), **1px 얇은 외곽선**, 고도에 맞는 **크고 부드러운 그림자**, 비활성 창의 **반투명·회색 처리**, 표준 캡션 아이콘과 상태별 반응, 제목줄의 OS 표준 동작(끌기·더블클릭·우클릭 메뉴)이다. 굵은 베벨이나 두꺼운 다층 테두리는 두 OS 어디에도 없다.
- 따라서 UI-10 의 "3px 베벨·그라데이션" 방향은 사용자 정정(23:25)에 맞지 않는다. 현대 OS 스타일로 한다. 다만 그림자 픽셀 값(오프셋·블러·투명도)과 닫기 hover 빨강, 캡션 버튼 크기, 맥 수치는 공식 문서에 없으므로 Pd 가 실제 OS 화면을 기준으로 정하는 설계값이 된다.
- 제목줄 높이는 스타일별로 정했다(자율 판단, 2026-10-28). Windows 스타일(기본)은 Win11 표준 32px, 클래식은 23px, macOS 는 28px 다(판정보고서 §6.2).
- 위 높이는 문서 창·SDI 창 제목줄(OS 창 크롬) 기준이다. 메인 창 안의 제목 줄(`shell.titleStrip`)과 제목 탭 높이는 이 문서 값이 아니라 화면 설계 공통원칙(`../09_화면설계/01_화면설계_공통원칙.md`) §2-1 이 정본이다.
- 미확인 값(그림자 오프셋·블러·투명도, 테두리 기본 색, 비활성 투명도, 캡션 버튼 크기, 닫기 빨강 등)은 Pd 설계값으로 정하고, Win11 실제 창 캡처와 비교해 조정한다.
- 문서 창은 MDI 안의 창이라 OS 최상위 창이 아니다. 위 값은 Pd 가 Avalonia 로 직접 그릴 때의 기준이며, SDI(OS 최상위 창)는 OS 크롬을 그대로 쓰는 선택지도 있다.
