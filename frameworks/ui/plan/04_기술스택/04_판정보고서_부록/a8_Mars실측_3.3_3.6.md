## 3.3.1 UI-10 Mars 실행 화면 실측 — 입체감 원인 판정 (2026-10-28 23:52)

사용자 질문(23:48) "mars가 더 입체적이고 깔끔한 느낌이다. 더 돌출되어 튀어나온 느낌인데 그림자 때문일까?"에 답하려고, 왼쪽 모니터에서 실행 중인 Mars 를 읽기 전용(PrintWindow·화면 복사, 이동·포커스 없음)으로 캡처했다. 증거는 `poc/ui/logs/odev1/mars_capture/`(원본 PNG, 8배 확대, 분석 `mars_palette_analysis.md`)다.

- 활성 MDI 자식의 네 변을 각 3곳에서 1px 단위로 잰 단면이 모두 같다. 바깥부터 MDI 배경 #778899 → 외곽선 1px #7988AF → 여백 띠 #40568D(좌·우 2px, 아래 3px) → 흰 본문이다.
- **그림자 없음**(창 바깥 11~15px 가 배경색 그대로), 베벨·이중선 없음, 제목줄 그라데이션 없음, 안쪽 경계선 없음, 모서리 직각이다. 합격기준 문서 §4.1 의 캡처 이미지 측정이 실행 화면에서도 재확인됐다.
- **판정: 입체감의 원인은 그림자가 아니라 명암 3단 계단이다.** 중간 톤 MDI 배경(#778899, 상대 휘도 0.24) → 진한 액자 띠(#40568D, 0.10) → 흰 본문(1.0)이고, 대비비는 본문:띠 7.2, 띠:배경 2.0 이다. 외곽선 #7988AF 는 배경과 대비 1.03 이라 거의 보이지 않는다.

PD 결정(리드, 2026-10-28)은 다음과 같다.
- PD 는 **Mars 의 띠 구조(중간 톤 MDI 배경 + 진한 액자 띠 + 흰 본문)를 기본**으로 쓴다. 라이트 기본 테마 색은 Mars 실측 팔레트(`mars_palette_analysis.md` §4)를 따른다.
- **둥근 모서리와 약한 그림자는 강화분**으로 둔다(Mars 에는 없다, `05_창크롬_OS디자인_기준.md` 참조). 그림자는 명암 계단을 대신하지 않고 보탠다.

3. 그 위치에서 창이 어느 작업 영역과도 100×100(창이 더 작으면 창 크기) 이상 겹치지 않으면 첫 작업 영역 가운데로 보정하고, 보정한 위치에도 2번을 다시 적용한다.
4. 크기는 바꾸지 않으며, 정한 좌상단을 차지한 자리로 등록한다.
5. 웹은 위 결과 (xf, yf) 에 x=min(xf, W−w), y=min(yf, H−h), 최소 0 을 더 적용한다(W×H 는 창 레이어 크기). 당긴 뒤 창끼리 좌상단이 같으면 FAIL 이다. 데스크톱은 1~4 그대로 판정한다.
