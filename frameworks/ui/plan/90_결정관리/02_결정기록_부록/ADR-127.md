# ADR-127 — 결정 143 디자인 효과 강화

> 작성 2026-11-22 · 상태 기록(결정 143)
> 근거 요구는 REQ-112(창 움직임 효과·배경)·REQ-113(메뉴 아이콘·제목 탭 표시·제목줄 즐겨찾기)·REQ-114(불러오는 중 스피너)·REQ-115(작업 표시줄 앱 아이콘)·REQ-116(효과 단계)이고 사용자 원문 정본은 `../../00_요구사항/01c_사용자요구사항_원문_4.md` §3-0y 다. D 행은 `../01_결정대기_부록/d569_결정143.md`(D-569~D-597)에 있고, D 의 상태와 권장안·대안·되돌리기는 그 부록이 정본이다(D-498). 이 기록은 D 번호만 적는다.
> 표기 규칙은 ADR-126 과 같다. 사용자 원문은 `사용자 원문`, 검사기·판정기·측정으로 잰 결과는 `실측`, 이름·열·경로·키·수치처럼 아직 정하지 않은 것은 `후보` 다.

## 1. 맥락

- 결정 134(ADR-118)가 색 테마와 직교하는 디자인 테마 축을 두었다. 열기 효과는 3D 묶음 키 `depth.open`(tilt) 하나뿐이었고 배경 장식은 세 가지, 창 아이콘은 고정 문서 글리프였다(실측, 코드 탐색).
- 2026-11-22 사용자가 애니메이션(창 열기·Ctrl+Tab·제목 탭 전환)·배경 확장과 사용자 이미지·메뉴 아이콘과 탭 표시 방식·제목줄 즐겨찾기를 요구했다(사용자 원문 y1). 이어 창 콘텐츠를 불러오는 동안 창 아이콘을 스피너로(y2), Windows 작업 표시줄 아이콘 미표시 해결(y3), 끌기 중 그림자 옵션화(y4), 효과(부하) 높음·중간·낮음 단계(y5)를 더했다.
- 탐색 결과 기존 진행 표시는 UI 스레드가 막히면 보이지 않아 창 아이콘 스피너의 근거로 쓸 수 없었다. 앱 실행 파일 아이콘(`pd.ico`)은 15개 크기가 모두 PNG 항목이고 창 생성 지점 어디에도 창 아이콘 지정이 없었다(실측). 둘 중 어느 쪽이 작업 표시줄 미표시의 원인인지는 미확인이다.

## 2. 결정 (결정 143)

## 3. 대안

효과 구현 방식(143-1)

| 안 | 내용 | 판정 |
|---|---|---|
| A(채택) | 효과를 데이터 표 + 공용 재생기 하나로 둔다 | 효과를 더할 때 표에 행만 더한다. 하드코딩 금지(REQ-99)와 맞는다 |
| B | 효과마다 전용 코드를 둔다 | 효과 수만큼 코드가 늘고 낮춤·중단 규칙이 흩어진다. 기각 |

불러오는 중 상태(143-5)

| 안 | 내용 | 판정 |
|---|---|---|
| A(채택) | 창 단위 계약을 따로 두고 진행 표시는 그 아래 표시 부품으로 남긴다 | 시작·끝 정의가 원문 '100% 로딩완료' 와 맞고 같은 개념을 두 곳에 두지 않는다 |
| B | 기존 진행 표시의 보임 상태를 쓴다 | UI 스레드가 막히면 꺼져 원문과 어긋난다. 기각 |

| 안 | 내용 | 판정 |
|---|---|---|

## 4. 결과

- 좋은 점은 이렇다. 움직임·배경·아이콘·진행 표시·부하 단계가 디자인 테마 축 위에 한 벌씩 얹혀, 새 효과·새 무늬·새 메뉴 아이콘을 더할 때 데이터 행만 더한다. 앱 정체성(작업 표시줄 아이콘)을 바로잡는다.
- 비용은 이렇다. 제목 탭 기본 표시가 아이콘+제목으로 바뀌어 탭 폭과 스크린샷 기대값이 바뀐다. 설정 키가 늘어난다(`ui.*`·`theme.style.*`).
- 위험은 이렇다. UI 스레드 차단 중 렌더 스레드 회전(미검증), 클립 애니메이션의 웹·Android 비용(미확인), 작업 표시줄 아이콘의 근본 원인(미확인)은 구현 단계 실측으로 판정하고 결과를 사실로 남긴다. 성능 기준은 PC 비움 때만 재며 그전에는 측정 보류(합격 아님)다.

## 5. 재검토 조건

- 사용자가 D-569~D-597 가운데 어느 행이든 대안을 고르면 그 행의 되돌리기와 바꾼 문서를 따라 고치고 새 결정 번호로 기록한다.
- 성능 실측(PERF-17)에서 중간 묶음이 PERF-12·13·02 기준을 못 맞추면 21 의 효과 단계 표와 D-593 을 함께 고친다.
- UI 스레드 차단 중 회전이 멈추는 것으로 실측되면 23 에 한계를 사실로 적고 사용자에게 보고한다. 계약을 완화하지 않는다.
- 셸 메뉴 ID 를 배정하면 셸 창 아이콘 고정 키(`shell.<이름>`)를 메뉴 ID 기준으로 바꾼다(TODO-659).

## 6. 개정한 이전 결정

- 결정 134(ADR-118)의 `depth.open` 은 열기 효과 정본 자리에서 읽기 전용 옛 별칭으로 바뀐다(D-569). ADR-118 본문은 결정 당시 서술이라 고치지 않고 현행 규칙은 18 §3 과 21 이다.
- `../../09_화면설계/01a_화면설계_공통원칙_끌기경량크롬.md` §2 의 '이동하는 동안 그림자를 끈다' 는 옵션의 기본값으로 바뀐다(D-589, 사용자 원문 y4).
- 18 §7 의 열기 효과 성능 기준은 04/03 §6.4 PERF-12 로 옮긴다(D-594).

## 개정 이력

- 2026-11-22 신설 — 결정 143(143-1~143-7)을 기록했다. REQ-112~REQ-116 을 근거로 두고 D-569~D-597 을 발급했다.
