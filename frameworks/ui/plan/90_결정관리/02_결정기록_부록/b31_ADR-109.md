## ADR-109. GPU 모드 3경로·자동 감지·실패 폴백과 개인 플래너 진입점·Pd 전환 깔때기 (결정 125, 2026-11-14)

### 1. 맥락

- 2026-11-14 사용자가 새 요구 2건을 냈다. 원문(요약하지 않고 그대로 옮긴다)은 다음과 같다. 원문 정본은 `../../00_요구사항/01a_사용자요구사항_원문_2.md` §3-0h 다.
  - "gpu를 사용할수 없는 pc나 환경(원격 등) 이라도 문제가 없도록 만들자. 우선 기동시 파라미터로 gpu모드를 끌수있어야하고 메인프로그램에서도 on off할수 있어야한다. 혹시 메인에이전트도 gpu기반이라 메뉴조차 보이지 않는다면 단축키를 통해 on off 스위칭 될수 있어야한다"
  - "개인만 대상으로 하는 무료서비스용 플래너+tofo+스케줄관리+알림+아이디어스케치+계산기+지도연동+여행계획+수강표+일정표+공부계획+등.. 을 서비스하는 프로그램도 같이 만들자. 물론 해당 기능은 동일한 구조로 pd에도 포함되어야하며, 마케팅용도로 개인들에게 갠편하게 사용하다가 좀더 복잡하고 파워풀한 기능이 필요할때 pd 무료계정으로 전환시키고 거기서 더 확장으로 유료계정으로 전환을 유도시키는 구조가 되어야한다"
- 'tofo' 는 할 일(todo), '갠편하게' 는 간편하게로 읽었다.
- GPU 기존 정본: 05 §3.5 는 설정 키 `GpuMode`(`Auto`/`Off`), 기동 파라미터 `--gpu auto/off`(이번 실행만, 저장 안 함), 시스템 메뉴 'GPU 가속모드 ▶ 자동/끄기'(저장 후 재시작 대화)를 정했다. 렌더 모드는 프로세스당 1회라 실시간 전환은 불가하다. 전역 단축키, 원격·GPU 부재 감지, 실패 폴백은 없었다(PLT-11 은 빠른 캡처 전용 `Ctrl+Alt+Shift+P`).
- 외부 근거(2026-11-14 조회): Avalonia `RenderingMode` 는 순서 목록이고 처음으로 초기화에 성공한 백엔드를 쓰며, 기본값 AngleEgl → Software 에서 Software 는 원격 데스크톱·GPU 없는 VM 대비 대체로 두라고 권한다(https://docs.avaloniaui.net/docs/platform-specific-guides/windows, https://api-docs.avaloniaui.net/docs/T_Avalonia_Win32RenderingMode). 따라서 초기화는 성공했으나 화면이 검게 나오는 경우는 Avalonia 가 스스로 대체하지 않는다(추정 — 문서에 대체 기준이 없음, PoC 확인 TODO-149). Windows 원격 세션은 `GetSystemMetrics(SM_REMOTESESSION)` 이 0 이 아니면 원격으로 본다(https://learn.microsoft.com/windows/win32/termserv/detecting-the-terminal-services-environment). 신뢰성 한계와 GPU 없는 VM 판정 신호는 미확인이다(TODO-149).
- 플래너 기존 정본: 결정 124(ADR-108)는 개인 모드를 별도 앱이 아니라 같은 Pd 의 규모 모드 0단계 Personal 로 정했고, 대안 ① '별도 개인 플래너 앱' 은 사용자 답 '같은 Pd 의 개인 모드' 로 기각했다. 이번 요구는 별도로 서비스하는 프로그램을 원하면서 '동일한 구조로 pd 에도 포함' 을 요구하므로, 기각 근거(계정·데이터가 한 제품에 있어야 함)를 지키면서 배포 입구만 하나 더 두는 방향으로 개정한다.

### 3. 대안

| 안 | 내용 | 실현 | 가치 | 위험 | 점수 | 판정 |
|---|---|---|---|---|---|---|
| A(채택) | GPU 3경로(기동 파라미터·메뉴·전역 단축키) + 원격·GPU 부재 감지 + 기동 표식 실패 폴백 | 4 | 5 | 2 | 10 | 채택(사용자 요구 3가지 모두 충족) |
| B | 실행 중 GPU 실시간 전환 | 1 | 4 | 5 | 0.8 | 불가(렌더 모드는 프로세스당 1회 — 기존 §3.5) |
| C | 기동 파라미터만 유지 | 5 | 2 | 3 | 3.3 | 기각(요구 ③ '메뉴조차 보이지 않으면 단축키' 미충족) |

| E | 별도 코드베이스의 개인 플래너 앱 | 2 | 3 | 5 | 1.2 | 기각(전환 때 데이터 이관 필요, 두 벌 유지 — ADR-108 대안 ① 기각 근거 유지) |
| F | 별도 배포 없이 같은 Pd 앱 안 '플래너로 시작' 모드만 | 5 | 3 | 2 | 7.5 | 대안 유지(D-323 대안 — 사용자가 배포 이름을 원하지 않으면 전환) |

- 점수는 실현 × 가치 ÷ 위험이다. GPU 는 A − C = 6.7, 플래너는 D − F = 2.5 로 차이가 2.0 이상이라 A·D 를 고른다.
- B 를 버린 이유 — 렌더 모드는 프로세스 시작 때 한 번 정해지므로 바꾸려면 재시작이 필요하다. 3경로 모두 '저장 + 재시작' 으로 통일한다.
- E 를 버린 이유 — 개인 계정이 Pd Free·Professional 로 넘어가거나 기업 테넌트에 초대받을 때 계정·데이터가 한 제품에 있어야 한다(ADR-108 근거 그대로). 코드를 두 벌 두면 '동일한 구조' 요구를 지키기 어렵다.
- F 를 대안으로 남긴 이유 — 마케팅 입구로서 별도 이름이 유리하다는 판단은 추정이며 브랜드는 사용자 결정이다(D-323).
- 빼낸 것(YAGNI) — 새 기능 ID·화면 ID·메뉴 ID·테이블·이벤트, 날씨·가계부 같은 '등' 확장 위젯(개인 팩 템플릿 추가로 열어 둠), 전환율 목표값(계측 뒤 — TODO-150), 지도 공급자 확정(TODO-151).

### 4. 결과

- 좋은 점: 화면을 못 봐도 빠져나올 길이 넷(기동 파라미터·안전 모드 바로가기·전역 단축키·실패 폴백)이 되고, 원격·GPU 없는 환경은 사용자가 손대지 않아도 이번 실행만 소프트웨어 렌더링으로 뜬다. 플래너는 코드·데이터 한 벌로 마케팅 입구를 하나 더 얻고, 전환 때 옮길 데이터가 없다(데이터 이관 0건).
- 남긴 과제: TODO-149(GPU 폴백 PoC — 원격 감지 신뢰성·VM 감지·기동 표식 폴백·전역 단축키 충돌·렌더링 초기화 전 단축키 수신 방식·웹 `?gpu=off` 실측), TODO-150(개인 플래너 진입점 설계 선행 — 스토어·설치본 등록 형태, 전환 계측, 플래너 화면 ID 메뉴 등재), TODO-151(지도 I-49 공급자 공식 조사·위치정보 법령 확인 뒤 D-326 확정).
- 새 판단 D-318~D-328 11건은 `../01_결정대기_부록/d318_결정125_확인대기.md` 에 확인 대기로 두었다. 기능 236건은 그대로이고 I-49 는 후보다.
- 비용: 기능 수는 늘지 않는다. WBS 는 WBS-M2-52 증분과 새 행 WBS-M4-49(GPU 폴백)·WBS-M4-50(개인 플래너 확장)이고 일수는 추정이다(31a §13).
- 위험: 원격 감지가 일부 환경에서 틀릴 수 있다(TODO-149). 실패 폴백 1회 기준은 기동 중 강제 종료를 오탐할 수 있어 알림의 [GPU 다시 켜기]로 되돌린다. 플래너 제품 이름은 사용자 확인 전이다(D-323).

### 5. 재검토 조건

- D-318~D-328 에서 사용자가 다른 선택지를 고르면 해당 항목(125-2~125-8)을 개정하고 이 부록 끝에 개정 이력을 남긴다.
- Windows 단축키 충돌 조사(TODO-149, D-278 방식)에서 `Ctrl+Alt+Shift+G` 가 널리 쓰이는 프로그램과 겹치면 초기 제시값을 대안 `Ctrl+Alt+Shift+F12` 로 바꾼다.
- 원격 감지 실측이 실패하거나(SM_REMOTESESSION 오판) 렌더링 초기화 전 단축키 수신이 PoC 에서 불가로 나오면 125-2·125-3 의 방식을 다시 정한다(경로 수는 유지).
- 플래너 전환율 계측(TODO-150)에서 안내 빈도·트리거가 이탈을 늘리거나 전환이 거의 없으면 D-325 초기 제시값과 125-8 깔때기를 다시 본다.
- 지도 공급자 약관·과금 조사(TODO-151)가 어댑터 방식이나 무료 플래너 제공과 맞지 않으면 D-326 과 I-49 를 다시 정한다.

### 6. 옵션

- 사용자 옵션 — `GpuMode`(렌더링 모드 저장값, 초기 제시값 `Auto`), `gpu.toggle_hotkey.enabled`·`gpu.toggle_hotkey.keys`(켬 · Windows `Ctrl+Alt+Shift+G` / macOS ⌃⌥⌘G, 회사 기본 키·허용은 회사 담당자 옵션), `gpu.toggle_hotkey.restart`(`auto_5s`, 대안 `confirm`), `gpu.toggle_hotkey.restart_delay_sec`(5초, 상한은 회사 담당자 옵션), `gpu.remote_auto_off`(켬, 회사 담당자 옵션으로도 지정), `planner.widgets`(오늘 할 일·일정·계산기).
- pd-admin 제품 옵션 — `gpu.failure_fallback.threshold`(1회), `gpu.safe_shortcut.install`(생성, 배포 구성), `planner.upgrade_prompt.enabled`·`planner.upgrade_prompt.max_per_week`(켬 · 주 1회, 사용자 끄기 허용), `planner.upgrade_triggers`(트리거 5종), `map.provider`(국가별 기본, 미정 — D-326).
- 회사 담당자 옵션 — `map.enabled`(켬), GPU 단축키 회사 기본 키·허용, `gpu.remote_auto_off` 회사 기본값.
- 클라이언트 settings.json 키는 기존 PascalCase(`GpuMode`·`GpuHotkey`·`GpuRemoteAutoOff`, 내부 `GpuStartMarker`)이고 점 표기는 서버·회사 옵션 이름 후보다. 고정 예외 근거는 §2 마지막 줄(무결성·위치정보 법령)이다.

### 7. 관련 결정과의 관계

- ADR-108(결정 124): §3 대안 ① '별도 개인 플래너 앱 — 기각' 을 개정(양립)한다. 개인 모드 = 규모 모드 0단계 Personal 정의와 기각 근거(계정·데이터 한 제품)는 그대로이고, 플래너는 그 모드로 고정해 여는 두 번째 진입점이다. Personal Free 한도(개인 프로젝트 3개 등)를 재사용한다.
- ADR-089(옵션화 대원칙): 이번 결정의 모든 값은 옵션이다. 예외는 §2 의 무결성·법령 항목뿐이다.
- ADR-040: 기존 시스템 메뉴·GPU 가속모드(05 §3.5)의 결정 위에 3경로·감지·폴백을 더한다.
- ADR-090(빌드 채널 원칙): 안전 모드(GPU 끔) 바로가기는 모든 빌드 채널에 둔다. 플래너 배포는 같은 코드의 진입 구성 값이며 채널 규칙을 따른다.
