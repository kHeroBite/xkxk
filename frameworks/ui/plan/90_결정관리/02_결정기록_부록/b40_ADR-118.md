# ADR-118 디자인 테마 축 신설 (결정 134, 2026-11-16)
> 작성일 2026-11-16 · 상태 **확정 전**(방향은 사용자 요구로 확정, 세부 D-373~D-384 는 권장안 먼저 적용·사용자 확인 대기)

## ADR-118. 결정 134 (2026-11-16)

### 1. 맥락

- 사용자가 색상 테마와 별개로 '디자인 테마'(아기자기·심플·화려·3D 효과 등)를 고객이 고르게 하고 여러 분야 앱을 참조하라고 요구했다(REQ-104). 진행 순서는 레퍼런스 조사 → 기술 타당성 → 요구·결정·ADR·D → 설계 → 구현 → 시험이다.
- 현재는 색 테마 내장 7종과 요소별 사용자 지정(REQ-101, ADR-115)이 있고 모양·효과를 묶어 고르는 축은 없다. 관리도구 같은 단일 인상에서 벗어나 취향별 인상을 고를 수 있어야 하되 색·접근성·성능·옵션화 대원칙을 깨면 안 된다.
- 기술 타당성은 Avalonia 12.1.4 공식 문서로 확인했다. 원근 기울기·3D 뒤집기·카드 회전목마는 가능하고(회전된 요소 히트 테스트는 시험으로 확인), 진짜 3D 공간 창 관리는 공식 미지원이다.

### 2. 결정 (결정 134)

| 번호 | 결정 내용 | 상태 |
|---|---|---|
| 134-1 | 색 테마와 직교하는 별도 축 '디자인 테마'(모양·효과 묶음)를 신설하고 REQ-104 로 등재한다. 내장 5종(기본·아기자기·심플·화려·3D 효과)이며 기본은 현재 화면과 같다(D-373) | 사용자 요구 + 권장안 |
| 134-2 | 요소 속성 합성에 디자인 테마 층 1개를 회사 값과 색 템플릿 사이에 삽입하고 REQ-101 요소 속성을 재사용한다. 효과 키(그림자·재질·장식·움직임·깊이 3종·크롬)는 설정 키 + 기본값으로 둔다(D-374) | 권장안 |
| 134-3 | 진짜 3D 공간 창 관리는 불가능으로 판정하고 대안 4종(원근 기울기 전환·3D 카드 전체 보기·페이지 3D 뒤집기·그림자)만 한다. 상호작용은 평면에서 한다(D-376) | 권장안 |
| 134-4 | 소프트웨어 렌더·움직임 줄이기·창 수 초과 때 깊이·움직임 실효값을 낮춘다(D-377·D-378). 회사 잠금은 접점만 설계한다(D-382) | 권장안 |
| 134-5 | 성능 기준(전환 p95 ≤ 300ms, 열기 ≤ ×1.15)은 초기 제시값이고 PC 미사용 구간에서만 측정한다(D-384) | 권장안 |

### 3. 대안

| 안 | 내용 | 기각·채택 이유 |
|---|---|---|
| A | 디자인 테마를 색 테마의 변형으로 두고 색 테마마다 Design 값을 채운다 | 색×모양 조합이 폭발하고 '직교' 요구에 어긋나 기각했다 |
| B | 별도 축 DesignTheme + REQ-101 요소 속성 재사용 + 효과 키 신설 | 기존 합성기에 층 1개만 넣고 색·요소별 지정과 충돌이 없어 **채택** |
| C | 디자인 테마마다 별도 XAML 테마 파일을 교체한다 | 레이어 분리·옵션화(REQ-99) 위배, 웹 트리밍 위험, 회귀 범위가 커서 기각했다 |

### 4. 결과

- 좋은 점은 색과 모양을 따로 고를 수 있고 기본(ds-classic)은 현재 화면과 같아 회귀가 없다는 것이다. 옛 프로필은 기본·빈 덮어쓰기로 읽힌다.
- 비용은 테마 모델 확장(DesignThemeId·MotionLevel·EffectOverrides), 효과 적용 층, 3D 오버레이, 편집기 탭 1개다. 새 파일은 12개 안팎이다.
- 위험은 소프트웨어 렌더에서 비아핀 변환·그림자 비용이 크다는 점(폴백으로 낮춤)과, 회전된 요소의 히트 테스트가 공식 문서에 없다는 점(확실하지 않음, 시험으로 확인하고 실패 시 평면 히트 영역으로 대체)이다.
- 이월은 움직임 수준 OS 연동(데스크톱·Android), 앱 안 배경 흐림, 서버 사용자 설정 저장(TODO-170)이다.

### 5. 재검토 조건

- Avalonia 가 3D 장면을 공식 지원하면 134-3 의 불가능 판정과 대안 범위를 재검토한다.
- REQ-100 문서가 회사 값·잠금 형식을 다르게 정하면 134-4 의 접점을 맞춘다.
- 사용자가 D-373~D-384 중 하나라도 다르게 답하면 그 D 행만 바꾼다(결정 번호 변경 없음).
- 성능 기준을 못 맞추면 기준을 바꾸지 않고 폴백 임계 또는 효과 범위를 조정한다.

### 6. 옵션

| 항목 | 기본값 | 설정 주체 | 비고 |
|---|---|---|---|
| `theme.style.id` | ds-classic | 사용자 | 회사 잠금 가능 |
| `theme.style.effect.<키>` | 비움(디자인 테마 값) | 사용자 | 희소 저장 |
| `theme.style.locked` | false | 회사 담당자(REQ-100) | PoC 는 공급자 없음 |
| `theme.style.depth.maxWindows` | 12 | 제품 설정 표 | 초기 제시값 |
| `theme.style.depth.softwareFallback` | true | 사용자 | 초기 제시값 |

### 7. 관련 결정과의 관계

- ADR-115(REQ-101 요소별 지정)의 합성 순서에 층 1개를 더한다. ADR-089·ADR-112(REQ-99)의 값은 설정 키 + 기본값 규칙을 따른다.
- 결정 125(GPU 모드)의 실제 적용값을 폴백 판단에 읽기만 한다.
